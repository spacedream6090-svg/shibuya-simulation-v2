### 0-2 「既定の道で読まれるか」の確かめ方(5 行)

1. `src/shibuya/cli.py` の argparse の既定(`--llm mock`・`--policy mock`・`--chooser nearest`・`--memory off`・`--relations off`・`--familiarity off`・`--store-memory off` ほか)と、既定が `None` の腕は各モジュールの `DEFAULT_*`/`arm()` の既定(環境変数は立っていないと仮定)を読んだ。
2. AST で src の全ファイルの import を集め、`shibuya.cli` から辿った。top-level の import だけの閉包が 152 本、関数の中の import まで含めた閉包が 232 本、どちらにも入らないのが 91 本(うち 79 本は `build/`)。
3. 関数の中の import は、`engine/run.py` の `run_day` → `engine/systems/conductor.py` → `build.py`・`table.py` のように条件なしで通る道を「はい」に数え、`if` の中(腕の判定)にあるものは腕の名を付けて「条件つき」にした。
4. 読み込まれても腕が立たないと持ち主が `None` のまま何もしないモジュール(`systems/table.py` が top で import する calendar2/3・contact・duties の層など)は「条件つき=腕の名」にした。読み込まれるだけで関数が呼ばれないものは「いいえ(import のみ)」「いいえ(定数だけ読む)」と書いた。
5. `build/` は実行時に import されない(`build/__init__.py` の docstring と閉包で確かめた)ので全部「いいえ」。src の外の呼び手は `tests/`・`tools/` を AST で数えて迷いの列と §5 に使った。

### 0-3 状態の読み方(この表での約束)

- **既定**=既定の引数のランで動く。`build/` だけは「今の構築の道(資産を作った段)で使う」の意味で使った(ランでは動かない)。
- **腕**=切替口(CLI の引数か環境変数)を立てたときだけ動く。既定が新しい道に切り替わった切替口のモジュール(`rate_rules`・`absent_processes`・`proximity`・`seat_release`・`economy_stage2`・`space/nav1`)は、中身が既定で動くので「既定」に入れた。
- **mock だけ**=mock の道のためにあるもの。既定のランは `--llm mock` なので、この 2 本は既定の道で動く(§4 の迷い 1)。
- **器だけ**=作ってあるが呼び手が無い、または呼ばれても値が空で結果に効かない。
- **研究**=計測・検査・試作。src の中に呼び手が無く、試験や道具だけが呼ぶものもここに入れた(5 区分に「試験」が無いため。§4 の迷い 2)。
- 出力を頼んだときだけ動く道具(`engine/tape.py` の `--tape`・`engine/state_codec.py` の `--state-out`)は結果を変えないので、状態は「既定」・既定の道は「条件つき」にした。

## §4 迷いの一覧

### 4-1 分類の約束そのものの迷い

1. **mock だけ と 既定**: 既定のランは `--llm mock`・`--policy mock` なので、mock の道=既定の道。docstring が「mock 専用」と書く `agents/schedule.py` と `llm/mock.py` だけを「mock だけ」にし、既定の道は「はい」にした。mock の道で動く他の部品(`engine/decision/ports.py` の `MockPort`・腕の層の仮のモデル)は、それぞれの腕に入れた。
2. **研究 と 試験**: 5 区分に「試験」が無い。src の中に呼び手が無く試験だけが呼ぶもの(`engine/systems/overrides.py`・`static_check.py`・`engine/rng_audit.py`・`core/serialize.py`・`engine/bridging/scan.py`・`world/processes/circularity.py`・`constitution.py`)は「研究」に入れた。「器だけ」とも読める。
3. **1 ファイル 1 領域と `engine/systems/*`**: 系のファイル(body・perceive・judge・remember・talk・decide・world・act)は中身が心・世界・社会の器・道具と口の呼び出しだが、run_day を割った進行役の一部として全部 runtime に置いた。中身に合わせると runtime → 他領域の辺の一部が領域の中の辺になる。
4. **core の置き場**: `core/*` は runtime に入れたが、`build/` を含む全領域が使う基盤。`core/wage_formula.py` だけは中身で経済に入れた。包みを分けるときは「基盤」を 10 番目の領域にするかが論点になる【推測】。
5. **切替口のモジュール**: 既定が新しい道に切り替わった切替口(`rate_rules`・`absent_processes`・`proximity`・`seat_release`・`economy_stage2`・`economy_rules`・`space/nav1`)は「既定」、既定がまだ旧道の切替口(`regional_clock`・`speech_clock`・`step_scope`・`decision/layer`・`speech/layer` ほか)は「腕」にした。`batching.py` は既定の幅でも窓で回すので「既定」。
6. **読み込まれるが動かない腕**: `engine/systems/table.py` が calendar2/3・contact・duties・experiment の層を top で import するので、既定のランでもこれらのモジュールは読み込まれる。持ち主が `None` で何もしないため「条件つき」にした。「読まれるか」を import の意味にとると「はい」になる。
7. **照合が薄い**: src の中で照合に入るのは 5 本だけ。anchors の名のファイル(`economy/anchors.py`・`engine/energy.py` の `load_anchors`)は照合の錨ではなく入力の値なので経済と心に入れた。build の検収の段(`build/audit/*`・`build/pop/w21_check*`・`w21_sources`)は構築に入れた。
8. **agents/ の割れ方**: `agents/state.py` は心、`agents/population.py`・`weekly.py`・`schedule.py` は構築(実行時のデータの読み口)に分けた。包みとしては 1 つの `agents` なので、分割の議論では 1 つに戻すかも論点。
9. **docstring と既定値の食い違い**: `economy/stage2.py` の docstring 1 行目は「既定 off」だが、`engine/economy_stage2.py` の `DEFAULT_ARM` は on(docstring も 2-4 版上げ 2 回目で既定 on と書く)。表は既定値の側に合わせた【推測: stage2 の docstring が古い】。
10. **cli の既定と run_day のライブラリ既定**: 表は cli の既定に合わせた。`run_day` を直接呼ぶ試験の既定は違うことがある(例: `engine/energy.py` は「CLI の既定 energy・run_day のライブラリ既定 v1」と書く)。
