## 0. 読み方

- 各行 = **旧名 | 新名(候補) | 意味(1 行) | 衝突していた相手 | 定義の出所**。番号は参照が壊れるので**保持**し、記号を語に置き換える。
- 「衝突」= 同じ記号が別の意味で使われていた相手。これが分かりにくさの主因なので、衝突している家族から先に直す。
- 英語のタグ・技術語(expedient / mechanism / holdout / ablation / checkpoint / seed / JSD / tick / tok など)は**残す**(§4)。初出で日本語の説明を添える。
- 記録(devlog・答申・親報告・受入報告)は**書き換えない**。旧名で読めるように本書に旧名を残す。

## 1. 命名の方針(候補)

1. **1 文字+番号 → 語+番号**。例: D-101 → 決定 101、U-4 → お願い 4、R-41 → 答申 41。
2. **同じ記号の多義は語で分ける**。例: T2 → 熟慮層 / 検証モデル / 決定論検査 B。
3. **造語は「何をするか」の語へ**。例: 起床 → 呼び出し、繰り延べアービタ → 呼び出しの割り当て。
4. **家族(アジェンダ・予算行・台帳)は家族名を先に置く**。例: M4(記憶アジェンダ)→ 記憶 4、M8(予算)→ メモリ予算(RSS)。
5. **コード識別子・CLI フラグ・manifest 欄名・parquet 列名は変えない**(ハッシュと golden が動く)。文書側で対応を書く。

## 5. 運用規則(候補・確定後に CLAUDE.md §6 へ)

1. 読者向け文書(README・概要 2 本・決定一覧・PENDING・STATUS・CLAUDE.md・決定台帳の見出し・以後の新規設計書)は本書の**新名**で書く。旧名は初出で括弧併記(例: 呼び出し(旧: 起床))。
2. 記録(devlog・答申・親報告・受入報告・bench)は書き換えない。旧名は本書で引ける。
3. 新しい語を作るときは本書に行を足してから使う。1 文字+番号の新設は禁止(語+番号にする)。
4. コード識別子・CLI フラグ・manifest 欄名・parquet 列名は対象外。変えるなら版上げとして別途判断。
5. 置換の順番: 用語集の確定 → README・概要 → 決定一覧・PENDING・STATUS → CLAUDE.md・決定台帳の見出し。各文書の置換は親が差分で示し、1 commit ずつ。

## 6. 確認の進め方

家族ごとに「候補どおり / 別案」で答えてもらう。順番(衝突の大きいものから): (1) 認知・呼び出し(§2-3)→ (2) 判断と記録の番号(§2-1)→ (3) 実験・検証(§2-2)→ (4) 世界・工程・予算(§2-4)→ (5) アジェンダ(§2-5)→ (6) 混同しやすい語(§3)→ (7) 運用規則(§5)。
