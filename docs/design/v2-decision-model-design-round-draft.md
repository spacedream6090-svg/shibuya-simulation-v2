## 1. 位置づけと決まっていること

本書は、決定モデルについて決まっていない事項だけを問いの形に並べたものです。次の事項はユーザーが決めたので、問いません。

### 1-1 指示書 10-03 §7-4 で決まっていること(決定モデル)

- 決定モデルは Jev 型です。選択・点数・はい/いいえを確率つきで返し、文章を生成しません。
- 分担は、日常の判断が決定モデル、会話と高度な判断(計画・内省・想定外の出来事)が LLM です。
- 今の LLM の呼び出し約 270 万回/日のうち、移動が 53%、購入が 39% です。ほとんどは決定モデルに移せる判断です。
- 有力な候補は Cloudflare の Clef(27B)と Clef-flash(9B)です。自前で動かして、厳密モード・結果の公表・自前のデータでの追加学習を自分で管理します。
- 本家 Jev(TypeSafe AI)の API は 39 万体の主役に向きません。使うなら比較の腕か、まれな判断用です。
- Jev の出力を真似て作ったモデル(JEV-27B など)は権利面のリスクがあるので、採用の前にユーザーへ相談します。
- Jev 型の「較正」は答えが正しい確率に合わせたもので、「人がその行動を選ぶ割合」とは別物です。どのモデルでも、人の行動データ(PT 2018 の行き先や手段など)で確かめて合わせます。
- 全員を 10 秒ごとに判断させるのは Jev 型でも重すぎます。「常時の見張りは Jev 型から蒸留した小さなモデル、実際の判断は Jev 型」の 2 段を候補にします。
- 画像による知覚は中心に入れません。視覚が本質の判断に絞った将来の腕の候補として残します。

### 1-2 指示書 10-03 §7-3 で決まっていること(認知の層)

- System 2 は夜の内省だけでなく、日中も必要なときに呼ばれます。
- 習慣は 2 つの形を両方入れます。繰り返しの自動化(決定モデルが LLM を呼ばずに選ぶ)と、本人が書く「もし〜なら〜する」(実行意図)です。後者は System 2 が書き、カレンダーか計画の記憶に置きます。本人が置くアラームもこの形です。
- 上の層を呼ぶかは本人(決定モデル)が判断します。決定モデルの選択肢に「よく考える(上の層に任せる)」を加えます。
- 驚きは「その人自身の予想からのずれ」です。エンジンは保存された予想と今の観測を並べて入力に載せるだけで、ずれの大きさは計算しません。
- 決定モデルは 1 回の計算で「どれくらい意外か(0〜5 の点数)」と「何をするか(行動の選択肢+よく考える)」の 2 問に答えます。
- 葛藤(出力の分布で 1 位と 2 位が拮抗している度合い)と驚きの点数は毎回記録します。確かめる材料と、蒸留の教師データになります。
- 話す・書くと、初めての状況は、必ず上の層を通します。
- 「よく考える」を選ぶ割合が人の熟考の頻度と合っているかを監視します。学習なしだと「いつも考える」か「まったく考えない」に偏るおそれがあり、09-25 §4.4 の蒸留の仕組みで育てる前提です。
- エンジンのコードに残る判断は、System 1 の「そもそも決定モデルを動かすか(何か変化があったか)」だけです。全員に常時かけられるようになれば、これも無くします。

### 1-3 ほかの節で決まっていること

- §7-2: 予定を考え直すかどうかを含めて、決定モデルが常に判断します。コードの閾値で上の層を起こす形(09-25 §5.3)はやめ、コードは「何が変わったか」「どんな予定が近いか」を渡すだけにします。
- §9-3: 「まで」の長さは推定の仕組みを作りません。いつやめるかも本人がその場で決めます。決定モデルが入るまでは 30 分固定のままにし、宣言します。
- §6 ⑨ (c): エンジンは常に決定論にします。LLM と決定モデルの出力は常に記録します。受入の試験・腕の比較・反実仮想の比較は厳密モード(バッチ不変の設定・決まった seed)で回し、長い観測のランは記録だけにします。manifest にモードを記録します。
- 09-25 §4.3・§4.4: 層は「変化の検出(コード)→ System 1.5(決定モデル・差し替え可能な枠)→ System 2α(小 LLM)/ 2β(大 LLM)」です。見張りの教師ラベルは「上の層を呼んだ結果、行動が下の層の答えから変わったか」です。
- 09-26 のユーザー決定 3: System 1.5 の仮の中身は (G)(自前艦隊の logprob 判断)で、出力は行動ごとの確率の分布に固定します。GPU が無い間は同じ形のモックで開発します。
- D-119(IMPLEMENTED #58): System 1.5 の古典モデル(社会生活基本調査の事前分布+食事の門+満足化の選び手・LLM 0 呼)が `--policy classical --chooser classical` の腕として入っています。層の記録 `decision_layers` は全ランで出ます。選び手の口 `Chooser.probs`(候補 → 和 1 の分布)は IMPLEMENTED #52 です。

以下の問いは、この決まった形の中で残っているものだけです。

### 2-1 重い問い

#### DM1 モデルの選択と、ライセンスと権利面の整理

- 何を決めるか: 決定モデルの主役の候補と、比べる相手。採らないモデルとその理由。
- 選択肢
  - (a) Clef-flash(9B)を主の候補にし、Clef(27B)を大きい側の腕にする(指示書 §7-4 の候補どおり)。
  - (b) Clef-flash と、Kev-9B または decider-4b を同じ場面で並べて測ってから主を決める(R-83 §7-2 H8-2 の親の案)。Kev と decider は追加学習の手順を公開しています。
  - (c) Clef(27B)を主にする。
  - (d) 主は 09-26 の決定どおり (G) のままにし、Jev 型は腕として測る。
  - どの案でも共通の扱いの候補: 本家 Jev の API は比較の腕だけ(DM12)。JEV-27B と JEV-27B-VL は採らない(採るならユーザーに相談)。OpenJev(openjev/openjev)は重みが非商用なので採らない。
- 材料
  - Clef と Clef-flash は Apache-2.0 です。基盤は Clef が Qwen3.8-27B、Clef-flash が Qwen3.5-9B です。学習データは「社内の合成データ」と書かれ、Jev の出力を使ったという記述はありません。ただし否定の明記ではありません(R-83 §2-1・§2-2)。
  - Clef と Clef-flash の決定論・バッチ不変・処理量(件/秒/GPU)・日本語の評価・ECE・選択肢の上限は、どれも空欄です(R-83 §8 の 5〜7)。公表されているのは遅延だけで、中央値 209.3 ms(27B)・38.8 ms(9B)です。測定の GPU と同時実行数は書かれていません(R-83 §2-1・R-73 §6-2)。画像は入ります(R-83 §2-1)。
  - Kev(0.8b・4b・9b・27b)と decider(2b・4b・12b・35b-a3b ほか)は Apache-2.0 で、「Jev の出力は使っていない」と明記しています。decider は「English only.」です。decider-12b の基盤は Gemma-4-12B-it で、基盤側の条件は R-83 に記載がありません(R-83 §2-1)。
  - JEV-27B と JEV-27B-VL は「Jev 1.13 の出力分布 498,010 行」で学習したと自分で書いています。重みは Apache-2.0 ですが、教師データの取得が TypeSafe の基本契約 §2.3(b)(出力で蒸留しない)に当たるかどうかは、R-83 は判断していません(R-83 §2-2)。
  - OpenJev(openjev/openjev)は重みが CC BY-NC 4.0 で、商用化の構想と衝突します(R-83 §2-2)。razorback16 版の Open-Jev は 24 GB が要る・精度の数値なし・決定論の保証なし、の 3 点で既に採らないとしています(OpenJev のノート)。
  - 第三者の評価(Decision Index 0.2.1)では、27B 級の自前ホストのモデルが本家 Jev(57.91)と同じ帯にあります。4B 級は 40 前後、1B 未満は 20 未満です(R-83 §3-1)。評価は英語中心で、日本語を含む評価を出しているのは OpenJev だけです(4 言語の合計)(R-83 結論 2)。
  - 公開の問題の点数だけで選ぶと、公開の問題に合わせたモデルを選ぶおそれがあります。decider-4b v2 の yes/no で公開 43 対 封印 19 の例があります(R-83 §3-2)。
  - (G) は vLLM の 8B 級の 1 トークン目の確率で、`VLLM_BATCH_INVARIANT=1` で logprobs 32/32 一致を実測済み(B14)です。弱みは選択肢の表層形の競合で、較正は後処理が要ります(R-83 §5・OpenJev のノート §5)。
- 影響する段と文書: 段 J1 / 09-26 のユーザー決定 3 / D-101 (ii)(iii) / 実装計画書の依存の一覧 / ライセンス台帳(重みを取得するとき)。
- 親推奨: (b)(Clef-flash と Kev-9B/decider を同じ場面で並べて測ってから主を決める)。JEV-27B は採らない(Jev の出力で学習と自己申告=権利面)。(d) の (G) は基準の腕として残す(DM6)。

#### DM2 最初に置き換える判断・置き換えの順・切替口・既定の切り替え

- 何を決めるか: LLM から決定モデルへ最初に移す判断の種類。次に移す順。切替口の形と、既定を切り替える時期(版上げ)。
- 選択肢(最初と順)
  - (a) 購入(39%)→ 移動(53%)の順(R-83 §7-2 H8-3 の親の案)。購入は選択肢が店と品目で閉じていて、正しさの較正と人の割合のずれを測りやすい、という理由です。
  - (b) 移動 → 購入の順。移動は行き先と手段を PT 2018 で照合できます(R-83 §7-2 H8-3)。
  - (c) 草案の案(未リサーチ)。購入と移動を同時に入れ、腕の比較だけ先に行い、既定の切り替えは照合データのそろう移動から行う。
- 選択肢(切替口と版上げ)
  - (d) 判断の種類ごとに切替口(`--decider` のような口を種類ごとに持つ)を付け、既定を切り替える種類ごとに版上げを 1 回行う。
  - (e) 草案の案(未リサーチ)。購入と移動を 1 回の版上げにまとめる。
- 材料
  - 呼び出しの量は、移動 143 万・購入 105 万、合わせて約 248 万回/日です(R-83 §7-1・推測)。
  - 購入の人の行動データ(個票)を v2 が持っているかは確認できていません(R-83 §4-3・§8 の 19・空欄)。移動は PT 2018 の行き先と手段の選択があり、D-119 で社会生活基本調査の事前分布も使っています(R-83 §4-3)。つまり (a) は「測りやすさ」が先、(b) は「照合の相手」が先です。
  - 購入の場面の人の錨としては、棚の前の滞在 平均 12 秒、選んだ品の値段を見た 58%、他の品の値段を比べた 22% 未満があります(R-88 §2-1 B4・○)。これは熟考の割合の錨で、選択の分布の錨ではありません。
  - 選び手の口 `Chooser.probs` は既にあり、D-119 の古典モデルが同じ口の 1 実装です。(G) は同じ口の別実装として GPU 後に比べる予定でした(空腹と古典モデルの草案 §2-2 の 1)。
  - 手段選択の微調整で、離散選択モデルと機械学習の分類器を上回った先行があります(Alsaleh & Farooq 2025・JSD 0.000245・R-83 §4-2・△)。
- 影響する段と文書: 段 J2〜J4 / 版上げの台帳 / checkpoint の版 / PENDING §2。
- 親推奨: (c)(購入と移動を同時に腕として比べ、既定の切り替えは照合データのそろう移動から)。切替口は (d) 判断の種類ごと・版上げも種類ごと。

#### DM3 較正の形(人の選択の割合に合わせる)

- 何を決めるか: Jev 型の確率(答えが正しい確率)を、人がその行動を選ぶ割合に合わせる方法。使う人の行動データと、較正用と封印用の分け方。
- 選択肢
  - (a) 温度のスケーリングだけ(1 パラメータ)。
  - (b) 分布に合わせる損失で追加学習する(LoRA)。調査の回答分布に 1 トークン目の確率を合わせた Cao ほか 2025 の形です(R-83 §4-2・§7-2 H8-4 の親の案)。
  - (c) 草案の案(未リサーチ)。モデルは触らず、出力の分布に状況の区分ごとの定数を掛けて、較正用データの周辺分布に戻す。D-119 の L7(乗数の後に時間帯ごとの定数で周辺分布を事前分布に戻す)と同じ形です。
  - (d) 較正せず、照合で外れ方を記録するだけにする(比較の基準として)。
- 材料
  - 温度 1 つでは確信の順位は変わりません(Kev「Calibration is a single temperature. It can't reorder confidences」・R-83 §4-2)。割合の形を直すには足りない場合があります。
  - 正しさに較正したモデルは、答えが割れる問いで確信の側へ寄る、という読みは推測で、直接測った文献は見つかっていません(R-83 §4-1・§8 の 16・空欄)。本家 Jev の ECE は Decision Index で 0.074(確信の平均 0.81 に対して正答率 0.74・自信過剰の側)です。ECE は評価セットで 3 倍以上動きます(Laya のカードでは Jev 0.246)(R-83 §3-1)。
  - Jev 型のモデルを人の行動データで較正した例と、社会シミュレーションで使った例は見つかっていません(R-83 結論 4・空欄)。近い先行は、分布に合わせる微調整(Cao ほか 2025)、手段選択の微調整(Alsaleh & Farooq 2025)、行動実験 1,000 万選択での微調整(Centaur)です(R-83 §4-2・どれも △)。
  - LLM は平均が合ってもばらつきが小さすぎることがあります。Bisbee 2024 では係数の 48% が実データと有意に違い、そのうち 32% は符号が逆でした(R-88 結論 1)。
  - (c) の形は、較正用データでは周辺分布が構成上一致するので、照合は封印用データでしかできません(空腹と古典モデルの草案 §2-2 の A3 注と同じ帰結)。
  - 追加学習ができるかはライセンス次第です。Clef・Kev・decider は Apache-2.0 で、Kev と decider は手順を公開しています(Kev-4B の学習 1 回が H100 で約 1 ドル)。本家 Jev の出力を教師にすると基本契約 §2.3(b) に当たります(R-83 §1・§2-1)。
  - 使える人の行動データは、PT 2018 の行き先と手段、社会生活基本調査の活動の事前分布です。購買は空欄です(R-83 §4-3)。較正用と封印用は先に分けます(CLAUDE.md §4)。
- 影響する段と文書: 段 J2 / パターン台帳(較正と封印の行)/ D-119 の較正データ / ライセンス台帳。
- 親推奨: (b) LoRA で分布に合わせる(Cao 2025 の形)を本線にし、(a) 温度のスケーリングを比較の腕、(d) 較正なしを基準に置く。(c) は照合が封印データでしかできないので採らない。追加学習の可否はモデルのライセンスで確かめる(DM1)。

#### DM4 入力の形と長さ・何を載せるか

- 何を決めるか: 決定モデルの 1 回の入力に何を載せるか。入力の長さの目標。人ごとの部分と共通の部分の分け方。入力の言語。選択肢の数の上限。
- 選択肢(長さ)

#### DM5 「よく考える」と上の層を呼ぶ規則・驚きの点数・葛藤の記録

- 何を決めるか: 「よく考える」を選択肢に入れる形。必ず上の層を通す例外(話す・書く・初めての状況)の判定の仕方。驚きの点数の水準の言葉。葛藤の測り方と記録の欄。

  - (e) 1 位と 2 位の確率の差(§7-3 の定義どおり)。
