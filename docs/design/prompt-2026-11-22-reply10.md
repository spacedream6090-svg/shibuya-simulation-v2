### 3-1 トークンの削減(記録 2-88 の A〜E)

1. **CLAUDE.md に決まりとして書く:**
   - 同時のサブは 4 本まで。
   - 発注文で節と行を名指しする。「全部読む」と書かない。
   - 形の確かめ(改行・パス・欄・数)と小さな直しは、サブを起こさず台本で行う。
   - 研究は 2 段にする(先に要点と出典の一覧、要る所だけ深く読む)。
   - 検収は台本を先に回し、モデルの検収は判断が要る所だけにする。
   - 第 N の区切りごとに、親は引き継ぎのファイルを書く(ユーザーが `/clear` する)。
2. **CLAUDE.md を軽くする:** 経緯・日付・理由を別の文書(例 `docs/reference/claude-md-history.md`)に移し、決まりの文だけを残す。移した後、決まりの文が 1 つも消えていないことを台本で確かめ、前後の行の対応表を報告に付ける。
3. **記録の索引:** 保管用の記録について、1 行 1 決定(ID・題・状態・行の範囲)の索引を台本で作る(`docs/reference/wallbounce-index.md` など)。新しい記録ができたら、同じ台本で足す。
4. **仕様書への写しは、次の作業で実装する項目と、研究で見つかった誤りの直しだけにする。** 決定の正は記録です。この決まりを CLAUDE.md と仕様書の README に書く。

### 3-2 試験の効率化(記録 2-88)

1. 文書だけの commit では重い試験を回さない(ランが実行時に読む文書 5 本が変わったときは回す)。
2. 作業の枝は PR のときだけ CI を回し、同じ commit で 2 回回さない。main は push で回す。
3. CI を途中で見に行かず、終わるまで待つ命令で 1 回だけ結果を受ける。
4. 手元では、変えた所に関わる試験だけを回す。全部は PR・群の終わり・版の札で回す。
5. byte-check は、ランに効くファイルが変わったときだけ回す。
6. 組ごとに 1 回、試験ごとの秒数を測る(`--durations=0`)。g1 を時間で割り直して、組を 4〜5 に均す。並列の数は実行機の CPU の数に合わせる。
7. 遅い上位 10〜20 本を速くする。作り直しを使い回す・人数を減らす・大きな規模が要るものは slow へ。速くする試験ごとに、何を守っているかを試験の地図で確かめ、大きな規模の版は slow に残す。
8. 測った時間と、直した前後の CI の待ち時間を報告に書く。
