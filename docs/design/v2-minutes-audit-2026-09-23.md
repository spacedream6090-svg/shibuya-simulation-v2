# 認知・社会アーキテクチャ議事録の監査と v2 への組み込み評価(2026-09-23・第255・親 Fable 5.1)

> **位置づけ**: ユーザーが別チャット(Fable 5.1)で積み上げた「渋谷 LLM 社会シミュレーション v2 認知・社会アーキテクチャ議事録」(54 節・以下「議事録」)を、v2 の**決定台帳・契約書・設計書・実装**に照らして監査したもの。目的は 3 つ。(1) 議事録の各主張が v2 の既決事項と**同じか・違うか・新しいか**を 1 行ずつ判定する。(2) 新しいものについて**組み込む妥当性と実装方法**(場所・状態・予算・切替口・受入・腕)を書く。(3) 議事録の中の**事実誤認・根拠なしの数値・v2 の既決やユーザー選好との衝突**を指摘する。
> **監査の根拠**: 本書の「v2 側」の記述はすべてリポジトリ内のファイルから取った(出所を相対パスで併記)。先行研究との照合は答申 R-41(個体側)・R-42(社会側・方法論側)を親が一次確認したうえで §3 に書く(親検収の印がない行は答申の申告)。議事録の原文はユーザー提供(2026-09-23)。**リポジトリへ写すかはユーザー判断**(写す場合の置き場: `docs/design/inputs/`)。
> **読み方**: 議事録の節番号は「§n」、v2 の決定項は「D-n」、本書の実装項は「I-n」、本書で新設する決定項は「D-103〜」。

## 0. 結論(先に)

1. **議事録の骨格は、v2 の決定台帳が 2026-08-28〜09-07 に決めた認知 3 層(案B′)を、別の語彙で再導出したものである。** 対応は 表 1-1 のとおり: 議事録の **System 1 = T0 習慣+T1 速い判断**、**再考層(議事録では「System 1.5」「Jev」)= T1→T2 の昇格**、**System 2 = T2 熟慮**。議事録の原則 A(世界≠知覚≠信念)・C(意図≠世界の変化)・G(壁時計≠シミュ時間)・H(思考中も世界は止まらない)・I(更新順序を因果にしない)・K(正典状態にモデル固有の隠れ状態を入れない)は **v2 に実装済み**(G/H は L1 レーン=1 tick のみ)、原則 F(3 層)・J(数値は実験対象)・L(熟慮を System 1 へ焼く)は**決定済み(仮)**。二つの対話が独立に同じ形へ収束したことは設計の妥当性の傍証だが、**語彙が二重化した**。このまま持ち込むと、決定台帳と設計書が二つの言葉で同じものを指す。→ **第一の推奨: 新しい層は作らず、語彙対応表(表 1-1)を決定台帳に 1 行で入れる**(D-103)。
2. **議事録が v2 に無いものを足しているのは 9 点**(§1-2)。うち直ちに価値が高いのは 3 つ。**(a) 予測状態と予測誤差を一級の量にする**(認知設計書 §3 の昇格スコア S(e) の「surprise」項は名前だけで実装ゼロ・expedient。議事録の「自分の計画から導いた期待 vs 実際」がその**機構的な定義**になる)。**(b) 経験ログ**(文脈・方針・意図・予測・結果・誤差)をモデル非依存に残す(D-101 の学生の教師データと、予測学習の入力になる)。**(c) 結果の鮮度検査**(何の状態を見て考えたか・いつまで有効か)。3 つとも**モックで実装でき、切替口を既定 OFF にすれば既定 checkpoint を動かさない**(I-1・I-4・I-6)。
3. **議事録の 3 か所は v2 の既決・ユーザー選好と衝突する。** (i) §22「System 1 が発話の意味(speech act・topic)まで決め、LLM は言語化だけ」= 憲法 3「表現形・宛先は LLM 出力から」・09-11 のユーザー選好「行動の多様性はエンジン規則でなく LLM から」に反する。**会話の意味は LLM(T1)に残す**(D-105)。(ii) §11〜§14 のマイクロ行動(前の人を避ける・減速・列に並ぶ・他者の軌道予測)は **v2 の宣言解像度(tick=1 分・セル 100 m 級・辺上位置)の外**。憲法 4「解像度は較正とペアでしか足さない」により、**歩行者流のアンカーデータが無い現状では作らない**。これは計算資源の問題ではなく、照合データと方法論の問題(D-106・U-9)。(iii) 「Jev」を層の名前に使う= ベンダー製品名。第242/253/254 で Jev は採らない(MCA §2.3(f)・非決定論・精度不明)。層名は「昇格(再考)」に統一。
4. **議事録の数値はすべて根拠がない**(議事録自身が「確定仕様ではない」と明記)。v2 には同じ量の**出典つきの値**が既にある: δ_think のレーン表(Rubinstein 2007)・L1 の T1 5〜20 回/T2 0.5〜2 回/人/日・M1〜M6 のバイト予算・不応期表・δ_perc の予期クラス。**議事録の数値は捨て、台帳の値を使う**(§2-3)。
5. **検証の設計(§34〜§43)は v2 の方法論と整合する**(パターン台帳ゲート・holdout 封印・事前登録・expedient の感度試験・自己修正の 3 つの輪)。新しいのは「創発妥当性」の層と仮説 H1〜H6 の形。ただし **H2(他者予測→群衆動態)は照合データが v2 に無い**(歩行者軌跡・レーン形成の実測)。取得はユーザー項目(U-9)。
6. **設計と実装の差(Explore 検査で確定・§1-3)**: 決定台帳は議事録を包含するが、**実装は T1/L1 の 1 段だけ**(レーン選択なし・T2 昇格なし・縮退実行は計数のみ)・記憶 0・関係 0・群 0・組織は経済台帳の雇用主としてだけ・社会系チャネル 3 本(知人・被注視・傍受)が no-op・信念/噂/信頼/SNS 0 件。**議事録の価値は「何を決めるか」ではなく「決めたものをどの順で実装するか」を問い直す点にある**。
7. **先行が変えたこと(第256・R-41/R-42 の親検収後)**。
   - **議事録 §28 の Agent LOD は先行に対して新しい**。群衆 LOD の 9 系統(1997〜2010)は**すべて観測者(カメラ距離・可視性)で解像度を決めている**。**エージェント自身の状況で決めた先行は無い**(R-41 Q8・Wißner 2010 の比較表を親が実読)。v2 の繰り延べアービタ(起床クラス・待ち時間・不応期)は既にその形なので、**これは v2 の独自性として外へ出せる**(未踏・論文)。
   - **休眠と復帰の要求は先行のほうが厳しい**: culling の先行は **consistency**(戻ったとき状態が正しい)と **completeness**(視野に入るべきものが入る)を明示の要求として立てている。→ **D-102(resume)の受入条件はこの 2 つの名前で書くのがよい**。
   - **再考の設計は 30 年前に実験で答えが出ている**(R-41 Q2・親が 3 本を逐語確認)。「何でも再考するのは盲目的コミットより悪い」(Kinny 1991)・「**実行時に方針を選ぶ適応エージェント**が bold/cautious の両方に勝つ」「計画費が上がるとコミットは下がる/世界が動的になるほどコミットは下がる」(Schut 2001)・「上位が生きていれば下位だけ直す」(Fox 2006: 最初の行動の一致率 **100% vs 44.3%**)。→ **I-3 は 5 値の状態機械でなく「repair か replan か」の 2 値+誤差で足りる**。
   - **議事録が本当に先行なしなのは 6 点**(R-41): 6 項の重みつき線形和 / Policy validity 5 値 / `valid_until` の鮮度検査 / 割り込み 5 状態・3 段強度 / 知覚 LOD の意味的 6 段 / **Agent 自身の状況で決める LOD**。最後の 1 つ以外は「先行が無い=良い」ではなく「**重みと段の数がそのまま設計者の指紋**」を意味する。
   - **規範は罰か負の報酬なしには立たない**(R-42 Q4・Sen & Airiau 2007 を親が逐語確認)。議事録 §30 の「驚きから始めてよい」は先行と部分的に矛盾。また議事録の「Norm = 共有期待」は Bicchieri の語では**慣習**(規範的期待が欠ける)。→ **I-9 ② の計器は「経験的期待」と「規範的期待」の 2 層で測る**。
   - **群の照合値が取れた**: 歩行者の **55%(集団 A)/ 70%(集団 B)** が集団で歩く(Moussaïd 2010・親が逐語確認・N=260/1,093 群)。→ I-9 ① 同行検出の合格線に使える。
   - **速度則の数値は空欄**(R-41 Q3)。熟慮を System 1 へ焼く先行は 4 系譜あるが、「どれだけ速くなるか」の数値は 1 つも取れていない。**v2 がここに数字を置けば設計者の指紋**になる。
   - **命名の衝突**: 「System 1.5」は心理学に用例が無いが、**2025 年の LLM 論文が同名を先取している**(親が確認)。外向きの文書では使わない。
8. **進め方(推奨順)**: ① 語彙対応表(D-103)→ ② 予測状態+経験ログ+鮮度検査(I-1/I-4/I-6・モック・既定 OFF)→ ③ D-101 の判断層(自前艦隊の logprob 判断 → 蒸留した学生)と ②を接続(学生の教師データ = 経験ログ)→ ④ 既存アジェンダ(C10 関係 R1〜R14・記憶 M1〜M16・D-102 resume)→ ⑤ 群・規範・組織は**計器を先に**(機構を足さない・I-9)→ ⑥ マイクロ層は歩行者データが入ってから(I-10)。

## 4. 組み込みの妥当性と実装方法(項目別)

> 各項に **妥当性**(憲法・契約・決定・ユーザー選好との整合)・**実装**(場所 / 状態 / tick 内の位置 / 切替口 / 受入 / 予算行 / 腕 / タグ / パターン台帳行)・**判断項** を書く。共通の前提: **切替口は既定 OFF・既定 4 種 checkpoint 不変**(退化検査)・SoA の欄は「腕でだけ確保」(記憶アジェンダ §0 の事実 3)・逐次ループ新設は P4 宣言・状態成長は D-R2-6 の YAML 5 欄。

### I-1. 予測状態と予測誤差(議事録 §5・§8 → S(e) の surprise の機構化)

- **妥当性**: 認知設計書 §3 の昇格条件は `T0→T1: 習慣の前提条件(場所・時刻・所持)が崩れた(決定論)` と `S(e)` の surprise 項を持つが、surprise の定義が無い(src に 0 件)。議事録の「自分の計画から導いた期待 vs 実際」はこれの**機構的な定義**であり、w1 を「設計者が置いた重み」から「体自身の予測誤差」に変える。憲法 6(粗くする場所は宣言して粗くする)と整合し、ユーザー選好(多様性は LLM から)にも反しない(期待は本人の W17 日課から導く=本人が書いた計画に対する誤差)。
- **実装**(モックで可):
  - **状態(SoA・腕でだけ確保)**: `exp_arrival_tick` int32(現ブロックの目的地への期待到着 tick = ブロック開始 + W3 next-hop 距離 ÷ 歩行速度)・`exp_density` uint8(目的地セルの期待 Fruin 段階 = 前日同時刻の実測 or 初期は W18 の密度場)・`pe_time` int16(実到着 − 期待・分)・`pe_density` int8(段階差)・`pe_persist` uint8(連続で誤差が閾値超の tick 数)・`unc_state` / `unc_dyn` / `unc_policy` uint8(3 分割・初期は定数=expedient)・`policy_validity` uint8(I-3)・`esc_score` float32・`esc_cooldown` uint16。**≈24 B/体 = 9.4 MB @390,067 体**(M1 の 0.08%)。
  - **tick 内の位置**: 概要 §4 の ③(変化検出 P6)の直後に**ベクトル 1 本**で更新(`searchsorted` 不要・全体一括)。逐次ループ新設なし。
  - **誤差の源**: ARRIVE/WAKE イベント(presence)・ResultCode(resolve)・密度段階(crowd 過程)。すべて既存の欄を読むだけ。
  - **接続**: `esc_score` を起床候補 INDIVIDUAL の**優先度**に入れる(アービタの整列鍵は変えない=候補の生成側で S(e) ≥ θ を条件にする)。B6 の「起床理由」に「期待より N 分遅れ」「期待より混雑」の短句を足す(=文面の版上げ・新版テープ)。
  - **切替口**: `--prediction-state {off,on}`(既定 off)。on でも**呼数は増やさない**(既存の起床条件の内側で優先度だけ変える)腕と、S(e) を起床条件に足す腕を分ける。
  - **受入**: off で checkpoint 4 種不変 / on でモック 5,000 体の pe_time 分布(到着の 8 割が ±5 分以内なら計画実行層が正しく動いている証拠にもなる)/ 決定論(同 seed 再ラン一致)/ 状態成長宣言 = `engine/growth_decl.py` の `declarations()` に 1 項(per_agent_bytes 24・per_cell_bytes 0・per_day_growth O(1)・retention 日内・worst_case_ops_per_tick 30 本)・SoA は `Registry.declare(byte_budget_per_agent=…, mechanism=…, doc=…)`(M9)。
  - **予算行(新設案)**: **P8「予測状態の更新 ≤10 ms/tick @40 万体」**(NumPy 要素演算 ≈0.3 ms/本 × 30 本)・**M13「予測状態 ≤64 B/体」**。
  - **腕**: `AB10-PREDICTION-STATE`(off / 優先度のみ / 起床条件に追加)。指標 = D-98 の 5 指標+起床理由の内訳+pe 分布。
  - **タグ**: 期待到着の式 = mechanism(距離÷速度)/ 閾値・unc 初期値 = expedient。
  - **パターン台帳行**: 「H2 ピーク時刻(holdout)」— 期待と実到着の差が計画実行層の遅れの検出器になる/「A4 交際 10 分/日」(social_exposure 経由)。
- **判断項**: D-104(着手の可否・既定 OFF の腕として)。

### I-2. 昇格スコア S(e) の門番(議事録 §6 → D-101 の門番の実体)

- **妥当性**: R-39 の一次確認(葛藤が引き金・監視は常時安い・介入はまれ・**確信度は妥当性の指標にならない**)と整合する形は、**S(e) をエンジン算術で常時計算し、閾値で昇格する**現行設計そのもの。議事録の E 式と同じ。**変えるべきは項の定義**(I-1 の予測誤差・結果コード≠期待・計画からの逸脱)であり、重みの数ではない。
- **実装**: `esc_score = w1·|pe| + w2·stake + w3·novelty + w4·recent_failures + w5·social_exposure`。stake = 現ブロックの種類(勤務/通学 > 一般)+内受容の閾値割れ・novelty = 初訪問(M13 の訪問カウンタ)・recent_failures = 直前 4 呼の失敗数(既存)・social_exposure = 被注視/知人(C10 の後)。**θ は「昇格率 ≈ 0.02 回/体/日」の予算方程式の解**(認知設計書 §3 の既決)。
- **受入**: 感度試験 ±50%(w・θ)で移動分布・経済フロー・情報伝播が動かないこと(既決の義務)。動くなら閾値が世界を駆動=不採用(認知設計書 §3)。
- **判断項**: 無し(既決の実装)。ただし **T1 の器が LLM のままか判断層か**は D-101。

### I-3. Policy validity と Goal の成功条件(議事録 §9・§10)

- **妥当性**: 新しい状態機械を持ち込まず、**既存の ResultCode と I-1 の誤差から導出**する。Goal の成功条件は W17 ブロックの「場所・時刻」から機械的に定まる(到着 = セル一致・時刻 = ブロック開始)。
- **第256 更新(R-41 Q2)**: 先行(Fox 2006)は **repair か replan かの 2 値**で足り、しかも「上位が生きていれば下位だけ直す」ことの利得を実測している(最初の行動の一致率 100% vs 44.3%)。**5 値は先行に無く、段を増やすほど指紋になる**。→ **既定は 2 値(`REPAIR` / `REPLAN`)+ 観測できない状態 `UNKNOWN` の 3 値**にし、5 値は腕として測る。
- **実装**: `policy_validity` uint8 = VALID(誤差 0・結果 OK)/ ADJUSTABLE(TRAIN_FULL・PARTNER_BUSY・OUT_OF_STOCK = 手段の変更で成立)/ DEGRADED(pe_time > τ_late または密度が期待より 2 段階上)/ INVALID(UNREACHABLE・CLOSED・NO_TRAIN・MONEY_SHORT = 現方針では達成不能)/ UNKNOWN(繰り延べ中・観測なし)。**表 1 枚で宣言**(指紋 1 表)。「Route INVALID ≠ Policy INVALID」= UNREACHABLE は経路(next-hop)の問題として次の辺で再評価し、目的地の CLOSED だけを INVALID にする。
- **接続**: DEGRADED/INVALID は S(e) の stake に加算。B6「直前の結果」の短句はそのまま。
- **判断項**: 無し(I-1 の内数)。

### I-4. 経験ログ(議事録 §19 末・§39 → 学生の教師データ)

- **妥当性**: 「行動が同じでも機構が違う」(§39)を検証するには、決定ごとに**何を見て・何を期待し・何を選び・何が起きたか**を残す必要がある。v2 のテープは prompt_hash と応答しか持たず(第254 で確認)、体ごとの本文は再生でしか復元できない。D-101 の学生(蒸留)の教師データもこれ。**モデル非依存**(原則 K)。
- **実装**: 新テーブル `experience.parquet`(テープと同じ場所・版 3): `call_id | agent_id | tick | policy(block id) | intent(action, target) | exp_arrival | exp_density | outcome(ResultCode) | pe_time | pe_density | esc_score | source(llm/engine/habit)`。**LLM の決定だけでなくエンジン継続の決定も 1 行**(source 欄)。サイズ: 32 B/行 × (4.0M LLM + 21M エンジン継続)/日 ≈ **0.8 GB/日 @390k**(S1 ≤5 GB/日の内側・圧縮前)。5,000 体なら 10 MB/日。
- **接続**: D-101 の学生の学習データ(文脈 = 観測レコードの機械表現+経験ログ・教師 = LLM の選択)/ 予測学習(I-5)の入力 / D-100 の状況固定オフライン評価の状況集合。
- **切替口**: `--experience-out PATH`(既定 空=書かない)。
- **判断項**: D-104 の内数。テープ版 3 の切り方(記憶アジェンダ M11 と同じタイミングにまとめる)。

### I-5. 予測学習(議事録 §20 → 期待値の更新)

- **妥当性**: 議事録が「初期に最も自然」とする予測学習は、v2 では**現実の密度と照合できる**唯一の学習(期待密度 vs 実測密度の誤差は holdout H1/H4 と同じ量)。ユーザー選好(多様性は LLM から)に触れない(本人の経験の統計)。
- **実装**: 体ごとの期待表は全セル×時刻では持てない(520×24 = 12.5 KB/体 → 4.9 GB)。**訪問した(セル, 時間帯)の上位 16 スロット**(M3 の習慣スロット表と同じ構造的有界)に (key int32, exp_density uint8, n uint8) = 6 B × 16 = **96 B/体 = 37 MB**。更新 = 訪問時に (n·old + new)/(n+1)(mechanism・平均)。初期値は W18 密度場の当該セル(共有・コピーしない)。
- **受入**: 複数日ラン(D-102 の後)で pe_density の分散が日を追って減ること(学習の証拠)/ 減らない腕(learning off)との差。
- **判断項**: D-102(複数日)の後。単日ランでは測れない。

### I-6. 結果の鮮度検査(議事録 §24)

- **妥当性**: L1(2.6 秒)では実質不要。**L2 82 秒・L3 300〜900 秒**では世界が動く。現行は t_apply 時に resolve が実行可能性を検査するので「実行できない結果」は既に弾かれるが、「まだ実行できるが前提が変わった結果」(密度段階が 2 つ動いた・会話相手が去った)は通る。
- **実装**: `LLMCall` に `based_on_hash`(発射時の B4/B5 ハッシュ)を持たせ(テープ列 +1)、t_apply 時に現在のハッシュと比べる。不一致かつ lane ∈ {L2, L3} なら `ResultCode.STALE`(新値・末尾追加)を返し、**再考は起床候補に再投入**(不応期免除・繰り延べと同じ経路)。既定 OFF(`--stale-check`)。呼数が増える腕なので L4 の内側で測る。
- **前提(Explore で確定)**: 現状は呼ごとのレーン選択が無く全呼 L1 = 1 tick なので、鮮度検査の対象呼は **0**。T2(L2/L3)の発火実装(認知設計書 §3・記憶アジェンダ M7)が先。
- **判断項**: D-108(頻度を測ってから)。

### I-7. 割り込み(議事録 §25)

- **妥当性**: ハード割り込み = 「危険・重大事象で高次推論を中断し System 1 の優先行動」。v2 では顕著行為の到達(p_notice)と会話ターンが既に最優先クラス(CONVERSATION=0)で起床する。**走行中の呼の取り消し**は vLLM 側で安くはできない(abort は可能だが決定論と再生を壊す)ので、**適用時の上書き**(割り込みの行動が pk で勝つ)で代替する = 既存の二相コミットで表現できる。ソフト/ミディアムは「次の起床で最新状態を読む」(知覚契約 §6 ①)で既に担保。
- **実装**: 新しい機構は要らない。`ResultCode.INTERRUPTED` は待ち行列の離脱であって思考の中断ではない(新しい値が要る)。L3 のブロック間中断(30〜120 秒)で顕著事象があれば次ブロックを発射しない規則を足すだけ。再開可能な `ReasoningState`(作業仮説・部分結論)は**テキストとして**持つなら原則 K と両立するが、L3 の発火が本番 0 回の現状では測る対象が無い。
- **判断項**: D-108(頻度を測ってから)。

### I-8. 会話の意図スキーマ(議事録 §22 → 意味は LLM に残す)

- **妥当性**: §2-4 (i)。意味(誰に・何を・どの行為で)を LLM が決め、エンジンは**構造化された欄**として受け取る。v2 の 2 行形は「行動: 会話 対象: 人ID ひと言: ≤20 字」で、speech act・topic の欄が無い。C10 R3 は「会話の応答に『約束: 場所/時刻』欄」を構造化する案を既に持つ=同じ方向。
- **実装**: 2 行形の版上げ(`ひと言` の前に `行為: ASK|TELL|ASK_FOR|GREET|…` と `話題: ≤10 字` を任意欄で)。寛容 parser で欠落は「なし」。**文面の版上げ = 新版テープ**(既存テープは全行 miss)なので、記憶 M4 の B5 記憶チャネル追加と同じ版で一度にやる。
- **判断項**: D-105(意味の所在=LLM・スキーマは C10/M4 の版上げに同梱)。

### I-9. 群・規範・組織(議事録 §29〜§33 → 計器を先に)

- **妥当性**: CLAUDE.md §3「造語・組織形成は促進せず観察する」。議事録も bottom-up を第一に置く(§30・§31)。したがって**機構(群の段階機械・規範の期待表・組織信念)を足す前に、それらが創発しているかを測る計器を作る**。計器は世界を変えない(原則 K・自己修正の内側の輪に触れない)。
- **実装(計器・ラン後バッチ・`tools/c8`)**: ① **同行の検出**: 同一辺・同方向・距離 ≤2 m(C9)が k tick 以上続く対 → 群サイズ分布。照合先は パターン台帳 A1(会話グループサイズ 2 人 53.9%・95% が 4 人以下=強アンカー)と、**Moussaïd 2010 の「歩行者の 55%/70% が集団で歩く」**(第256・親が逐語確認。ただし文脈依存=地下街では独行が 80% 超の報告もある)。② **規範への同調度(第256 更新・R-42 Q4)**: Bicchieri の 2 層で測る=**経験的期待**(文脈ごとの行動分布のエントロピーと最頻行動の占有率=D-68 と同じ計算)と、**規範的期待**(他者の逸脱に対する反応の有無=`断る`・会話の拒否・距離の取り方)。**片方だけなら「慣習」であって「規範」ではない**と宣言する。③ **組織行動**: 役割語 12 の発火と `NO_PERMISSION` の頻度(現状は開閉店 1 か所だけが検査される)・「権限なき者の試行」の件数(逸脱として観測する設計)。**担当従業者の丸振り(expedient)を W6 の組織表に結線する**のが機構側の最初の一手(組織信念より先)。④ **情報の伝播**: 看板・顕著行為・傍受の到達件数と、その後の行動変化(既存の p_notice 診断)。
- **機構(後)**: C10 R1〜R14(関係辺・約束・会話の起点・口コミ)と記憶 M1〜M16 が先。群の段階機械は R9(関係の更新 +Δ/−Δ・減衰)で表現できる。組織の義務は W17 の勤務ブロック、権限は役割語+NO_PERMISSION で既に在る。**足りないのは「組織についての信念」(閉店したらしい・上司が居ない)= C11 の記憶で扱う**。
- **判断項**: D-107(計器先行)。

### I-10. マイクロ層(議事録 §11〜§14・§16 → 条件つき)

- **妥当性**: §2-4 (ii)。v2 の解像度は tick 1 分・セル 100 m 級・辺上位置(C9)・密度は Fruin 段階で、「前の人を避ける」「減速」「列に並ぶ」は表現できない。憲法 4 により、**照合できる現実データ**(歩行者軌跡・レーン形成・ボトルネック流量)が台帳に入るまで実装しない。データが入れば、議事録 §28 の Agent LOD の考え方どおり**熱いセル(スクランブル交差点・駅コンコース)限定のサブ tick 群衆層**として宣言つきで足す(P1 ≤50 ms/フレーム@40 万体は予算宣言書に既に在る=ORCA-GPU 50 万体 33 ms/frame の根拠つき)。
- **実装(データ後)**: 群衆物理はエンジン(social force / ORCA・古典が強い層は古典で較正=憲法 6)、「誰をどう避けるか」の選好は System 1 の学生(教師 = LLM の理由行)。**パターン行**: 基本図(密度-速度)・レーン形成の順序パラメータ・信号 1 サイクルの横断者数(R-42 Q7 の一次出典待ち)。
- **判断項**: D-106・U-9(データ取得の可否)。

### I-11. 検証(議事録 §34〜§43 → 事前登録 v2.0 への写し方)

- **妥当性**: v2 の方法論と同じ。足すのは (a) 受入表に「創発」層の行(いまは機構=T 系テスト・行動/マクロ=holdout の 2 層)、(b) 仮説 H1〜H6 を**事前登録 v2.0(D-90)の形**で書く(予想・合格線・データ・停止則)、(c) ablation 行列は**一因子ずつでは回らない**(72 万通り・第256 訂正)ので、感度分析の screening(R-42 Q9 の答申待ち)で主効果の大きい因子に絞る。
- **H1〜H6 の照合データ(v2 の現在地)**: H1(System 1 → micro realism)= 歩行者データ無し(U-9)/ H2(他者予測 → 群衆)= 同上 / H3(記憶・学習 → 時間的持続)= 複数日ラン(D-102)+K-2〜K-4(記憶アジェンダ M15)/ H4(昇格 → 新奇な擾乱への応答)= 世界過程 road_works・large_event を holdout 外の摂動として使える(**既に素材あり**)/ H5(社会情報 → メソ/マクロ)= 看板・顕著行為の伝播は診断あり・口コミは C10 後 / H6(組織・規範 → 長期)= 複数日+計器(I-9)。
- **判断項**: D-90(事前登録 v2 ラウンド)の内数。

### I-12. 議事録 §54「次の優先議題(Interaction / Neighbor / Social graph)」への答え

- v2 には既に 3 段の graph がある: **空間**(セル 520・サブセル 25 m・辺上位置 C9・W3 距離表)→ **知覚候補**(近接 top-k・可視性表 M10・p_notice 打ち切り 80 m=±1 リング 9 セル ≈26,000 体・P7)→ **社会**(関係辺 k=15・C10 R1 未実装)。縮約は不応期と注意予算。**議事録が「次の主要設計対象」とするものは、v2 では C9 実装済+C10 アジェンダ(14 決定項・親推奨つき)として既に机上にある。** 新しい設計ラウンドは要らず、C10 の決定を進めればよい。
