# v2ディープリサーチ・プログラム(2026-09-01提案・承認待ち)

> 棚卸し(v2-inventory-and-bottlenecks.md)の全分野に対するディープリサーチ計画。
> **カバー済み領域は再調査しない**(答申18本: 知識/予測/判例=3面深掘り済み・データ契約/ゲーム技術/記憶/
> 小資源検証/ベンチマーク/DT実名/線引き/学習シム/世界モデル/人流×2/科学/事業/リスク=1本ずつ済み)。
> 形式: 1ユニット=2〜3面のOpusサブ並列→統合答申(これまでのディープリサーチと同形式)。ユニット間は逐次。

## Wave 1: 設計の未決を閉じる(最優先・4ユニット)

**U-A 境界条件と人口の出自**(#27=最大の未設計・U10)
- 面1: 開放系ABMの境界設計(交通シムの外部ゾーン・疫学の importation・「境界が結果を支配する」問題の定式化と対処の先行)
- 面2: 渋谷の流入実態データ(昼間人口・OD・来街圏・時間帯別流入の実測資産)と合成人口の接続(通勤・来街・観光の区別)
- 面3: LLM社会シムの境界処理の先行(GenWorld/AgentSociety/CityRealは街の外をどう扱ったか・入退場エージェントの記憶/関係の扱い)
- 成果物: 境界モデルの選択肢比較(閉鎖/静的流入/低解像度外界エージェント)+推奨+U10起草の材料

**U-B 経済SFCの具体設計**(U11)
- 面1: SFC会計の実装形(Godley&Lavoie系の最小構成・部門勘定・取引フロー行列を紙上で閉じる作法・ABM経済の保存則テスト)
- 面2: LLMエージェント経済の実測(EconAgent以後の発展・価格形成/雇用/倒産をどちらに任せたか・失敗報告)
- 面3: 渋谷スケールの経済データ(経済センサスの活用・産業連関・家計調査・v1経済監査の教訓の整理)
- 成果物: 価格・賃金・倒産・RoW境界の設計案+紙上バランスシート雛形

**U-C 適応3ループの複合安定性**(#28・先行ゼロ領域)
- 面1: 結合適応系の理論(multi-timescale learning・co-adaptation・二重学習の発振/干渉・カリキュラムと安定性)
- 面2: 工学の先行(推薦システムのフィードバックループ崩壊・マルチエージェント学習の非定常性・ゲームのメタ進化とバランス運用)
- 面3: 設計対処(時定数の分離・凍結ウィンドウ・変更のバッチ化・カナリア・相互作用の観測計器)
- 成果物: 習慣×判例×記憶統合の相互作用リスクマップ+時定数分離の設計規則

**U-D パターン台帳の候補収集**(U12=Phase 0ゲートの実体)
- 面1: 都市・社会の再現すべき定型化事実の収集(人流・経済・社会ネットワーク・SNS・時間利用の stylized facts 30-50本・出典つき)
- 面2: 各パターンの照合データ入手性と判定規則の下調べ(ベンチマーク答申の5層構造に流し込む形)
- 成果物: パターン台帳ドラフト(あなたと選定する土台)

## Wave 2: 実装準備(5ユニット)

**U-E 並行実行の意味論**(U9): 二相コミット/予約→確定の先行(離散事象シミュの同時性・PDES・conflict resolution・公平性)・ゲームのロックステップ/ECSスケジューリング・id順バイアス根治の具体形
**U-F 会話生成の実装**: ターン逐次の実装形(誰が発話権を持つか=turn-taking model)・小モデルの会話品質実測(8-14B帯の日本語対話)・会話の中断/割り込み/多者会話・会話予算とδ結合
**U-G ペルソナ・人口合成の最新**: IPF以後(深層生成人口合成・世帯構造)・個体差の注入(分散再現の具体手法)・v1プール736MBの移植性
**U-H LLMサービング実務**: vLLM艦隊構成(モデル混載・LoRAマルチテナント・量子化AWQ/GPTQ実測・prefix cache)・T1/T2使い分けの運用・スループット最適化の定石(※9/10までのサーバー実測と対)
**U-I 長期運用SRE+ストレージ**(#21-23): 数週連続ランの無停止設計(チェックポイント戦略・自動復旧・監視)・科学計算のSRE先行・アーカイブ戦略(S3クラス・圧縮)・観測I/Oの非同期書き込み設計

## Wave 3: 制度・社会・体制(6ユニット)

**U-J 制度の最小足場**: 選挙・行政・警察をどこまで用意するか(Sidの足場実証の詳細・制度ABMの先行・「足場なしの失敗を観測対象にする」設計)
**U-K コンテンツ安全・モデレーション**(#26): シム内有害生成の扱いの先行・公開物のモデレーション方針(Chronicle実文公開との両立)・ローカルモデルの安全チューニング実務
**U-L 法務・ライセンス**(#19): ODbL派生データの実務解釈・ODPT/人流データ規約・LLMライセンス比較表(商用条件)・シム出力の権利・個情法(仮名加工情報等)
**U-M 資金調達の実務**(#18): 未踏(IT/アドバンスト)の要件・締切・採択傾向/ABCI利用資格/クラウドクレジット(Google TRC・AWS Activate・さくら等)の要件/科研費以外の個人可助成/企業スポンサーの型
**U-N 出版戦略+倫理審査**(#24-25): venue比較(JASSS/AAMAS/NeurIPS D&B/PNAS系の要求・所属なし投稿の実情)・preprint戦略・人間評価を伴う場合の倫理審査アクセス(提携/民間IRB)
**U-O 観測射影L-OBS/L-REC設計**: プライバシー攻撃・防御のテストベッド設計の先行詳細・射影の定義形式・攻撃者モデルの標準(※U4採否の判断材料)

## 実施要領

- ユニット内=2〜3面並列/ユニット間=逐次(これまで通り)。1ユニット≈15〜30分+統合。
- 答申はdocs/research/へ・[事実]/[推測]区別・出典必須・「見つからなかった」明記・既存答申との重複禁止を各プロンプトに明記。
- 全消化で15ユニット。**推奨順: Wave 1(U-A→U-B→U-C→U-D)→Wave 2はU-H(サーバー期限と連動)を先頭に→Wave 3**。
- 対象外(リサーチでなく実測・起草・交渉で解くもの): サーバーベンチ(9/10期限の別トラック)・D16統合図(起草)・アドバイザー獲得(N2)・データ退避(#17実行中)。
