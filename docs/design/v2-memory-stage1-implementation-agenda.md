## §1 段 6a: 記録

1. **表**(`AgentState(memory_columns=True)`・`--memory on` のときだけ): 体ごとに **N=128 行**(`MEMORY_N`・M2・感度 64/256)。1 行=`mem_kind` uint8(事象の種類=下の `EVENT_KINDS`)・`mem_tick` int32(最初の tick)・`mem_last` int32(最後の tick)・`mem_cell` int32・`mem_partner` int32(体 id・−1)・`mem_object` int32(POI 索引 ≥0 / 場所 −(cell+2) / 人 1<<30|id=#56 と同じ符号化・−1=なし。**会話の行では店 ID**=会話が起きた POI(`poi_ref`)・無ければ −1=M1 決定の「店 ID の欄」)・`mem_result` uint8(`ResultCode`)・`mem_importance` uint8(固定表)・`mem_n` uint16(同じ鍵の反復回数=A の n)=**27 B → 32 B/行に揃える(宣言)→ 4,096 B/体**(M4 の 6.1 KB/体の内側・39 万体で 1.6 GB=腕でだけ)。空行=`mem_kind=0`。
2. **会話の要旨(M1 (b))**: 会話の行だけ 40 字の自由文を持つ。SoA には入れず Python 側 `MemoryLayer.gist[(agent, row)]`(**体あたり上限 16 件・環状**・40 字=最大 120 B → ≤1.9 KB/体・宣言)。中身=**自分の発話の「ひと言」欄(`comment`)の先頭 40 字**(いま捨てている値を `run.py` の `conv.utterance` 呼び出しの場所で拾う)。相手の発話は本段では持たない(B5 傍受は未実装のまま)。
3. **書き手 `EVENT_KINDS`(宣言表・実装役が起草して問いで返す)**: (a) **行動の成否**(`resolve._ok/_fail` の後・成立行と失敗行): 購入・食事・並ぶ・移動の到着/`TOO_FAR`/`UNREACHABLE`・乗車(`TRAIN_FULL`/`FARE_SHORT`)・就寝(`NO_BED`)・会話の開始/`REFUSED`/`PARTNER_BUSY`/`PARTNER_GONE`・通報・手伝い(`INSUFFICIENT_ABILITY`)=**partner/object/result を鍵に**。(b) **会話**: 1 会話 1 行(開始時に作り、発話ごとに `mem_n`+1・要旨は最初の発話)。(c) **気づき**: `noticed_agents` に入った体に 1 行(object=顕著行為の主・cell)。(d) **強い看板(修正 1 の二本立て)**: p_see の通過は #56 の露出に数えるだけ。エピソードにするのは**初見**(親しみの表にその POI の行が無い最初の通過)**だけ**(W6 に看板の大きさ・演出の欄は無い=「大型・目立つ演出」は判定不能・宣言。後で欄が来たら足す)。(e) 記録しないもの(宣言): 内受容の跨ぎ(状態は B5 に在る)・範囲外の食事(予定由来)・p_see の通過(露出)・移動の各 tick。
4. **統合**: 同じ鍵(kind・partner・object・result)が同じ日にもう一度起きたら **新しい行を作らず `mem_n`+1・`mem_last` 更新**(#56 と同じ最適化学習の形)。
5. **importance 固定表(M3 (b))**: 失敗 3・会話 2・成功 1・気づき 1・強い看板 1、初回(その鍵の最初の行)は +1、上限 4(宣言・1 表で指紋を閉じる)。
6. **A(m) と score の読み口**: `A = ln(n/(1−d)) − d·ln(L+1)`(d=0.5・L=tick−mem_tick・#56 と同じ近似・Petrov 2006)。`score = w_r·A + w_i·importance`(w_r=1.0・w_i=0.5=宣言・感度腕。w_v=0=M6 (a) 埋め込み無し)。`MemoryLayer.scores(agent_ids) → (N,) float32`・`top(agent, k, mask)`。
7. **忘却(M2 (b))**: 満杯で新しい鍵が来たら **score 最小の行**を落とす(`memory_evictions` を数える)。(c) 自由文の先落としは内省(段2)。
8. **訪問カウンタ**: #56 の表を正とする(記憶からも数えられるが二重にしない=宣言)。
9. **計測**(mock 5,000・seed 1・v3 既定・energy・`--memory on`): 行数/体の分布・満杯の体数・追い出し・`EVENT_KINDS` 別の件数・result 別の失敗の件数・importance と A の分布・会話の要旨の件数(mock は「ひと言」を出すか確認・出さなければ空=記録)・強い看板(初見)の件数・+B/体・壁時計と RSS。**既定 15 腕の final が不変**。実 LLM テープ 17 本のリプレイ: 成立行・会話・気づきから 1 日の供給量を数え 8.9/体/日 の見込みと並べる(エンジンは回さない)。

## §2 段 6b: 想起 → B5「記憶」チャネル

1. **クエリ q(M5 (a))**: 起床の級(`WAKE_CONDITION_CLASS`)+現在セル+直前の結果(`last_result`・`last_action`)+会話なら相手 id+対象(意図があれば `intent_target`)。**ID 一致で候補を絞る**(partner==q.partner ∨ object==q.object ∨ cell==q.cell)→ 候補を score で並べる → k 件。候補が k 未満なら全行から score 順で補う(宣言)。埋め込みは無し(M6 (a))。
2. **k(M4 (a)+修正 2)**: 会話 **3**・計画境界(PLAN_*・活動の満了)**2**・**驚き=個体(内受容・知人・近接・被注視・傍受)とセル(CELL_BLOCK)の System 2 呼も 2**(修正 2=「個体/セル起床 0」を上書き・呼数は増えない)。
3. **τ(M16 (a))**: `A ≥ τ` の行だけ想起(τ=−1.0=宣言・感度 −0.5/−2.0。#56 の A の分布(露出で決まる)を見て実装役が値を提案して問い)。
4. **B5「記憶」チャネル**(テンプレ **v1.2**・`template_sha256` が変わる=記録・v1.1 の文面は `--memory off` で 1 バイトも変わらない): `TEMPLATES["B5.memory"] = "[B5 記憶] {items}"`・項 1 件 ≤ 20 tok の定型「HH:MM <場所/相手/対象>で<事象>(<結果>)。」(場所=POI 名かセル ID・相手=P-<id>・結果=`RESULT_TEXT` の語・会話は「P-<id>と話した: <要旨 40 字>」)。**チャネル予算 60 tok**(`GROUP_TOKEN_BUDGET["individual"]=300` の内・他チャネルは削らない・`truncate_lines` で 60 に切る)。想起 0 件なら行を出さない(`B5.memory_empty` は作らない=tok 節約・宣言)。B5 の順位付け(`_b5_ranked`)には「記憶」を最後に置く(宣言)。
5. **テープ版 3(M11 (c))**: `calls` に `recalled_rows` 列(list<int32>・想起した記憶の行番号・末尾追加=`class_rank` 不変を確認)。EventClass の追加(M11 (b))は段2(内省呼)で。
6. **既定不変**: `--memory off` は描画バイト・checkpoint・テープ列(列は足すが値は空)・prompt_hash が不変(テスト)。on の腕は新版テープ(既存テープの再生は全行 miss=宣言)。
7. **合格線の計器(M15 (c)+修正 4=K-5 失敗の回避)**: manifest に (i) K-2 の材料=同一モチーフ(同じ鍵)の再出現数と無作為期待 (ii) **K-5**=失敗の記憶(REFUSED/CLOSED/OUT_OF_STOCK/TRAIN_FULL/PARTNER_BUSY)がある場所・相手への**再訪の件数と率**、失敗の記憶が無い場合の再訪率と並べる。**判定は複数日ラン+実 LLM の後**(本段は計器だけ・宣言)。
8. **計測**(mock 5,000・on): 想起件数/呼(入口別)・τ で切られた行の割合・候補が k 未満で補った割合・B5 記憶行の tok 分布(最大 ≤60)・個体枠 300 の超過 0・既定 15 腕不変・on 腕の final/呼数・壁時計(想起は呼ごと O(k)・体数に比例した逐次ループを新設しない=P4)。実 LLM テープのリプレイ(17 本): 各呼の入口と q から「想起があれば何が載るか」を組み立て、載る件数と種別の内訳・記憶行の tok を出す(mock の一様抽選より現実の供給に近い)。
