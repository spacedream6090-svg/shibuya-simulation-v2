> **何のための表か**: 決定台帳 §9 は「行動はオブジェクトの affordance 由来」と決めている。趣味を体へ配る前に、**その趣味を渋谷の舞台のどのオブジェクトが支えるのか**を 1 行ずつ確かめる。支えるオブジェクトが無い種目は、体に配っても**舞台の外(自宅・域外)でしか起こせない**。本書はその線引きを種目ごとに書き切る。
> **本書は分布を決めない**(誰が何をどれだけやるかは答申 §2・§7 の話)。本書が決めるのは**受け皿の有無**だけ。

## 0. 読み方

| 列 | 意味 |
|---|---|
| **場所** | 渋谷の舞台で行える場所。`cat\|subcat`(W6 POI カタログ)と、そこから写る**場所語**(`PLACE_*`・`build/sched/vocab.py` の 12 語)。 |
| **件数** | **改訂後の W6**(`src/shibuya/build/geo/poi_class.py` 導入後)で実際に数えた件数。改訂前の件数と違う行には「(前 N)」を付ける。 |
| **要る物** | その種目に要る物を売る/貸す POI。無ければ空欄。 |
| **舞台の外** | 自宅 / 域外 / 路上。**舞台の外 = 在圏しない時間**(`PLACE_OUTSIDE`)か、POI を要さない路上(`PLACE_STREET`)。 |
| **根拠** | `tag` = OSM の生タグ(**一次**)/ `name` = POI 名の一般名詞一致(**expedient**)/ `答申` = 答申の記述 / `なし` = 受け皿が無いという事実。 |

**根拠の強さ**: `tag` は OSM の生タグからの純関数(`poi_class.SUBCAT_TAG_VALUES`)。`name` は生タグがリポのどのファイルにも残っていない POI だけに掛ける**最後の手段**で、**expedient**。件数は W6 ヘッダの `poi_subcat_source_counts` で層ごとに分けて出る(実測: `osm_tag` 274 / `frozen` 98 / `name` 21 / `none` 1,944)。

**※e = その「種目 → 受け皿」の対応そのものが本書の自前(expedient)**。答申 `v2-hobby-preference-research.md` §5-2 が書いていない対応を、実装サブが判断で足した行に付ける(書道→文具店、華道/園芸→花屋、絵画・彫刻/陶芸・工芸→画材店、創作→文具店、球技 4 種→体育館、つり/登山→スポーツ用品店、サイクリング→自転車店、人文・社会・自然科学→図書館)。**親の確認が要る**。※e の無い行は答申の §5-2 の対応表そのまま。

**「空欄(舞台に無い)」の意味**: 渋谷 bbox の **W6 カタログに受け皿が 0 件**ということ。現実に 0 かどうかは別問題(OSM の取得タグ次第=答申 §9 の空欄 8)。0 件の種目は、体が持っていても**域外か自宅**でしか実行できない。

## 7. `nightlife` の扱い(R-37 答申が見つけた同型の穴・親から追加指示 2026-09-17)

**本節はコードを変えていない**(既定 checkpoint 不変)。選択肢と根拠だけを置く。

### 7-1 何が起きているか

`src/shibuya/world/assets.py` の `hash_free_cat_code(cat)` は cat 名の**部分文字列**で価格帯 0/1/2 を決める:

| コード | 判定 | 当たる cat | 件数 | `poi_price` |
|---|---|---|---|---|
| 0 | `conv` / `コンビニ` / `shop` を含む | `shop` | 721 | 300 |
| 1 | `food` / `飲食` / `restaurant` / `cafe` を含む | `food` | 823 | 800 |
| 2 | 上のどちらでもない | **`nightlife` 259** ほか 10 cat | 793 | 1,500 |

`World.eatery_mask`(語彙 v2 の行動語「食事」の前提)は `hash_free_cat_code(cat) == 1` を**そのまま再利用**しているので、**`nightlife` 259 件が飲食店として数えられない**。`engine/resolve._apply_eat` の前提「飲食店セルに居る」から永久に外れ、そのセルでの「食事」は `NOT_IN_EATERY` で失敗する。

> この食い違いは `world/state.py` の `eatery_mask` の docstring に**すでに宣言されている**(「`cat == "nightlife"` は…含まれない…直すならカテゴリ表そのものの改版=親判断」)。未申告の欠陥ではなく、**保留された判断**。

**効き目の実測**(改訂後 W6 + 現行 W7・開いている POI 数):

| 時刻 | `food` が開いている | `nightlife` が開いている |
|---|---|---|
| 12 時 | 777 | 31 |
| 19 時 | 790 | 238 |
| 22 時 | 689 | 255 |
| **23 時** | **58** | **252** |

→ **23 時以降、体が「食事」を成立させられる POI は実質 58 件**。同じセルに 252 件の居酒屋・バーが開いていても使えない。深夜の食事が構造的に消える。

### 7-2 生タグから見た `nightlife` 259 件の実態(一次)

`poi_opening_hours_overpass_20260907.json` と v8 の `poi_id` を突き合わせた**実測**:

| OSM `amenity` | 件数 | 食事の affordance | 本改訂後の subcat |
|---|---|---|---|
| `bar` | **143** | **あり**(日本の OSM の `bar` は 居酒屋・ダイニングバーが主) | `nightlife\|`(無し) |
| `pub` | **71** | **あり**(同上) | `nightlife\|`(無し) |
| `nightclub` | 18 | **なし**(踊る場・料理を出さない) | `nightlife\|club` |
| `karaoke_box` | 12 | **なし**(飲食は出るが「食事の場」ではない) | `nightlife\|karaoke` |
| 生タグ無し | 15 | 不明 | `nightlife\|`(5)・`karaoke`(5)・`sauna`(4)・`net_cafe`(1) |
| **計** | **259** | | |

- **`cuisine` タグを持つ nightlife が 21 件**(`japanese` 13・`chicken` 2・`串焼` 1・`british`/`french`/`italian`/`american`/`standing` 各 1)= 料理を出していることの生タグでの実証。
- 逆向きの証拠: cat=`food` の側にも `amenity=pub` 3 件・`bar` 1 件が入っている。**v1 の分類規則の時点で food と nightlife の境は業態ではなく判定順で決まっていた**(`_poi_category_v7` は `restaurant/cafe/fast_food/food_court/ice_cream` を food、`bar/pub/nightclub/karaoke_box/izakaya` を nightlife に振る)。
- **リポ内の別の表はすでに「飲食サービス業」と判定している**: `economy/entry_capital.POI_CAT_TO_INDUSTRY` は `"nightlife": "M"`(宿泊業,飲食サービス業)= `food` と同じ大分類。**`hash_free_cat_code` だけが違う線を引いている**。

### 7-3 選択肢

| 案 | 中身 | 効く範囲 | 根拠 | 副作用 |
|---|---|---|---|---|
| **(a)** `nightlife` 全体を食事の affordance とする | `hash_free_cat_code` に `nightlife` → 1 を足す | `eatery_mask` **823 → 1,082**(+259) | `entry_capital` が既に M・`bar`/`pub` 214 件は飲食店営業 | **`poi_price` が 1,500 → 800 に下がる**(259 件)= 経済の売上と保存則が動く。`nightclub` 18・`karaoke_box` 12 まで「食事の場」に入る |
| **(b)** subcat で 食事 / 飲酒・遊興 を分ける | 食事 = `cat=="food"` ∨ (`cat=="nightlife"` ∧ `subcat` が `club`/`karaoke`/`sauna`/`net_cafe` **でない**) | `eatery_mask` **823 → 1,042**(+219) | 除外集合が**既存の subcat でそのまま表せる**。生タグ 244/259 で裏が取れる(`bar` 143 + `pub` 71 = 214 が `nightlife\|`) | 新しい subcat は要らない。**価格帯を触らないので `poi_price` は動かない** |
| **(b′)** (b) + `bar`/`pub` subcat を新設 | `amenity=bar`→`bar`・`amenity=pub`→`pub` を `SUBCAT_TAG_VALUES` に足す | 同上(生タグ無し 5 件の扱いが明示的になる) | 生タグの純関数で決まる | subcat 語彙 +2・W7 `CATEGORY_DEFAULTS` +2 行 |
| **(c)** 何もしない | 現状維持 | — | 「深夜に食事する体は居ない」という世界を選ぶ | 23 時の飲食店 58 件・**D-77/語彙 v2 の「食事」が夜に死ぬ** |

**(b) の副産物**: 「食事 = `cat=="food"` ∨ `nightlife` の遊興 subcat 以外」の集合は **1,042 件**で、これは W17 の場所語 **`PLACE_FOOD`(飲食店)に写る POI の数と完全に一致する**(§5 の実測 1,042)。つまり (b) は「**`eatery_mask` = 場所語が『飲食店』になる POI**」と言い換えられる。カテゴリ表を 2 つ持つ(`hash_free_cat_code` と `CAT_TO_PLACE`/`SUBCAT_TO_PLACE`)いまの形を 1 つに寄せられる。層契約(`world` は `build` を import できない)上、表は `world/assets.py` 側に二重定義になる(`BAND_WORDS` と同じ前例あり)。

**本書の推奨(expedient・親判断)**: **(b)**。理由は 3 つ — ①価格帯(`poi_price`)を動かさないので checkpoint への影響が「食事の成立件数」だけに閉じ、経済の保存則と切り分けて測れる ②除外集合が生タグ 244/259 で裏付けられる ③場所語と一致するので、LLM が読む場所語「飲食店」とエンジンの前提が**同じ集合**になる(いまは食い違っている=LLM は「飲食店」と見えているセルで「食事」が失敗する)。

### 7-4 いつ入れるか

**この再生成(W6 改訂)とは分ける**。W6 の再生成は資産(parquet)の話で、`eatery_mask` は**実行時のコード**。同じ回で両方動かすと、checkpoint の差が「公園の場所語」由来か「食事の成立」由来か分けられない。順序の推奨:

1. まず W6 再生成だけ入れて checkpoint を張り直す(§ 再生成手順)。
2. その後に `eatery_mask` を切替口つき(例 `--eatery {food,place_food}`・既定 `food`=現行バイト不変)で入れ、**腕として**差を測る。
