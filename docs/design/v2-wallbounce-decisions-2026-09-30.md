## 0. 横断の方針(全作業に適用)

### 0-1 品質を最優先する(スピードより品質・バグを出さない)
1. **計器は答えの分かっている場面で先に検算する。** 第309 の node 幾何の重なり(群れの計器が重なりを数えていた)の再発防止。新しい計器は、正解が既知の小さな場面(2 人が 1 m 離れて立つ等)で値を確かめてから読む。
2. **不変条件をテストにする。** 例: 体が壁・建物にめり込まない/人数の保存/同じ入力で同じ結果(決定論)/縦の接続を容量以上が通らない/歩行速度の分布が錨の範囲。
3. **大きな段(物理・ナビメッシュ・セル廃止・記憶の作り直し)の検収は、親に加えて実装を見ていない別のサブで行う。**
4. **一段ずつ・切替口つき。** 旧挙動は切替口で再現できること。既定 checkpoint を動かす変更は版上げ 1 回に束ねる。
5. **異常が出たら止めて報告する。** その場で直して先へ進まない。

### 0-2 時間の扱い
- **時間に関わる確率・長さは「秒あたり/時間あたり」で書く**(tick 数で書かない)。起床の頻度や tick の長さを変えたときに挙動が変わらないようにするため(Q48 と同じ理由)。

### 0-3 古典の腕は公平な比較相手にする
- 「古典だけ腕 vs LLM 腕=LLM が足すもの」は研究の主張の中心。**古典の腕が弱いと LLM の効果が過大に見える**ので、古典の腕の質(対応表・選び手)に手を抜かない。

### 0-4 差し替え可能な口を先に作る(将来の拡張のため)
- **経路の提供者**(いまは経験と好みで選ぶ 1 つ。将来「地図アプリ(インターネットの層)」を足し、従うかをエージェントが判断する)
- **会話を LLM に回すかの判定**(いまは「話すことがあるときだけ」。将来は全部を LLM に回して群知能を見る腕)
- **車の扱い**(いまは通過交通を流れで扱う。将来は全車両をエージェントにし、範囲も広げる)

### 0-5 順番(ユーザー決定)
1. **D-102 の土台**(乱数の鍵に日番号・カウンタ型の乱数・checkpoint の方式)
2. **急ぎの修正**: 会話と近接を実距離で判定(まず既存の `--geometry edge` の腕で)+ node 幾何で出た近接系の数値の点検(§1-2 追加 A)
3. **空間の設計ラウンド**(草案 → ユーザー確認)
4. **空間の実装**: S1〜S3 → 物理(全域)+ ナビメッシュ → 坂 → デッキ・地下街 → 駅の縦の接続 → セル廃止と知覚の個人化 → 建物の上階
5. **記憶の作り直し**: 設計は 3 と並行・実装は複数日ランが回ってから(1 の後)。共有の台帳は 4 のテープ・出来事ログと形を合わせる
- **GPU が来ても中断しない**(ユーザー: 実装のほうが先に終わる見込み)。

## 1. 空間(D-122 と派生項目)

### 1-1 D-122 P1〜P10

  - 〔10-03 上書き〕P1 (b) の文言は「S層を先に作る。D層は全域。重すぎたときの退路として、混雑地区だけに絞る形(LOD)を残す」(I-2)、P7 は「移行の間だけ下に敷き、最後は廃止する」(I-1)、S1・S2 はセル間の表では作らない(I-3)。[指示書 10-03](v2-wallbounce-decisions-2026-10-03.md) §5-5。

### 1-2 追加(ユーザー採用)
- **追加 A**: S1 の前に、近接判定の再点検を行う。対象=C10 の偶然の出会い(2 m 内の知人)・知人出現の起床(セッション +37〜45%)・同席の腕(同セル 2 m 内)・B5 近接行。**edge 幾何で読み直し**、node 幾何の重なりによる水増しを測る。Q155 と同じ回でよい。
- **追加 B**: 連続位置が既定になるまで、node 幾何で出た近接系の数値には「暫定・node 幾何」の印を付け、結論に使わない。

### 1-3 セルの廃止(ユーザー決定)
- **「何でも兼ねる 100 m 升目」としてのセルを廃止し、役割ごとに分ける:**
  1. **近傍の索引** = 細かい格子(物理の 2〜5 m・表に出ない仕組み)
  2. **環境の場** = 場ごとに解像度を選ぶラスタ(騒音・日陰・視線)
  3. **名前のある場所** = 地名帳(§1-5)
  4. **照合の区域** = データ側の区域。テープから事後に集計する
- **最初にやること: セルに依存している箇所の全リスト**(知覚 B2/B4 の共有・変化検出の起床・近接 top-k の同セル制限・会話の同セル代用・行き先のセル番号と代表ノード・密度・騒音/日陰・就寝容量・5 エリアの写像・距離表/視線表 など)。
- **会話と近接は実距離で判定する(最優先)。** 現状の「同じ 100 m セル=会話できる」は、141 m 離れても会話でき、1 m 隣でもできない。
- 検証: 共有が崩れたときの LLM の費用(入力の約 2 割が共有から外れる見込み=実測)・毎 tick の変化検出の費用・地名帳で LLM の行き先指示が成立する率。
- 知覚契約(同セル × 5 分帯 × 種別で B0〜B4 がバイト一致)を変えることになるので、設計ラウンドを通す。

### 1-4 位置と経路
- **「位置としてのノード」は廃止**(位置の正本は物理の xy)。
- **経路の構造は OSM の線のグラフからナビメッシュ(歩ける面から作る)へ置き換える**(広場の斜め横断・歩道幅を表せる・物理と同じ形を使う)。三角分割の実装(JuPedSim の三角分割 LGPL/他のライブラリ)を比較。Recast の Python 版は Windows のみ・更新停止(R-53)に注意。全組の next-hop 表は作れない前提で、1 回の探索の費用を実測。
- **経路選択 = (c)+(d)**: 経路コスト = 所要時間(混雑・坂・信号・縦の接続の待ち)+ 重み(曲がる回数・慣れた道・雨天の屋根・人ごとの急ぎ)。錨のある要素から重みを入れ、無いものは既定 0+感度腕。**(d) 散策のモード**(店を見ながら歩く)を別モードで。LLM が経由地を言ったときだけそれに従う(地名帳で解釈)。錨のリサーチ: スペースシンタックス(角度変化の少ない道)・GPS 軌跡の最短経路とのずれ。
- 将来: 地図アプリ(インターネットの層)を経路の提供者として追加(§0-4)。

### 1-5 LLM に渡す「場所」の単位 = 地名帳 (e)(ユーザー決定)
- **決定: (e) 階層の地名帳**(町丁目 > 通り・広場・ランドマーク > 施設・店)。LLM はどの層の言葉で答えてもよく、エンジンが実際の目標に解決する(範囲ならその中の一点・施設なら入口)。知覚では「いまいる場所: 宇田川町・センター街・○○前」のように層を重ねて渡す。記憶の「どこで」も同じ単位。
- 比較対象(構成要素)として一行ずつ: (a) 街区 1,227(形はあるが名前が無い・索引として残る可能性)/(b) 町丁目(統計の小地域と一致)/(c) 通り・広場・ランドマーク(人が使う言葉・範囲があいまい)/(d) 施設・店。
- **作り方は Claude Code がリサーチして草案を出す**: 層の定義・名前と範囲の起こし方(OSM の名前・既存のランドマーク資産から機械的に・手で足した部分は記録=設計者の指紋を管理)・LLM の自由記述の照合(店名は実 LLM で 1% の件に注意)。(e) を覆すべき根拠が出たら実装前に報告。

### 1-6 知覚の個人化(ユーザー決定)
- **(a) 位置+(b) 向き(視野)+(c) 目の高さ・階を幾何として入れる。** 視野の角度などは文献の値を錨に(要リサーチ)。
- **(d) 注意は段階的に**: 既定は中立(乗数 1.0)・腕で効果を測り、錨が見つかった要素から既定へ。**ただし「目的による注意」(空腹なら飲食店が目に入る)は仕組みとして先に入れる**(値は宣言+感度腕)。
- 費用の形: 起床時だけ本人の知覚を丸ごと描画(1 日 300〜500 万回の見込み)・毎 tick の変化検出は安い信号(周りの人数・近づいた出来事・視界の大きな変化)で。

### 1-7 3 次元(ユーザー決定: 範囲は全部)

### 3-2 記憶の作り直し(設計は空間と並行・実装は複数日ランの後)
背景: 09-29 朝の壁打ち(ユーザー優先=行動の説明可能性と一貫性)。記憶=ログへのポインタ+本人の主観の注釈、注釈の書き手は認知の層に合わせる(System 1=機械的な値/System 1.5=判別と選択/LLM=そのときの理由づけをそのまま/夜間の System 2=解釈と信念)、判断ごとに引いた記憶を記録、注釈は追記だけ。
- **A 記憶の器 = (c)**: 共有の出来事ログ+一人ずつのポインタと主観の注釈+**「自分が知覚した部分」の印**(会話の一部しか聞こえなかった等=記憶が完璧すぎる問題を防ぐ)。
- **B 記憶の種類 = (b) 4 種類に分け、忘れる速さを別に**: エピソード/意味(信念・評価)/習慣(手続き)/親しみ(潜在・LLM に見せない)。既存の表(エピソード表・店の評価・関係辺・親しみの表)を種類として位置づけ直す。
- **C 固定(内省) = (a) 就寝直後に 1 呼**(記憶アジェンダの段 2 内省の設計どおり)。**信念は上書きせず追記だけ**(当時の判断理由を残す)。
- **D 習慣 = (b)**: 同じ状況で同じ行動を繰り返すほど System 1.5 が LLM を呼ばずに選ぶ確率が上がる。錨の候補: Lally ら 2010(自動化まで中央値 66 日・18〜254 日)。**どの判断が習慣由来か LLM 由来かを必ず記録**(日を追うと呼数が減り、古典 vs LLM の比較が日で変わるため)。
- **E 個人差 = (b)**: 忘れる速さと想起の閾値を人ごとに(年齢など錨のある所から)。**容量(行数)を独立に振るのは過剰(錨が無く (b) と二重に数える)**=容量は保存の都合として十分大きく取り、実効量は (b) から自然に決まる形に。
- **F 箱の中の社会**(オフィス・学校・家): **空間を持たない、組織化された部屋**。会話相手は既存の関係辺(C10 の初期網=共在時間の長い相手)の強さで選ぶ(8b の招待の重みと同じ考え)。部署の会議・昼の誘い合いなどのグループの場面は関係辺のまとまりから起こす。部署の大きさを別に発明しない(錨が要る)。**LLM に回すのは「話すことがあるとき」だけ = (b)**(新しい店・予定・出来事。判定は System 1.5)・それ以外は「話した」事実を記録して関係を強める。会話の機会の頻度は錨を探す(社会生活基本調査等・無ければ expedient 宣言)。判定は差し替え可能な口(将来 (a) 全部 LLM で群知能を見る)。
  - 背景: セルを廃止して会話を実距離にすると、箱の中の人は誰とも話せなくなる=穴。職場の会話は口コミ・関係辺の維持(Q91)・同僚との昼/飲み会の人流に効く。
- **G 説明可能性の記録**: **LLM を呼ぶたびに引いた記憶の行 ID をテープに残す**。既にあるか確認し、無ければ足す(GPU 不要・安い)。
- **H 候補として記録(実装は複数日ランの結果を見てから)**: 追い出した記憶を手がかりで戻す(Wagenaar 1986: 思い出せない 2 割も手がかりで戻る)・楽しい出来事ほど覚えている偏りの感度腕(同)・重要度を固定表から予測誤差(D-104)へ。
