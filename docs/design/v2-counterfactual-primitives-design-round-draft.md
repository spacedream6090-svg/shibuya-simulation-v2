## 1. 位置づけと決まっていること

本書は、部品と検査、反実仮想の入口、ラン中の裁定の腕について、決まっていない事項だけを問いの形に並べたものです。次の事項はユーザーが決めたので、問いません。

### 1-1 指示書 10-03 §6 ② 判例のループ: (c) を目指して実装する

- 段階 1。状態を変える基本操作(部品)と、その検査を先に作ります。① の出来事の記録(契約行)にも要るので、無駄になりません。
  - 部品の例は、お金を動かす(帳簿の送金の口)、物を動かす、位置を変える、関係を変える、決まった種類の記録や物を作る、本人の状態を変える、です。契約・所有・権利の移転も含めます(⑦ 7-2)。
  - 検査の例は、保存則(お金と物は湧かない)、権限(他人の物は動かせない)、物理(届かない場所には行けない)、所有です。
- 段階 2。ラン中の裁定を、切替口つきの腕(既定 OFF)で作ります。裁定の件数、却下率、監査で見つかった誤りを測ります。
- 段階 3。既定にするかは、計測の後で決めます。比較実験の本線では OFF のままにし、創発を観る長いランで ON にする候補とします。

### 1-2 裁定の約束と退路(§6 ②)

- 裁定役は自由に書かず、部品の組み合わせを選ぶだけです。部品で表せないものは却下し、本人に「できなかった」と返します。
- 裁定で変えられるのは、本人の状態と、本人が権限を持つ物だけです。他人の心は決めません。他人への効果はその人の知覚に届くだけで、どう反応するかはその人が決めます。
- 止まらないための退路を 4 つ持ちます。
  1. 時限を過ぎたら「記録して待機」(今の動き)に落とす。
  2. 不正な組み合わせは機械が却下する。
  3. 一度に大量に来たら列に並べ、上限を超えた分は今の動きに落とす。
  4. 判例の鍵に状況を含めて失効させ、後から監査する。
  最悪でも今と同じ「その行動は何も起こさない」になるようにします。
- 比較実験では、ラン開始時の規則集の版を固定し、ラン中の裁定の件数と中身を必ず報告します。
- あわせて行うこと: 意義書と未踏の書類の主張は取り下げずに「実装中」と明記する(済み。§3 の 1)。AB7 の自由文を辞書を通さずに読み直し、足りない行動の一覧を作る(R-86 で済み)。GPU の後に System 2 のメニュー無しの腕と (c) の裁定の腕を回す。

### 1-3 ほかの節で決まっていること

- ⑦ 7-2 (b)。世界を変える専用の道具(出店・提案・集会・チラシ・団体)は作らず、現実の制約の範囲でできる限り自由に行動できる作りにします。そのため ② の部品に契約・所有・権利の移転まで含めます(出店には物件の賃貸契約・資金・許可が要る)。付録 A の「世界を変える道具」の行も同じ扱いです。
- ⑦ 7-3 (b)。反実仮想の入口(道を閉じる、営業時間を変える、など)は後回しにし、後で詳しく壁打ちします(§12 の 3。本書がその材料です)。
- ⑦ 7-4 (a)。本番の反実仮想の実験と予測は、アンサンブル(何本ものランの分布)を標準の出力にします。本数はばらつきの実測から決めます(D-46 の規則)。基準と改変のランは同じ本数で比べ、共通乱数で改良します。開発中の腕の比較(salt 3/5/3 本)は今のままです。
- ⑨ (c) 用途で分ける。エンジンは常に決定論です。LLM と決定モデルの出力は常に記録します。受入の試験、腕の比較、反実仮想の比較は厳密モード(バッチ不変の設定、決まった seed)で回します。長い観測のランは記録だけにし、再実行での一致は求めません。manifest にモードを記録します。
- ⑮ (a)。腕の比較と反実仮想は共通乱数(CRN)の対で回し、並べ替え検定(対の差の符号反転)、効果の大きさ、信頼区間を出します。CRN の健全性の確認(改変した時点までは 2 本の記録が一致すること)を自動で行い、10f の道具に入れます。
- ① (a) の仮決定。すべての状態の変化を原因つきの出来事として記録します。スナップショットの用途 4 つの 1 つが「そこから分岐して反実仮想を始める」です。
- §10-2 の 3(承認済み)。世界の状態を書く口(帳簿の送金、在庫の移動など)に、元の call_id を持たせます。エンジン由来の書き込みには過程の名前を入れます。
- §7 の方針。「判断はエージェント(決定モデルか LLM)がする。エンジンは破れない法則だけを持ち、行動を強制しない」。7-1 の表で「行動が成功するか(在庫、営業中、お金、距離)・資源の取り合い・体の変化」はエンジンの判定として残すと決まっています。
- ⑧ 8-1 (a)。賃金は必ず帳簿の送金の口を通し、払う側の口座から受け取る側の口座へ移します。範囲の外の分は「域外」部門の口座から払い、無から湧かせません。帳簿の送金の口は部品の第 1 号に当たります。
- ⑧ 8-3 (a)。経済は段階で入れます。賃金 → 店長による価格とシフト → 採用と解雇 → 与信・倒産・家賃。
- §8 3-4-5(承認済み)。物理的に不可能な行動を防ぐ試験 5 本(位置の変化が速さの上限以内か接続口を通ったもの・建物の出入りは入口を通る・同じ時刻に 2 か所にいない・容量を超えない・仮想空間で起きたことに印)を受入の試験として強制します。

#### CP2 既存の書き口と部品の関係

- 何を決めるか: 今の行動(購入・食事・乗車など)と世界の過程(賃金・補充・廃棄など)を、部品の上に載せ替えるか。載せ替えるならいつか。
- 背景: 部品を新しい口として足すだけだと、状態を書く道が「既存の口」と「部品」の 2 本になります。どちらかの検査が抜けると保存則が破れても見つかりません。一方で載せ替えは golden を動かさない手順が要ります。
- 選択肢
  - (a) 載せ替えない。部品は裁定と反実仮想の改変だけが使う新しい口にする。
  - (b) 一度に載せ替える。状態を書く口を部品だけにし、AST の検査で「部品以外から状態を書かない」を強制する(10b の追加 C の AST 検査の形を流用)。
  - (c) 段階で載せ替える。10b の原因の欄の配線と同じ順で、帳簿の 9 口 → `apply` の中の処理 → 残りの口、と移す。各段で呼数・行動の件数・final が動かないことを確かめる(指示書 §3-3 の版上げの作法)。
  - (d) 草案の案(未リサーチ)。お金と物の口だけ載せ替える(保存則が効く口)。位置と本人の状態は今の口のまま、原因の欄だけ足す。
- 材料
  - 帳簿の送金は既に「単一の口・残高の直接代入は静的に禁止」の作りです(`engine/ledger_api.py` の正典の引用。境界・経済設計書 §2.3)。科目の列挙に無い送金は実行できません(`economy/accounts.py`)。お金はほぼ部品の形になっています。
  - 物の単一の口 `move_goods` は在りますが、エンジンから呼ばれていません(10b-prep §3-2)。
  - 賃金のアジェンダの W1 の案 (B) は「帳簿に `pay_wages_many` を足し、世界過程として払う」で、受入の試験 1 は「賃金は送金の口だけを通る(AST 検査)」です。
  - 行動契約 §2 の共通の必須事項 ① は「効果は resolve でのみ適用」です。
- 影響する段と文書: 段 1 / 10b・10e の版上げの手順 / 賃金の実装 / 行動契約 §2。
- 親推奨: (c)(段階で載せ替える: 帳簿の 9 口 → apply の中 → 残り。各段で呼数・行動の件数・final の不変を確かめる)。最終形は (b) の AST の強制。

#### CP3 検査をどこで強制するか

- 何を決めるか: 保存則・権限・物理・所有の 4 種を、部品の中で強制するか、呼び出し側(resolve の各処理・裁定の腕・改変の口)で強制するか。既存の二相コミットとの関係。
- 背景: 今の二相コミット(`engine/commit.py`)は、Phase A で意図を集め、Phase B で資源ごとに優先度の順で確定し、Phase C で resolve が単一の書き手として適用します。在庫の減算は Phase C だけです(保存則)。競合のクラスに「権限行動=原則 1 人」があります。`engine/arbiter.py` は名前が似ていますが、LLM の起床の繰り延べの配分で、行動の裁定ではありません(要件の改訂記録 ② (ii) も同じ判断)。
- 選択肢
  - (a) 4 種とも部品の中で強制する。部品は検査に落ちたら失敗の符号を返し、状態を書かない。今の帳簿の `TransferStatus`(失敗は戻り値)と同じ形。
  - (b) 呼び出し側で事前に検査し、部品は書くだけにする。
  - (c) 分ける。破れない法則(保存則・所有)は部品の中で強制する。前提の検査(権限・物理の到達・営業中・残高)は Phase B の前に検査し、取り合い(最後の 1 個・席)は今の Phase B のまま。
  - (d) 草案の案(未リサーチ)。(a) に加えて、静的な検査(状態を書く口は部品だけ)と、実行時の検算(日の締めで全部門の合計+境界の出入り=一定)の 3 重にする。
- 材料
  - 世界過程の設計 §2 の軸 4 は違反可能性を regimented(違反不能=エンジン強制)/ enforced(違反可能+検知+制裁)/ unenforced に分けます。保存則と物理は regimented、所有や許可のような制度は enforced に当たる、という読みができます(草案の読み・未リサーチ)。
  - 行動契約 §2 は「語彙は全種別共通・権限はエンジンが検査」で、「権限なき者の試行」を逸脱の創発として観測する(U18 の入口)としています。権限の検査に落ちた試行を数える欄が要ります。
  - 金の帳簿の生ログは宣言 3.0 行/体/日に対して実測 4.07 行/体/日で、リングから 3,978 行が落ちていました(10b-prep §3-4・10b のアジェンダ K17)。ログを読む検算は、この溢れを直してからでないと閉じません。
- 影響する段と文書: 段 1 / `engine/commit.py`・`engine/resolve.py` / 行動契約 §2 / 世界過程の設計 §2。
- 親推奨: (c)+(d)(破れない法則は部品の中・前提の検査は Phase B の前・取り合いはアービタ。静的な検査と日の締めの検算を足した 3 重)。

#### CP4 契約・所有・権利の表し方

- 何を決めるか: 賃貸契約・資金の貸し借り・許可(営業の許可など)・物の所有を、台帳のどこにどの形で持つか。v2 に無い概念(組織の所有、物件)をいつ入れるか。

#### CP6 改変を誰が行うか(CLAUDE.md §3 との関係)

- 何を決めるか: 反実仮想の改変を、実験者がエンジンの外から直接当てるか、世界の中のエージェントの行動として起こすか。
- 背景: CLAUDE.md §3 は「世界の変化はエージェント行動の結果として実装」「エンジン規則による代替は conf 宣言つきフォールバック限定」としています。反実仮想の改変は、実験者が世界の条件を変えるもので、エージェントの行動ではありません。v1 の原因台帳は「実験者の介入」を boundary(観測の枠の外)に分類しました(R-72 §2-2)。
- 選択肢
  - (a) 実験者の改変は境界条件として直接当てる。原因の欄に「実験の条件」を入れ、CLAUDE.md §3 の対象外(世界の外からの入力)と宣言する。
  - (b) 改変をエージェントへの知らせとして入れる。たとえば営業時間の改変は「本部から店長への通達」として届け、変えるかどうかと実行は店長の行動にする。
  - (c) 種類で分ける。物理の改変(道・建物・容量)は (a) で直接当てる。制度の改変(営業時間・催し・新しい店)は PlanSpec の改訂として入れ、実行(開け閉め・催しの準備)はエージェントの行動にする。実行役がいないときは今の `executor=engine_rule` のフォールバックと同じ扱いで、宣言と被覆率を台帳に残す。
- 材料
  - 営業時間は既に「PlanSpec が正、店主が開け閉めする。担当の従業者がいなければ engine_rule のフォールバック(ActualLog に REPLACEMENT)」の作りです(`engine/processes/opening.py`。W7 の出どころは業種の既定 1,801・OSM 477・チェーンの既定 59)。

  - (b) にすると改変が「起きるかどうか」もエージェント次第になり、基準と改変のランの差に「改変が実行された割合」が混ざります(草案の読み・未リサーチ)。
- 影響する段と文書: 段 3 / CLAUDE.md §3 の文言(変えるならユーザー確認)/ 10b の原因の欄の種類 / 世界過程の設計 §2。
- 親推奨: (c)(物理の改変は直接当てて原因「実験の条件」・制度の改変は PlanSpec の改訂として入れ実行は本人の行動)。CLAUDE.md §3 に触れるのでユーザー確認。
