## 核心の発見: v1の失敗5件は全て文献上の既知の失敗型だった

| v1の失敗 | 文献上の名前 | 処方箋 |
|---|---|---|
| ①積み増しでstep時間膨張 | 散漫化+複雑性pitfall(JASSS 15(2)5) | 性能予算を機能追加**前**に数値化しCIゲート化。新機能PRに「寄与パターン名」「step時間実測」2欄必須 |
| ②capが世界の法則化 | **artefact**(Galán: 付随的仮定が結果を駆動) | 全capに`mechanism\|expedient`タグ。expedientは感度試験ID必須(振って結果非依存を示す)。示せなければ限界として明記 |
| ③経済の循環定義 | 概念モデル妥当性の欠如(Sargent) | 実装前にSFCバランスシート(取引フロー行列)を**紙上で**閉じる+保存則ユニットテスト |
| ④機能3割死蔵 | speculative generality(YAGNI 4コスト) | 門前条件:「どの実験・どのパターン照合で使うか」1行で書けない機能は作らない。N期参照ゼロは削除候補 |
| ⑤ablation不実施 | モデル分析の省略(TRACEでは必須8要素の1つ) | Phase 0で計算予算のablation取り分を先取り確保・**スケール前の小規模段階を完了条件**にする |

## v2開発の手順書(フェーズ+ゲート・前ゲート未通過で次へ進まない)

**Phase 0: 目的とパターンの固定(コードを書かない)**
研究質問1文(例: world-changer創発条件k*)。**評価基準パターン台帳**=再現すべき現実の観測パターンを
複数スケールで列挙し照合データと合格基準を付す(ODD 2020の要素1+POM)。この時点で較正用/検証用holdoutに分割。
予算宣言(step時間・メモリ・ablation用GPU時間の取り分)。
→ゲート: パターン台帳+予算表+研究質問1文。

**Phase 1: 概念モデルとODDドラフト(まだ書かない)**
ODD 7要素ドラフト・全設計判断にRationale+「機構/便宜」タグ。経済はSFCを紙上で閉じる(循環定義はここで露呈する)。
TRACEノートブック開始(devlog運用をTRACE 8見出しに揃えると論文化時に転用可)。
→ゲート: ODDドラフト+閉じた会計表+タグ全付与。

**Phase 2: 最小骨格+eval基盤**
パターン台帳の説明に必要な最小機構のみ(中庸解: **舞台データはKIDS的に豊かに・機構はパターン駆動で最小に**)。
mock駆動テスト・シード固定・保存則テストを最初から。**性能予算をCIゲート化**。
LLMはゴールデンプロンプトセット+版管理+固定evalセットでの回帰確認(EDDOps)。
→ゲート: 全テスト緑+予算内。

**Phase 3: 較正**
holdout非接触。合成データで較正手続き自体を先に検証(calibration verification)。LLMプローブ較正はここ。
→ゲート: パラメータと根拠の文書化+holdout非接触の記録。

**Phase 4: validation+ablation(スケールアップ前=安いうちに)**
holdoutパターン照合は**機構適合的指標**で(文体でなく行動分布・反応関数・ネットワーク統計)。
**分散も報告**(LLMは平均整合・分散不足の実測あり→不足時は主張を集団レベル定性パターンに限定)。
expedientタグ全capのartefact試験。ablationマトリクスは完了条件(余力があれば項目ではない)。
→ゲート: 照合レポート+artefact試験+ablationマトリクス。

**Phase 5: スケールアップと本番**
段階的に規模を上げ各段で予算とパターン保存を確認。新しい近似は必ずタグ登録。
リハーサル→監視(オンライン評価)→全ラン記録(シード・conf・版)。

**横断ルール**: 手動確認2回で自動テスト化(Wilson)/意図的負債は台帳記録+返済期限(Fowler 4象限=
STATUS/PENDING運用が相当)/プロンプト・モデル変更は固定evalで回帰確認(2語で精度10-15pt動く実測)。

## LLM社会シム固有の検証規律(AI Review 2025の分野批判への対応)

- 主観評価・LLM自己評価の循環を避け、**外部データ**で機構適合的に検証(35論文中22件が主観主体という分野の現状)
- 人間データと厳密比較するとLLM出力は「長く・礼儀正しく・雄弁」で実は似ていない——文体類似を妥当性の根拠にしない
- 複数実行+感度分析の報告を標準に(多ラン並列=第一目標の存在理由)
