## 1. 位置づけと決まっていること

本書は、ビューアについて決まっていない事項だけを問いの形に並べたものです。次の事項はユーザーが決めたので、問いません。

### 1-1 指示書 10-03 で決まっていること

- ゼロから作り直す(§6 ⑭)。v1 のビューアのコード(`viz/` の make_viewer・make_viewer3d・make_hub・notable_events・unreal、Chronicle)は移植しません。Chronicle の画面(A/B の対比・関係の伝記・語の一生・物語のピン)は考え方の参考にとどめます。
- 最初の画面は忠実度の計器盤(§6 6-6 (a))。パターン台帳の判定関数の結果をランの記録から読んで表示します。中身は次の 4 つです。
  - 見出しは I_M(全アンカーの I_i の最大値)。
  - 強い行は全部合格が必須(合否)。
  - 弱い行は重みづけの点数。
  - I_i = |シミュの平均 − 観測値| ÷ √(シミュのばらつき² + 観測の誤差² + モデルの不一致²)。3 以下で合格。モデルの不一致は最初は 0 と置いて宣言します。アンサンブルが前提で、1 本のランでは計算できません(§6 ⑫)。
- 実名を架空名に置き換える段を、全部の出力の口に置く(§9-1 の手当ての 2 つ目)。ビューア・報告・Discord・データの書き出しのすべてが、この段を通らないと外に出せない作りにします。住民の自由文の中の店名も置き換えます。シミュレーションの中とプロンプトは実名のままです。
- 観測の不変性(§10-3)。ビューアと書き出しの口が、ランの結果を 1 バイトも動かさないことを試験で確かめます。
- 表示の高さ(§10-3・§8 3-1)。位置は (x, y, 階) なので、地面と階の高さから表示の高さを決めます。v1 の「人が空中に浮く」はこれで防ぐ方針です。
- 実装はユーザーの確認の後(§10-3・§14-2)。詳細アジェンダを先に出し、細部まで答えをもらってから作ります。

### 2-1 重い問い

#### VR1 読み手と、配信・共有の形

- 何を決めるか: ビューアを誰が何のために見るか。どの形で配るか(手元で開く静的な HTML・共同研究者への共有・Discord に貼る画像)。公表物に出すときに架空名をどう強制するか。
- 選択肢(読み手。R-74 §8-3 の 1)
  - (a) ユーザーが挙動を確かめる道具に絞る。
  - (b) (a) に加えて共同研究者と共有する。
  - (c) (b) に加えて顧客(商業施設)へのデモに使う。
- 選択肢(配り方)
  - (d) 静的なファイル一式(HTML+JS+データ)を手元で開く。サーバーの処理は持たない(R-74 §8-2 の案)。共有は同じ一式を `public/` から渡す。
  - (e) 手元の小さなサーバーで開く(R-74 §8-3 の 5 の (b))。
  - (f) v1 のような 1 ファイルの HTML(R-74 §8-3 の 5 の (c))。
  - Discord に貼る画像は、草案の案(未リサーチ)として「ビューアと同じ前集計のデータから、架空名の段を通した後に画像を書き出す道具」を別に置く形を挙げます。画面の撮影で作ると、架空名の段を通らない経路ができるためです。
- 材料
  - §9-1 は公表物を「論文、報告、デモ、共同研究者への共有」と定めています。(b) と (c) はどちらも公表物に当たり、架空名の段を必ず通ります。
  - v1 の 1 ファイルの作りは大きくなりました。2D は「125.7MB・L1全件展開・無間引き」と v1 自身が失敗として記録し、3D の runB の HTML は 53,976,177 B、軌跡は約 285 MB でした(R-74 §1-5・v1-check §3)。
  - v1 は改善を「既定 OFF=バイト一致」の旗の裏に置いたため、良くした見た目が既定の出力に出ませんでした(R-74 §1-2 の 6)。R-74 §1-6 はこれを引き継がない案です。
  - file:// で開いたページのタイル要求に Referer が付くかは確認できませんでした(R-74 §9 の空欄 2)。背景地図を外の配信に頼ると、手元で開く形では動かない可能性が残ります。
  - DuckDB-Wasm は WebAssembly のメモリの上限が 4 GB です(R-74 §7-1・#14)。ブラウザだけで読む形の上限になります。
- 影響: VR6(架空名の段の厳しさ)・VR5(見た目にかける手間・背景地図)・VR4(データの置き方)。CLAUDE.md §7 の秘密スキャンと同じ「見つかったら止める」形を出力の段に入れるか。
- 親推奨: 読み手は (b)(ユーザーの確認+共同研究者)。顧客へのデモ (c) は架空名の段(VR6)が通ってから。配り方は (d) 静的な一式を手元で開く(サーバーの処理を持たない)。

#### VR4 データの形と、① と C5 の前に今の出力で先に見せるもの

- 何を決めるか: ランの出力からビューアまでの流れ(何を前集計し、ブラウザで何を読むか)。① の出来事の記録と C5 の位置の記録ができる前に、今の出力で何を先に見せるか。
