## 2. ハードウェア前提 【DECIDED-2: 2026-08-28】

**決定**: **(b)クラウドGPU都度借り + (d)次の借用機会想定**の二本立て。
自宅常設・特定マシン前提を捨て、**可搬性(portability)を最優先の設計制約**とする。

含意:

- 課金対応: 「回す時だけ借りる」に合わせ、resume堅牢性(v1の--resume-accept-config系)と
  時間あたりコストの見える化(円/シミュ日)を標準装備

## 3z. 設計スタンス 【DECIDED-3z: 2026-08-28 ユーザー指示】

- **完全ゼロベース**: v1の要素(夜の内省等を含む)をv2に実装する縛りは**ない**。フラットな白紙から、
  v1の設計史・運用知見・矛盾監査・コードを「参考資産」として1から再構築する。
  活用できる遺産はなるべく使うが、義務ではない。
- **シンプル優先**: v1は要素の積み増しでシミュ時間が膨張した。最小限の設計で現実を十分な解像度で
  再現する状態を目指す(要素を足すこと自体を成果としない)。
- **追加要素の最適化容易性**: 新要素を入れてもシミュ時間が異常に増えない構造を強制する——
  ①全ての新要素はSoA配列演算またはイベント駆動ハンドラとして書く(逐次ループの新設は宣言必須)
  ②要素ごとに時間予算(ms/シミュ分)を宣言しperf回帰テストで監視(状態バイト予算と対)。

## 3a. 設計原則=v2の憲法 【DECIDED-3a: 2026-08-28 ユーザー承認】

監査3根の裏返し(1-3)+解像度の規律(4-6):
1. **計算制約は「打ち切り」でなく「解像度」で吸収する**——ゼロ発火帯・n人上限・記憶切り捨てを
   世界規則から追放。全員が常に考えるが、遠い/重要でないものは粗く考える(LOD)。
2. **経済は実フローで閉じる**——消費→店の預金→賃金→倒産。域外から金が湧く経路を断ち、
   価格・雇用を主体の判断に返す。失敗(倒産・失業・貧困)は世界の正当な出来事。
3. **心と世界は相互に見える**——身体感覚・内面状態はプロンプトへ、表現形・宛先はLLM出力から。
   実文のない「会話」が世界を動かすことを禁止。no-fingerprintは実験条件語のみに限定。
4. **解像度は較正とペアでしか足さない**——検証する現実データを対で用意できない細部は装飾であり
   実装しない。解像度と忠実度は別物(「精密に間違う」ことを恐れる)。
5. **知覚されない細部は作らない**——どの心にも観測にも届かない計算は存在しないのと同じ
   (v1教訓: 精緻な屋内SFM座標を知覚が一度も読まなかった)。
6. **粗くする場所は宣言して粗くする**——その場しのぎの削減(v1のcap群)を禁止。
   層の選択: 古典が強い層(物理)は古典で較正、古典が空洞な層(意味・規範・噂・値付け)にLLMの
   意味的解像度を実装、両層の結合(知覚契約・行動契約)を双方向かつ正直に。
   目的は現実の複写でなく反実仮想の生成力。

## 4. 物理エンジンコア 【OPEN-4】

- 技術路線: (a) numpy SoAベクトル化(pure Python脱却・まず単核で5-10x狙い)
  (b) +numba/JIT (c) +GPU常駐(CuPy/torch=位置・速度・近傍探索をGPUに)
  (d) Rust/C++コア(pyo3等・最速だが開発コスト大)
- 並列モデル: id順遅延書き戻し(read全員→compute並列→write id順)を最初から前提にする
- 空間構造: 現行ゾーン+セルの見直し(近傍探索がGPUに乗る形=uniform grid / spatial hash)
- 群衆モデル: ORCA継続かSFM統一か(viz/sfm.py資産・屋内人流計画との整合)

→ 08-28 リサーチ完了(9路線比較・一次ソース本文確認済みのみ数値採用)。要点:

**最重要アンカー(査読済み実測)**: ORCAのGPU化前例あり=GTX 970(2015年級)で10万体60fps・
50万体33ms/frame・マルチコアCPU比30x(Charlton et al. 2019, arXiv:1908.10107)。
**40万体の物理は現代GPUでmsオーダーに落とせる規模**。
Amdahl注意: 現行の「純Python 43.4%だけ」速くしてもstep全体は最大1.77x=物理コア全体の置換が必要(方針は正)。

| 路線 | 実測根拠 | 可搬性 | 判定 |
|---|---|---|---|
| numba+SoA | GIL外prange・純Pythonループ置換に最適 | CPU万能・追加依存ゼロ級 | **第1段階採用候補** |
| torch GPU常駐 | ORCA-GPU論文30x+WarpDrive(コピー排除100x)| CUDA/ROCm/CPU同一コード=最良 | **第2段階本命** |
| NVIDIA Warp | HashGrid内蔵・分岐カーネル可・v1.16.0活発 | CUDA限定(AMD不可) | torch代替(NVIDIA限定と割切るなら) |
| JAX | JAX MD 64k粒子10.5ms(K80)・vmapで多ラン | CUDA/ROCm/TPU | torchで足りるため学習コスト分劣後 |
| FLAME GPU 2 | Boids 8万体51ms/100iter(A100)・数億体・ensemble標準 | CUDA専用・移植コスト最大 | 第3段階(100万体+)候補 |
| Taichi | TaiCrowd(ORCA実装60x主張=比較対象未確認) | 設計は理想的 | **非推奨=2023年からmaintenance mode** |
| Rust/pyo3 | 40万体級公開ベンチ発見できず | CPU万能 | 非推奨=numbaで同到達点に数分の一の工数 |
| AgentTorch | NYC 840万体主張(ベースライン不記載) | - | 対象外=**空間物理を持たない**(mobility network) |

多ラン並列: CUDA MPS同居(GROMACS実測1.8-3.5x)・ラン次元バッチ化(Madrona/GPUDrive前例)・
FLAME ensemble・CPU路線はNプロセスで自明。

**推奨段階プラン**:
- 第1段階(数日-2週): numba+SoA整理=ORCAペアループを@njit(parallel)+uniform gridへ。
  分岐だらけのLPをアルゴリズム変更なしで移植できる唯一のCPU路線・GIL構造的消滅・
  CPUフォールバックここで確保。SoA化がそのまま第2段階の下準備。期待: 物理10-100x(推定)・step全体3-10x
- 第2段階(数週): torch GPU常駐=全状態GPUテンソル・grid近傍探索・ORCA近傍cap k≤10のマスク演算化。
  期待: 昼帯80分→物理は秒未満級(外挿・推定)。torch vs Warpは「AMD機を借りる可能性」で決める
- 第3段階(100万体+): FLAME GPU 2移植 or torch多GPU化=**第2段階の実測が出てから判断**

## 4b. 世界再現の方式=「手続きを書かず基盤を書く」三層 【OPEN-4b: 2026-08-29起案・リサーチ中】

ユーザー提起「ルールを事前設計する仕組みには限界がある。どうすれば世界を再現できるか」への設計答案:
v1は世界の手続き(返還率・接客手順・解雇確率)を個別にコード化した→書いた場所だけ動き、書けない場所が
矛盾になり、書く量は永遠に足りない。**LLMは手続きを既に知っている**(店員の仕事・医師のトリアージ)のに、
v1は心だけLLMに任せて手続きを自分で書いた。v2は逆にする:

- **層1: エンジンは「破れない法則」のみ**——保存則(金・モノ・身体・空間・時間)・物理・台帳(所有・契約・記録)。
  数十規則で閉じる有限の仕事。SFC会計とα較正済み時間モデルが先行実装。
- **層2: 手続きは「役割の知識」として実行**——役割(あなたは店員だ)+汎用行動プリミティブ(渡す・受け取る・
  記録する・断る)だけを与え、手順は本人のLLM世界知識から。エンジンは実行可能性の検証のみ。
  「手続きを書く仕事」が「役割を配る仕事」に変わる(役割名簿=センサス9,872社は既有)。
- **層3: 未定義の行動は裁定・判例が結晶化**——エンジン語彙にない行動(v1のundefined_action)を却下せず、
  裁定者(GM的LLM)が保存則内で帰結を決定。同型裁定の繰り返しはキャッシュ規則へ結晶化=
  **世界のルールブックが判例集として自己成長**。事前設計の限界を事後設計の自動化で越える。
- 較正アンカー37本の役割転換: 「手続きが正しいか」→「創発した結果が現実と一致するか」の検証装置へ。

**リサーチ答申(08-29・全出典検証・詳細は答申本文)**: 三層仮説は**先行研究の進化方向と収束**——
Concordia v2(GM=grounded variablesのPython側強制+コード/LLM裁定の混合を設計原則化)と
Orchestrated Reality(正準状態木+スキーマ検証済み差分のみコミット)が独立に同じ三層構造へ到達。
Project Sid(500体Minecraft=保存則だけの世界)で役割分化・文化伝播が足場なし創発=層2の基礎を支持。

**採用する修正3点**:
1. **裁定の出力は自由散文でなくスキーマ検証済み状態差分に限定**(PDVA型)。LLMに保存則を守らせるのでなく、
   破った差分を機械が拒否する。定量根拠: 純LLM状態管理は非自明遷移59.9%・10ステップ連鎖で累積精度<1%
   (ACL 2024)・GM長期矛盾40-68%/30ターンで無矛盾ほぼゼロ(NCP-Bench)
2. **判例結晶化に検証ゲート+失効再審**: 保存則違反ゼロで複数回再現した裁定のみ昇格(Voyager型の実行検証)。
   無検証のLLM自作ルールは効果ゼロの実測(SkillsBench)。早期誤裁定の恒久バイアス化に対する再審機構は
   先行例がなく自前設計
3. **制度(選挙・行政等)は役割知識だけでは自己実行しない**(Sidの実証: 課税・投票・宗教は全て設計者の足場が
   必要だった)→最小限の足場を用意するか、足場なしの失敗自体を観測対象として設計

**新規性の空白地帯**: 開放的行動空間×1万体級のGM裁定+判例キャッシュは先行ゼロ。
判例ヒット率・裁定コスト・矛盾率を最初から計測項目に→**それ自体が論文貢献候補**。
コスト構造の要: 判例キャッシュのヒット率がスケーリングの支配変数(CBR系のLLM呼償却の文脈)。
補正認識: 「コード化はスケールしない」の正確な形は「体数はスケールするが行動空間の開放性がスケールしない」

## 10. 追加議題(2026-08-28 Claude起案・ユーザー了承待ち)

- 【DECIDED-10a: 2026-08-28】**時間の設計**:
  - **三層の時計を採用**: 物理=連続時間・小刻み(密度LOD付き)/認知=**イベント駆動**(需要スパイク解消・
    GPU常時満杯)/制度=時間帯・日次(宣言的に粗く)
  - **思考はシミュ内時間を消費する: 採用**。δは固定値でなく**推論トークン数に比例**(ユーザー発案):
    δ = max(δ_min, α×出力トークン)。αは人間の熟考時間スケールで較正(例: 100tok≈30秒)。
    自然な帰結として「長く考える人は反応が遅い」という現実的トレードオフが生まれる。
    工学ノート: 応答未着でシミュ時刻がt+δに達する場合は適用イベントが待つ(実効的にはδ_minと
    艦隊スループットが壁時計ペースを規定)。
  - **粒度のハードウェア可変**(ユーザー要望)は「**忠実度プロファイル**」として採用:
    物理dt・LOD閾値・認知レート等をプロファイル化し、ハード探査から自動提案・run manifestに記録。
    ただし規律: **比較するラン同士は同一プロファイル必須**(粒度が変わると世界が変わるため、
    ハード差を粒度差に転嫁したまま比較しない)。
  - **α較正完了(2026-08-28文献リサーチ・全出典URL確認済み)**: δ = max(δ_min, α×出力token)
    | 種別 | α(秒/tok) | 根拠 |
    |---|---|---|
    | T1速い判断 | δ_min固定(比例なし) | Evans&Stanovich(System1=即時)+Stivers応答潜時0-200ms |
    | T2熟考(CoT) | **0.04**(帯0.012-0.054) | 発話0.27÷内語圧縮比~10倍(Korba 1990)。検算: 500tok=20秒≒CRT実測中央値19-25秒と定量一致 |
    | 内的独白(逐語) | 0.24 | Netsell 2016(展開内語=外語の1.11倍速のみ) |

    | 読解・知覚 | 0.18 | Brysbaert 2019メタ分析238-260wpm(日本語直接値は未確認) |

    - **長考の関数形【DECIDED 08-28・文献答申をユーザー採用】**: 線形維持・**対数圧縮は不採用**
      (圧縮された思考はチャンク化で最初から短いCoTになる=対数割引は圧縮の二重計上。
      de Groot/Chase&Simon/Burns 2004)。N>7,500tok(≈5分)は**中断を挟んだ断続に分割**
      (中断30秒-2分挿入・Moxley 2012の5分枠+注意減衰5-15分+インキュベーション効果d=0.29準拠)。
      個人差: 知能係数g_i=0.9-1.1の狭帯域のみ(IQ×速度r≈−0.24-−0.30→±10%)・
      熟達係数e_iは原則1.0固定(CoT長との二重計上回避)。キャップが要る場合は時間でなくトークン側で切る。
    - **会話の時間構造【DECIDED 08-28】**: **ターン逐次(実時間スケール)**=各発話がα_speech×tokの
