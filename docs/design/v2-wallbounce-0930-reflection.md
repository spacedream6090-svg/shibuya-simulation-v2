## §4 確認と解析の結果(指示書 §8-1)

### 4-1 tick のループと LLM(§1-1)・[記録](../bench/analysis/wallbounce-0930/tick-llm-overlap.md)

- 発射は待たずに進む。ただし本番の設定(`--fleet-wait-s 120`)では、次の tick の頭で実行中の呼が 0 になるまで待つ(`engine/run.py:2896`)。tick ごとに同期の障壁がある。
- 物理は LLM の待ちに重ねられる。いまの移動の処理も、発射から次の tick の待ちまでの区間に既に入っている。
- 39 万体の実 LLM ランでは 1 tick 約 22.9 s のうち LLM の待ちが 19.4〜21.1 s(84〜89%)。物理の見込みは dt 0.5 s で 3.4 s/tick・0.25 s で 6.7 s/tick なので、平均では隠れる。
- 注意: 壁とナビメッシュつきの物理の費用は未測・艦隊のクライアントが同じプロセスにいるので GIL の取り合いがある(別プロセス化は実装計画書に条件として既にある)・夜は呼が減って待ちが短くなり、物理が隠れない時間帯がありうる(時刻別の壁時計の記録なし)。
- 副次の発見: 艦隊の経路では応答の適用が「発射+2 tick」・mock は「+1 tick」(D-102 のアジェンダ 問い A9)。

### 4-2 tick 単位の定数(§0-2・§1-10)・[一覧 45 行](../bench/analysis/wallbounce-0930/tick-constants-inventory.md)

- tick 数で書かれた定数が約 30 個ある(不応期の表・アービタ・会話の拒否/沈黙/寿命/招待待ち・列の離脱 15・回転率 30・意図の上限 60・退出の歩行 60・疲労の周期 30 ほか)。
- 記憶・親しみ・店・関係の経過時間、エネルギー、edge 幾何は分や秒で換算済みで、tick の長さを変えても変わらない。
- 1 tick=60 秒を前提にしたコードが 4 系統ある(知覚の時計・時刻の換算・分=tick の扱い・1,440 の定数)。

### 4-3 セル依存の全リスト(§1-3)・[一覧 67 行](v2-cell-dependency-inventory.md)

### 4-4 近接系の読み直し(追加 A・Q155)・[記録](../bench/analysis/proximity-edge-2026-09-30/README.md)

- edge 幾何でも、立ち止まっている体はノードの座標に戻される。2 m 内の組の 99.9% 以上が距離 0 で、node でも edge でも同じ。水増しが測れたのは歩行者の量だけ(群れ歩き 12〜15 倍・同行 125〜531 倍)。
- 実距離の判定が立つのは「edge かつ語彙 v2」のときだけで、既定の v3 では立たない。
- Q155: edge の歩行者の体・分が node の 4 割になる主因は歩行の速さ(node 0.41 m/s・edge 1.09 m/s)で、「変位 0 を数えない」ではなかった。
- 詳細と実装の順は [実距離のアジェンダ](v2-proximity-distance-implementation-agenda.md)。
