## §0 要旨

1. 旗は店ごとに 3 欄(`値付けの権限`・`品揃えの権限`・`基本の営業時間の権限`)を置き、値は `店 | 本社` の 2 つとする。置き場は「権利台帳の店の行」と「PlanSpec の欄」の 2 案。PlanSpec 側には既に `revising_authority` があり、W7 の 2,337 行はすべて `store_manager` になっている。
2. 初期化は W6 の POI ごとに OSM の生タグを読む(W6 には brand の欄が無い)。対象 2,112 件のうち、brand の何かを持つのは 463 件(21.9%)、`brand:wikidata` は 446 件。`brand:ja` と `brand:wikidata` が `brand` 無しで現れる例は 0 件だった。
3. 経済センサス 2021(事業所ベース・渋谷区・大分類)の法人の割合は 58〜100% で、brand の割合は全 12 業種でそれより低い。差は −48〜−100 ポイント、中央値 −75 ポイントで、12 業種すべてが 20 ポイントを超える。二つの量は物差しが違うので(1 店だけの会社も法人)、法人の割合は brand の割合の上限の検査にしか使えない。
4. 日本の OSM の `operator` は本社の法人名か入居する建物の名で、加盟者の名は 43 組の中に見当たらない(目視)。R-134 題 5 の (c)「operator ≠ brand をフランチャイズの印にする」は、このデータでは働かない。
5. 外=入力の 4 つ(本社の価格とメニュー・区と国の制度・大家の家賃・ダイヤ改正)を A1-8 の型で書き、「無い」の 3 つ(店の出入り・雇う/辞めさせる・新しい品目)を A3 へ送る。錨と知識の検査は既存の行を引くだけにした。営業時間の分布(OSM `opening_hours`)は W7 の初期化に使っているので `burned` の扱いが要る。

## §1 旗 3 欄の設計

### 1-1 欄

| 欄(日本語) | 識別子の案(R-134 §5-1 の名) | 型 | 値 | 旗が覆う書き換え(差分の対象) |
|---|---|---|---|---|
| 値付けの権限 | `pricing` | 2 値の列挙 | `店`(`store`)\|`本社`(`hq`) | 店の値札(SKU ごとの価格)。今の価格は `world/assets.py` の `SYNTHETIC_POI_PRICES`(業態 3 つで 300/800/1,500 円・1 店 1 価格・expedient) |
| 品揃えの権限 | `assortment` | 同上 | 同上 | 棚に置く SKU の集合(既存の SKU の中から選ぶこと)。新しい SKU を作るのは「無い」(§4) |
| 基本の営業時間の権限 | `base_hours` | 同上 | 同上 | W7 の PlanSpec `opening_hours` の版の改訂(`PlanSpec.revised`=`world/processes/records.py:665`) |

- 各欄に添えるもの: 持ち主の参照(店=`("store", POI の番号)`・本社=`("org", 閉じた表の外の番号)`。後者は `rights/initial.py` の `OUTSIDE_EMPLOYER_ORG` と同じ形)・出どころの文(`osm:brand:wikidata=Q…`・`osm:brand=…`・`osm:none`)・原因(初期状態は `None`)。
- 「店」の中で誰が決めるか(店主・店長)は雇用の行(`employ`)と役割で決まり、旗には持たせない(11-02r §3 の 2「それ以上の権限の表は作らない」)。
- 旗は行動の規則ではなく「誰がその権利を持つか」の事実として持つ(11-02r §3 の 2)。読むのは差分の検査だけにし(R-134 §2-1 の段 6)、頻度の規則や判断の入力には使わない。
- バイト: 権利台帳に入れる案なら 2,337 店 × 3 行 × 72 B(`ROW_BYTES`)= 約 0.50 MB(試算)。

### 1-2 置き場(両案・既定を置かない)

| 案 | 中身 | 利点 | 欠点・食い違い |
|---|---|---|---|
| (A) 権利台帳の店の行 | `KINDS`(`engine/rights/ledger.py:83` の own・lease・employ・licence・credit)の末尾に 3 種類を足し、`OBJECTS_OF_KIND` は `(STORE,)`。holder が店か本社かで旗の値を表す(R-134 §5-1 の (α)) | 11-02r §3 の 2 の文言(「権利台帳に」)どおり。5W1H・出どころ・原因の欄がそのまま使え、`holds_each` で配列ごと引ける | 種類の列のコードが増える(末尾に足せば既存の 5 つのコードは変わらない=4-2 で credit を足したときと同じ形)。`base_hours` は PlanSpec の改訂権者と二重になる |
| (B) PlanSpec の欄 | `base_hours` には既存の `revising_authority` を使う(今は W7 の 2,337 行がすべて `store_manager`=`build/field/w7_planspec.py:733`)。`pricing` と `assortment` には PlanSpec の新しい kind(価格表・品揃え表)を足し、それぞれに `revising_authority` を持たせる | 「改訂権者でなければ `PermissionError`」という検査が既に在る(`records.py:665`) | 11-02r §3 の 2 の「権利台帳に」と合わない。改訂権者は自由文(`records.py:17` の expedient)。今は値札と品揃えが PlanSpec に無い |

- どちらの案でも、W7 の 59 行(`src=chain_default`=同じ brand の営業時間を写した行)と `revising_authority=store_manager` の組み合わせは見直しが要る。brand から本社と読んだ店の営業時間を店長が改訂できる、という状態になっているため。
- R-134 §5-1 の (β) 店の欄 3 つ(int8)と (γ) `licence` の下位の種類は、同節の表を正とし、ここでは繰り返さない。

### 1-3 差分の検査が読む形(R-134 題 4・両案)

| 案 | 旗が本社のとき | 本人への返し | 記録 | 根拠と食い違い |
|---|---|---|---|---|
| (1) できない | 差分を当てない(全か無か) | 「値段は本部が決めるので変えられなかった」の型(R-134 §2-1 段 6・`ResultCode.NO_PERMISSION`=`agents/state.py:242`) | 「叶わなかった望み」の行(`stage=6`・`reason=flag_hq`) | 11-02r §3 の 2 の文言どおり。一方で [指示書 10-12](v2-wallbounce-decisions-2026-10-12.md) §1-4・CP3 は「権利に反する行動は止めず記録」で、向きが逆(R-134 §0 の 6) |
| (2) 止めず記録 | 差分を当てる | 返さない(起きたことになる) | 権利台帳に「許可のない行動」。気づく人・本社の反応は事後(口ができてから) | 10-12 §1-4 と合う。11-02r §3 の 2 の文とは合わない |

- R-134 題 4 には第 3 の案(c)「その欄を入力の持ち物にし、世界の中から書く口を置かない」もある。本書では扱いを繰り返さない。
- 推測(未確認): チェーンの店では、レジの価格マスタを本部が配る仕組みが多い。その場合の「値札は変えられてもレジの値は変わらない」は、物理的に止める仕組み(回答 11-01 §5 の `machine`)として (1) の根拠になりうる。ただし加盟店では加盟者が販売価格を決めると公取委が認定している(R-134 §5-2 の法の事実)。店ごとにどちらかを確かめた資料は手元に無い。

### 1-4 時間の方針

- 時刻は世界の時刻(ナノ秒・`SimTime`)で持つ。`since_ns`/`until_ns` は権利台帳の欄のまま(11-02r §2-2)。刻みの番号には依存しない。
- 初期化の行は `since_ns=None`(開始の前から)・`until_ns=None`。ランの中で旗が変わるかどうかは §7 の題 8。

## §2 OSM からの初期化の手順

### 2-1 読み方

1. W6 の POI(`data/world/v2/w6_poi.parquet`・2,337 行)の `poi_id` は `p_` + 要素の種類の頭文字 + OSM の id の形をしている。これで生タグ(`data/realworld/osm/poi_tags_overpass_20260928.json`・3,516 要素)を引く。W7 の組み立て(`w7_planspec.py` の `tags_by_poi`)と同じ引き方で、W6 には brand の欄が無い。
2. 読む鍵: `brand`・`brand:ja`・`brand:en`・`brand:wikidata`・`operator`。今の W7 は `brand` か `brand:ja` だけを読む(`w7_planspec.py:628`)。
3. 生タグが無い POI は 78 件(パッチ由来のモヤイ像を含む)。旗は「生タグなし」として、物差しとは別に数える。
4. 業種は主のタグで決める(`shop` → `amenity` → `tourism` → `leisure` → `healthcare` → `office` → `craft` の順で最初に当たった鍵)。

手元のデータで分かったこと(W6・対象 2,112 件):

| 量 | 件数 |
|---|---|
| brand・brand:ja・brand:en・brand:wikidata のどれか | 463(21.9%) |
| `brand:wikidata` | 446 |
| `brand:ja` か `brand:wikidata` があって `brand` が無い | 0 |
| brand があって `operator` もある | 115 |
| そのうち operator の名が brand と違う(正規化して互いに含まない) | 32 |
| shop=convenience(全件 brand あり) | 91 |
| brand が無く、名がほかの要素の brand の名を含む(タグの抜けの目安・誤当たり 2 を含む) | 11 |

`operator` の 43 組(brand と operator の組)を目視で読んだ。中身は本社の法人名(セブンイレブン・ジャパン・シャノアール・ドトールコーヒー・ゼンショー・すかいらーく・元気寿司・KDDI など)か入居する建物の名(Shibuya Hikarie の 5 件)で、加盟者と読める名は見当たらなかった。OSM の wiki が挙げる「フランチャイズでは brand と operator が別」(R-134 §9 の #8・#9)の書き分けは、このデータでは使われていない(推測を含む)。

### 2-2 物差し 3 案(R-134 題 5・既定を置かない)

| 案 | 本社の旗にする条件 | W6 の本社の数(対象 2,112) | 備考 |
|---|---|---|---|
| (a) brand の有無 | brand・brand:ja・brand:en・brand:wikidata のどれか | 463 | 11-02r §3 の 2 の文言どおり |
| (b) `brand:wikidata` に限る | `brand:wikidata` | 446 | (a) との差は 17 件 |
| (c) (a) から値付けだけ店に戻す | (a) のうち shop=convenience でなく、operator が brand と同じか無いもの | 345(値付けの旗) | 公取委の認定(加盟者が販売価格を決める)を写す案。ただし operator の差 32 件は本社の名の違いで、加盟店の印ではない(§2-1)。実質は「コンビニ 91 件を店に戻す」案になる |

### 2-4 ずれの報告の形と結果

1 業種 1 行で「POI の数・本社の旗の数と割合(物差しごと)・センサスの事業所数・法人の割合・個人の割合・差」を出す。結果の表と JSON は [a2-flags-1102/README.md](../bench/analysis/a2-flags-1102/README.md) にある。要点は次のとおり。

- 経済センサス 2021 の事業所ベースの表(e-Stat `0004006322`・表 2-1・渋谷区・民営・大分類 × 経営組織 3 区分)は手元にあった。法人の割合(会社+会社以外の法人)は 58.1%(医療，福祉)〜100%(複合サービス)。
- 差(brand の割合 − 法人の割合)は物差し (a) で −48.0〜−100 ポイント、中央値 −75.0。12 業種すべてが 20 ポイントを超えた。POI が 10 件以上の 10 業種に絞っても中央値は −66.8 ポイント。
- 店の旗が主に効く 3 業種(I・M・N)を合わせると、brand は 1,896 件中 440 件(23.2%)、法人の割合は 87.1% で、差は −63.9 ポイント。
- **向き**: brand の割合が法人の割合を上回った業種は 0。「チェーンの店はほぼ法人」という前提が正しければ、法人の割合は本社の旗の割合の上限になる。上限の検査としては 12 業種すべてが通った。
- 差の中身は「法人だが brand の無い店」(1 店だけの会社など)と「OSM のタグの抜け」(郵便局 11 件は brand が無く operator=日本郵便・不二家・丸亀製麺など)に分かれる。いまの表ではこの二つを分けられない。
- 小分類の表(表 9-2・e-Stat `0004005689`)は未取得。卸売と小売を分けられないので、渋谷区の I は卸売の事務所を含んだ値になる。

## §4 「無い」と宣言するもの

## §7 決めるべき題(R-134 §7 との差分だけ)

R-134 §7 の題 4(旗が本社のときの扱い)と題 5(物差しと検査の順)は本書 §1-3・§2-2 に材料を足しただけで、題そのものは R-134 を正とする。以下は R-134 に無い題。

1. **「基本の」営業時間の範囲**: 臨時休業・早じまい・その日の延長を旗の内に入れるか外に置くか。(i) 旗は PlanSpec の版の改訂(基本の時間)だけを覆い、その日の運用は店の判断 /(ii) その日の運用も旗に従う。根拠: 11-02r §3 の 2 の欄の名に「基本の」が付いている。
2. **旗を本人の文脈に出すか**: チェーンの店長が「値段は本部が決める」と知っているかどうか。(i) 知識として本人の文脈に出す /(ii) 出さず、試みて「できない」の文で知る /(iii) 出さない(R-134 題 4 の (2) を選んだ場合)。根拠: 11-02r §3 の 1「何をするかは本人が考える」・D3。設計者の指紋になりうるので、先に決める。
3. **置き場**(§1-2): (A) 権利台帳の店の行 /(B) PlanSpec の `revising_authority` と新しい kind。どちらにしても、W7 の `revising_authority=store_manager`(2,337 行)と `chain_default` の 59 行との整合を取る。根拠: R-134 §5-1 は (B) を挙げていない。
4. **ずれの物差し**(§2-4): 法人の割合は上限にしかならず、全 12 業種が 20 ポイントを超える。「ずれが大きければ報告」の比べる相手を選ぶ。(i) 法人の割合のまま(上限の検査=「brand の割合 ≤ 法人の割合」を見る)/(ii) 小分類の表 9-2(`0004005689`・未取得。e-stat.go.jp は取得の許可の一覧にある)で小売と卸売を分ける /(iii) 複数事業所の企業の割合(企業ベース・`0003449701`・本所の所在地で数える=参考の列。I 20.3%・M 12.2%・N 11.7%)/(iv) 比べず、物差しの違いを宣言する。
5. **業種の写像の検収**: §2-3 の「推測」の 6 行(internet_cafe・studio・copyshop・printing・craft・library の公営の扱い)を JSIC の項目で確かめるか。数が小さく(W6 で合わせて 17 件)、主な 3 業種(I・M・N)の割合はほとんど動かない(推測)。

7. **本社の価格とメニューの初期値の出どころ**(§3): 各社の公式サイトは自動で取得しない(CLAUDE.md §7)。(i) 親かユーザーが手で確かめて表に書く /(ii) 統計(小売物価統計など)の業態の値で置く /(iii) 今の合成価格のまま宣言する。R-134 §8 の 6 で未決として挙がっている。
8. **旗はランの中で変わるか**: (i) 初期状態で固定(店の出入りと同じく A3)/(ii) 本社の方針の変更が入力として届けば変わる(`until_ns` を使う)。
9. **知識の検査の相手を旗で分けるか**(§5): BOJ 2000・Fabiani 2006 の設問を、旗が本社の店長にも聞くか。
