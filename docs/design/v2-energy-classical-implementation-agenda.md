## §1 段 5a: エネルギー収支(K1 (c)・K7・K8・K9)

1. **体の定数**(W16 の性・年齢から・ラン開始時に決定論で): `weight_kg` float32=国民健康・栄養調査の性・年齢階級別の平均±SD から `stream(seed,"body.weight",agent)` で正規抽選(下限 35・上限 150)・`eer_kcal` float32=基礎代謝基準値(性・年齢階級・`bmr_pal_2025.json`)× 体重 × PAL ふつう(1.75/1.70/1.70)+個人差 N(0, 199/164)。年齢階級の境目(18 未満は 18〜29 の値で代用=宣言)。**SoA に 2 欄(8 B)**+`since_meal_kcal` float32+`energy_balance` float32(K8 の 2 変数)=**+16 B/体・既定で確保**(checkpoint は動く=K5)。`hunger` uint8 は**語の段の写し**(満腹 0/ふつう 1/空腹 2/とても空腹 3 → 既存の 0〜10 の目盛に 1/5/8/10 を置く=`INTERO_UP_EDGES=(4,7,9)` の跨ぎがそのまま段の跨ぎになる・宣言)。
2. **消費(K1 (c))**: 毎 tick `since_meal_kcal += eer/1440 × METs(kind)/AVG_METS`・`energy_balance −= 同じ値`。METs=就寝 0.95・その場/在店/なし 1.3・目的地つき移動 3.5・あたり 3.0(`activity_kind`+`Activity.SLEEPING`)・`AVG_METS=1.364`(宣言・座位中心の基準日)。感度腕 `--energy-rate bmr`(K1 (a)=BMR×METs)。
3. **摂取(K7 (a)・K3 (a))**: 食事の成立(`_complete_eat`)=時間帯の比 × EER(朝 5〜10 時 0.19・昼 11〜15 時 0.34・夕 17〜23 時 0.47・その他 0.34=宣言)→ `since_meal=0`・`balance += 摂取`。購入の成立で対象が飲食系(cat food/convenience subcat)=軽食 0.12 EER・飲料(subcat drink/vending)=0.03 EER → `since_meal = max(0, since_meal − 摂取)`・`balance +=`。宣言表 `INTAKE_SHARES`。
4. **語(K2 (a))**: `since_meal_kcal / (eer/3)` の比で 満腹 <0.25 / ふつう / 空腹 ≥0.75 / とても空腹 ≥1.5。B5 の内受容行は **語で描く**(「いま空腹です」の形・数値は見せない)=文面の版上げ(`RESULT_TEXT` と同じく `templates.py` に語 4 つ・prompt_hash は空腹の段が変わった体だけ変わる)。閾値をまたいだときだけ注入(既存の change_detect の跨ぎ)。
5. **範囲外(K9 (a))**: `transit_state==2` の体は消費を進めるが、**W17 の域外行の活動語が 食事 の行の開始で `since_meal=0`・摂取は時間帯の比**。域外に食事行が無い体は既定の時刻 7:10/12:30/19:15(宣言)で同じ処理。件数を `meals_out_of_area` に。**照合の集計は範囲内(在圏中)の食事だけ**(付帯)。
6. **日次**: 体ごとの `energy_balance` を日次センサスへ(憲法4・列 3 本: 摂取・消費・差)。翌日持ち越しは D-102 の後(いまは日次で記録するだけ)。
7. **切替口**: `--hunger-model {v1,energy}` 既定 energy。v1 は旧規則そのまま(`hunger` +1/30 分・−4)=旧 checkpoint(a1036ab5 等)を `--hunger-model v1` で再現するテスト。
8. **計測**(mock 5,000・v3 既定・energy): §1-2b (4) の予想表の各行(理由欄は mock では取れない=行為の分布と起床入口の内訳・深夜の購入・実現購入/食事の回数で代替)・**食事開始の 15 分刻み分布(範囲内)**と `ssb2021_meal_rate_15min.json` の形の比較(照合=K4・K6 (i) により較正には使っていない)・朝食欠食率(20 代・`nhns_r6_skip_breakfast.json` の 31.1% と)・語の段の時間割合・energy_balance の日次分布(3 食の日は 0 付近に閉じるはず)・15 腕の前後(v1 腕で旧値の再現)。

## §2 段 5b: 古典的選択モデル(L1〜L8)

1. **口**: 既存 `engine/chooser.py` の `Chooser` に `ClassicalChooser` を足す(`--chooser classical`)。**DestinationChooser**(店選び・L3/L8): 候補(2a の絞り込み)に対し (i) **習慣**: 親しみの表(#56)の `visits` が多い候補があれば確率 p_h(宣言 0.5・感度 0.25/0.75)でそこ (ii) **満足化**: 願望水準=空腹の語(とても空腹=最初に見えた飲食店・空腹=営業中+予算内・ふつう=+カテゴリ一致・満腹=食事の門を通らない)を満たす候補に順位の揺らぎ P(k) ∝ exp(−rank_k/τ)(rank=可視順・τ=1.0 宣言・感度 0.5/2.0)。距離減衰は入れない。分布を返す(one-hot ではない)。
2. **ActivityChooser**(活動の選択・L2・L7): 事前分布 P(活動 | 15 分帯・曜日・性・年齢階級・就業状態)を社会生活基本調査の行動者率から(`ssb2021_*` の**食事以外の行**=K6 (i))。v2 の行為/活動への対応表(20 種 → 移動/購入/会話/就寝/なし+活動文の型)は実装役が起草して**問い**で返す。状態の乗数 m(場所の種別)・m(次の予定まで N 分)・m(直前の活動)を掛け、**時間帯ごとの定数 c_t で周辺分布を事前分布に戻す**(L7・1 次元 IPF)。乗数は宣言(初期 1.0=感度腕)。
3. **食事の門**(K6 (i)・§1-2 6): P(食事 | 語, カレンダー, 周囲)=語(満腹 0/ふつう 0.1/空腹 0.6/とても空腹 0.9=宣言)× カレンダー(昼休み・「まで: 次の予定」の残り ≥30 分なら ×1・未満 ×0.3)× 周囲(B2 に飲食店 ×1・無し ×0.5・B4b に食事中の人 ×1.2)。**社会生活基本調査は使わない**。
4. **方策 `--policy classical`**(「古典だけ」腕=L5 (a)): LLM を 0 呼で、起床ごとに ActivityChooser+食事の門+DestinationChooser から **5 ラベルの応答文**(理由は定型・行動・対象・活動文の型・まで)を生成して既存の経路(パーサ→コミット)に流す=mock v3 の置き換え。**mock v3 は凍結**(`MockLLM(form="v3")` と golden はそのまま)。
5. **層の記録(L4 (a))**: manifest に 時間帯(1 時間)× 層(System 1=予定/習慣で呼ばない・1.5=選択器・2=LLM or mock)× 起床入口 の判断数と割合(SOFAI 形式)。`classical` 腕では 2 は 0。
6. **計測**: 受入表(在圏・行動分布)+LLMob 4 指標(SD/SI/DARD/STVD の JSD=既存の計器があれば流用・無ければ簡易版を起草して問い)で mock v3 / classical / (GPU 後 LLM)を並べる。店の集中(上位 k・Gini)は D-120 と同じ物差し。
