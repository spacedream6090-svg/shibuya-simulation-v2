**実測・delta(2026-09-10・D-53「経済台帳のO(t)ログのリング容量をN比例へ」)**: 決定項(M8・S1の宣言値)は変えない。**S1/M8への割当**として、`cap_budget_row` に「S1/M8(親が割当・要delta)」と書いてあった2本の実数を記録する。

- `transfer_log`(金の台帳・`economy.ledger`): **72 B/体/日 × N**(3.0取引/体/日 × 24 B/行・保持窓1日・畳み先=日次取引フロー行列)。→ 5,000体は宣言投影0.36 MB・**実容量は下限の0.39 MB**(実測213,216 B=8,884行)・**390,067体 28.1 MB**(28,084,824 B=容量1,170,201行)。
- `delivery_log`(物の台帳・`economy.goods`): **32 B/体/日 × N**(2.0移動/体/日 × 16 B/行・保持窓1日・畳み先=日次SKU別収支行)。→ 5,000体は宣言投影0.16 MB・**実容量は下限の0.26 MB**(実測71,296 B=4,456行)・**390,067体 12.5 MB**(12,482,144 B=容量780,134行)。
- **合計 40万体で≈40.6 MB = M8(RSS≤24GB)の0.17%**(旧実装比 +32.2 MB・実配列は23 B/行・14 B/行なので実RSS増は**≈+30 MB**)。リング容量=cap=宣言投影(D-R2-6の`declared_over_cap`が等号で通る)。小規模は下限16,384行(0.39 MB / 0.26 MB)=**旧既定より小さい**ので、小規模ランのRAMは減る側にしか動かない。
- **〔改訂(第334・2026-10-14)=K17・回答 10-13b §3〕** 金の生ログの輪の係数を 3.0 → **6.5 行/体/日**(実測 4.07 の 1.5 倍以上)に広げた(第 1 期 1-9)。容量: 5,000 体 16,384 → 32,500 行・390,067 体 1,170,201 → 2,535,436 行。宣言の投影 transfer_log 28.1 MB → 60.9 MB(cap 60.9 MB)・目印の列(1-3 の出来事の id)金 30.4 MB+物 9.4 MB。**39 万体の金と物の輪の合計 40.6 MB → 113.1 MB=M8 の 0.47%**(`declared_over_cap` なし)。溢れた件数は manifest `economy.raw_overflow` と日次の記録に出す(19 構成の 5,000 体で 0 件・1 日 2.28〜4.04 行/体/日)。根拠は [cp2 の記録](../bench/analysis/wallbounce-1012/cp2/README.md) の K17 の節。
- **〔追加(第334・2026-10-14)=1-5 権利台帳〕** 権利台帳(engine/rights)は列ごとの配列で 1 行 72 B。5,000 体の既定のランで 7,095 行(0.51 MB)、全母集団(雇用 222,849 行+担当と賃借 ほか)で約 16.4 MB=M8 の 0.07%。営業許可と住まいの行(4-2)を足しても同じ桁の見込み。根拠は [r15 の記録](../bench/analysis/wallbounce-1012/r15/README.md)。
- **〔追加(第334・2026-10-14)=1-7 道具の台帳〕** 連絡先の印(`RelationLayer._contact_flags`・体 × 4 手段・uint8)は関係の記憶のあるランだけで、全母集団で約 5.9 MB。グループの一覧(世帯 27,404+事業所 9,872=37,276 行)は約 2.8 MB。道具の台帳の最初の中身は 7 行(定数)。看板を読んだ出来事の腕(`SHIBUYA_TOOL_EVENTS`・既定 off)を on にすると出来事の記録が 5,000 体で 32,158 → 97,160 行/日(全母集団に比例で約 365 MB/日・保持窓 7 日で約 2.6 GB)=既定にするかは 2-4 で量と一緒に決める。根拠は [c0 の記録](../bench/analysis/wallbounce-1012/c0/README.md) §3・§6・§13。
- **〔追加(第334・2026-10-14)=1-8b 発話の口〕** 腕 `--speech-port on` では B6 の末尾に 2 行(届いた発話の行 ≤ 20 tok・会話の番の指示の行 10 tok)が付く。共有部 B0+B1+B3 の分布は HEAD と同じ(744〜747 tok)。**B6 のブロックの枠 80 tok を超える呼は、指示の行と発話の行が両方載る呼だけ=既定 v3 で 10/65,597(0.015%)・最大 93 tok=門にしない**(個体群の最大 260 ≤ 300)。既定 off では 1 バイトも変わらない。根拠は [s8b の記録](../bench/analysis/wallbounce-1012/s8b/README.md) §4・§14。
- **〔追加(第334・2026-10-14)=2-1 経済 EC 段階 2〕** 金の生ログに `method`(支払いの方法)の列を 1 つ足した(1 B/行)。段階 2 の体あたりのバイトは 41 → **107 B**(購入の呼の `call_id` を行為へ運ぶ体ごとの呼の控え=状態のファイルには保存しない=宣言)。ATM の表は OSM の ATM 43 点+銀行の支店 23 点(55 点・42 セル)。腕 `--economy-stage2 on` のランは生ログが 0 日目 8.8 行/体(賃金・引き出し・IC の運賃・税の行が増える)=腕のランだけ輪の係数を **16.0**(39 万体で約 224.7 MB)。既定 off の係数 6.5 は 2 日の和の最大 6.19 行/体=余裕 5%=**2-4 で係数を見直す**。信用の器(`economy/credit.py`)は空。ATM の表は OSM の 43 点+銀行の支店 23 点(組み立てで作り読むだけ)。根拠は [ec21 の記録](../bench/analysis/wallbounce-1012/ec21/README.md) §7。
