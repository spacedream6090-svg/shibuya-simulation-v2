## §0 要約

- **D-120 記憶・口コミ**: 店の記憶を **記憶 第 1 段のエピソード(M1)の 1 型**として構造化する(POI id・向き 3 段・出どころ 4 値・確からしさ・時刻・回数=13 B/行・上限 32 行/体・腕でだけ確保)。書き手は (i) 自分の訪問(結果コード由来・M12 と同型)(ii) 会話(System 2 の応答から店名を閉じた POI 集合に照合して抽出・不一致は捨てて数える)(iii) 看板(「知っている」だけ)(iv) ネット(D-121)。確からしさは**精度**(出どころ別の雑音 σ)で持ち、順序 自分 < 伝聞 < 看板 の錨はあるが**比は無い**=宣言+感度腕。減衰は既決の ACT-R d=0.5 に揃える(GA 5.8 日・CitySim 23 日は感度腕)。選択は**想起優先**(思い出せて評価 ≥ 0 で到達可能な店があればそこへ・無ければ可視順の満足化=D-119 L8)。初回訪問の割合(業界値 22.5%)と「店頭で決めた」割合(22.2%)は**較正帯ではなく照合量**にする(A1 と同じ教訓)。計測は Salganik の Gini・U を **口コミ off/on × 看板 off/on** の 2×2 で。
- **D-121 ネット**: **店ごとの評価点を保存して初期値にできる実データ源は無い**(食べログ 9.(1)[1]・Google 3.2.3(a)(iii)(b)(c)(vii)・Yelp は東京圏外・ホットペッパー/ぐるなび/Retty も不可=R-50 の逐語・親検収 ✓。法的助言ではない)。よって **シミュレーション内ネット**(体が書き・エンジンが POI ごとの評価・件数・順位表に集約・実データは公表された集計値を照合パターンにだけ)を第一候補にし、**冷スタートの初期評価は感度腕**(Muchnik の群集化)。検索は候補を「到達可能圏」(D-120 N7 と同じ制約)に限り**プラットフォームの順位(評価×件数)**で並べて満足化(位置効果=Ursu の形。半径・重力は入れない)。LLM には最終候補 1〜3 件だけ(LLM の位置偏りを避ける)。「スマホ操作中」は活動の種別に語を足さず**移動/その場に直交する旗「画面注視」**にし、検索・閲覧・投稿の行為が旗を立てる(p_see の乗数 0.49=Hyman ✓・歩速 −18〜30%・照合は観察の瞬間割合 7.3〜7.8% ✓)。ネット広告は MRC/IIG 2.0 の表示定義で看板と**同じ台帳の同じ列**に載せる(形だけ用意・実装は AD 腕の回)。

### 1-2 案

1. **記憶の行(N1)**: 記憶アジェンダ M1 のエピソード型に **種別「店の評価」**を足す。欄: `poi`(int32)・`valence`(int8: −1/0/+1)・`source`(int8: 0 自分/1 伝聞/2 看板/3 ネット)・`precision`(float16: 確からしさ=精度の和)・`tick`(int32: 最後に更新した tick)・`count`(uint8: 更新回数)=**13 B/行**。体ごとに上限 **32 行**(=416 B/体・40 万体で 166 MB)を**腕でだけ確保**(既定 checkpoint 不変=C9a/C9b と同じ形)。同じ POI の行は 1 本に統合(精度を足す・向きは精度加重)。
2. **書き手(N2・N3・N4)**:
   - (i) **自分の訪問**: 購入/食事の結果コードから向き(OK=+1・売り切れ/閉店/満席=−1・それ以外 0)。M12(関係辺の符号を ResultCode から)と同型。LLM に評価を書かせない(8B は数値尺度で壊れる=M10)。**LLM の 3 値ラベル**は書式率を測ってから腕で。
   - (ii) **会話**: 発話本文はテープにしか残らない(R-48)ので、**応答のパース時**(`run.py` の `conv.utterance` の周り)に「店名+評価語」を抽出し、**W6 の POI 名(別名表つき)へ照合**。照合できなければ捨てて `wom_unmatched` に数える。聞き手の行に書く重みは行動契約書 §4 の転写(宛先 1.0/非宛先 0.5/傍受 0.2)を精度の係数に使う。LLM に構造化出力(「店: 評価:」の 2 ラベル)を書かせる形は書式率の後(D-117 M1 (c) と同じ扱い)。
   - (iii) **看板**: B2 に看板行が出た(p_see を通った)POI を `source=看板`・`valence=0`(知っているだけ)で書く。AD 腕(第232)と同じゲート。
   - (iv) **ネット**: D-121 O1 の答えで決まる(出どころ 3 の枠だけ予約)。
3. **確からしさ(N4)**: 出どころ別の雑音 σ_src を宣言し 精度 = 1/σ² を足し上げる(ベイズ/Kalman の形=Zhao・Erdem & Keane・CitySim)。**順序は錨**(自分 < 伝聞 < 看板 < ネット の σ)・**比は宣言**(初期 σ 自分 1・伝聞 2・看板 4・ネット 2 [expedient]・感度腕で 1:1:1:1 と 1:4:16:4)。複数の出どころからの補強で精度が閾値を超える=複雑感染(Centola)の形が自然に出る(閾値は N6 の τ)。
4. **減衰(N5)**: 既決の **ACT-R 基底活性 A(m)=ln Σ(Δt+1)^−0.5** に揃える(記憶アジェンダ M2)。GA の指数 0.995/時(半減 5.8 日)と CitySim の中立回帰 λ=0.03/日(半減 23 日)は**感度腕**(値が 2 桁散り店の評価の記憶を較正した先行は無い)。
5. **候補集合の合成(N6・D-119 L3/L8 と組)**: **想起優先**(R-49 §5 の型 (c)): 想起できた店(A(m) ≥ τ・`valence` ≥ 0・到達可能=N7)のうち**願望水準(L8 α)を超えるものがあればそこへ**(複数なら精度加重の分布=`Chooser.probs`)、無ければ**可視順の満足化+揺らぎ(L8 β)**。二段型(P_new=ρS^−γ で 戻る/探す を先に抽選)は採らない: 初回率をモデルに入れると 22.5% が**構成上一致**し照合にならない(A1 と同じ教訓)=**初回率は照合量**。
6. **遠い記憶の店(N7)**: **到達可能性の制約**で候補から外す: 次の予定までの残り分 × 歩速(D-51 の 1.5 km/h 相当)で届かない POI は候補に入れない。これは**上限つきの制約であって距離減衰ではない**(魅力度 × 距離^−β の形を持たない)=「ハフ型は入れない」に触れない(R-37 が「到達可能性による候補集合の制約」を許容と整理 [サブ値])。届く店へは D-114 案 A(意図を保持して歩く)。
7. **言う側**: 口コミの発話は強制しない(憲法・「多様性は LLM から」)。B5 の記憶チャネル(M4・会話起床で k=3)に店の記憶の行を **1 行 ≤ 15 tok**(「最近 X に行った(良かった)」)で見せ、話すかどうかは System 2。再伝播(聞いた話をさらに話すか)も観測だけ(小川 2003 の 2.1% [サブ値]は目安)。
8. **計測(N8)**: manifest に (a) 訪問ごとの決め手の内訳(見えていた/自分の記憶/伝聞/看板/ネット=SOFAI 形式)(b) 店の集中=業態別の Gini・上位 k 店の占有率・HHI (c) 不予測性 U=seed 間の占有率の差の平均(Salganik)(d) 伝播=店 X を知る体の割合の時系列(e) `wom_unmatched` 率(f) 初回率(照合: 22.5%)(g) 決め手「店頭」の割合(照合: 初回の 22.2%)。腕は **口コミ off/on × 看板 off/on × seed**(口コミ off=独立条件)。**C1/C3/C4 には触れない**(holdout)。
9. **切替口**: `--store-memory {off,on}`(既定 off=checkpoint 不変・記憶 第 1 段と同じ腕で on)。

### 1-3 予算(宣言)

- バイト: 13 B × 32 行=416 B/体(M1 の記憶 6.1 KB/体の内側・既定 127 B の外=腕でだけ)。
- 呼数: 増えない(抽出はパース時の正規表現+辞書照合・LLM 呼なし)。B5 の記憶チャネル 60 tok は M4 の枠内。
- 逐次ループ: 抽出は呼ごとの文字列処理(呼数に比例・1 呼 ≤ 数十 µs)=宣言。想起は配列演算 O(32)。
- 決定論: 精度加重の分布からの抽選は run_salt の blake3。

### 1-4 順序と空欄

(1) 記憶アジェンダ M1〜M16 のユーザーの答え(前提)→ (2) 記憶 第 1 段(エピソード SoA・A(m)・訪問カウンタ M13)と同じ回に「店の評価」型を足す → (3) D-119 `classical` の DestinationChooser に想起優先を接続 → (4) 会話抽出(W6 の別名表を先に作る=空欄)→ (5) mock 5,000 で決め手の内訳・Gini・`wom_unmatched`(mock は店名を書かないので抽出は実 LLM 待ち=GPU 後)。
空欄: W6 の POI 別名表(略称・チェーン名)/ 集まりの店選び(主に他の人 25.0%=GM 裁定か同行者の記憶か=C10 の約束と同じ回)/ 出どころ比・減衰の一次(無い)/ 日本の評点の因果効果(無い)。

### 2-2 案

1. **ネットの中身(O1)**: **シミュレーション内ネット**。エンジンが POI ごとに `net_rating`(精度加重の平均・D-120 の記憶の行と同じ 3 段)・`net_count`(件数)・順位表を持つ(世界側の表・体の記憶ではない)。書き手は体(O4)。**実データの評価点は取り込まない**(2-1 の規約)。POI の存在・カテゴリは OSM(既存)+必要なら FSQ OS Places(Apache 2.0・閉店日・カテゴリの補完=取得時にライセンス台帳へ行)。**冷スタート**(ラン開始時の評価・件数)は 0 件から始める腕と、業態別の一様な初期値の腕の**感度腕**(Muchnik の群集化で初期値が結果を動かす)。実データは**公表された集計値**(リクルートの情報源割合・Luca の独立店だけの段差・Muchnik の非対称)を**照合パターン**にだけ使う。
2. **検索と候補集合(O2・D-119 L3 との衝突)**: 検索は行為「探す」(語彙 v3 に無い=**活動文で「店を探す」と書いたとき System 1.5 が検索経路に入る**・契約語は足さない)。候補=**到達可能圏**(D-120 N7 と同じ「次の予定までに歩ける範囲」の制約=距離減衰ではない)の営業中 POI を **プラットフォームの順位(評価 × log 件数)**で並べ、願望水準(L8 α)+順位の揺らぎ(L8 β の rank を順位表の順位にする)で満足化。**半径(段差の距離項)と重力(ハフ型)は入れない**。**LLM には最終候補 1〜3 件だけ**渡す(LLM の位置偏り=Zheng/Liu を避ける)。位置効果(Ursu: 順位は「見に行く先」を変え、見た後の選択は変えない)は「検索で候補に入る店」と「入った後の評価」を分けて記録すれば照合できる。
3. **スマホ操作中(O3・D-117/D-116 に絡む)**: 活動の種別に語を**足さない**(語彙 v3・二層の契約は不変)。移動/その場に**直交する旗 `screen_gaze`**(uint8: 0/1・腕でだけ確保)を置き、**検索・閲覧・投稿の行為が旗を立てる**(持続=その行為の間)。効果: p_see の乗数 **0.49**(Hyman 通話 25.0/51.3 ✓・D-117 M2 の錨の本来の宛先)・歩速 −18〜30%([サブ値])・停止中(信号待ち)は打ち消す(渋谷の知見 [サブ値])。照合=**観察の瞬間割合 7.3〜7.8%**(旗が立っている体の割合・時間帯別)。**「ネットを使うこと自体が看板を見落とす物理コスト」になり、ネット広告と看板の注意の奪い合いが機構で出る**(設計者の指紋になる挙動の追加=ユーザー判断)。
4. **読む・書く(O4)**: 読む=エンジン(検索時に順位表を引く・LLM を呼ばない)。書く=在店の持続の終わり(食事/購入の結果 OK)に確率 p_post で System 2 に 1 呼(「ひと言 ≤ 20 字+良い/ふつう/悪い」の 2 ラベル)→ 閉じた POI に照合して `net_rating`/`net_count` を更新+書いた体の記憶に `source=自分`。p_post は宣言(上限の目安=経験率 21.1%/42.8% [サブ値]・来店あたりの率は空欄)・感度腕。SNS フィード(OASIS 型・友人の投稿を読む)は **C10(関係辺)の後**(呼数 L5 に触る)。
5. **ネット広告(O5)**: 検索結果/フィードの広告枠を「表示」と数える定義を MRC(画素 50%・1 秒)/IIG 2.0 に合わせ、看板(段0〜3)と**同じ台帳の同じ列**(表示 → 店ページを開く → 来店 → 購入)に並べる。広告ゼロ腕(AB6-AD-ZERO)と同じ反実仮想で incrementality。段3 の p_act 上限と C1 のカスケード線はそのまま掛かる。**形だけ用意し実装は AD 腕の回**。
6. **計測とパターン台帳ゲート(O6)**: 口コミ=Muchnik の非対称(+32%/+25% [サブ値])と Luca の独立店だけの段差 ✓ / 検索=初訪問の情報源割合 ✓ と位置効果 [サブ値] / スマホ=瞬間割合 7.3〜7.8% ✓ / ネット広告=MRC・IIG の表示定義。腕: ネット off/on × 口コミ off/on × 看板 off/on(D-120 N8 の 2×2 を 2×2×2 に)。**初期値・p_post・順位式は感度腕**。
7. **切替口**: `--net {off,on}`(既定 off・checkpoint 不変)。`screen_gaze` は腕でだけ確保。

### 2-3 予算(宣言)

- バイト: POI 側 `net_rating`(float16)+`net_count`(uint16)=4 B/POI(世界表・体ではない)。体側 `screen_gaze` 1 B(腕でだけ)。
- 呼数: 検索 0 呼(エンジン)。投稿 p_post × 実現購入/食事(2〜3 回/体/日・D-118 の予想)=p_post 0.1 なら +0.2〜0.3 呼/体/日(L5 の内側かを実装前に宣言)。
- 逐次ループ: 順位表の更新は POI 単位の配列演算・投稿の照合は呼ごとの文字列処理(D-120 N3 と同じ)。
