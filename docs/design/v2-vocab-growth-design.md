## 1. 先行から動かない結論(設計の前提)

| 前提 | 根拠 | 設計への効き |
|---|---|---|
| **オフラインで束ねて検証する方が、即時追記より良い** | AWM §3.2.2 にオンライン獲得で性能が下がる実例・LearnAct は 2 反復で最適以降は過学習・2026 の SkillCAT/Trace2Skill は「束ねて検証」へ移動(サブ実読) | ユーザー決定と一致。ラン内注入口は作らない |
| **同じ入力に同じ裁定を LLM で保証できない** | 温度 0 でも同一文字列は出ない(Atil 2024・親確認) | 段4 の決定論は**契約表の参照**でしか作れない=採用済みの語は LLM を呼ばない |
| **「N 体が試みたら登録」の頻度閾値に先行は無い** | 6 出典すべてに無し。Generative Agents「150 in our implementation」・AGA「0.97 in our implementation」は指紋として明記 | 閾値 N は**指紋として宣言**する(隠さない) |
| **オブジェクト由来で語彙は増える** | SayCan 551 技能 = 動詞族 7 × オブジェクト 17(サブ実読)/ Emergence World: 15 日×5 世界でエージェント作の道具は**2 件**(親確認)=「自動では増えない」 | 決定台帳 09-17 の原則を支持。**人が通す形は創発を潰しているのではない** |
| **24 語は少なくないが、階層が無く「食事」が無いのは異常** | 公式分類の第一階層は 17〜20(親確認)。ATUS は Eating and Drinking が一次カテゴリ・社会生活基本調査は 20 種の 1 つが食事 | 第 1 の起草材料は食事。段0 辞書が非公式の第 2 層になっている(語彙政策 v0) |
| **失敗分類 → 語彙追加の手続きを書いた先行は LearnAct 1 本** | MAST/AgentErrorTaxonomy は分類まで。LearnAct は更新の 86〜92% が既存行の書き換え(サブ実読) | 新語の追加より**既存契約行の書き換え**が主になる前提で件数予算を組む |

## 2. 仕組み(推奨案の具体形)

```
ラン中   未定義行動を台帳に残すだけ(実装済み: UndefinedActionRegistry・段0 辞書・段1 記録+待機・M3 の N 到達印)
         └ 実 LLM でも mock でも同じ。ランの決定論・テープ再生は壊れない(内側の輪に修正を入れない)

ラン後   tools/vocab/adjudicate.py <run の undefined_registry / c8 出力>      … 中間の輪(オフライン・バッチ)
  段2   台帳の語を正規化(語彙政策 v0 の分類を列で持つ)→ 起草対象を選ぶ(§3 A)
        → T2 モデル(温度 0・裁定プロンプト固定・版つき)に 1 語 1 呼で契約行の草案を出させる(§3 B)
        → 草案 JSON(対象クラス / affordance / 前提 / 効果 / コスト / 失敗コード / 保存則の科目 / パターン台帳の照合行)
  段3   自動検査 4 つ(§3 C): ①正しさ(mock 5,000 体で発火し保存則が閉じる)②使用(未定義台帳の該当行が減る)
        ③妥当性(世界状態が実際に変わる)④非退化(既存の受入行・checkpoint 系列が悪化しない)
        → 保存則・性能予算に触れる草案は自動で不採用(§7 段3 の現行規定)
  親検収 → ユーザー承認(語彙の追加は「先に聞く」の範囲・§2-6)
  段4   採用 → 契約表(llm/contract)に**版つき**で追加(§3 F)。以後は表参照=LLM を呼ばない(§3 H)
         → 次のランから有効。manifest に語彙の版と、語ごとの使用率(§3 J)

現実照合  採用した語が現実側の量(在圏・行動分布のアンカー)を悪化させないことを、次のランの受入表で見る
         (自己修正 3 原則の (i): 発火は現実側との距離で・自分の出力では発火しない)
```

- **run.py への注入口(`adjudicator=`)は作らない**(第202 の親案を撤回)。`UndefinedActionRegistry.adjudicate` は残すが本番では呼ばれない(mock テスト専用)。
- 起草の呼数は語数(≤30)×1 呼=**数十呼**=PC で回る。サーバー不要。

## 3. 決定アジェンダ(A〜J・親推奨つき。番号で答えられる形)

| # | 決定項 | 選択肢 | 親推奨 | 指紋として宣言するもの |
|---|---|---|---|---|
| **A** | 起草対象の選び方(閾値 N) | (a) N=10 体で起草 / (b) 全件保持+起草は件数予算で切る / (c) 被覆(体・セル・時間帯の広がり)で順位づけ | **(b)+(c)**: 台帳は全件保持(CBR §8.1「失敗も事例として保持」)。起草へ回す順位は 体数×セル数×時間帯数 の被覆で付け、1 バッチの件数予算(例 10 語)で切る。N=10 は「被覆の下限」に降格 | 件数予算・被覆の式・下限 N |
| **B** | 草案の形式 | (a) 現行 §7 の 6 欄 / (b) **検証可能な欄を必須**(失敗コード名・保存則の科目名・対象クラス)/ (c) 自由文 | **(b)**。ASI の「検証できる形にしたことが効果の主因」(サブ実読)。**対象クラス+affordance を必須欄**にし、決定台帳 09-17 の原則を草案の形で強制する | 欄の並び・必須欄 |
| **C** | 自動検査(段3) | 4 検査(上記 ①〜④)+ 合格線 | **4 検査を採用**。合格線: ①保存則残差 0・②該当行 −50% 以上・③状態差分が非零・④受入表の PASS 行が減らない | 合格線の数値(②の 50%) |
| **D** | 実行の位置 | (a) ラン後オフライン(ユーザー決定)/ (b) シミュ日ごとの締め / (c) ラン内 | **(a)**。(b) は先行が無い=採るなら expedient。S4 の 7 日ランで (b) の要否を再検討 | — |
| **E** | オブジェクト由来との関係 | (a) 動詞を足す / (b) **オブジェクトに affordance を足し語彙はその直積** / (c) 両方 | **(b) 第一候補**。「食事」は動詞の追加ではなく **飲食店オブジェクトの affordance `eat`**(前提=店内・所持金≥価格 / 効果=満腹↑・所持金↓・在店時間 / 失敗=NOT_IN_EATERY・MONEY_SHORT)。契約表を (対象クラス, affordance) に正規化できるかは実装で確かめる | 直積のどこを「語」と呼ぶか |

| **H** | 段4 の決定論 | (a) 採用語は契約表参照(LLM を呼ばない)/ (b) 温度 0 で呼び直す / (c) 完全一致キャッシュ | **(a)**。(b) は成立しない(親確認)。裁定 LLM の出力は草案の一度きり | — |

## 4. 自己修正ループ 3 原則との対応

| 原則 | 本設計での担保 |
