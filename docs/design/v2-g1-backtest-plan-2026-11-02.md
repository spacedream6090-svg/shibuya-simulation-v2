## 1. 位置づけ

- **門 1(G1)** = 渋谷で、較正に使っていない過去の現実の変化を、宣言した手順で当てられるか(後ろ向きの答え合わせ)。**門 2(G2)** = 渋谷で較正した係数のまま天神で検証し、転移の落差を測る([回答 10-25](v2-answers-2026-10-25.md) §4-10 Z1)。〔仮〕呼び方「門 1・門 2」は、用語集の G1〜G13(幾何 1〜13・C9)との衝突を避ける親案(R-122 末尾の 4)。
- 外に出す主張(「再現できた」)の前に通る必須の判定の 1 つ(CLAUDE.md §4 の (c))。予測の台帳(回答 10-25 §4-11・C-3)の 1 行として載せる。
- 的の候補の比較は R-129(答申中)。本書は D1b で答え合わせができる唯一の候補=東棟(2019-11-01 開業)に絞って手順を書く。渋谷ストリーム(2018-09-13)は D1b の期間の前なので門 1 には使えない(R-122 §2)。

## 3. 問いと量(定義だけ)

| 項 | 定義 |
|---|---|
| コア 4 | 渋谷駅を角に持つ 3 次メッシュ 53393585・53393586・53393595・53393596(地上セル 453 のうち 373=82% が入る。R-122 §1-3) |
| Q1(主) | 開業の前後で、コア 4 の中の滞在人口の**割合**がどう動いたか。主の量 s₉₆ = P₉₆ / Σ_{コア 4} P。腕: 86+96 の対の割合(東棟の重心は 96 の南の境から約 16 m=R-122 §1-3) |
| Q2(副) | 同じ前後で、96(と 86+96)の**昼/深夜の比**と**平日/休日の比**がどう動いたか(オフィスと店が入れば昼と平日が増える向き) |
| Q3(副) | コア 4 の合計と対照メッシュの差の差。**東京都の zip が手元にあるので可能になった**(R-122 問い 3 の解消)。対照の選び方は事前登録で決める(案: 開業の無い都心のターミナルのコア 4 を 2〜3 組。選定の規準=2019-01〜10 の月次の揺れが渋谷と同じ桁・駅の乗降が同じ桁・2019-11〜2020-02 に大きな開業が無い) |
| 窓 | 前 = 2019-01〜10(本則)・2019-05〜10(腕)。後 = 2019-11〜2020-02(本則・コロナの前)・2019-12〜2020-02(開業の月を外す腕)・2019-11〜2020-03(腕) |
| 比べ方 | 向き(符号)の一致と、差の大きさが帯に入るか。絶対量は使わない(比と割合だけ) |
| フロア(併記・合否にしない) | 前の窓の月どうしの揺れ(s₉₆ と各比の月ごとのばらつき)。現実どうしのずれとして必ず並べる(CLAUDE.md §5) |
| 合格線 | 事前登録 v1.4 草案([preregistration_v1_4_draft](../bench/instruments/anchor_gauge/preregistration_v1_4_draft.md))の形で、定義・母集団・窓・腕・線を先に書いて封をする。**線の値は後の窓を開ける前に決める** |

## 4. シミュレーション側

| 項 | 案 |
|---|---|
| 反実仮想 | 〔仮〕2026 年の世界(W21c)から東棟(建物・POI・入口・駅との連絡・従業者)を外した「東棟なし」の世界を作り、同じ seed の束で「あり − なし」の差を出す(CLAUDE.md §3「反実仮想は同じ出発点からの差」)。2019-10 の世界は作らない(親案・R-122 §3-3 の 1) |
| 量の作り方 | 体の journal から、メッシュ × 時間帯(昼・深夜・終日)× 日種の「1 日の滞在人口」を作る。Agoop の換算(滞在時間で按分=定義書 p.11)に合わせ、時間帯の中の滞在分を按分する形を本則に、「何分いれば 1 人」の θ を腕にする |
| 休日 | Q2 の平日/休日の比に休日のランが要る(v1.4 草案 §6 の合成の腕と同じ条件) |
| 較正との分離 | 東棟の「あり/なし」に効く係数(店の吸引の強さなど)を D1b を見て合わせない。合わせてよいのは別の材料(区の KDDI・PT・センサス)で較正した係数だけ。係数の一覧は事前登録に書く。構築の入力に D1b が無いことは `w21_sources.py` の検証側の語で見張る(R-122 §3-4) |
| 交絡 | 同じ月に渋谷パルコの再開業(2019-11-22・R-129 で一次確認)・渋谷フクラス(2019-12)・2020-03 の自粛(窓の腕)・コロナ(2020-04 以降は使わない)。パルコの重心は 95=Q1 の 86+96 の対にはほぼ入らない |

## 5. 必要な実装(書くだけ・src/ は 11-01p の段の外=ユーザーの指示の後)

1. D1b を test の層に登録: W19 の `HOLDOUT_LAYERS`・`SOURCE_FAMILIES` に層 `d1b_mlit_1km`(案の名・元の系=Agoop/国交省 1 km)と「目視済み(前の窓のコア 4 の比だけ)」の印。パターン台帳 :67 の行に置き場と封印の印を足す。
2. セル → 3 次メッシュの写像の表(R-122 §1-3 の計算を道具に。重心で振るか面積で按分するかの腕)。
3. 計器: journal → メッシュ × 時間帯 × 日種 の 1 日の滞在人口(θ は腕)。
4. 「東棟なし」の世界の生成口(建物・POI・入口・連絡通路・従業者を外す。外した体の行き先の扱いを決める)。
5. 休日のラン。
6. 事前登録の文書と採点のスクリプト。採点は前の窓と後の窓を分けて読み、**後の窓は封を切るまで読めない**(ファイルを分けて置き、読む口を封の鍵で止める)。
7. 予測の台帳(回答 10-25 §4-11)に 1 行。
8. Q3 の対照メッシュの選定(東京都の zip の中から。選定は前の窓の値だけで行い、宣言してから後の窓を開ける)。

## 6. 手順(封を切るまでの順)

1. R-129 の比較表が出たら、親が的を選ぶ(本書は東棟を前提に書いた)。
2. 事前登録の文書を書き、ユーザーの確認を取り、commit の sha で封をする。
3. 上の実装 1〜8(段の指示を待つ)。
4. 「あり − なし」の束を回し、量を出す(前の窓の値だけで係数の検算)。
5. 封を切り、後の窓を読み、符号の一致・帯・フロアを一緒に書く。結果は合っても合わなくても台帳へ。
