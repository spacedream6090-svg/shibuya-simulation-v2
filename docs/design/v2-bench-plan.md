## 1. 目的(4つ)

1. **W1(壁時計≤8h/シミュ日)予算の実測改訂** — token/s実測から壁時計/シミュ日を再導出。
2. **U14の分岐決定の素材** — 艦隊構成3案(A均質DP7 / B T1×5+T2×2 / C DP6+1予備)・量子化(INT8 vs W4A16)・**T2大モデルの要否**。
3. **未踏アドバンスト応募用の実測データ**(9/24書類に載せる)。
4. 答申の「最初に確認する3つ」: ①vLLM最新化でModel Runner V2の恩恵(+56%の可能性) ②A5000(CC8.6)でFP8がW8A16に落ちる確認=**INT8本命の裏取り** ③本番型プロンプトのprefix cacheヒット率(0%なら固定節先頭寄せが最安の改善)。
5. **品質一次スクリーニング(2026-09-01ユーザー要望で追加)** — 複数モデルをv2実タスク型の固定評価セットで比較(§3b)。U14最終選定の素材(本選定はPhase 2-3のeval基盤で)。

## 2. 実機制約(borrowed-2026-09の反映)

- A5000はCC8.6=**FP8演算不可→W8A8-INT8が本命**(答申の量子化指針)。
- NVLinkなし・NUMA 4+3分割→**スケールはDP(データ並列)基本**。T2大型のTP実験は**NUMA0側の4枚以内**で。
- vLLMプロセスあたりCPU物理2+Nコア確保(64論理で7プロセスは余裕)。

## 3. 測定マトリクス

**優先18条件(最初の1.5時間・方式の絞り込み)**: モデル{Qwen3-8B, Qwen3-14B}×量子化{BF16, INT8, W4A16}×max_num_batched_tokens{2048, 8192, 16384}——単GPU・`vllm bench serve`+random dataset(本番想定の入出力長: T1=入力1-2k/出力~128tok・日本語)・`--max-concurrency`掃引。

**本マトリクス(7GPU並行で1日圏)**: 優先18条件の勝者を軸に max_num_seqs{256,512,1024}×prefix cache ON/OFF+`VLLM_BATCH_INVARIANT=1`のオーバーヘッド1本+priority scheduling 1本。

**構成実測(1日)**: 勝ち構成での**DP7均質艦隊のスループット合算**+同一エージェント→同一レプリカのアフィニティ試験。T2候補(32B級AWQ・TP2/TP4@NUMA0)を1本。

**短縮系の追加条件(2026-09-01ユーザー要望)**: 投機的デコード(draftモデル)1本・**出力長感度{64/128/256tok}**(出力を絞るほど時間もシミュ内δも減る=原則4「量はスカラー」の実測裏付け)。

### 3b. 品質プローブ(追加・複数モデル比較)

- **候補モデル**: Qwen3-8B/14B(v1実績=基準)+32B級AWQ(T2候補)+**代替系統1-2本**(日本語品質重視・A5000適合とモデル実在をベンチ前にHF/APIで確認してから確定=記憶で断言しない規律)。
- **固定評価セットv0(約50問・5系統・Claude起草→ユーザー目視10問)**: ①T1行動判断(JSON形式遵守+妥当性) ②発話生成(日本語自然さ・**会話を短く切り上げられるか**=A1/P09バイアスの直接プローブ) ③役割知識(店員・駅員の手順=層2の前提能力) ④T2内省・要約 ⑤裁定差分(スキーマ検証済み状態差分を書けるか=層3の前提能力)。
- **採点は機械判定中心**(方法論の分野批判=LLM自己評価の循環を避ける): JSON/スキーマ遵守率・拒否率・出力長分布・語彙多様性・応答時間。LLM判定は補助(相互順位付けのみ・自己採点禁止)+ユーザー目視サンプル。
- 記録: `docs/bench/quality_ledger.csv`。GPUコストは軽微(50問×モデル数=分オーダー)・9/5の構成実測に相乗り。

## 5b. LLM時間短縮の工夫一覧(要望対応・どこで効かせるか)

**ベンチで実測するもの**: vLLM最新化(MRV2)・INT8量子化・batched_tokensチューニング・prefix cache(+ヒット率実測)・投機的デコード・出力長短縮の感度・DP7+セッションアフィニティ。
