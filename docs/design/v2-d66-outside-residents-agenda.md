## §0 症状と根(第138)

- rail.py `_build_external_home` は域外居住を**乱数 12%**(`EXTERNAL_HOME_PERMILLE` 120・C4 の繋ぎ expedient「W17 待ち」)で決め、W16 の `home_cell<0` を見ない。
- run.py `_schedule_with_population` は自宅のない体の自宅セルを `Population.start_cell`(職場→学校)で代入し、`np.clip(…, 0, n_cells-1)` で −1 を潰す。就寝境界(resolve `begin_planned_sleep`)は `target_cell<0` を `schedule.home_cell` に落とすので**職場で寝る**。resolve `initialize` は `cell_rep_node[home]` を −1 のまま索引する(ガード要)。
- 退出の口は LLM の「乗車」(呼の 1.7%)と「退去」(0.4%)だけ。週次表の境界イベントは活動の**開始**でしか出ない。
- 同じ乱数 12% を hotel(`external_home=rail.external_line>=0`)と civic(`_arrive` が `transit_state==2` の先頭 N 体を引き込む)も使う。
- 結果: C7 c7-day-2 の 5 エリア在圏 00 時 208,227・09 時 253,757=昼夜比 1.22。mock 5,000 体でも 03 時に 4,427 体が域内(通勤 2,346 中 2,060・来街 637 中 565)・09/03=1.19。

## §4 保存則・バイト・性能・テスト・リスク(親確認)

- 乗客保存則(在圏+乗車中+域外=体数)は `rail_arrive`(2→0)/`rail_depart`(0→2)の 2 本だけで閉じる。新しい `transit_state` 値は作らない。
- M1 個体 SoA(127 B/体)は増やさない。`arrival_train` はイベント CSR(rail の私物・約 306,410×16 B≈4.9 MB)へ。P4: 追加ループは線数(≤8)と便数ぶんのみ。
- テスト候補 12 本: 乱数不使用・帰無腕で旧挙動一致・T4 規模不変・保存則全 tick・決定論・到着が間に合う・日 2〜3 回の出入り・非来街日は終日域外・職場で寝ない・退出後の帰りの便(D-61 整合)・居住区分で `inbound_starts` が変わる・civic 干渉なし。
- 変わる golden: mock 5,000 体 checkpoint(現行 c96baf82)・C5/C6 の在圏構成と rail counters・T5 帰無腕(D-64)・hotel(母数 12%→88.8%)・b6_invite の率・在圏 journal と C7 計器の昼夜比。
- リスク: ①09:00 に 10.9 万体が同 tick 到着(密度・変化検出・会話相手選択が跳ねる)②8 ホームセルへの降車集中(降車側に容量なし・出口セル W11 `station_exits` へ散らす案)③**昼夜比 5.1 の過剰の可能性**=夜間在圏が W16 の域内居住 43,622 体で頭打ち。5 エリアの実夜間人口(国勢調査 町丁目)で当たりを付ける(答申 §4 待ち)④hotel の宿泊需要が客室在庫(89 POI)を突き抜ける ⑤`--replay` は帰無腕でのみ意味 ⑥D-63 (iii)(W17 の深夜配置)は残る。
