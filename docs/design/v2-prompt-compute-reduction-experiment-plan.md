## §1 目的と物差し

目的は「同じ情報を渡したまま、LLM の処理量を減らす」こと。削るのは書き方と並びと送り方で、中身ではない。

| 物差し | 何を測るか | いつ測れるか |
|---|---|---|
| M1 答えの不変 | **固定の評価セット**(⑥ で作る。場面を固定したプロンプトの組と、既定の腕の応答の分布)で、変更の前後の応答の分布の差(行動の種類の分布・発話の長さ・JSD)。閾値は評価セットを作るときに宣言(seed 間のばらつき=フロアを併記) | GPU の後(8B で実測)。それまでは mock で「prompt_hash が変わる呼の数」だけ数える |
| M2 入力トークン | 1 呼あたりの実トークン数(tokenizer で数える。概算 tok ではない) | **今(CPU)** |
| M3 prefix の再利用率 | GPU ごとの呼の列で、直前 N 呼の窓の中で先頭が一致する長さの割合(R-66 §3 の数え方) | **今(CPU・テープの再生で)** |
| M4 処理量 | 応答/秒・GPU 時間/シム日・壁時計 | GPU の後 |
| M5 出力トークン | 1 呼あたりの出力の長さ(番号で返す変更が効く) | GPU の後(mock の応答は固定なので測れない) |

合否の線: M1 が閾値の中で、M2〜M5 のどれかが改善したものだけ既定にする。M1 が閾値を超えたものは腕に残す(既定にしない)。

## §2 実験(指示書 §5 の 6 本)

| # | 実験 | 変えるもの | 変えないもの | 見込み(出どころ) | 今測れるもの |
|---|---|---|---|---|---|
| E1 | **SR6 の 3 つの並び** | ブロックの順: (a) 今の順 / (b) 時刻と天気 B3 を個人の部分より前へ(既定の候補) / (c) (b)+場所の定型文を共有 | 各ブロックの中身 | (b) −6〜−25%・(c) −4〜−22%(R-66 結論 4・推測。SR6 の宣言は「−3〜−19%(中央 −8%)・推測」) | M2・M3(テープの再生で 3 通りに並べ替えて数える) |
| E2 | **同じ情報を短く書く** | 文章の形 ↔「項目: 値」の形(B2・B4・B5 の各行) | 載せる項目の集合と値 | 空欄(未計測)。BN-2 の「個体長 300→800 で −40.6%」は長さの効果で、形の効果ではない | M2(tokenizer で両形を数える) |
| E3 | **変わらない部分の書き方をそろえる** | 呼び出しの間で変わらない部分(B0・B1・場所の定型・B6 の問いの型)の表記の揺れを無くし、共有できる範囲を広げる(B6 は種類が 4% しか無く intern が効く=10a のアジェンダ §1) | 中身 | 空欄(未計測) | M3(共有ブロックの再利用率) |
| E4 | **先頭が同じ呼び出しを並べて送る** | 艦隊への振り分けと並び: GPU ごとの窓の中で先頭(共有静的+場所)が同じ呼を隣り合わせる(今は体の順) | 呼の集合・tick | prefix の再利用 48〜73% → 上限は「同じ先頭の呼の数」で決まる(R-66 §3) | M3(振り分けの再現で数える) |
| E5 | **選択肢から選ぶ判断を番号で返す** | 出力の形: 行動の選択を番号(1 桁か 2 桁)で返し、本文は会話などに限る。構造化出力(09-09 の実測で使える)で強制 | 選択肢の集合・判断の主体 | 出力 o64 既定の一部が 1〜3 トークンになる(推測)。判断モデルの導入(DM)と同じ口 | M5 は GPU の後。今は「番号で返せる呼の割合」を数える |
| E6 | **サーバーの設定** | vLLM の prefix caching の窓(ブロックの大きさ・キャッシュ量)・バッチの大きさ・構造化出力の有無 | モデル・プロンプト | 空欄(未計測) | GPU の後 |

注意: E1〜E4 は prefix の再利用を上げる方向なので、**知覚契約 §2.2 の「順序=変化率の昇順・末尾重視」と両立するか**を M1 で確かめる(並びを変えると LLM の読み方が変わる可能性がある)。

## §3 手順(今できること → GPU の後)

1. **今(CPU)**: 既存のテープ(c7-day-4 の calls 2,706,593 行・blocks 1,482 行。gitignore 下)と 5,000 体の mock のテープを使い、E1 の 3 通り・E2 の 2 形・E3・E4 の並べ替えについて M2・M3 を数える道具を作る(読むだけ。テープは書き換えない)。結果は表にして 1 回報告する。
2. **評価セット(⑥)の設計**: 場面の抽出(時刻帯 × 場所の種類 × 本人の状態の層別・各層 n 件)・固定の seed・応答の分布の物差し・閾値(フロア=同じプロンプトを seed 違いで回したときのばらつき)を宣言する。これは別のアジェンダ(詳細アジェンダを先に出すもの)。
3. **GPU の後**: 評価セットで M1 を測り、合否の線を越えたものだけ既定にする。SR6 は結果を見て既定を決め直す(ユーザー指示)。
4. **版上げ**: 既定を切り替えるものは版上げに束ねる(呼数・行動の件数・prompt_hash の動く量を記録)。

## §4 先に聞くこと

- 評価セット(⑥)の設計を、本計画の実測より先に出すか(親案: 先に出す。M1 が無いと既定は切り替えられない)。
- E5 の「番号で返す」は、判断モデルの導入(DM)の口と同じ形にするか(親案: 同じ形。別に作ると二重になる)。
- E2 の「項目: 値」の形は、知覚契約の文言(語の段・単位)を変えずに書けるか=中身を削らない範囲の線引き(具体の候補が出たら 1 つずつ見せる)。
