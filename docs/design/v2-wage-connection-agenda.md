# 賃金をつなぐアジェンダ(短い版・2026-10-03・第317)

> **位置づけ**: ユーザー決定([指示書 10-03](v2-wallbounce-decisions-2026-10-03.md) §6 ⑧ 8-1・§3-7 A11)=「賃金は 10g(複数日の mock)の前につなぐ。実装の前に短いアジェンダ(払う口・域外部門・初期の運転資金の出典・売上の流入の作り方・『払えなかった』の数え方)を出す」。材料は [賃金の材料](../bench/analysis/wallbounce-1003/wage-prep.md)(実行役 Opus 5.5・親が引用した行を HEAD で実読)。順番は 10a〜10f → 11a → 11c → 賃金 → 10g(指示書 §2)。
> 全決定は仮(CLAUDE.md §2-1)。問い W1〜W8 はユーザーの判断待ち(PENDING §1-1)。

## §0 事実(測って分かったこと)

- **今あるもの**: 送金の口(`transfer`・`transfer_many`)、賃金の科目 3 本(雇用主→世帯・店舗→世帯・外界→世帯。外界からの分は境界の流入=faucet)、残高不足を「払えなかった」として返す戻り値、参入資本の入口(ex nihilo 禁止の口)、月の賃金の関数 `anchors.monthly_wages`、日次の締めとセンサスと検算。**どれもランから呼ばれていない**。
- **無いもの**: 雇用主の口座が 1 つだけ(`cli.py` が `n_employers` を渡していない)/ `org_id` がランの帳簿に渡っていない / 外界→雇用主の「範囲外からの売上」の科目が無い(12 科目の外)/ 店舗(POI)と組織の対応が無い / 預金を超える引き出しを止める検査が無い / 不払いを科目別・日別に数える欄が無い / 複数日を回す口が無い。
- **1 日に減る所持金(5,000 体・mock・seed 1・HEAD)**: 139,575,428 円 → 136,896,828 円(**−2,678,600 円・1 体 536 円**)。内訳は購入 2,335,700 円+運賃 342,900 円。賃金 0 円。5 日で初期の 90.4%(推測・単純な 5 倍)。
- **規模の差(推測)**: 区内の組織に勤める体 2,421 体の月の賃金は約 9.7 億円(東京都の所定内給与)。うち店員型の組織は約 2.5 億円/月だが、ランの中の購入は 30 日で約 7 千万円。**指示書の「範囲外からの売上をオフィスにだけ入れる」形では、店員型の組織で「払えなかった」が出る見込みが高い**。
- **日の頭のリセット 26 件**(A11 の一覧=[材料 §2](../bench/analysis/wallbounce-1003/wage-prep.md)): お金 3・物 3・体 7・位置と在圏 4・関係と記憶 4・世界の過程 5。お金の 3 件(財布の外界からの入れ直し `resolve.py:518-524`・店舗の参入資本の入れ直し `cli.py:287-289`・帳簿の作り直し)は「ランごとに外界から入れ直す」作りで、複数日を `run_day` の繰り返しで回すと**毎日お金が湧く**。A11 の自動補充の禁止に当たるので、10d(再開)と 10g で「2 日目以降は入れ直さない」を必ず入れる。
- **ランの保存則の式が賃金で崩れる**: `RunResult.conserved`(`run.py:1111-1118`)は「Σ所持金+Σ売上+Σ運賃=初期」で、賃金が入ると必ず NG になり、終了コード(`run.py:4214`)も失敗になる。帳簿の検算(全部門の合計+境界の出入り=一定)に置き換える必要がある。
- **出典(取得済み・`data/calib/wage/`・e-Stat・md5 は MANIFEST)**: 法人企業統計 2023〜2025 年度(現金・預金 ÷ 月の人件費: 全産業 16.06 か月・飲食 7.20・情報通信 15.16)/ 経済センサス 2021 企業等の表(渋谷区。本所の全国分の値)/ 賃金構造基本統計調査 令和 7 年(東京都 × 産業別)。給料日の分布の公的な錨は**無し(空欄)**。

## §2 受入の試験(既知の答え)

1. 賃金は送金の口だけを通る(AST 検査)。払う側が減り受け取る側が増え、全部門の合計が変わらない。
2. 外界→世帯の賃金は faucet に数えられ、外界の残高が同額だけ負に動く。
3. 暦の給料日にだけ払いが起きる(土休の前倒しを含む)。給料日でない日は 0 件。
4. 雇用主の残高 0 の対照で、不払いの数と額が正しく数えられ、送金は起きず、例外も出ない。
5. 初期の運転資金が式どおりで、参入資本の科目で入っている。
6. 外界→雇用主の流入が日次で登録され faucet の合計に入る。
7. 預金を超える引き出しは拒まれる。
8. 給料日を含む複数日(24〜26 日をまたぐ 3〜5 日)の mock で、毎日「全部門の合計+境界の出入り=一定」・検算①・残差 0。
9. 既定の腕で不払い 0 件。
10. 2 日目以降の外界→世帯の持ち込みは来街者の来街だけ(住民・通勤者・従業者には入らない=A11)。
11. 同じ seed の 2 回のランで帳簿の状態ハッシュが一致。
12. 賃金の口を切ったラン(切替口)では今の checkpoint が 1 バイトも動かない。

## §3 直す前に報告する食い違い

- `RunResult.conserved` の式と終了コードは、賃金を入れると必ず失敗する(W8)。
- 日の頭の「財布の外界からの入れ直し」と「店舗の参入資本の入れ直し」は、複数日では A11 の自動補充に当たる(10d・10g で「2 日目以降は入れ直さない」を入れる)。
- 指示書 8-1 の「売上の流入はオフィスにだけ」は、店員型の組織の賃金の規模(約 2.5 億円/月の推測)に対してランの中の購入(約 7 千万円/30 日)が小さく、不払いが出る見込み(W5)。
- 給料日の分布の公的な錨は見つからなかった(空欄)。既定は「毎月 25 日・土休なら前倒し」を expedient として宣言する案。
