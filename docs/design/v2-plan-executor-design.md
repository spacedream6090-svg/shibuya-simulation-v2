## §0 目的と足かせ

- 足かせ(第143 の親の名指し): **世界が「誰がいつ舞台に居て何をしているか」を機構として持っていない**。W17 は起床条件を出すだけで実行されず、在圏は LLM の乗車 1.7% と乱数 12% の副作用でしか動かない。
- 症状の連鎖(1 つの穴から出ている): 域外居住 88.8% が常駐 → 昼夜比 1.194(現実 14.8)→ 深夜の呼が減らない(D-56)→ 職場で寝る(D-62)→ 帰りの便が要る(D-61)→ 夕方の空白(D-63 (ii))→ 起床率が a(h) に届かない。
- **継ぎ足しを止める形**: 上の 6 個は別々の穴ではなく「計画が実行されていない」の 6 つの影。**在圏と計画の実行を一級のエンジン層**にして、影を個別に塞ぐコード(乱数 12%・`_assign_return`・就寝抑止・補完規則・hotel/civic の判定)を**吸収**する。
- 目的は「D-66 を直す」ではなく **「計画どおりに舞台へ出入りする世界」を持つこと**。良否は `tools/c7/presence_yardstick.py` の 6 指標で**前より良い**を示す(§12)。

## §3 イベントと tick 処理

**日次に 1 回**、`(tick, agent, type)` 昇順の決定論イベント列を組む(構築は `lexsort` のみ・P4 の個体比例ループなし)。

| type | 名 | 発火 | 実行(resolve の口) | arg |
|---|---|---|---|---|
| 0 | ARRIVE | 到着便が**ホームへ入る** tick | `rail_arrive`(降車セル) | 便索引 |
| 1 | DEPART | 在圏ブロックの**終了** | `rail_depart`(線) | 線索引 |
| 2 | SLEEP | 就寝ブロックの開始 | `begin_planned_sleep` | 就寝地セル |
| 3 | WAKE | 非就寝の計画境界 | `wake_from_plan` | − |
| 4 | WORK_START | 勤務/通学ブロックの開始 | `target_node` を職場へ(LLM が上書き可) | target_cell |
| 5 | AT_HOME | 自宅行の開始(域内居住のみ) | `target_node` を自宅へ | home_cell |

- **tick 処理**: `searchsorted` 1 本で当 tick の区間を切り、type ごとに `flatnonzero` → ベクトルで resolve を叩く。逐次ループは type 数 ≤6 と、この tick にホームへ入る便数ぶんだけ。
- **到着の便(宣言)**: 線 = `direction_node`→線表(W12 `NODE_DEFS` の `lines[0]`)。**乗換・所要時間は持たない**(D-51 §8 の宣言を継承)。便 = 「ブロック開始に**間に合う最も遅い便**」(`enter_tick ≤ start` の右端)。始発前は始発。`direction_node` 8/9(徒歩 2,339・道路 5,893 = 2.4%)は**非鉄道ゲート**=便を使わず開始 tick ちょうどにゲートセルへ置く(expedient)。
- **退出の実行形(既定 (a))**: ブロック終了 tick に**即時 `rail_depart`**。理由=到着が容量も所要時間も見ない宣言なので、退出だけ受容関数に通すと 18:00 の 61,361 体/分が 8 ホームに殺到し打ち切りを量産する。切替口 `--exit-mode immediate|board_intent|walk_to_platform`(`board_intent` は D-51 の待ち行列を通す=第2陣)。
- **山の分散**: 同一便の到着人数が `定員 × 混雑率上限` を超えたら、超過分を**より早い便へ決定論で溢れさせる**(agent_row 昇順・backward fill・上限 `ARRIVAL_SPREAD_MAX_TRAINS`=8)。
- **降車セルの分散**: ホームセル 8 個 → **W11 `w11_station_exits` の出口セル**へ round-robin(`ProcessAssets` に `station_exit_cell` を載せる=新規ローダ 1 本)。

## §4 LLM との分担

| 場面 | 計画(世界が実行) | LLM | 衝突時の優先規則 |
|---|---|---|---|
| 計画境界(PLAN_*) | WAKE で起こす | 起床して行動を選ぶ | **両立**(現行どおり・呼が落ちても起きる) |
| 就寝境界 | SLEEP で寝かせる | 呼ばない | 計画優先(D-62 のまま) |
| 退出 tick に**会話中** | DEPART を保留 | 会話を続ける | **LLM 優先・次 tick へ繰り延べ**(`plan_flags` bit2・上限 `EXIT_DEFER_LIMIT` 30 tick 後は強制退出) |
| 退出 tick に**乗車中/域外** | 何もしない | − | 二重退出なし(§5) |
| 退出 tick に**買物中**(`poi_ref≥0`) | `release_indoor` → 退出 | − | **計画優先・中断** |
| 退出 tick に**待ち行列**(`queue_poi≥0`) | `balk_queue` → 退出 | − | 計画優先・離脱 |
| 到着 tick に体が既に在圏 | ARRIVE を捨てる | − | 世界の実状態が正(二重到着なし) |
| LLM が「乗車」を選ぶ | 計画は触らない | D-51 の意図保持で乗る | **LLM 優先**。域外へ出たら当日の残り DEPART を落とし、次の在圏ブロックに ARRIVE を張り直す |
| LLM が「退去」を選ぶ | 同上 | 同上 | LLM 優先 |

- **D-56(就寝抑止)の扱い**: 計画実行で `activity=SLEEPING` が正しく立つので抑止の**効き目は縮む**が、内受容・セル変化由来の候補は寝ている体にも出続けるため**規則としては要る**。→ 残す(既定 True)。`--no-sleep-suppression` は帰無腕に降格し、C8 で「計画実行あり×抑止なし」を 1 本測る。

## §5 不変条件と診断

- **I1 乗客保存則**: 在圏 + 乗車中 + 域外 = 体数。全 tick で検査(既存 `rider_census`)。遷移は `rail_arrive`(2→0)/`rail_depart`(0→2)の 2 本だけ。
- **I2 二重到着なし**: ARRIVE は `transit_state==2` の体にだけ適用。**I3 二重退出なし**: DEPART は `transit_state==0` の体にだけ適用。
- **I4 civic 整合**: `LargeEventProcess._arrive/_leave` は層へ `notify_pulled_in(ids, tick)` / `notify_pushed_out(ids, tick)` を送り、層が当日の該当イベントを無効化・張り直す(D-61 追補の公開口 2 本の後継)。
- **I5 域外の体は寝ない・食べない・買わない**: `begin_planned_sleep` の「触らない」規則を維持。**I6 −1 ガード**: `home_cell<0` のまま `initialize` / `target_cell_at` / `cell_rep_node` を索引しない。
- **診断**: 在圏 journal(`--occupancy-every 60`)に **`transit_kind_counts`(9 種別 × 3 状態)** を 1 本足す(108 B/正時)。`presence_yardstick.py` は無改造で読める。要約 1 行 `計画実行: 域外居住 N / 到着 N / 退出 N / 終日域外 N / 計画一致率 x.xxx / 昼夜比 09-03 x.xx`。**計画一致率** = 毎正時「計画上その時刻に在圏のはずの体」のうち実際に `transit_state==0` だった割合と、逆側(域外一致率)の両側(§10-7)。`c7lib.parse_run_summary` に当たらない書式にする。
