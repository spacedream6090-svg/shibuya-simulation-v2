## §1 段 2a: 選択器の口と候補の絞り込み

1. **口**: 新規 `engine/chooser.py`。`class Chooser(Protocol): def probs(self, candidates: np.ndarray, context: ChoiceContext) -> np.ndarray`(候補 POI 索引の 1 次元配列 → 同じ長さの確率・和 1・候補が空なら空)。`ChoiceContext`=dataclass(体 id・tick・現在セル・現在ノード・行為コード・対象の種類(名指し/カテゴリ/なし)・対象の文字列・空腹の語(いまは `hunger` の段)・可視順(W8 の視点数)・距離(W3 `cell_dist` の値=**実行時に初めて読む**・同じセルは 0))。抽選は `core.rng.stream(seed, "engine.chooser", tick, agent_id)` の決定論(分布から 1 つ引く)。**分布が one-hot でも抽選は通す**(口を同じにする)。
2. **既定の選び手 `NearestChooser`**(憲法⑥の宣言つき暫定): 同じセル内は距離 0 なので**可視順(視点数の降順)→ POI id** の順に 1.0(=満足化の「見えている順」の最初)。セル外の候補は `cell_dist` の昇順(2b/2c で使う)。`--chooser {nearest}`(D-119 の `classical`・GPU 後の `logprob` はここに増える)。manifest に `chooser`。
3. **候補の絞り込み(エンジン・D-114 (a))**: 行為が購入/食事/並ぶのとき、候補=**現在セルの POI** のうち (a) 営業中(`open_mask`)(b) 意図に合う: 食事なら `eatery_mask`(既定 food)・購入なら物販+飲食(現行の対象と同じ集合)・対象欄がカテゴリ語なら **カテゴリ一致**(第270 の対象欄の語 → W6 の cat/subcat への対応表=辞書 v5 `TARGET_HINTS_V5` を土台に実装役が起草し「問い」で返す)(c) 到達可(同じセルなので自明)。**(i) 名指し**(対象欄が POI 名に一致=C9b の目印照合 `parse_target(landmarks)` を POI 全体に広げる・完全一致 → 名⊂入力 → 入力⊂名 の順)は候補を**その店 1 件**にする(セル内にあるとき。セル外は 2c)。
4. **落選の理由を分ける**: 候補 0 の理由を `BAD_TARGET`(対象が解決できない)/`CLOSED`(合う店はあるが全部閉店)/`OUT_OF_STOCK`/`NOT_IN_EATERY` に分けて書く(いまは最小 id の 1 店の状態で決まる=閉店 28% の 79% は同じセルに開いている店があった(D-114)=**この段で消えるはずの損失**)。
5. **計数(manifest)**: `target_resolution` = {(i) 名指し, (ii) カテゴリ語→候補→選び手, (iii) なし→候補→選び手, (iv) 候補なし(理由別)} の件数と、選び手の分布のエントロピーの平均(one-hot なら 0)。
6. **並ぶ**(語彙 v3)は購入/食事へ委譲済み(#47)なので同じ経路。**乗車のホーム選択(A13・直線距離順)は触らない**(別段)。
7. **テスト**: 口の契約(和 1・空・決定論)・NearestChooser の順序・候補の絞り込み(閉店/カテゴリ/名指し)・落選理由・manifest 列・既定 checkpoint の新値を版の台帳へ(15 腕)。mock 5,000 で 成立率の前後(D-114 の実測は実 LLM テープの 41%=mock は別の値になる=前後だけ見る)。**リプレイ計測**: 第270 の `v3_d114.py` の手順で実 LLM テープ 8 本の対象欄を新しい候補解決に通し、(i)〜(iv) の件数と「候補 0 の理由」を出す(エンジンを回さない・GPU 不要)。

## §2 段 2b: 行き先を対象欄から(D-112 ②)

1. 移動の対象欄の解決順: **セル ID**(「セル」接頭辞つきも=#45)→ **名指し**(POI 名・目印名 → その POI/目印のセル)→ **カテゴリ語**(2a の候補解決を**近傍のセル**に広げる: 現在セルに無ければ W8 で見えている POI → それも無ければ `cell_dist` の昇順で最初に候補があるセル(上限=R セル・宣言・初期 5)→ 選び手)→ **なし/説明語**(現行の既定=職場/自宅のうち今いない方を**保つ**・宣言)。
2. 「探す」(第270 のクラスタ ★探す ≈2,800 体)は 移動 対象: カテゴリ として上の経路で受ける(草案 §4-6)=`SYNONYMS` の写像はそのまま。
3. 到達判定は next-hop の有無のまま(時間予算は D-122 S1 で)。`UNREACHABLE` に「経路なし」と「対象が解決できない」を分ける(後者は `BAD_TARGET`)。
4. 計数: 移動の対象の解決内訳(セル/名指し/カテゴリ/目印/なし→既定)・カテゴリ解決で選んだ距離の分布(cell_dist)。
5. **触らないもの**: C9b の「近づく」(`_approach_dest_node`)は既存のまま(名指しの目印はそちらを通る)。

## §3 段 2c: 意図の保持(D-112 ①・D-114 案 A)

1. **表現**: SoA に `intent_action` int8(行為コード・−1=なし)・`intent_target` int32(POI/セル/体)・`intent_kind` int8(対象の種類)・`intent_since` int32=**+10 B/体・既定で確保**(D-112 ② で既定 checkpoint は動くと決まっているので腕にしない。D-102 Q1 の behavior-hash が入れば挙動列)。
2. **いつ立つか**: 購入/食事/並ぶ/会話/就寝の対象が**現在セルに無く解決できる**(名指しで B2 に見える店・カテゴリで近傍に候補・会話の相手が別セル・就寝の寝床が別セル)とき。エンジンは行為を「意図」に保存し、**目的地つき移動**(活動層 `activity_kind=1`・`until_kind=ARRIVAL`)を始める(二層の仕組みを流用=活動中は CELL_BLOCK を起こさない=C05 がそのまま「進行中は場所の変化で起こさない」)。B5 に「いま <行為> のため <対象> へ向かっている」の 1 行(≤ 15 tok・個体枠 300 の内)=「観測に現在の意図を載せる」。
3. **着いたら**: 到着満了(#47 の経路)で LLM を呼ばず**エンジンが意図の行為を実行**(System 1・呼数 0)。成立なら意図を消す。失敗(閉店・売り切れ・満席→列・相手が去った)は結果コードを書き、意図を消し、活動層の規則(失敗∧活動なし → 次 tick 満了 → 再考)に任せる=**失敗即時の規則はそのまま**(§7 の決め)。
4. **満了**: `INTENT_MAX_TICKS = 60`(宣言・expedient・感度腕 30/120)を超えたら `TOO_FAR`(**新コード**=D-122 P6 の先取り・「経路はあるが遠すぎた」)で消す。経路なしは `UNREACHABLE`。乗車の意図(`board_line`・D-51 (c)・打ち切り 30 tick)は別経路のまま(統合は問いとして返す)。
5. **計画実行層との衝突**: 計画境界(DEPART・SLEEP)が来たら意図を捨てる(計画が優先=現行の受動的な上書きと同じ・件数を数える)。会話の招待は意図中でも受ける(相手の判断)。
6. **計数**: 意図の設定/到着/成立/失敗(理由別)/満了/計画で捨てた の件数・意図中に抑止した CELL_BLOCK の件数・意図の平均所要 tick。**D-112 ① の予想**: 乗車と同じ形で「歩く 28 tick の間の受動的な呼び出しで意図が落ちる」(実現の損失 27%)が消える=購入/食事の成立率が上がり、受動的な呼が減る(mock で前後)。
7. **mock 方策**: mock v3 は対象を自前で選ぶ(セル内)。2c の経路を mock で通すには、mock の対象に **B2 に見えるセル外の POI 名**を一定確率で出す口を足す(`MockLLM(form="v3", out_of_cell_target_p=0.1)`・既定 0=golden 不変)。実 LLM の計測は GPU 後(D-114 の 19,553 呼が対象)。
