# 仕様書 v0 第 10 章 外への口(interfaces)

> 位置づけ: [返事その 6](../prompt-2026-11-05-reply6.md) §3-1b の仕様書 v0。決定の正は原文で、すべて仮決定です。理由の出どころは、11-01 までは各回答の理由の文、11-02 以降は[壁打ちの記録](../../reference/wallbounce-record-2026-11-02_05.md)(「記録 2-17」の形で引く)です。記録に無い理由は「理由の記録なし」と書きました。食い違いは [`conflicts.md`](conflicts.md)。

## 要約

この章は、シミュレーションの中身を外へどう見せ、何を言ってよいかを決めます。

ビューアは細かく設計しません。最小の形は、渋谷の地図の上を点が時刻とともに動き、再生、停止、時刻の移動、速さの切り替えができて、点を押すと今の行動と考えが見える、というものです。機能はシミュレーションを回しながら足します。最初から守ることは 3 つあります。ランの記録を十分に残すこと、ビューアは記録を読むだけにすること、外に出すときだけ架空名の段を通すことです。

計器盤(現実との一致を見る報告)は、今の Markdown と JSON の報告で足ります。つなぎの台帳と、まだ測っていないものの一覧を足します。

シミュレーションの中とプロンプトは実名で、公表物では架空名に置き換えます。置き換えの段を通らないと外に出せない作りにします。

言葉の使い方も決めました。現実の渋谷を公開データから組み立てていること、実際の LLM で 39 万人 × 1 日を回したこと(日付つき)、答え合わせの計画があることは言ってかまいません。「渋谷を再現した」「人の流れを予測できる」「人と同じように考える」「未来が分かる」は言いません。論文や応募書類で「再現できた」と述べる前には、台帳の判定、holdout(封印した照合用データ)、ablation(1 要素を外して効果を測る実験)、感度試験(仮の値を振って効きを見る試験)を通します。何を主張と呼ぶかの線引きはユーザーの確認待ちです。

PLATEAU AWARD は新しくランを回さず、今ある物から作ります。優先はシミュレーションの作り込みの後で、11 月 14 日に一度止まって、出し方をユーザーが決めます。公開、外部への連絡、ODbL(OSM のデータの共有条件)の提供方法は、ユーザーの判断を待つ止まる地点です。

未決は、ビューアの細部、ODPT の作品の範囲、見た目の欄の倫理の線、データの権利です。食い違いは 6 件あります。施設名と組織名の扱い(C-01・C-02)、仮の名前と言わないことの関係(C-03)、ビューアの仕様を決める場所(C-13)、ODbL を決める時機(C-14)、倫理の安全条件と語彙(C-15)です。
