## 1. これは何か

現実の渋谷を仮想空間に再現する **LLM 社会シミュレーション第 2 世代**。
今の既定の世界は 345,858 体(国勢調査に基づく再合成=W21c)。人は 1 分刻み(1 tick)で 1 日 1,440 tick を過ごす。
実 LLM で 39 万体(390,067)を 1 日回した実績は 2026-09・3 seed のもの。第一目標は「世界そのものがプロダクト」——
現実整合アンカー台帳を育て、**歪む場所を宣言する**こと(`CLAUDE.md` §1)。

設計の背骨(`CLAUDE.md` §3・2026-10-12 のユーザー決定 K2):

> **世界の状態と集約と破れない法則はエンジン(コード)。知覚・記憶の強さ・変化の検出は System 1(コード)、日常の判断は判断モデル、会話とよく考える判断は LLM。**

エンジンが世界の法則(保存則・物理・台帳)を持つ。行動を止めるのは物理と、現実でも物理的に止める仕組み(鍵・改札など)だけ。
世界の変化はエージェントの行動の結果として起こす(棚が減るのは、店員が補充行動をしたから)。

## 2. 三層

```mermaid
flowchart LR
  subgraph A["世界資産 W0〜W21 凍結 parquet"]
    A1["地理・建物・POI<br/>520 セル / 2,337 POI"]
    A2["母集団 345,858 体"]
    A3["週次日課 W17<br/>3,074,698 行"]
  end
  subgraph B["エンジン Python + NumPy"]
    B1["個体 SoA と世界過程 18 本"]
    B2["繰り延べアービタ<br/>誰を起こすか"]
    B3["resolve 唯一の書き込み口"]
    B4["経済台帳と保存則"]
  end
  subgraph C["LLM 艦隊 7 x Qwen3-8B 2026-09・いまは停止"]
    C1["観測 B0〜B6 を読む"]
    C2["理由 / 行動 / 対象 / ひと言"]
  end
  A --> B
  B --> C
  C --> B
```

- **世界資産**は 21 段階(W0〜W20)のビルドで一度だけ作り、ハッシュで凍結する。同じ入力から作り直すとバイト一致する(`src/shibuya/build/run.py`)。人口の作り直し(W21・W21b・W21c)は別に組み、W16/W17 の表へ当てた(`IMPLEMENTED.md` #118)。
- **エンジン**は破れない法則だけを持ち、世界状態への書き込み口は `engine/resolve.py` の 1 本に閉じている。世界過程も例外にしない。
- **LLM** は世界を書き換えられない。返すのは 2 行の文字列だけで、エンジンが前提条件を検査して受理/拒否する。

## 3. 1 tick で起きること

```mermaid
flowchart LR
  A["1 前 tick の応答を適用<br/>apply_key 昇順"] --> B["2 世界過程 18 本<br/>鉄道・混雑・営業・経済"]
  B --> C["3 変化検出と起床候補"]
  C --> D["4 繰り延べアービタ<br/>会話 → 計画境界 → 個体 → セル"]
  D --> E["5 観測 B0〜B6 を描画<br/>入力 1,300 tok 以下"]
  E --> F["6 艦隊へ非同期で発射<br/>出力 64 tok"]
  F --> G["7 二相コミット<br/>意図 → 資源裁定 → resolve"]
  G --> A
```

要点は 3 つ。

1. **全員は毎 tick 考えない。** 起床候補は 4 クラス固定優先で並ぶ。呼数に上限を置くと(`--l4-scale 1`=2026-09 の既定)、あふれた分は捨てずに**繰り延べ**される(`src/shibuya/engine/arbiter.py`)。今の CLI の既定は上限なし(`--l4-scale 0`)で、L4 の 10 呼/体/日は監査線(`IMPLEMENTED.md` #55)。
2. **普段はエンジンが日課を進める。** 各体は W17 の予定表どおりに動き、LLM は「起床」したときだけ介入する。5,000 体の検証ラン(2026-09)では、世界で実行された行動 270,424 件のうち **87.6%(236,860 件)がエンジン継続**、LLM が決めたのは 12.4%(33,564 件)だった(旧 `PENDING.md` D-98)。
3. **LLM の出力は 2 行に固定。** 1 行目「理由: 40 字以内」/ 2 行目「行動: 語彙 1 語 対象: … ひと言: 20 字以内」。行動語彙は 24 語で、語彙外の語は辞書で写すか未定義行動として台帳に残す(`docs/design/v2-action-contract.md` §1・§7)。これは語彙 v1(ライブラリの既定)の形。今の CLI の既定は語彙 v3 で、ラベルは 理由/行動/対象/活動/まで の 5 つ、行動は種別横断 11 語+「なし」と役割語 11 語(`IMPLEMENTED.md` #46〜#48)。

## 6. いま分かっている穴(数字つき)

下の表の「いまのシミュレーション」は 2026-09 の実 LLM ラン(390,067 体・L4 の按分あり)の値。その後の版上げと母集団の差し替えの後は、実 LLM で測り直していない。

| 何 | 現実 | いまのシミュレーション | 比 |
|---|---|---|---|
| 思考の回数 | 4,000〜6,240 回/日 | LLM 呼 6.90 回/日 | **1/580〜900** |
| 会話 | 覚醒時間の 27.9% | 0.00105 セッション/体/日 = 410 件/日(参加 0.0021/体/日) | 事実上ゼロ |
| 内省・心のさまよい | 覚醒の 46.9% | 日次内省 **0 回**(本番で発火していない) | ゼロ |
| 活動の切り替わり | 13.9 回/日 | 計画ブロック 8.88 本/日 | 0.64(桁は合う) |
| 在圏のピーク時刻 | KDDI 15〜18 時 | 10〜13 時(5 エリア全部) | **3〜8 時間早い** |
| 来街者比 | KDDI 0.40〜0.76 | 0.14〜0.39 | 半分以下 |

出所: 現実側 = `docs/research/v2-thought-frequency-anchors-note.md` §1(Tseng & Poppenk 2020 ほか)/
holdout 側 = `docs/bench/c7/prereg_arms_v1.md` §8(開封結果 0/4 NOT PASS)。

**この表がこのプロジェクトの正直な現在地**である。人間 1 人ぶんの思考量に LLM 呼で届かせるのは、
本番規模で L4 の 390 倍が要り、この艦隊でも 100 倍の艦隊でも不可能(同ノート §4)。

## 7. 2026-09-19 時点で決めようとしていたこと

2026-10-23 時点の注: D-99 は呼数の上限なしの形で実装した(`IMPLEMENTED.md` #38・#55)。D-98〜D-101 の行は 09-28 に旧 PENDING の全文として凍結した(`docs/log/pending-archive-2026-09-28.md`)。今の判断待ちは `PENDING.md` §1。

- **D-98 検証指標の組み直し** — 「販売数 ÷ 呼数」のような単一比を忠実度に使わない。実現量/体/日・実現/選択・呼あたり効率・費用・選択分布の差、の 5 本に分ける。
- **D-99 予算 L4 の感度腕 AB8** — 10 呼/体/日という上限が結果を形作っていたかを、0.5×/1×/2×/無制限の 4 腕で測る。
- **D-100 状況固定のオフライン評価** — テープの同じ観測に腕ごとの文面で答え直させ、世界を挟まずに選択分布だけ比べる。
- **D-101 思考の階層と目標頻度** — ① 活動の切り替わり ② 型付きの速い判断 ③ 言葉の熟考 ④ 会話、の 4 階層に分け、各階層の目標頻度を人の錨に結ぶ。

いずれも旧 `PENDING.md` の D-98〜D-101。全決定は仮であり、何度でも変更できる(`CLAUDE.md` §2-1)。
