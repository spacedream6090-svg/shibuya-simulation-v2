### 5. 宣言と問い

- **Q55 EVENT_KINDS v0**(§1 の表)。記録しないもの(退去・断る・計画の就寝・移動の開始)を含めて確認したい。
- **Q56 importance の「初回 +1」**: 鍵が同じなら行を作らない(統合)ので、全部の行が「初回」になる=実質 一律 +1。「その種類(kind)の最初の行」など別の読みにするか。
- **Q57 会話の要旨**: mock v3・classical は「ひと言」を出さない=要旨は 0 件。v3 の書式に「ひと言」は無いので、実 LLM(v3)でも空になる。要旨の源を「活動」欄(10 字)や応答全文の先頭 40 字にするか、v3 に ひと言 を戻すか。
- **Q58 看板の初見の判定**: 親しみの表(入った回の露出を含む)で判定すると描画の時点で既知の看板が大半(15,608 → 2,296)。描画による露出だけで判定する(親しみの表の「描画の露出」だけを見る)か、いまの形か。
- **Q59 気づきの供給**: テープでは 0.22 件/体/日(上限)で、見込みの 1.9 と合わない。見込みの出所の確認(R-48 の計算)と、顕著行為の発生率の既定(3/万/日)の扱い。
- **Q60 会話の行の数え方**: 会話の行は「開いたセッションの参加者ごと」に作る(招待者の 会話 の成功は記録しない=二重にしない)。発話は `mem_n`+1(`mem_last` 更新)。招待が保留のまま断られた・期限切れになった場合は、エンジンが体の `last_result` に書いた分だけ記録される。
- **Q61 1 行の実バイト**: アジェンダ §1-1 の「27 B」は数え直すと 25 B(1+4+4+4+4+4+1+1+2)。宣言は 32 B/行のまま(詰め物は予算の側)。
- 宣言(expedient): 気づきの object=事象のセルの場所・通報/就寝の object=今いるセル・手伝いの partner=intent の対象・結果の走査は `last_result_tick == tick` の配列比較(体数の配列演算・逐次ループではない)。
