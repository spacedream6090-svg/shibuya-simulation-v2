### 1-5 項 4 食事の門を時間あたりに — **式は確認・「最初の門」に問題**

- 手計算との照合(テストとは別の値):
  - p_h=0.6・Δt=1 分: 1 − 0.4^(1/60) = 0.0151555 で一致。
  - p_h=0.6・Δt=600 分: 1 − 0.4^10 = 0.99989514 で一致。
  - 1 分 × 600 回を合成すると 600 分 1 回と同じ値になった。
  - Δt が 0 や負なら 0。p_h > 1 は 1 に、負は 0 に切られる。p_h=1 かつ Δt=0 なら 0。
- Δt は `(tick − 前回) × minutes_per_tick`=分で正しい。前回の門の初期値は −1 で、int32(4 B/体)。per_wake では配列を確保しない(`_gate_last is None`。テストでも確認)。
- カレンダーの係数(0.3 倍)と周囲の係数は、p_h に掛けてから時間の換算をする。率に掛ける順なので、Δt=60 分のときは旧と同じ値になり、分け方にも依らない。ただし係数は門を引いた**その時点の状態**で決まり、Δt の全区間に遡って当てられる(空腹の段・次の予定・飲食店が見えるかも同じ)。睡眠をまたぐ Δt(実装役の問い 2)はこの一例。
- **睡眠をまたぐ Δt の影響(数値)**: 上のランで門は 108,754 回。前回の門からの Δt の内訳は、≤5 分 22,445・≤30 分 34,191・≤60 分 39,476・≤180 分 6,405・≤360 分 1,069・**>360 分 351**。>360 分の門の期待通過数は、換算後 247.0 に対し、p_h をそのまま使うと 107.7(差 +139)。1 日のランでは小さい。
- **影響が大きいのは「最初の門=Δt 1 tick」のほう**: 最初の門は 4,817 回あり、時刻の中央値は tick 499(08:19。10〜90% は 06:38〜14:07)。つまり実質的に朝の門。その期待通過数は、Δt の置き方で次のように変わる。

| 最初の門の Δt | 期待通過数(5,000 体・1 日) |
|---|---|
| 1 tick(実装) | 62.5 |
| 60 分(旧の per_wake と同じ値) | 889.4 |
| ラン開始からの経過(上限 180 分) | 1,493.0 |
| ラン開始(00:00)からの経過 | 2,070.0 |

  このランの食事は全体で 9,277 回。最初の門の置き方ひとつで ±800〜2,000 回動く。README §2A-4 の per_wake → per_hour の差(門を通った回数 12,939 → 9,216・収支 +177 → −141 kcal)の一部は、時間あたりへの換算そのものではなく、この expedient から来ている可能性が高い(構成が違うので割合は推定しない)。さらに `ClassicalPolicy` は `run_day` ごとに作り直されるので、日ごとにランを分ける複数日ランでは**毎朝**この規則が効く。
- 時間の規律(§0-2): 「最初の門の Δt=1 tick」は tick 単位で書かれている。tick の長さを変えると挙動が変わる。

## 2. 見つけた欠陥・問題(重い順)

1. **(中)項 4: 最初の門の Δt=1 tick が結果を動かす expedient なのに、感度の対照が無く、tick 単位で書かれている。**
   - 再現: classical・記憶・関係・`meal_gate=per_hour` の 5,000 体ランで `meal_probability` を包み、最初の門の (p_h, tick) を集める。上の表のとおり、置き方で期待通過数が 62〜2,070 と変わる。
   - 直し方の案: (a) 最初の門の Δt を分で宣言する(例: 60 分=per_wake と同じ値になる中立の置き方。または起床からの経過)。(b) 感度の腕(1 tick / 60 分 / ラン開始から)を用意し、方法論 §4 の「expedient が結果を駆動していないことの証明」を済ませる。(c) 実装役の問い Q-2A-2 と一緒に、食事の束の版上げの前に決める。既定は per_wake なので急ぎではない。
2. **(小〜中)項 3: 会話中(と、コードの上では就寝中)の知人を選ぶ。** 近くに話しかけられる知人が居るのに失敗する(27/342 回・うち 20 回は別の知人が居た)。
   - 直し方の案: `_classical_acq` で、相手の `activity` が `_UNADDRESSABLE`(会話中・就寝中)なら −inf にする。edge 幾何のランでは、距離 2 m 以内の条件も合わせる(`talk_within_reach` を使う)。「会話中なら 3 人会話に加わる」を許す腕(`conv_max_participants=3`)との整合は親の判断。
3. **(小)検算スクリプトの穴**: `wave2_bytecheck.py compare` が `src_is_worktree` を検査しない(1-1 参照)。今回の結論には影響しない。
4. **(小)バイトの宣言**: per_hour の 4 B/体が予算宣言に無い(1-6)。

## 3. 設計の問い(欠陥ではない・親/ユーザーの判断)

- **関係 off の古典の腕は会話を 1 件も始めない**: 既定の classical 5,000 体で、符号 18 の 874 回がすべて「待つ」になり、`reply_talk` は 697 → 0。関係 on でも、会話の返事は 765 → 226、呼数は 114,338 → 110,431 に減る。LLM の腕(mock・関係 off)は見知らぬ人とも話すので、指示書 §0-3(古典の腕は公平な比較相手)に照らすと、古典と LLM の比較は関係 on で行う、と決めておく必要がありそう。指示書 §4 の「誘う」(遠くの知人)は C10 8d の後で、未実装(宣言あり)。
- acquaintance の規則は、関係 on のときの C10 8b の重みつき抽選(残りの 40% は見知らぬ人)を通らない。古典の腕は見知らぬ人に一切話しかけなくなる。指示書の「見知らぬ人との会話が C10 と記憶を汚している」に沿った決めだが、LLM の腕との非対称が 1 つ増える。
