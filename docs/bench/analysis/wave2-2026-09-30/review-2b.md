## 2. 見つけた欠陥・懸念(重い順)

### 2-1(中・記録)項 2 の総呼数の変化の説明が成り立たない
- **README の主張**: 2B-2「ランの総呼数は変わる(…以後の空腹の上げ跨ぎと classical の門が変わるため)」。Q-2B-2「食事の後の空腹の上げ跨ぎと、方策の門が変わるため」。
- **再現**: base と home を `tape_path` つきで回し、`calls.parquet` の `agent_id` を体ごとに数えた。
  - mock: 全体 −421。自宅で食べた 30 体の差の合計は **+1**、その他の体が **−422**(呼数が変わった体 1,897)。
  - classical: 全体 +429。食べた 28 体の差の合計は **0**、その他の体が **+429**(2,590 体)。
  - 最初の自宅の食事(tick 360)より前の呼は、両ランで同じ件数(849/849・1,199/1,199)。
  - 疲労の跨ぎ(食事が直接は変えない量)も動く: mock の起きて範囲内の疲労の下げ跨ぎ 16,164 → 16,101。
- **読み(推測)**: 30 回の食事が作った小さな摂動が、共有された状態(混雑・店・会話・乱数の順)を通じて全体へ広がった。食べた体自身の上げ跨ぎは差をほとんど作っていない。呼数の ±0.4% は仕組みによる増減ではなく、摂動の雑音の大きさとして読むのが妥当。
- **直し方の案**: 2B-2 と Q-2B-2 の説明を上の事実に置き換える(食べた体の寄与は ≈0・差は他の体へ広がった分)。「呼数を増やさない」の判定には、別の無害な摂動(たとえば食べる体を 1 体だけ変えた腕)の呼数の差を雑音の床として併記する(CLAUDE.md §5 のフロア併記)。

### 2-2(低・記録)`OutOfAreaMeals` の docstring の誤った前提
- `engine/energy.py` の `OutOfAreaMeals` の docstring(項 1 の段落)に「W17 の食事行由来の食事は変えない(**食事行と就寝の行は重ならない**)」とある。実データでは就寝の行の中に食事の行が入る対が 12 本あり(5,000 体・月曜)、食事行由来の食事 2 件が W17 の就寝中に置かれている(README 2B-1 自身もこの 2 件を書いている)。
- **直し方の案**: 括弧の中を「重なる行がある(W17 の欠陥・Q-2B-3)が項 1 の外」に改める。挙動は変えない。

### 2-3(低・版の管理)all の腕の `template_sha256` は描画を正しく表さない
- `templates.template_sha256()` の payload に `"hunger_draw_min_stage": HUNGER_WORD_DRAW_MIN_STAGE`(=2)が入っている(`perception/templates.py` の payload)。all の腕はこの値を実行時に 0 で上書きして描くのに、SHA は「2」を名乗ったまま出る。
- all のランの文面は、manifest の `hunger_words: "all"` からは辿れる(テストで確かめている)。ただし SHA だけを見る照合(テープの互換判定など)では区別できない。語の行を「テンプレ本体ではない」として SHA の外に置くのはリポの先例(意図の行・活動の行など)と同じだが、**この定数は payload の中にある**点が先例と違う。
- **直し方の案**(Q-2B-4 への材料): 版上げで all を既定にするときは定数を 0 にして SHA を上げる。それまでの腕の間は、manifest の `template_sha256` の隣に `hunger_words` を並べて読む約束を README に明記する。

### 2-4(低・宣言の不足)同じ時間帯の重複と per_hour の門
- **自宅の食事+飲食店の食事が同じ時間帯**: mock 8 件・classical 14 件(per_hour all_on 8 件)。自宅の食事は、直前に飲食店で食べたかを見ない。W17 の食事行が同じ時間帯に 2 本ある自宅の体も 1 体あり、その体は 1 行 1 回のまま同じ時間帯に 2 回食べる(合成の場面で確かめた)。範囲外の食事にも同じ形が既にある(範囲内+範囲外の同じ時間帯の重複は mock base で 731 件)ので、新しい種類の欠陥ではない。ただし「同じ時間帯に 2 回食べない」は項 1 についてだけ成り立ち、項 2 では成り立たない。宣言に 1 行ほしい。
- **per_hour の門**: 自宅の食事(と範囲外の食事)は `_gate_awake_min`(前回の門の後に起きていた分)を 0 に戻さない。食後に次の門を引くとき、Δt に食事の前の分が入る。門の定義(「前回の門の後」)どおりの挙動だが、予定の実行の食事との相互作用として宣言されていない。値への効き目は測っていない。

### R-3 残る注記(軽い・受け入れを止めない)

1. **揺らぎの床は「傾向」までしか言えない**。
   - 1 kcal の揺らぎは段の跨ぎを最大で 1 tick ほどずらし得る(消費は 1 分あたり約 1.7 kcal)。したがって「挙動に効かないはず」ではなく「効き得る最小の揺らぎ」で、床の測り方としてはむしろ妥当。
   - classical の 3 本は +315・0・+7 で、裾が重い。幅は 3 本では言えない(README も「粗い」と書いている)。
   - mock の k=0 と k=1 は final が同じ `9beb7834`。別の食事を突いたはずなので、同じ体を突いた・`since_meal` が次の食事で消えた等の可能性がある(**確かめられない**=突いた体の記録は作業用の出力にしか無い)。その場合、mock の床の標本は実質 2 本。
   - 案: 「呼数を増やさない」の判定に使うなら、標本を 10 本以上に増やす。
2. **v1+classical+per_hour** の組では、食事で H が戻らない(宣言済み)。この組を禁じるか、v1 の食事の経路でも戻すかは、版上げのときの確認事項に残すとよい。
