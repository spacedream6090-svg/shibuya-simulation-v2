# 封印の語の表をまとめた語での空回し(第348・2026-11-21)

[返事その 9](../../../design/prompt-2026-11-20-reply9.md) §1 の 3 と §5-5 の記録。語・ファイルの名・道筋は、この記録にも画面にも出していない。前の回の比べは [sealed-tokens-347](../sealed-tokens-347/README.md)(2 つの表は 12 語と 3 語で、共通は 1)。

## 指示

2 つの表を、1 つの表(どちらの守りに使うかの印つき)にまとめる方向で進める。ただし先に、まとめた語の全部で 2 つの守りを空回しして、新しく当たる数だけを守りごとに数える。新しく当たるのが 0 ならまとめる。1 つ以上なら、数だけを報告して止める。

## 空回しのしかた

| 守り | 置き場 | 空回しのしかた |
|---|---|---|
| 読みの守り | `tools/instruments/read_guard.py` の `deny_hit`(表は `SEALED_TOKENS`) | 道筋を見る守りなので、リポにある道筋の全部を母数にした。母数は、git が追跡するファイルと、`data/` の下のファイルの名(名だけを並べた。中は開いていない)。今の表で当たらず、まとめた語で当たる道筋を数えた。計器の段の表(`GAUGE_DENY_TOKENS`)でも同じ数を出した |
| 構築の封の守り | `src/shibuya/build/audit/w19_freeze.py` の `scan_build_sources`(表は `HOLDOUT_TOKENS`) | 本物の関数を、表だけをまとめた語に差し替えて呼んだ(走査の範囲と除く物は本物のまま)。今の表で当たる組(ファイルと語)を引いた残りを数えた |

道具は `python tools/instruments/sealed_tokens_dryrun.py --json <置き場>`。出すのは数と真偽だけ。終了コードは 0=両方の守りで 0・1=どちらかで 1 つ以上・2=誤り。試験は `tests/tools/test_sealed_tokens_dryrun.py`(数え方と、出力と記録に語が 1 つも出ないことを確かめる)。コードの表は変えていない。

## 扱い

- 新しく当たる数は、読みの守りが 0、構築の封の守りが 11(ファイル 3 本)だった。指示のとおり、**まとめずに止めた**。コードの表は変えていない。
- 構築の封の守りで新しく当たるのは、読みの守りの表にだけある語が、構築のソースに書かれているためである。どの語がどのファイルに当たるかは、開いていない。
- 当たった 3 本が、構築が読んでよい物を名指ししているのか、読んではいけない物を名指ししているのかは、確かめていない。確かめるには、語と場所を親が読む必要がある(指示は「語・ファイル名・道は出さない」なので、していない)。

## 確かめていないこと

- 読みの守りの母数は、道筋の文字列だけである。計器が実際に開く道筋を、ランの中で差し替えて確かめてはいない。
- 2 つの守りの試験を、まとめた語で回してはいない。
