- 執筆モデル: Claude Opus 5.5(claude-opus-5-5・1M context)
- 問い(ユーザー原文): 「なぜ会話などが極端に少なかったの? どのようなことに LLM の出力が用いられたのか調査して、なぜ今回のような結果になったのか分析して。」→ 本書の担当は**会話と、会話に近い社会的な行動(手伝い・待ち合わせ・知人)**。
- 手段: テープ(`data/tape/c8_*/*/calls.parquet` 28 本)を `shibuya.llm.parser.parse_two_line`(v1、`*_v2` 腕は v2)で読み直した集計と、コードを読んで確かめた内容。ランは回していない。holdout は開いていない。

- 表記: **[実測]**= テープや記録から再計算した値。**[記録]**= 過去の報告の写しで、本書では再計算していない値。**[推定]**= 本書の近似規則(§2-2 に定義)で出した値で、runner の診断そのものではない。**[推測]**= 根拠はあるが確かめていない読み。

## §0 結論(先に)

1. **会話が始まるには、LLM が普段の起床で自分から「会話」を選ぶしかない。しかし 8B はほとんど選ばない。** 現行の 5,000 体×1 日では 36,906 呼のうち「会話」は 25 呼(0.068%)[実測]、成立したセッションは 3 件(0.0006 件/体/日)。39 万体では 4,040 呼(0.149%)で 410 セッション(0.00105 件/体/日)[実測+記録]。mock は 12 語から一様に引くので 1/12=8.3% の確率で会話を選ぶ(`src/shibuya/llm/mock.py:115`)。実 LLM はその約 1/120。
2. **「近くに誰もいないから」ではない。** 同じ tick に同じセルで呼ばれている別の体がいる呼だけで 41.9%(15,463/36,906)ある[実測]。これは下限で、観測の B5 行に人物が載る呼はもっと多い。それでも会話を選ぶ呼は 0.1% 未満。
3. **社会的なきっかけで起こす仕組みが無く、観測には人を話しかける材料も無い(実装の未完)。** 起床条件 11 行のうち社会系の 4 行(知人出現・近接入替・被注視・傍受)は、それを発生させるコードがどこにも無い(`src/shibuya/engine/change_detect.py:40-41,217-228`)。知人表と被注視はレンダラに渡されていない(`src/shibuya/engine/run.py:1452-1463`)ので、人物はすべて「P-123(未知)」とだけ書かれる(`src/shibuya/perception/renderer.py:1315`)。関係・記憶・約束・誰かに会う予定はどれも 0。手伝いは実装上必ず失敗し(`src/shibuya/engine/resolve.py:1847-1849`)、待ち合わせはまだ無い(`src/shibuya/world/state.py:56`「約束そのものは C10」)。
4. **会話を選ぶかどうかはプロンプトの小さな差で大きく動く。** 会話を選ぶ判断は材料に支えられておらず、揺れやすい。看板行(B2・約 25 tok)を消すと会話の選択は 25→108 呼(×4.3・上限あり)、190→493 呼(×2.6・予算なし)[実測]。行動欄に「当てはまる語が無いときだけ自由文」と足しただけで 25→159 呼(×6.4)[実測]。さらに、**自分から会話を始めた呼の 16〜69% は理由が食事絡み**だった(現行 11/16・ヒント腕 54/104・予算なし×看板なし 44/277)[推定]。空腹を満たす手段として、店員らしき人に話しかけている(例: 「食事が必要なため / 会話 対象: P-546 ひと言: おすすめの飲食店は?」)。
5. **LLM が会話を選んでも、会話を選んだ呼 100 本あたりのセッションは 10〜18 件だけ[実測]。** 原因は相手の指し方と TTL。自分から始めた呼の 22〜69% は、対象欄に人の ID ではなく「物のカテゴリ」などを書いていた[推定]。自分から始めた呼の 0〜30% は相手が期限内に 1 度も呼ばれず、名指しした招待の 18〜40% は相手が別の行動で答えた[推定]。招待を見せさえすれば承諾率は高い(C6 の A/B で 87/101[記録]・本書の推定でも名指し招待の 3/5〜16/40)。
6. **成立した会話は 1 回あたり LLM の発話が 2〜4 回で終わり、中身も相手に届かない。** 1 体の上限は 3 呼(`src/shibuya/engine/conversation.py:84`)。相手の「ひと言」は相手の観測に載らず、渡るのは「会話の相手が話し終えたため、応じる必要があります。」という定型文だけ(`src/shibuya/perception/templates.py:473`)。成立した対の LLM 会話呼は中央値 3(現行・予算なし・看板なし)[推定]。
7. **予算は倍率を動かすが、桁の差は埋まらない。** 予算なしにすると呼は 2.1 倍、会話は 7.6 倍(25→190)、セッションは 10 倍(3→31)。それでも 0.0062 件/体/日で、人は覚醒時間の 27.9% を会話に使う(`docs/research/v2-thought-frequency-anchors-note.md:18`)[実測+記録]。一方、予算を半分(×0.5)にすると名指し招待 3 件の相手が 1 人も起こされず、セッションは 0 になった[実測]。昇格した大量の待ち呼が会話クラスの枠を埋めるためと読める[推測]。

### 1-3 観測に人が載っていたか(下限)

## §2 会話が成立するまでの経路の全段

### 2-1 経路(コードで確かめた順)

## §3 プロンプト側 — LLM が「会話」を選ぶ材料は観測にあるか

### 3-1 共有部(テープの `blocks.parquet` から逐語)

現行 ×1 の 1 呼目の B0(603 tok)の関係する行(`data/tape/c8_ab8_s1/AB8-L4-SCALE__l4_x1/blocks.parquet`・block_id 70c1…)。


### 付録: 再計算の手順(親の照合用)

- 腕別集計: 各 `calls.parquet` を `ORDER BY tick, agent_id` で読み、`parse_two_line(response, "v2" if 腕名が _v2 で終わる else "v1")`。`action == "会話"` を数える。種別は `block_ids[1]`、密度段階は `block_ids[4]`、セルは `block_ids[2]` の「セル(\S+?)\(」を `blocks.parquet` から引く。
- 漏斗: §2-2 冒頭の規則。食事絡みの判定は正規表現 `食|空腹|餓|お腹|腹|飲|コーヒー|ご飯|昼|弁当|おむすび` を理由欄に当てる。受け手の理由の判定は `話しかけ|提案|呼びかけ|応じ|応答|応酬|続け|から会話`。
- runner との突き合わせ: 会話 呼 はテープの再計算と runner の `action_counts.会話` が 28 腕中 25 腕で一致。不一致は語彙を見せない 3 腕(AB7 s1 open 3 vs 7・AB7 s2 open 0 vs 3・AB7c s2 open_v2 0 vs 1)で、runner 側は段0 辞書の写像を含むためと読める[推測]。セッションは runner の値をそのまま使った(再計算していない)。
