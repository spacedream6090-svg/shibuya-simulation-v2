# sub_a: LLM の呼数(1 体 1 日 約 7 回)と LLM 出力の使い道(2026-09-24)

- 書き手のモデル: **Claude Opus 5.5(1M context)**(claude-opus-5-5[1m])。調査サブ(コード変更・台帳編集なし)。
- 問い(ユーザー原文): 「なんで検証ランや本番の 1 日ランを回す中で LLM の呼び出しが 1 体あたり 1 日に 7 回ぐらいしかなかったの? どのようなことに LLM の出力が用いられたのか調査して、なぜ今回のような結果になったのか分析して。」(会話の少なさは別サブ。本書は**呼数**と**出力の使い道**)
- 数値の再計算用: [sub_a_numbers.json](sub_a_numbers.json)。【測】= テープ/ログ/JSON から本書で再計算した値、【引】= 既存報告から引いた値(出所併記)、【推】= 推測。

## §0 結論

1. **「7 回」は呼数の上限(予算行 L4)が作った値で、需要の値ではない**。5,000 体 × 1 日の現行予算では 7.38 呼/体/日【測】。同じ構成で上限だけを外すと 15.46(発射)/14.56(応答が返った呼)【測】。L4 は「上限 400 万呼/日・**平均 10 呼/体/日が繰り延べアービタの制御目標**」とする設計上の決定(docs/design/v2-budget-declaration.md:60・2026-09-06 新設)。根拠は「W1 ≤24 h/シミュ日 + BN-5 実測 75.3 呼/s」。
2. **10 ではなく 7 になるのは、1 日ぶんの枠を 1,440 tick に均等に割り、余った枠を 2 tick ぶんしか持ち越せない実装だから**(`call_budget_per_tick`=src/shibuya/engine/arbiter.py:131-145・`POOL_CAP_TICKS=2`=arbiter.py:48-50,116・expedient)。夜は需要が枠を大きく下回り、その余りは昼に回らない。5,000 体では、時間ごとの「min(上限なしの需要, ×1 の枠)」の和が **37,224 呼で、実測 36,906 呼とほぼ一致**【測】。使わずに終わった枠は 2.56 呼/体/日【測】。39 万体の c7-day-4 でも同じ形で、07〜19 時の 13 時間が **162,528 呼/h = L4 の按分(2,708.8 呼/tick × 60)**で頭打ちになり、未使用の枠は 1,194,077 呼 = 3.06 呼/体/日【測】。
3. **訂正(写しの誤り)**: build-report-C7 §1j(docs/ops/build-report-C7.md:139)は 162,528/h を「**艦隊上限**」と書いているが、これは L4 の按分値。艦隊の実処理量は 78 応答/s ≈ 28 万呼/h【引・同 :63】。同じ文書の §1h(:101)は「=2,709/tick・計画どおり」と正しく書いている。**艦隊が決めたのは呼数ではなく壁時計**(fleet_wait = tick 周期 22.9 s のうち 20.45 s【測・c7-day-4 ログ】)。艦隊側の繰り延べは 14,798 呼 = 0.55%【測】で、呼数への影響は小さい。
4. **上限を外しても 15 回前後で止まるのは、LLM を起こす入口が 4 つしか動いていないから**。上限なしの内訳は、セル変化 7.02・内受容 3.84・計画境界 3.65・会話 0.05 呼/体/日【測・起床クラス別】。起床条件 11 種のうち **知人出現・近接入替・被注視・傍受の 4 種はどこからも発生しない(no-op)**(発生源は change_detect.py:223-228・weekly 境界・conversation・salient だけ)。さらに次の 3 つが設計で決まっている。周期ハートビートの廃止(知覚契約書 :121・決定 09-03)、就寝境界では LLM を呼ばない(D-62・run.py:1760-1771)、就寝中の体・域外の体の呼の抑止(D-56/D-66・arbiter.py:331-380)。**日次内省(T2)は 0 回**で、実装は記録用のカウンタだけ(resolve.py:39,1890)。
5. **LLM 出力のうち世界を動かすのは、「行動」の 1 語と、会話のときだけ使う「対象」の人 ID**。「理由」を読むコードは無い(パーサで切り出した後に誰も参照しない・テープに原文が残るだけ)。「ひと言」は会話ターンのとき `conv.utterance(comment=…)` に渡されるが、関数の中で使われず捨てられる(conversation.py:611-648)。既定の腕(node/語彙 v1=AB8・C7)では「対象」欄も移動・購入に効かない。移動先は「職場/自宅のうち今いない方」をエンジンが決め(commit.py:635-641)、購入先は「現在セルの id が最小の POI」をエンジンが決める(commit.py:681-685)。役割語(補充・開閉店・発車など)は選ばれても「待機」に落ちる(llm_bridge.py:672-675)。そもそも 8B は役割語を選ばない【引・build-report-C6:79/テープ再集計で補充/開閉店/発車/停車/指示 0 件】。
6. **「LLM 判断 12.4% / エンジン継続 87.6%」(第239)の出所は `RunResult.action_usage`**(run.py:2420 → ablation runner JSON の `action_usage`)。ただし「エンジン継続」は**移動中の体が 1 tick ごとに経路を 1 歩進んだ延べ回数**(commit.py:526-543)で、LLM の判断(1 回ごと)とは数え方の単位が違う。しかもその歩みの多くは LLM が選んだ「移動」を実行している分。比として読むと誤解を招く。4 腕で再計算すると LLM 側は 9.6% / 12.4% / 16.9% / 19.3%【測】。
7. **原因の大きさの順**(§5): ① L4 上限(設計の決定)> ② 均等割り+持ち越し 2 tick(実装の expedient)> ③ 入口が少ないことによる需要の天井(設計の決定+実装の未完)> ④ モデルの挙動(会話・役割語を選ばない)。④ が呼数に効く量は小さい。

## §2 呼数を決めている仕組み(全経路)

1 tick の流れ(run.py): ② 変化の検出(:1745-1748)→ 計画境界の候補(:1751-1790)→ 会話ターンの候補(:1793-1798)→ 顕著行為の候補(:1802-1807)→ 艦隊の繰り延べ分の再投入(:1873-1895)→ ③ アービタ(:1925-1940)→ ④ 選ばれた体を呼ぶ・不応期を張る(:1955・:2035 で `llm_calls` に加算)。

### (a) 予算 L4 の按分

- 式: `4,000,000 / 1,440 × n / 400,000`(arbiter.py:131-145)。5,000 体では **34.72 呼/tick**(2,083 呼/h・50,000 呼/日)、390,067 体では **2,708.8 呼/tick**(162,528 呼/h・3,900,670 呼/日)【測: 式の計算】。`--l4-scale` はこの値に掛ける倍率で、0 は体数ぶん=無制限(cli.py:288-334)。
- 頭打ちの掛け方: 1 tick に選ぶ数 `n_sel = min(コスト基準, floor(使える呼数), 候補数)`(arbiter.py:458)。使える呼数は `pool = min(pool + budget, budget × 2)`(:578)で、**持ち越せるのは 2 tick ぶんまで**。
- 値の由来(設計書の引用): 予算宣言 L4「**上限400万呼/日(o64)**=憲法1の監査点/**平均10呼/体/日が繰り延べアービタの制御目標**(T1分≈358万)。超過分は破棄でなく繰り延べ | W1≤24h+BN-5実測(v1サイズ・o64で75.3呼/s)」(v2-budget-declaration.md:60)。W1 の行は「中央400万呼=19.2h(o64・c64-128)=24h内に収まる」(同 :13)。**C7 の 78 応答/s から逆算した値ではない**(L4 は 09-06 に宣言、C7 は 09-10〜09-14)。
- 知覚契約書は、需要を約 17.4 呼/体/日(696 万呼)と見積もったうえで「W1(24h)の約400万(o64)を超える…残りはアービタで破棄でなく繰り延べ」「平均を10呼/体/日に合わせるのはアービタの仕事」と書いている(v2-perception-contract.md:138,140)。
- **1 日の枠を tick に均等に割ることと、持ち越しを 2 tick に抑えること**は、設計書には書かれていない実装側の expedient(arbiter.py:48-50「繰越を無制限にすると夜間に溜めた枠で昼に暴発するので、繰越の在庫に蓋をした(**expedient**: 契約書は繰越を規定していない)」)。§1-4 のとおり、これが 10 → 7.4 の差を作っている。

### (c) 計画境界が作る上限

- 就寝以外の境界は 7.50/体/日(§1-7)。不応期は同じ種類の境界の間にだけ効く(就業 150・一般 60・移動 15 分)。

### (d) 就寝・域外の体は呼ばない(計画実行層)
