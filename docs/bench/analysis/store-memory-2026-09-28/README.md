### 4. 宣言と問い

- **Q69 1 行の実バイト**: アジェンダ §1-1 の「19 B」は `sm_last` の 4 B を数え落とし=実 23 B(4+4+4+4+4+2+1)。宣言 24 B/行・768 B/体はそのまま収まる。
- **Q70 `--store-memory on` は `--memory on` のときだけ**(書き手がエピソードの書き手に乗る・記憶 off で on にすると `ValueError`)。記憶 off のまま店の表だけを持つ腕が要るか。
- **Q71 想起できる店の τ**: 記憶の想起と同じ `MemoryLayer.tau`(`--memory-tau` に連動)。店だけの τ の口は 7c の感度腕で足すか。
- **Q72 減衰の腕の形**(アジェンダは口だけ): ga=A を `ln(0.995)×最後からの時間`(n は使わない・同じ τ で切る=1 日のランでは全部想起できる)・citysim=A は actr のまま・向きの強さを書くとき/読むときに `exp(−0.03×最後からの日数)`(精度は回帰させない)。この読みでよいか。
- **Q73 追い出しの順**: 店の行の score=A+0.5×min(4, precision)(アジェンダ §3-3 の 7c の形を先取り)の最小。エピソードの追い出しで店の行は消さない(§4 (g))。1 日では mock 最大 15 行・テープ最大 22 行で M=32 は溢れない(M=16 はテープの一部で溢れる)。
- **Q74 向き 0 の結果も精度を足す**: 所持金不足・飲食店にいない・途中打ち切り・到達不能で店が決まっていた行は「知っている」証拠として精度 +1/σ²・向き 0。また mock では**落選(LOST_ARBITRATION)の −1 が 2,159 件**と閉店より多い(資源の取り合い)。落選を −1 にするのはアジェンダどおりだが、7c で「満席の店を避ける」に効きすぎないか。
- **Q75 σ の感度腕「1:4:16:4」の読み**: 既定 σ 1:2:4:2 は精度の比 1:1/4:1/16:1/4(=σ² が 1:4:16:4)。計測では「1:4:16:4」を **σ の値**として回した(精度 1:1/16:1/256:1/16)。草案の意図が σ² の比(=既定そのもの)なら、感度腕は 1:1:1:1 と別の点(例 σ 1:4:16:4)でよいか。
- **Q76 看板だけの行(向き 0)が行の 6 割**(mock・テープでは 4 割)。7c の候補「A ≥ τ ∧ 向き ≥ 0」に看板だけで知っている店がそのまま入る(1 日の終わりに想起できるのは看板だけの行の 9.7%)。これでよいか・看板だけの行を候補から外す/精度の下限を置くか。
- **Q77 並ぶの成功と、その先の購入/食事の成功**が同じ店に 2 件の +1 になる(1 回の訪問で 2 件の証拠)。並ぶの成功を向き 0(知っているだけ)にするか・このままか。
- 宣言(expedient): 同じ体の同じ tick の店の事象は 1 件ずつの回に分けて統合(逐次ループ宣言 1)・人の符号(1<<30|id)と場所(−(cell+2))は店にしない・要約は出どころの組の数ぶんのループ(≤ 16)。CLI `--memory-tau` の help の「既定 −1.0」を −2.0 に直した(第295 の決めの写し漏れ)。
