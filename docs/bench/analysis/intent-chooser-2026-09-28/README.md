## 1. 何を足したか

- **口**(`engine/chooser.py`): `Chooser.probs(candidates, context) -> 確率`(和 1・候補が空なら空)。`ChoiceContext`=体 id・tick・現在セル・現在ノード・行為コード・対象の種類(名指し/カテゴリ/なし)・対象の文字列・空腹の段・可視(W8 の視点数)・距離(W3 `cell_dist`=**実行時に初めて読む**・同じセルは 0)。抽選は `core.rng.stream(seed, "engine.chooser", tick, agent_id)`(one-hot でも抽選を通す)。
- **既定の選び手 `NearestChooser`**(憲法⑥の宣言つき暫定): 距離の昇順 → 可視(視点数)の降順 → POI 索引。可視=`World.poi_visibility`=W8 `w8_t1_cell` の「その POI の自分のセルの視点のうち見えている数」(実資産 2,309/2,337 が > 0)。
- **候補**(`engine/poi_target.py`): 現在セルの POI のうち **意図に合う**(食事=`eatery_mask`・購入/並ぶ=**店舗系 cat `BUYABLE_CATS`**=food・shop・nightlife・service・leisure・cinema・attraction。除く office・hotel・school・landmark・hall・education=Q12。合成世界の 3 種 コンビニ/飲食/物販 は作りからして店なので候補に入れる=`SYNTHETIC_BUYABLE_CATS`・実資産の cat とは重ならない)∧ カテゴリなら**カテゴリ一致** ∧ **営業中**(`open_mask`)∧ 購入(と並ぶの飲食店以外)は**棚在庫 > 0**。名指しは候補を**その店**に絞る。セル外の名指しは段 2c=いまは失敗。
- **対象欄の読みの順**: (a0) 総称語(店・店舗・ショップ・お店)→ なし (a) 全体がカテゴリ語 → カテゴリ (b) `food1954` 形(描画の合成名=cat+索引)→ 名指し (c) POI 名(完全一致 → 名⊂入力 → 入力⊂名・C9b の目印照合と同じ順)→ 名指し (d) カテゴリ語を含む → カテゴリ (e) それ以外(なし・説明語・セル ID・人 ID・自由文)→ なし。
- **落選の理由**(候補 0): 合う店が無い → 対象 −1(購入/並ぶ=`BAD_TARGET`・食事=`NOT_IN_EATERY`)/ 合う店は全部閉店 → その代表 1 件(`CLOSED`)/ 開いているが全部在庫切れ → その代表 1 件(`OUT_OF_STOCK`)/ 名指しがセルに無い → −1(理由 `named_out_of_cell`)。結果コードは `engine.resolve` の既存の判定がそのまま付ける(新しいコードは作っていない)。
- **計数**(manifest `target_resolution`): `i_named`・`ii_category`・`iii_none`・`iv_no_candidate`(理由別)・`iv_by_kind`(対象の種類 × 理由)・`attempts`(種類別)・`chooser_entropy_mean_bits`(nearest は one-hot=0)。`--poi-target legacy` のランは空 dict。
- **切替口 `--poi-target {candidates,legacy}`**(Q13・既定 candidates): `legacy`=段 2a 前の「現在セルの最小 id」(`commit._poi_in_cell`)をそのまま通す=**旧 checkpoint の再現用**。
- **触っていないもの**: 移動の行き先(2b)・意図の保持(2c)・乗車のホーム選択(A13)・C9b の近づく・語彙・契約表・B0・W7・W17・W10 の切替口(既定 OFF のまま)・資産。

## 5. 対応表 v0(第286・宣言・59 語・`engine/poi_target.CATEGORY_WORDS`)

POI が「cat が集合に入る **または** subcat が集合に入る」とき一致。長い語から照合。総称語(店・店舗・ショップ・お店)は「なし」。

| 食品・飲み物(買う物) | 食品カテゴリ/食料品/食品店/食品/食料/食べ物/飲み物/ドリンク/飲料/コーヒー → food ∪ subcat convenience |

## 6. 問いと空欄

- Q11〜Q15 は親が決めた(冒頭)。
- 空欄: 実 LLM で選び手が効く場面((ii)(iii) の候補が 2 件以上)の割合(nearest は one-hot=エントロピー 0)。在庫切れの理由はリプレイでは測れない(テープに在庫の状態が無い)。対応表 v0 の語の過不足(実 LLM の対象欄の語の被覆)は GPU 後。

### 2c-1 何を足したか

- **いつ立つか**(`commit` → `IntentLayer.propose`・語彙 v3 × 活動層 on × `--poi-target candidates` のランだけ): 購入/食事/並ぶ/会話/就寝の対象が**現在セルに無く解決できる**とき。
  - (i) **名指しの店**が現在セルに無い → 名指しの店のうち意図に合い(食事=飲食店・購入/並ぶ=店舗系)・**いまのセルから見える**(W8=B2 の可視物)・**営業中 ∧(購入は)在庫あり**(2a の候補と同じ=Q21)のものを選び手(nearest)で 1 件。見える店が全部閉店なら**歩かずに**その代表 1 件を返す=`CLOSED` を即時に(全部在庫切れなら `OUT_OF_STOCK`)。
  - (ii) **カテゴリ語**で現在セルに営業中・意図に合う(購入は在庫も)候補が無い → 2b と同じ近傍探索(見えている POI → `cell_dist` の近いセル R=5)で 1 件。
  - (iii) **会話**の相手(人 ID)が別セル → その人の**立てた時点の**セル(Q23=追わない)。(iv) **就寝**の寝床(自宅セル)が別セル → 自宅。ただし**計画就寝の意図(`sleep_pending`)が立っている体には立てない**(Q22=計画が優先・件数 `bed_skipped_sleep_pending`)。「なし」の対象は意図にしない。
- **歩く**: 行為は意図(SoA 4 欄)に保存し、行為の代わりに**目的地つき移動**を適用する。移動が始まった体にだけ意図を立て、活動を `MOVE_TO`・`until_kind=ARRIVAL`(上限 480 分)に上書きする(活動の文は応答のまま)。歩いている間と着いた tick は `CELL_BLOCK` で起こさない(件数 `cell_block_suppressed`)。移動が始まらなかった体(経路なし)は `UNREACHABLE` の主語を元の行為に書き換える(B6「直前の購入は到達不能…」)。
- **意図中の応答(Q20)**: **なし・待機(「新しい行為が無い」)と行き先が同じ移動は意図を保つ**(件数 `kept.none_or_wait`/`kept.same_dest_move`)。`_apply_wait` は意図を持って歩いている体を止めない。保った体の活動は目的地つき移動(到着まで)に戻す。着いた体がその応答を返したら、その応答の行を外して意図の行為を実行する(`kept.due_response_dropped`)。**上書きする**のは世界に触れる行為(購入/食事/並ぶ/会話/乗車/就寝/退去/通報/手伝い/断る)と行き先の変わる移動だけ(`superseded`)。着いた後に戻す活動は意図を立てたときの応答の活動のまま(途中の なし の活動欄は使わない=宣言)。
- **着いたら**: 到着満了(`ACTIVITY_EXPIRY`)は LLM を呼ばず(件数 `expiry_suppressed`)、次の tick の Phase A で**エンジンが意図の行為を実行する**(`IntentBatch`・資源=店/相手/就寝スロット・`t_notice`=tick 開始)。結果コードは `resolve` の既存の判定(途中で閉店・在庫切れ・所持金・満席→列・相手が去った・寝床なし・落選)。実行した後は LLM が言っていた活動(文・「まで」)を**実行の tick から**戻す=失敗∧活動なし → 次 tick 満了(失敗即時の規則はそのまま)。
- **満了**: 歩いて `INTENT_MAX_TICKS`(60・宣言・`--intent-max-ticks`・感度腕 30/120)を超えたら `TOO_FAR`(歩みを止め・意図を消し・次 tick に満了=考え直す)。経路の途中の行き止まりは `UNREACHABLE`(主語=意図の行為)。乗車の意図(`board_line`・30 tick)は別経路のまま(Q19)。
- **衝突**: 計画境界(域外へ出た=DEPART・就寝の実行/就寝の意図=SLEEP)で捨てる(`dropped.plan_*`)。会話の招待は意図中でも受ける(承諾で会話に入れば `interrupted` で捨てる)。
- **B5 の 1 行**(意図を持つ体だけ・テンプレ本体ではない=`template_sha256` 不変): 「[B5 意図] いま<行為>のため<対象>へ向かっている。」(≤ 15 tok・対象の名を末尾から切り詰め・省略記法の語を含む名は「目的の場所」・会話=`P-17`・就寝=「自宅」)。「直近」の行の次に差し込み、個体群の予算 300 を超えるなら載せない(件数 `b5_lines`/`b5_lines_over_budget`)。**意図を持たない体の prompt は 1 バイトも変わらない**(テスト)。
- **Q18**(2b の問いへ): 移動の対象が人 ID → その人の**いまのセル**(自分=今いるセル・域外/存在しない人=`BAD_TARGET`)。2 m の「近づく」(対象ヒント approach)は従来の経路のまま。`move_resolution.person`/`person_self`。
- manifest `intent`: 提案(種類別)・設定(行為別)・設定の失敗(結果別)・到着(=実行)・成立(行為別)・失敗(結果別)・`too_far`・捨てた(理由別)・保った(`kept`)・`bed_skipped_sleep_pending`・`cell_block_suppressed`・`expiry_suppressed`・`mean_ticks`(立ててから実行/満了まで)・`b5_lines`。`target_resolution.v_intent`(名指し/カテゴリで意図にした行)と `named_out_of_cell_detail`(名指しがセル外で意図にならなかった内訳=域外・意図に合わない・見えない・**閉店(即時)**・**在庫切れ(即時)**)。

### 2c-6 検証で見つけた欠陥(保存則・事後報告)

- **何が起きたか**: 2 回目の v3 既定(mock 5,000)で `conserved=False`(Σ所持金+Σ売上+Σ運賃 が 1,500 円減った)。tick 856 に**満席の列の捌き**(`resolve._serve_poi_queue`・D-113 ③)が**棚 1 個**の店(POI 1713)へ同じ tick に 2 人(体 925・1858)を席に入れ、`_complete_buy` の台帳経路が**2 人から支払いを受けた後に**品を 1 個しか出せず、2 人目は `OUT_OF_STOCK` なのに代金 1,500 円が消えた。2 人とも意図を持っていない=**既存の経路の潜在的な欠陥**が軌跡の違いで表に出た(2a/2b・2c 1 回目の v3 既定では起きていなかった)。
- **直し方**(`_complete_buy`・台帳の物の脚があるときだけ): 同じ店への買い手が棚の合計(`world.pois.stock`=台帳の写し)を超えたら、超えた分は**支払いの前に** `OUT_OF_STOCK`(並び=呼び出し側の順・件数 `ResolveOutcome.n_buy_over_stock`)。超えない限り 1 バイトも変わらない=保存則が成り立っていた 14 腕と mock の他の腕は final が動かない(再計測で確認)。v3 既定だけ `4c3cfeca` → `6845e3ac`(購入 2,958 → 2,957=`n_purchases` が失敗した 1 人も数えていた分)。
- テスト: `tests/engine/test_intent_hold.py::test_buyers_beyond_the_shelf_fail_before_paying_so_money_is_conserved`(偽の台帳で 2 人・棚 1 個 → 2 人目は払わない・合計が保たれる)。切替口は置いていない(旧挙動は保存則違反=ゲートの外)。
- 残り(直していない・問い): `_complete_buy` の `n_purchases += n_win` は台帳が落とした行も数えている(件数の過大)。列の捌きの `in_stock` 検査も 1 人ずつ `stock > 0` を見るだけ(今回の修正で支払いは守られる)。
