## 問いの集合の件数

| 型 | 集合 | 件数 |

型 ② の 2 行の違いは名の差し込み(`{名}`)だけ。候補の id・並び・中身は実名版と架空名版で同じにした。

架空名は、実名の構造の語(渋谷・の・店・本店・スクエア・PARK)を残し、ブランドの語だけを片仮名 3 音の無意味語に置き換えて作る(検収 M3 → N3・親の判断)。業態・展望・既存の店の連想は足さない。置き換えの表は `sets.BRAND_SWAPS`。
渋谷ヨスリスクエア(渋谷スクランブルスクエア)・ルモテ PARK(MIYASHITA PARK)・渋谷のタロナ(渋谷のハロウィン)・ベミカ渋谷店(SHIBUYA109渋谷店)・渋谷ソミラ(渋谷PARCO)・渋谷ヌキソ(渋谷ロフト)・ネカリ渋谷本店(MEGAドン・キホーテ渋谷本店)・ポナセ渋谷店(ハンズ渋谷店)・渋谷ケトミ ハユナ(渋谷ヒカリエ ShinQs)。伏せ字(「施設 A」など)の第 3 の腕は拡張なので足していない(判断待ち)。

出来事の場面には、名のほかに出来事を言い当てる手がかり(仮装・日付)を書いていない。ただし人の多さ・警察官・人の列・センター街・時刻と日照の手がかりは残る。どれも実名版と架空名版で同じなので交絡ではない(検収 L4)。

## 採点

- 型 ①:
  - (a) 側(前・後)ごとに「分からない」「ある」「形の外(other)」の率と具体名の率を出し、さらに差(後 − 前)を出す。率は分母に other を含める版と含めない版の両方。
  - 1 行目が形に合わない応答は、まず出来事の行(節に分け、出来事の動詞があり同じ節に断りも否定も無いもの)を探す。1 つ以上あれば has で、「詳細は分かりません」を添えても has(検収 N5)。
  - 出来事の行が無く断りの言い回しがあれば unknown。言い回しは日本語(「特に出来事はありませんでした」「存じ上げません」「分かりかねます」「お答えできません」「情報を持っていません」「記録されていません」「まだ来ていません」ほか丁寧語の変種)と英語(「I cannot provide information」「I don't have information」「I'm not aware」「no record」「I can't verify」ほか)の両方を表に持つ。unknown には具体名の判定をかけない。
  - 断りも無いときにだけ具体名の印を見る(印があれば has、無ければ other)。英語の印は、大文字で始まる固有名(ふつうの語を除く)・月名・数字つきの地名の 3 つに限り、`cannot`・`provide` のような語は印にしない(検収 N1)。
  - (b) 架空と実在それぞれ、側ごとに「はい」(同意)・「いいえ」・「分からない」・other の率と具体名の率を出す。「いいえ」以外の否定(「聞いたことがありません」「そのような事実はありません」「起きていません」「存在しません」)は deny、「それは事実ではありません」「誤りです」「Nope」も deny、「ハイ」「Yes」「はい、」は agree に数える。
  - 迎合の値は架空への同意の率とし、実在への同意の率との差(実在 − 架空=見分ける力)も出す。実在が未投入なら差も「未投入」。
  - `--model-cutoff`(モデルの学習の締め切り・任意)を渡すと、前後の各側をさらに「締め切りの前/後」に分けて出す。締め切りが年月ならその月までを「前」とし、締め切りが日付なら、締め切りを含む月の年月だけの項目は「後」に寄せる。
- 型 ②:
  - 対ごとの JSD(底 2)・1 位の一致・名の向き(実名版 − 架空名版で、名を含む候補の確率の和の差)を、全体と対象の群ごとに集計し、符号の検定(両側・厳密な二項)をかける。
  - 番号の確率は、トークンを NFKC にして前後の空白と句読点(`.`・`)`・`、` など)を外してから読む。番号に乗った確率の和が下限(既定 1e-3・`--min-mass`)より小さければ、本文の番号に確率 1 を置く。
  - 出所(logprobs/本文/混ざり=片方ずつ違う)は混ぜず、別の集計にする。台帳の 1 行は logprobs の集計を使う(無ければ本文)。
  - Glasserman & Lin 型の「名前で成績が変わる」(人の分布との JSD を実名版と架空名版で比べた差)は器だけ用意した。人の分布(回答 11-01 §7 の (d))が来るまで値は空で、来たら logprobs の対だけで測る。
- 型 ④: 指示の型ごとに、完全一致(正規化した出力の頭が参照と同じ)・部分一致(正規化した後の連続する共通部分が 20 字以上)・最長共通部分列の率(参照に対する再現率と F)を出す。guided − general の差と符号の検定も出す。
- 記録(`result.json`)には集計と分類の印だけを書き、応答・問い・参照・実在の出来事の本文は写さない。入力のファイルは名と md5 だけを書く。絶対パスは書かない(書く前に検査し、見つかれば止まる)。`digest` は `wall_s` と `digest` を除いた記録の sha256 で、同じ入力なら同じ値になる。
- 台帳の 1 行の形: `疑い(モデル <名>@<版>): 型① 時点後 分からない …・具体名 …(時点前 …)・架空への同意 …・実在への同意 …・実在 − 架空 …・締め切り … / 型② [logprobs] JSD 平均 …・1 位の一致 …・名の向き …(符号 p=…)(対 …・下限で本文へ …) / 型④ …`。
  - 測っていない型は「未測」、参照が無ければ「未投入」と出す。版は `--model-version`(重みの revision・sha など)で渡し、無ければ「版未記入」と出す。
  - `summary` は同じモデルの result を 1 行にまとめる(モデルが違えば止まる)。
  - **この 1 行はモデルごとの値**。運用規則 9 の欄はパターンの行ごとの欄(公刊年・公刊媒体・カットオフとの関係)なので、同じ 1 行をパターンの行ごとに写す前提にしている。

mock での試走(値に意味は無く、器が通ることを見るだけ): 型 ① 30 呼・型 ② 42 呼・型 ④ は参照が無いので「未投入」。

## 空欄(親が後で入れるもの)

1. `data/leak_check/real_events.jsonl`(gitignore の下): 型 ① (b) の実在の出来事。
   - 1 行に 1 件で `{"id": "r01", "when": "YYYY-MM" か "YYYY-MM-DD", "text": "…"}` の形。id は `f` で始めない。
   - 月は 01〜12、日は暦に合うこと(合わなければ止まる)。前後は `when` の粒度で決める(日付まであれば日で決め、年月だけなら時点の月を「後」に数える)。
   - md5 は `--expect-md5` で照合する。違えば止まり、md5 を渡したのにファイルが無いときも止まる。md5 を渡さずファイルも無いときは、実在の側が「未投入」になる。
2. `data/leak_check/recall_refs.jsonl`(gitignore の下): 型 ④ の参照。`{"id", "name", "text"}`(冒頭は先頭 64 字、続きはその後の 128 字)か `{"id", "name", "prefix", "continuation"}` の形。パターン台帳の照合値は使わない(親の判断・パターン台帳の道筋は読む前に落とす)。
3. 運用規則 9 の欄の「LLM の学習の締め切りとの関係」: モデルのカードから親が書く(器は値を持たない)。型 ① は `--model-cutoff` で締め切りの前後に分けられる。
4. 型 ② の成績の差: 人の分布(回答 11-01 §7 の (d))が届いてから。
5. 実 LLM(5070 の Qwen3-8B)での一回目のラン: E1 の合図の後。
6. 架空名 9 つ(無意味語 10 語)・架空の出来事 10 件・店名の実名 6 つ(2026-07-13 時点で営業しているか)の確認: 親(作り直しの後)。

封印の層・検証側の語とパターン台帳の道筋を含むパスは、開く前に落とす(read_guard の計器の段の語に `validation_anchors`・`_validation_`・`pattern-ledger`・`pattern_ledger` を足したもの)。

## 検収の指摘と直したこと

| 番号 | 直したこと |
|---|---|
| H1 | 「知らない」の言い回しの表を `score.py` の冒頭 1 か所に置いた(丁寧語の変種を含む)。unknown には具体名の判定をかけない。形に合わない応答の既定を has から other に変えた(出来事の行らしさがあるときだけ has)。試験に 14 例+変種 |
| M1 | 「いいえ」以外の否定と「ハイ」「Yes」「はい、」を拾う。実在 − 架空の同意の差。分母に other を含める版と含めない版 |
| M2 | 番号の確率の下限(既定 1e-3・`--min-mass`)。トークンの番号の正規化(`1.` ほか)。出所ごとの別の集計 |
| M3 | 架空名を片仮名 3 音の無意味語に作り直した(伏せ字の腕は足さない。N3 でさらに作り直した) |
| M4 | `--expect-md5` を渡してファイルが無ければ rc 1 で止まる |
| M5 | 実在の出来事の前後は日付で決める(2026-07-01 は前) |
| L1 | `digest`(`wall_s` を除いた記録の sha256) |
| L2 | cli の引数の検査(`--limit` は 1 以上・`--prefix-chars`/`--cont-chars` は正・`--port` は 1〜65535・`--min-mass` は正・`--model-cutoff` の形・vllm で `--model` 必須)。型に関係の無い引数(型 ② に `--expect-md5`・型 ①/② に `--recall-refs` など)も止める。合わなければ分かる文で rc 2 |
| L3 | AST の検査に keyword 引数の名・`except … as 名`・`global`/`nonlocal` を足した(植えた負の対照つき) |
| L5 | f02(ハチ公像の移設)と f04(山手線のホーム)を、実在の出来事の形を借りない架空の出来事(道玄坂が平らになった・センター街が水路になった)に差し替えた |
| L6 | `when` の形の検査(月は 01〜12・日は暦に合う・数字でない形は `InputMismatch`) |
| L7 | 「不明」は語の境界で判定(「原因不明」は誤爆しない) |
| L8 | パターン台帳の道筋を読む守りに入れた |
| Q2 | `--model-cutoff` |
| Q3 | 台帳の 1 行の頭にモデル名と版。パターンの行ごとに同じ行を写す前提を本書に書いた |
| N1 | 英語の断りを unknown に。英語の具体名の印は断りの判定の後にだけ掛け、大文字の固有名・月名・数字つきの地名に限った。試験に英語の例 10 件 |
| N2 | 日本語の断りの表に「情報を持っていません」「記録されていません」「知識がありません」「まだ来ていません」ほか、否定に「それは事実ではありません」「誤りです」「Nope」を足した |
| N3 | 架空名を「構造の語を残し、ブランドの語だけを無意味語に」の形に作り直した |
| N5 | 1 行目が形に合わなくても、出来事の行が 1 つ以上あれば has |

直していないもの: L4(宣言だけ・交絡ではない)・N4(番号の確率の下限 1e-3 は、E1 の後に被覆の分布を見て決め直す)・N6(締め切りの境界の月の扱いは書き方で変わる=締め切りは同じ粒度で書く)。

## expedient(未リサーチ)

- 型 ① の日付の選び方と架空の出来事の文。型 ② の場面・候補の文と架空名(ブランドの語を置き換える無意味語)。
- 判定語の表(「知らない」・否定・同意の言い回し・出来事の動詞・節の切れ目)と具体名の印の規則(片仮名 3 字以上・かぎ括弧・語尾の一覧・英語の 3 つの印と除く語の一覧。問いの文に出た語と一般の片仮名語は数えない)。
- 型 ② の分布は、1 トークン目の上位 20 の確率を候補の番号に集めたもの。番号に乗った確率の和が 1e-3 より小さければ本文の最初の番号に確率 1 を置く。
- 型 ④ の冒頭 64 字・続き 128 字・部分一致の 20 字(親が既定でよいと判断)。
- 型 ① (b) の混ぜる順は、種と qid の sha256 の順。型 ② の候補の並びは固定(巡回は要らない=親の判断)。
