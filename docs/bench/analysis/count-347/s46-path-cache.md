## 1. 試験: 控えの有り無しで返る線が 1 バイト一致

`tests/engine/space/test_nav1_route_cache.py`(新規)。

### 1-1 「無し」の作り方と理由

| 方法 | 使えるか | 理由 |
|---|---|---|
| 控えの上限を 0 にする | 使えない | 捨てる行 `if len(cache) >= cap: cache.pop(next(iter(cache)))` が空の控えでも走り、`next(iter({}))` が StopIteration で止まる(本番の世界の面で試した) |
| 控えを通らない内側の関数 `NavPlanner.plan` を直に呼ぶ | 照合の 3 本目にだけ使う | 鍵の作り方と float32 への丸めを飛ばすので、控えの有り無しのほかの違いが混ざる。丸めを手で同じにし(`float(np.float32(x))`)、問い合わせの順を逆にして呼ぶ=道の計算が呼ぶ順(作業の配列の前の中身)に依らないことの確かめ |
| **`_shape` を呼ぶ前に毎回 `_shape_cache.clear()`(採った)** | 使う | 鍵・丸め・計器・道の計算は同じ道を通り、控えだけが毎回空になる。インスタンスの `_shape` を包むので `ensure_routes` からの呼びでも効く |

### 1-2 試験の名前と確かめていること

| 試験 | data | 確かめていること |
|---|---|---|
| `test_cache_on_and_off_give_byte_identical_lines_on_the_synthetic_mesh` | 不要(合成の小さな面・CI で毎回) | 問い合わせ 249 回(重ならない組 83・鍵 67)を `_shape` に当て、控え有り=控え無し=逆順の直の計算。線の全欄(`dataclasses.fields` で引く=欄が増えても比べ漏らさない)を dtype・形・バイトで比べる。丸めると同じ鍵になる、別の float64 の出発点の組(x を float64 で 1 つずらした双子)と、引けない問い合わせ(None)を混ぜる。控え有りの計器が「計算=鍵の数・控えから=残り」、無しが「控えから 0」 |

## 2. 計測: 座標の丸め(float32)で道が変わる件数

運転用のスクリプト `s46-path-cache/measure_rounding.py`・数 `s46-path-cache/s46_rounding_w6_v3_default.json`。

### 2-1 丸めの場所

丸めを外す口はコードに無い。丸めは 3 か所で同じ値に掛かる。

1. 位置の欄 `xy` と出発点の欄 `nav_ox`・`nav_oy` が float32(`src/shibuya/agents/state.py` 519・721・724 行)。位置を書く所で丸める:
   `src/shibuya/engine/resolve.py` の `_nav_stop`(1596-1597 行・面への寄せ)・`_nav_step`(1638-1639 行・進んだ位置)・
   `_nav_positions`(1675-1676 行・面への寄せ/1683-1684 行・節の点への置き直し)。
2. `NavSpace.ensure_routes` が出発点を float32 で持つ(`nav1.py` 920-924 行)。
3. `NavSpace._shape` の鍵 `np.float32(ox).tobytes()`(832 行)と、道の計算 `planner.plan(float(np.float32(ox)), …)`(837 行)。

### 2-2 丸める前の float64 の取り方

関数を包んで読むだけ(戻り値も状態も変えない)。「丸める前の値」は、位置を float32 の欄に書く直前に計算された float64 の値と
する(それより前の丸め=経路を引いた出発点・進んだ時間 `nav_t` の float32 は戻していない)。

| 出どころ | 取り方 | 問い合わせの回数 |
|---|---|---:|
| 進んだ位置 | `NavSpace.advance` の戻り値 `x`・`y`(float64) | 11,944 |
| 節の点への置き直し | `_nav_positions` の後に動いた体のうち、`nav1_anchors` の float64 の点を丸めた値と一致する体 | 1,834 |
| 節の点(問い合わせのときに照らした) | 控えた値と合わず、今の節の点(float64)を丸めた値と一致(初めの配置で節の点が W1 の節の点と同じ float32 の値=書いても値が動かない体) | 4,653 |
| 面への寄せ | `onto_surface` の float64 の戻り値(寄せる前の float32 の位置に当て直し、丸めると書いた値と一致) | 36 |

## 3. 確かめていないこと

- 丸めの計測は「位置を float32 の欄に書く直前の 1 回の丸め」が 1 本の道の計算に効く量だけ。丸めない世界でランを通したとき
  (位置・出発点・進んだ時間の欄を float64 にする)の結果の差は測っていない(src を変えないと回せない)。長さの差 0.06 mm 以下は、
  希望の速さの下限 1.0 m/s(`DESIRED_SPEED_MIN_MS`)なら所要時間で 0.06 ms 以下(坂と混み具合で遅くなる分は除く)だが、刻みの
  境で着く刻みが 1 つずれる体があるかは数えていない。
- 構成は `w6_v3_default` の 1 本・1 日・seed 1・5,000 体だけ。全規模(35 万体)・2 日以上・腕(曲がる重み `person`・坂 `tobler`・
  密度の推定)・再開のランは測っていない。
- 控えの捨てる行(5 万件で溢れる)は標準のランでは通らない。溢れの場合は試験の小さな上限(3 と 16)でだけ確かめた。
- 2 本の線の離れ方は頂点で測った近似(線分の途中の最大は見ていない。頂点どうしが µm で重なる形なので差は小さいと見込む【推測】)。
- 試験は重みが組み立てのときに固定の間の一致だけを確かめる。重みや道の選び方を途中で変える口は、試験の中で動かしていない
  (負の対照で、変えれば差が出ることだけ確かめた)。
