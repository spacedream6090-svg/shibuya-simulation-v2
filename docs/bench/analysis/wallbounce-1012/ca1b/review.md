## 欠陥

### 高

- **H1 計画一致率と 15 分ごとの率が体の居場所を見ていない・勤務中に舞台を出た体を層が追わない**(`engine/calendar_self.py`
  `_sample`・`note_rode_out`・`_opportunities`)。率は層の段(`phase == 約束の場所`)から数える。mock の行為の抽選で乗車を選んだ体は
  発車で舞台を出るが(連続性の検査は「電車で出た」で正しく通す)、段は「約束の場所」のまま、次の機会は終わりの時刻だけになる
  (計画実行層の張り直しも腕では止めている)。そのため 1,336 体(49%)が勤務の途中で域外に出て、終わりの時刻まで戻らない。README
  §4 は「計画一致率(約束の時刻の中で約束の場所)0.942/0.993/0.988」と書くが、体の居場所では 0.642/0.500/0.330。
  直し方: 計器は体の居場所(在圏・約束の場所のセルか建物)から数え、段からの値は別の欄に分ける。約束の場所の段で本人の行為で
  舞台を出た体を数える欄を足す。挙動は、出た体の段を変えて本人の次の機会(時計を見る習慣)を出すか、今の形を仮採用として
  つなぎの台帳と README §4・§11 に書く(既定は変わらない)。

### 中

- **M1 逆算の検査が帳簿だけ**(`calendar_self.py` `_opportunities` の `ref < 0` の数え・`tests/engine/calendar/test_ca1b_runs.py`
  `test_negative_backward_wake_is_caught`)。検査は「機会に参照の id が無い」ことだけを数え、植えた写しも id を外している。本当の
  道のりから逆算した時刻に id を付けて置くと 0 のまま通る(上の追加の負の対照)。直し方: AST の試験で、層の中の `next_T`・
  `plan_T`・`arr_T` への代入が `start_T`・`d_out`・`walk_go`・`lead` から作られていない(判断の口の答えか本人の器の値だけ)ことを
  確かめ、負の対照(id を付けた逆算)で落ちる形にする。実行時には、通知とアラームの時刻が本人の予想(`Prediction`)だけから
  口の答えで決まったことを照らす。検収役の AST の走査では、今のコードの代入はどれも口の答えか今の刻みと間隔からで、`start_T` から
  作るものは無い。
- **M2 口の約束との違い**(`calendar_self.py` `Observation`・`_set_reminders`)。(a) 観測は 1-2 の `Percept`(`time_view`)でなく
  独自の型。(b) 通知とアラームの時刻は `choose` を通らず、mock の `planned_departure` を直に呼ぶ(この関数の無い口では 0 時に
  なる)。(c) 腕 1b の判断は LLM のランでも層が持つ mock の口で、ランの判断の口ではない(`DOC-ca1b-provisional-model` に宣言
  あり)。直し方: README §2 の口の表に違いを書き、(a)(b) を判断モデルの段で J0 に載せる(つなぎの台帳の行の「外す段」に書く)。

## 親に確かめてほしいこと

   張り直しも止まるので、H1 の「出たまま戻らない」はこの範囲と組み合わさって起きる。
