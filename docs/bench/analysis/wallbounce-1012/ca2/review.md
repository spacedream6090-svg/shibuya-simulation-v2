## 欠陥(重さ順)

### 中

- **M1 時刻を変えたアプリの行の知らせが、古い時刻に 2 回鳴る**(`src/shibuya/engine/calendar2/layer.py` の `_change`(時刻を変える)・
  `_schedule_row`・`_opportunities` の知らせの段)。時刻を変えても `notify_ns` は元のまま(`edit` は `start_ns`・`end_ns` だけ)で、
  `_schedule_row` が同じ刻みに知らせの印をもう 1 つ置く。合成の台で 15 時の約束(知らせ 30 分前)を 18 時に変えると、体 0 の
  `約束:知らせ` が 14:30 に 2 行出る(自分の試し)。知らせの時刻が既に過ぎた後で変えると、印が過ぎた刻みに置かれて二度と取り出され
  ない(帳面に残る=有界化の外)。アプリの知らせは予定の時刻について動くのが道具の性質(CA4「道具が現実に教えること」)。**直し方**:
  アプリの行は時刻の変更で `notify_ns` を同じだけずらす(道具の性質=観測の欄でなく道具の欄として口を足す)か、知らせの判断を
  もう一度呼ぶ・知らせの段に「その行の `notify_ns` の刻みが今の刻みでなければ捨てる」の印の照合(始まりの印と同じ形)・過ぎた刻みに
  印を置かない。負の対照=時刻を変えた行の知らせが新しい時刻に 1 回だけ。
- **M2 思い出せない頭の中の行を「自分の約束を変える」で触れる**(`layer.py` の `_on_turn` の `own`・`_change`)。会話の番の判断の
  候補「自分の約束を変える」は、相手との自分の行が**あるだけ**で出て、`_change` は置き場所を見ない=頭の中の行も思い出しを通らずに
  変えられる・取り消せる。合成の台で、手がかりなしでは思い出せない刻み(1,041)に相手が別のセルに居る会話の番を回すと、候補に
  「自分の約束を変える」が出て、行が「有効 → 取り消し」になった(思い出しの計器は 0 回=口を通っていない)。CA3「本人には記憶で
  思い出せたときだけ見せる」の破れ(メッセージと通話の番では相手が同じセルに居ない=手がかりも無い)。手帳の行(その日に開いた
  ときだけ見える)も同じ道で触れる。**直し方**: `own` を `_visible` と同じ口で絞る(頭の中=思い出せたとき・会話の相手を手がかりに
  数えるかは宣言)・負の対照=思い出せない頭の中の行は「変える」の候補に出ない。
- **M3 出来事の記録の有無で、腕 arm のランの behavior-hash と final が変わる**(`layer.py` の `_write_own`・`_outside` が行の観測の欄
  `event` に `_log` の戻り=出来事の id を書く・`_propose` が誘いの `event` に書く。行は CA2B・誘いは CA2O=どちらも behavior)。
  口の約束 1-3 の (1)「記録の有無で final・テープ・behavior-hash 不変」の破れ。自分の試し(合成 80 体・720 刻み・腕 arm だけ):
  記録 on/off でテープ・計器(出来事の数を除く)・行の中身(`event` を除く)は同じ・`event` だけ list/None=checkpoint の behavior-hash
  が刻み 179 から違う・final が違う。**C1(腕 c1)にも同じ形がある**(C1 だけのランも刻み 59 から違う=先例・本段の前から)。
  **直し方**(親の判断): 出来事の id を diag・discardable の別の表に置く(行の中は記録に依らない番号だけ)か、腕のランは記録 on を
  組み立てで要る(off なら止める)として台帳と 1-3 に宣言する。C1 と同じ直し方に揃える。

## 実装役の問い(記録 §13)への意見

記録 §13 の問いは 6 つ(1〜6)。

1. 記憶の器に予定の種類を足すか: 本段は今の形(器に足さない・行が目印と痕跡を持つ)で受け入れてよい。器に足すのは記憶の版上げ(6-5)と
   一緒に。その前に M3(目印の出来事 id が記録 off で None)を直す。
2. 呼び数を `calls_by_model` に足すか: 足す(C1 の M5 と同じ内訳 `calendar_2`)。TM9 は判断モデルと LLM を分けた呼び数を求めていて、
   37 万回/日が manifest の深い所にしか出ないのは量の判断を誤らせる。既定のランは欄が出ない形なら不変。
3. 誘いの機会の形と量: 既定にしない(台帳どおり)で、C1 の量の判断と束ねる。グループのチャットで成員の全員が番ごとに判断する形が量の
   大半(約束の族 229,558 行のうち)=判断モデルの段で「番の出力に畳む」の前に、グループの返事の機会を絞る形を先に決めるのがよい。
4. 範囲外の過ごし方: 範囲の外に出た刻みに本人が書く形でよい(計画実行層の表を読まない理由も妥当)。
5. 共有ファイル: `llm_io.utter` の 4 行・`turn_sink`・`DIAG_EXITS` の 1 項とも影響は腕の中だけ(#5 で確かめた)。系の `reads` は L3。
