# v1 で手持ちのお金が極端に少なくなった原因の確認(指示書 10-12 §4-11)

- 実行役: Opus 5.5(2026-10-12)。読むだけ。v1 リポ(`<v1>` = Desktop の `shibuya-simulation`)にも v2 の src にも書き込んでいない。
- 読んだもの: v1 の記録(`<v1>/docs/research/`・`<v1>/docs/log/`・`<v1>/IMPLEMENTED.md`・`<v1>/STATUS.md`)、v1 のコード(`<v1>/src/society/`)、v1 のランの実データ(`<v1>/runs/*/l1_events*.parquet`・`l2_metrics*`・`l3_snapshots*`・`agents.json`・`config.yaml`)、v2 の記録とコード。
- ランの実データの集計は自分で行った(pyarrow で読むだけ)。スクリプトは `docs/bench/analysis/wallbounce-1012/v1-wallet-scripts/`(引数はランのフォルダ)。v1 の記録に書かれた値と、自分の集計の値は分けて書く。「推測」と書いた値は自分の試算。

## 要約

1. v1 で残高(現金+口座)が尽きたのは、ほぼ全員が**来街者**。来街者には口座も収入もなく、持ち金は来街時の 1 回分(1〜3 万円)だけだった。本選の Run B(8/26・16 時間)で逼迫(現金+口座 < 2,000 円)と数えられた 6,979 体のうち 6,806 体が来街者で、**その全員がエンジンの規則で宿泊費 12,000 円を払った体**だった(抽選の確率は 0.4。払える額の判定は現金だけ)。100 日ラン mem100 では、財布の補充が OFF のため来街者 4 体全員が 10 日以内に 2,000 円を切った。
2. **居住者**の「手持ちが少ない」は、総額の不足ではない。現金の割合(初期資産の 20%)と ATM の作りから来る見かけの不足で、口座には ATM がありお金も増えていた。それでも現金 < 2,000 円の時間は 17〜43%(口座 ≥ 20,000 円の時間に限っても 13〜43%)に達した。原因は 3 つ: LLM に見せる所持金が現金だけ、建物内の購入と宿泊の判定が現金だけ、引き出しは本人の判断ではなく「支払いの瞬間に不足したら自動」だけ。
3. 仮説の判定: (a) 口座から引き出せない = **形を変えれば裏付けあり**(来街者は口座そのものが無い。居住者は本人が引き出せず、判定と表示は現金だけ)。(b) 賃金が未接続 = **来街者には裏付けあり**(収入の経路が無い)。居住者は較正ランでは接続済み(本選の前に 2 つの欠陥を直した記録はある)。(c) 初期の財布が小さい = **裏付けあり・寄与因**(来街者 1〜3 万円に対し宿泊 12,000 円/泊)。(d) LLM が買いすぎる = **直接の裏付けなし**(LLM が選んだ購入は 3 ランで 0 件。課金は到着時のエンジンの規則)。
4. 主因は「来街者 = 1 回分の現金だけ・口座なし・収入なし」に、エンジンの大きな課金(宿泊)と補充の欠如が重なったこと。居住者の分は「現金だけを見せて現金だけで判定する」表示と判定の問題。
5. v2 の今(賃金 0・口座の行はあるが預け入れも引き出しも呼ばれない・財布 1 本)は、**v1 の来街者で財布の補充を OFF にした形(mem100)と同じ型**。v1 の居住者の型(口座はあるのに現金だけ見える)は、v2 に口座を入れたときに起きうる。

## 3. 仮説ごとの判定

| 仮説 | 判定 | 根拠 |
|---|---|---|
| (a) 口座から引き出せない | **形を変えれば裏付けあり** | 引き出しの口そのものはあった(自動 ATM `scheduler.py:683-698`、mem100 で 18 回・calib_final_100d で 445 回・daily300_100d で 1,360 回)。ただし (i) 尽きた体はほぼ全員が来街者で、**口座がそもそも無い**(`economy.py:256`。Run B の逼迫 6,979 体のうち 6,806 体、mem100 の 4 体)。(ii) 居住者は本人が引き出せず、ATM は支払いの瞬間に不足したときだけ動く。建物内の購入(`scheduler.py:3914`)と宿泊(`lodging.py:118`)の判定、LLM に見せる所持金(`planning.py:82`)、「お金が足りない」の判定(`day_plan.py:1418`)は現金だけ。その結果、居住者は口座 ≥ 20,000 円なのに現金 < 2,000 円の時間が 13〜43% あった(§1-2 (3))。Run B の 16 時間の引き出しは 30,226 体で 6 件 |
| (b) 賃金が未接続 | **来街者には裏付けあり。居住者は較正ランでは接続済み** | 来街者は賃金なし(mem100 の来街者の賃金 0・`sim-improvement-analysis.md:88`)。補充の `visitor_refresh` が収入の代わりで、mem100 では OFF。本選の前に「L2 の大半が無給・給料日が来ない」欠陥があり、第112 で直した(`finals_observe.yaml:1052-1060`・`IMPLEMENTED.md:413`)。修正後の Run B は 16 時間で給料日を含まず、尽きたのは宿泊した来街者で賃金の有無とは無関係。較正ランの居住者は賃金(約 5,826 円/日)が支出(約 2,158 円/日)を上回り、口座が増え続けた |
| (c) 初期の財布が小さい | **裏付けあり(寄与因)** | 来街者 10,000〜30,000 円(`economy.py:288-290`)に対し宿泊 12,000 円/泊(`lodging.py:34`)。宿泊の判定は「現金 ≥ 12,000」なので、12,000〜14,000 円の体は泊まると 2,000 円を切る。Run B の 6,806 体は初期の中央 13,100 円 − 12,000 円 ≈ 1,100 円(式: 中央値どうしの差・推測)。居住者の現金は初期資産の 2 割(会社員なら 10,000〜30,000 円、大学生なら 1,000〜6,000 円) |
| (d) LLM が買いすぎる | **直接の裏付けなし。間接は判断できない** | LLM が選んだ購入(`chosen`)は 3 ランで 0 件。課金は到着・入館・宿泊の抽選・固定費というエンジンの規則。食事と夜の飲食の回数は daily300_100d で中央 155 回/100 日(1.55 回/日)、Run B で中央 1 回/16 時間。ただし mem100 の来街者 0 番は step 64〜81(約 2 時間 50 分)に食事 4 回で 3,600 円を払っている。到着するたびに空腹と関係なく課金される規則の影響で、LLM の行き先選びがどれだけ効いたかは分けられない |

**量の比べ(式つき)**

- 本選 Run B の来街者: 支出の 89% が宿泊(626,316,000 ÷ 702,877,149)。2,000 円を切った 6,806 体は全員が宿泊者で、宿泊者 52,192 体の 13.0%(6,806 ÷ 52,192)。
- mem100 の来街者: 初期 16,700〜29,900 円、収入 0、補充なし。5.5〜9.5 日で 2,000 円を切った。居住者 1 番は賃金 777,363 円 > 支出 354,486 円で総額は増えたが、現金は 43.2% の時点で 2,000 円未満。
- 較正ランの居住者: 賃金 ≈ 支出の 2.7 倍(24,470,923 ÷ 9,061,807)。総額 < 2,000 円は 1.1〜2.7% の時点だけ。

**主因のまとめ**: 残高そのものが尽きたのは、来街者の「1 回分の現金・口座なし・収入なし」に、エンジンの大きな課金(宿泊 12,000 円)と補充の欠如(mem100 は補充 OFF、本選は宿泊中に補充されない)が重なった結果。居住者の「手持ちが少ない」は総額の不足ではなく、現金だけを表示・判定し、口座を本人が使えない作りによるもの。
