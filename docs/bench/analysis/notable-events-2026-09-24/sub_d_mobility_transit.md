## 2. 出来事ごとの原因

### 2-1 乗車が駅の無い場所で選ばれる(D1)

- **ホームは 2 セルしかない**: `ProcessAssets.line_platform_cell` = 井の頭・副都心・埼京・山手・東横・田園都市・銀座 → セル 291(`g1_-1_UG`)、半蔵門 → 239(`g0_-1_UG`)(W11 の `station_nodes` の `kind=platform` から・`assets.py:1051-1071`)。【確定】
- **ホームのセルの B2 は駅を名乗らない**: `g1_-1_UG` の B2 は「地下の区画に飲食店、物販店が見える / 目印: 渋谷東口、渋谷C2」。「駅」を含む B2 は 19 種類あるが、全部地上/デッキのセル(例 `g-2_-1_GL`「目印: 渋谷渋谷駅」)でホームではない。B2 のテンプレートにホーム・改札の欄は無い(診断書 §4 と同じ所見)。【確定】
- **場所への依存が無い**: ×1 の乗車率は、B2 に駅あり 2.45%・なし 2.46%・ホームのセル 2.31%(3/130)。ホームで呼ばれても乗車が増えない=8B はホームに居ることを知らない。【確定】
- **理由欄**: ×1 の乗車 907 のうち「食」を含む 464(51%)、「仕事」53、「通勤」13、「駅」8、「電車」1、「帰」1。上位は「空腹で食事を探す」119・「空腹で行動を起こす必要がある」66・「空腹で行動が必要」57・「地下通路から地上へ移動するため」17。**通勤・帰宅の足として選ばれた乗車は少数**。【確定】
- **時刻・種別・起床クラス**: ×1 の時刻別 06〜10 時 384(42%)・20〜23 時 201。種別 通勤者 422・来街者 251・居住者 189・従業者 44。起床クラス 0/1/2/3 = 234/381/160/132。c7-day-4 はクラス別の選択率 1.33 / 2.34 / 1.46 / 1.19%(計画境界が最も高い・`tape_stats.json`)。【確定】
- **対象欄は使われない**: ×1 の乗車で対象に駅名(「渋谷渋谷駅」「渋谷駅」)を書いたのは 8。エンジンは対象を見ずに**直線距離で最寄り**のホームを選ぶ(`resolve.py:1348`・経路長ではない=expedient)。【確定】
- **テープの実例**(×1): 通勤者 06:39 `g1_-2_GL`「空腹で食事を探す」→ 乗車。従業者 21:22 `g1_-5_GL`「餓感があり、飲食店を探すべき」→ 乗車。来街者 13:39 `g-2_1_GL`「お店を見つけて行動を決定する」→ 乗車。
- **原因の型**: モデル(8B が「乗車」を移動の言い換えに使う)+ 設計(観測にホーム・改札の手がかりが無い・行き先は対象を見ない)。

### 2-2 実現・待ち・打ち切り(D2・D2′・D3)

- **漏斗の各段のコード**:
  1. 選ぶ → `_apply_board`(`resolve.py:1291-1384`): 乗車中・域外なら `NO_TRAIN`(`:1318`)。ホームに居れば待ち行列へ。居なければ最寄りのホームへ `target_node` を張って `MOVING`(**成功 `OK` を返す**=「列車なし」ではない)。
  2. 歩く → エンジン継続が 1 tick 1 ノード進める(`graph.py:75-88`)。着いたら待ち行列へ(`resolve.py:1003-1006`)。
  3. **途中で別の行動を選ぶと意図が落ちる**: 意図を保つのは 乗車・待機・エンジン継続だけ(`resolve.py:195`)。それ以外を選んだ体は `board_line=-1`(`:833-842`)。会話に引き込まれるなど自分以外の理由で歩みが止まった体も掃除される(`:1466`)。
  4. 待つ → 停車中の列車へ FIFO(`_serve_board_queue`・`:1387-1446`)。定員の受容関数は 5,000 体でも 39 万体でも発火しない(乗り残し 0)。
  5. 打ち切り → ホームで 30 tick 待っても乗れなければ `NO_TRAIN`(`BOARD_WAIT_LIMIT_TICKS=30`・`:191`・`:1451-1459`・expedient)。平日の時刻表は 01〜04 時の発車が 0 本(時刻別の便数 `[49, 0, 0, 0, 0, 141, …]`)。打ち切りは主にこの時間帯とみられる(×1 の 01〜04 時の乗車選択 21・打ち切り 1)。【機構は確定・時間帯は推定】
  6. 乗る → 運賃 180 円を外界へ払い、`transit_state=1`(`:1497`)。
- **どこで落ちるか**: ×1 は ホームに着くまでに 244(27%)、ホームで 15(打ち切り 1+その他 14)。c7 は 10,627(22%)と 958(打ち切り 185+その他 773)。**落ちるのはほぼ歩行中**。「その他」は待っている間に別の行動を選んだ体とみられる(運賃不足の件数はログに無い=空欄)。【数は確定・「その他」の内訳は推定】
- **歩行が長い理由**: 5,000 体の乗車地点からホームまで、経路は中央値 757 m(直線 542 m)で 28 hop。1 hop の長さの中央値 25.7 m=**約 1.5 km/h**(C9 アジェンダの全体値 ≈2.3 km/h より遅い)。人の歩行 1.0〜1.6 m/s(C9a の希望速度)なら 8〜13 分の距離に 28 分かかる。【確定】
- **待ち行列の数の読み違い**: ログの「待ち行列 7,712」は `ResolveOutcome.n_queued`(購入・食事で店が満席のとき・`resolve.py:1575/1687`・`run.py:803`)。鉄道は「乗車待ち 37,392(打ち切り 185)」。【確定】

### 2-3 降車 0(D7)

- **乗車中の時間が 1 tick しかない**: 通過型の線は `dep_tick` の 1 tick だけホームに居る(`DWELL_TICKS=1`)。その tick の Phase C で乗った体は、次の tick の先頭の `RailProcess.step` で `dep_tick == t-1` の便として運び出される(`rail.py:644-656`)=`transit_state` 2(域外)。終端の 2 線(銀座・井の頭)だけ 2 tick。`occupancy.npz` の乗車中の人数は正時の標本で最大 115(08 時)。【確定】
- **乗車中の体は呼ばれない**: 計画実行層のランでは `transit_state != 0` の体を起床候補から外す(`run.py:1933-1936`・D-66 域外抑止・例外なし)。c7-day-4 の「域外宛ての呼 0(抑止 2,998,005)」。【確定】
- **判断は早くて次の tick に落ちる**: `t_apply = 起床 + δ_perc + δ_think` を分 tick へ切り上げ(`run.py:11`・`llm_bridge.py:45-48`)。仮に呼べても、その時には列車は出ている(D-15 の元の説明)。【確定】
- **「乗って来て降りる」体が居ない**: 域外から来る体は計画実行層の到着(`_do_arrive` → `rail_arrive`・`presence.py:1182-1204`)で改札のセルへ直に置かれる。車内の体として舞台に入ることは無い。【確定】
- **c7 の 降車 23 呼**: 舞台に居る体が選んだもの。`_apply_alight` は「乗車中かつ停車中」でないと `NO_STOP`(`resolve.py:1511-1537`)。
