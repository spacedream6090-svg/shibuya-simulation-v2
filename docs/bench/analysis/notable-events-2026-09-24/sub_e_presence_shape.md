## §0 結論(先に)

1. **ピーク時刻(sim 10〜13 時 vs KDDI 15〜18 時)の原因は、種別の構成ではなく各属性の時刻形状にある**。
   - 反実仮想で確かめた: sim の属性シェアを KDDI の値に合わせて重み付けし直しても、5 エリアのピークは 10/11/11/11/13 時のまま一つも動かない(確定)。
   - 形状を作っているもの(1): W17 の来街者は 09 時台に着き 13 時台に出る。VISITOR の 66.9% が 12〜14 時台に退出し、15 時以降に到着するのは 2.0% だけ(確定)。
   - 形状を作っているもの(2): 計画実行層に非対称がある。到着は駅出口セルへ降ろすが、そのうち 8/25 セルが central にある。退出は今いるセルから即時に消す(`resolve.py:2098` `cell=-1`)ので、夕方に central(駅)を通る流れがない。central の在圏は 10 時の 55,208 から 17 時の 11,051 へ落ち、H1 の超過(エリア別 JSD の合計)の 67% を central 1 エリアが占める。規則は確定、効果の大きさは推定。
2. **来街者比(sim 0.14〜0.39 vs KDDI 0.40〜0.76)**
   - 5 エリア合計で来街/勤務の比は sim 0.345、KDDI 1.658 で、差は 4.8 倍。
   - sim 側を分解すると、体数の比 0.596(W16)と 1 体あたり在圏時間の比 0.58(W17)がほぼ同じ重さで効いている(確定)。
   - ただし現実同士でも食い違う。PT のピーク内訳では 所属なし/勤務通学 = 0.16 なのに KDDI は 1.66 で、KDDI の「来街者」は定義が広いか週末を含むと見られる。H5 の外れを W16 だけに帰属させることはできない(推定)。
   - 写像 `KIND_TO_ATTR` の注意点: STUDENT を来街者側に入れているのに比率が足りない。
3. **昼間の絶対水準**
   - 12 時の 217,435 は PT ピーク 145,000 の 1.50 倍、国勢調査昼間人口 130,167 の 1.67 倍。09 時の 147,606 は 1.13 倍だが、これは v2.1 で到着が遅れた分で低く見えているだけ。
   - 12 時の内訳: 勤務・通学系 169,017(PT 勤務通学 112,000 の 1.51 倍)、来街系 41,584(PT 所属なし 18,000 の 2.31 倍)、住民 6,834。
   - 従業者に概念差 1.41(D-67)を当てはめると 12 時は 174,387(PT の 1.20 倍)になる。これは線形の推定。出勤率 0.88 の実測(c7-day-5)は未実行なので空欄。
4. **深夜 03 時(27,716・帯 1.5〜3 万の内側)**
   - 構成は 訪日 13,019(47.0%)・住民 10,905(39.3%)・従業 2,246・通勤 1,438。★ 種別の合計は **1,541**(5.56%)。依頼文の「1,545」は記録(物差し §3)とも再計算とも合わない。
   - 帯に入ったのは D-66 の効果で、域外居住者の自宅行を域外として読むようになったため(確定)。
   - 残っている通勤者のうち約 1,240 体は計画(580)より多い。mock でも同じ数なので LLM 由来ではない。原因は空欄。
5. **seed 差と構造差**
   - seed 1 と 2 の JSD は 0.000162 で、合格線 0.0122 の 1/75.3(再計算で一致)。3 対の平均 0.000178 に対して holdout の H1(6〜23 時)0.02207 は 124 倍。
   - 「外れは seed ではない」は言える(確定)。ただし 3 seed は W16/W17 の生成を 1 回に固定しているので、生成のばらつきは「構造」側に入っている。
6. **LLM の寄与**
   - bbox 単位の時刻形状はほぼ計画で決まっている。実 LLM と計画の差は最大でも −7,800(11 時・2.4%)。LLM は形状を作っていない(確定)。
   - 一方、エリア内の配置は LLM が作っている。ランダム方策の mock は H4 の JSD が 0.041 で、central シェアが 0.353 まで膨らむ。実 LLM では 0.009。H4 の同値合格は LLM が計画の行き先へ体を運んだ結果(確定)。
   - その H4 の合格は写像に脆い。境界を ±50 m 動かすと JSD は 0.0148 / 0.0346 になり、どちらも線 0.0122 を超える(確定)。

3. **H5 の定義を合わせる感度腕**(物差し・未リサーチの案)。KDDI の 3 区分の公式定義を一次で確認する。「推定勤務地がそのエリア内」が条件なら、`KIND_TO_ATTR` をエリア単位の写像に替えた版を感度として出す。そのためには journal に体の職場エリアの軸が要る。
4. **次の holdout(`shibuya_jinryu`)を事前登録する前に、日種の軸があるかを確認する**(未リサーチの案)。KDDI 層は年間合算で週末を含み、平日 1 日の sim とは日種が違う。事前登録 v2 の指標は、平日だけで比べられる量にする。
5. **H4 を主張する前に写像を固める**(D-67 (d)・未リサーチの案)。±50 m で合格が消えるので、事前登録 v2 では H4 を ±50 m の 3 点で報告し、3 点すべてが線の内側であることを合格条件にする案。
