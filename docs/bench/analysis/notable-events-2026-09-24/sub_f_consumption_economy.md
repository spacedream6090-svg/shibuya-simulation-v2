9. **宿泊は経済にも LLM にもつながっていない。**(確定)チェックインは 21:00 の 1 回だけ、来街者で、しかも**そのセルにホテルがある体に限られる**。支払いは無い(`civic.py:235-345` に台帳の引数が無い)。ホテルが最小 id の 6 セルでは、「購入」が 1,500 円の物販として立つ。

## §2 出来事ごとの原因

### F-1/F-2 購入の成立 36〜41%(推定・再構成モデル)

| 内訳(x1・16,169 呼) | 件数 | 比 | 原因のコード |

| 閉店(最小 id の店が営業時間外) | 4,573 | 28.3% | `resolve.py:1560`・W7 |
| 裁定で落選: 最小 id が売り切れ(受入 = min(4, 在庫) = 0) | 3,199 | 19.8% | `commit.py:311-316` |
| 裁定で落選: 1 tick に 4 人を超えた | 60 | 0.4% | 同上 |

- **売り切れの落選は、テープにも runner にも出てこない**。在庫 0 だと Phase B の受入数が 0 になり、`OUT_OF_STOCK` ではなく `LOST_ARBITRATION` として返る(`commit.py:311-316`・確定)。x1 で売り切れた最小 id の店は 34 店(x0.5 25・x2 57・無制限 55)で、売り切れた時刻の中央値は 16 時台。購入の時刻別の落選率は、12〜16 時の 23〜28% から 17〜20 時の 34〜41% へ上がる。補充は 10:00 の 1 回だけで、量も ≤6 個(納品ロット = 64×0.05×2・`goods_flow.py:83, 98, 363`)。
- **[ab8 親報告](../../c8/ablation/ab8_s1_parent_report.md) の「×2 で飽和し始める」は、供給側の上限と読むのが筋**(推定)。×2 → 無制限では、売り切れによる落選が 4,586 → 4,491 とほぼ動かない一方、4 人/tick を超えた落選が 194 → 2,160 に増える。したがって「×1 は飽和点の 69%」は、需要の飽和ではなく最小 id の店の在庫と受入の上限を指している。
- **意図との食い違い**(確定=テープの対象欄と W6 の照合): 対象欄の 65.6%(10,600/16,169)は「物のカテゴリ」「食品カテゴリ」「目標:」など欄名の写しで、店は指定されていない。店名が書かれた 908 呼のうち、最小 id の店と一致したのは 192 呼だけ。102 呼は同じセルに書かれた店があるのに別の店で精算され、614 呼は書かれた店がセルに無い。食べ物の意図(対象欄か理由欄)を持つ購入 13,983 呼のうち 3,740 呼(26.7%)は、飲食店でも物販でもない POI で精算された。上位は「食事が必要なため」→ 中渋谷教会 120・天狗(nightlife)46・渋谷みどり薬局 41・忠犬ハチ公像 34・私立青山学院高等部 26。
- テープの実例(v1): 大盛堂書店(shop・300 円)の 1 店が、セル g-1_0_GL(POI 29・うち飲食 11)の購入を全部受けている。選択 948 呼に対し、在庫の上限は 64 + 6。

### F-4 食事 → 休憩の連鎖(確定=テープ・推定=引き金)

| 直前の食事(s1)の前提 | 次の呼の数 | 次が休憩 | 次がまた食事 |
|---|---|---|---|
| 前提を満たす(大半は成立) | 7,624 | **36.6%** | 1.4% |
| 閉店で失敗 | 4,081 | 6.5% | 1.4% |
| 飲食店の無いセルで失敗 | 2,644 | 3.8% | 0.3% |

- 休憩の理由欄 3,154 件のうち、「食後/食事の後/食事後/食べた後」が 2,634 件(83.5%・s2 82.3%)。「営業時間外/閉」49 件、「疲れ/体力」1 件、「満腹/いっぱい」0 件。実例: 直前の理由「食事の必要性が高い」→ 休憩の理由「食事の後は休憩が必要です」「食後は休憩が効率的」。食事から休憩までの間隔の中央値は 53 tick(s1)。
- **読み**: 連鎖は「食事の成立」という世界の状態に依存している(失敗後は 1/6〜1/10)。ただし 8B が見ているのは満腹感ではなく、成功の報告(B6 は「直前の{行動}は成功しました」`templates.py:464`)に対する型どおりの応答だと考える(推定。B6 はテープに無い)。体の状態は、この休憩を正当化していない。空腹は 2 から 30 tick ごとに +1 で、04:00 には 10 になる。1 食で −4 なので、食べた後も「空腹は 6 で閾値を超えています」が出る(閾値 4・`renderer.py:131`)。
- v1 で購入の前提を満たした後に**また購入を選ぶ 36.4%** には、売り切れの落選が 1/3 ほど混ざっている。成功の後か失敗の後かは分けられない(空欄)。
