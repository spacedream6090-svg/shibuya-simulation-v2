## 主要な結論(2026-09-02)

1. **量子化W8A8-INT8が支配的レバー**: 8B 470 tok/s(BF16比1.74x)・14B 218 tok/s(3.15x)。
2. **系はprefill律速**(input1500/output128でtotal≈6,000 tok/s)。max_num_seqs・concurrencyを上げてもスループットは平坦でTTFTのみ悪化(c=1024で170秒)=バックプレッシャ設計(bounded queue)の実測根拠。
3. **最大のレバーはprefix cache×プロンプト規約**: 共有プレフィクス1,000tokで **789 tok/s(c32・1.81x)→1,032 tok/s(c128・2.39x)**。キャッシュが効くと並行度がやっと効き始める。「固定節先頭寄せ」規約の定量的裏付け。
4. **出力を絞ると呼び出し数/秒が増える**: o64+prefix=9.15呼/s/GPU(o128素=3.7呼/s)。
5. MRV2(0.28.0)の利得は本負荷形状では**測定できず**(0.27.1と同等・±1%)。
6. BATCH_INVARIANT=1のコストは**-2%以下**=検証ラン(論文級)に常用可。
7. 14B INT8はKV狭くmax-model-len緩和でも~213 tok/sで平坦。

## 第2段の追補(サブ最終報告の検収反映・2026-09-02)

- **天井の正体はKV容量**: 8B INT8のKVプール≈80k tok・1リクエスト1,628tok→**実効並行≈49**(14Bは≈16)。予測KV使用率0.654 vs 実測0.648で検証済み。max_num_seqs=128は最初からKV上限の2.6倍上にあった。
- **prefixの機構**: 共有1,000tokでリクエストあたりKVが1,628→628tokに縮み実効並行49→132。ヒット率実測67.4%(理論66.7%と一致)。ランダム対照はON/OFF差0.7%=効果は共有プレフィクス起因と因果確認。
- **第1段の訂正**: randomデータセットは偶発的prefixヒット(0-42%)を含み470 tok/sはやや過大。**キャッシュなしの清浄な床値=443 tok/s**。
- 14BのKV制約はmax-model-len 4096でも緩まない(プールでなく上限を絞るだけ)。残る手=fp8 KV量子化・tp2・8B採用。
- ulimit(既定1024)が高並行測定を静かに壊す罠→ドライバに対策済み(引き継ぎ事項)。

## 第3段の結論(2026-09-02・現実的prefix分布ほか)

1. **現実的階層prefix(セル32)は上界寄りに落ちた**: 720-761 tok/s=床値441の1.64-1.98倍・上界1,008の75-93%(c32基準)。床値と上界は第2段と独立に再現(441 vs 443・1,008 vs 1,032)し、ヒット率も理論一致(d2=53.3%完全一致)。**「支配変数はprefix共有率」の結論は現実的分布でも生存**。
2. **効くのは種別層までの共有**: セル数の感度は弱く(8→512で-8%)、セル128超ではセル節を足しても種別止まりと同等(KVプール82.9k tokに載りきらずLRU追い出しの定常状態)。**Zipf混雑(現実の渋谷型)は一様より+6-8%**=一様値は保守側。
3. **DP7線形性はフル負荷実測で100.2-100.4%**(合算5,336 tok/s@o128/c128)。**NUMAアフィニティ効果ゼロ(±0.3%)**=系はprefill律速でCPU律速でない(tasksetによるCPU束縛のみ・membind未実施)。
4. **並行度の膝はc=64/GPU**(KV使用率0.58・スループット最適)。c128でKV1.00に張り付きTTFTのみ悪化→**bounded queue上限=64 in-flight/GPUが実測推奨値**。
5. **ngram投機的デコードは全8点で-23〜-30%の損**(prefill律速でデコード帯域の余りがないため棄却分が純損)。この負荷形状では不採用。ドラフトモデル方式は未測定。
6. **32B AWQ TP4は4枚で264 tok/s=14B INT8の1枚(317)以下・8Bの1/10/GPU**(NVLinkなしPCIe Gen3のTP通信が支配・KVは潤沢)。**この実機でT2に32B級はthroughput上不成立**(品質差の判定は品質プローブへ・TP2×2レプリカは未測定)。

## 第4段の結論(2026-09-03・BN-1/2/2C)

1. **セル数は律速でない**: o128/c64一様でセル32/139/556=854/814/820 tok/s(再現幅±2-4%内で平坦)。Zipfは小幅改善(139セル: 6.36→6.55→6.72呼/s・ヒット55→58→62%)。膝はc64のまま(c128は−7-8%)。第3段のアンカー条件(セル32・c64)を再測=854 vs 846(+1.0%)=接続良好。
2. **共有長に崖はなく、個体長に崖がある**: 共有600→1400tokで−12.5%(−1.6%/100tok・ヒット率は44.7→67.9%に上昇)。**個体末尾300→800で−40.6%(−8.1%/100tok)**。同じ1,300tokでも「共有1000+個体300」=8.64呼/s vs「共有800+個体500」=6.98=**個体から共有へ200tok移すだけで+23.8%**。
3. **崖の正体=セル節長(BN-2C)**: 139セルでB_cell 200/500/800=6.81/5.32/4.05呼/s(−22%・−24%)・ヒット率は59.4→48.8%へ低下=**セル節は共有でなく個体トークンと同じ値段になっている**。機構=KV容量82,912tokに対し(種別10×セル数N×B_cell)の常駐上限はN≈41/16/10(B_cell 200/500/800)・生存リクエストだけで96,000tok(c64×1,500)=容量超過→**実効セル上界は10-40セル・100m格子139は既に圏外**(だからセルを縮めても効かない)。B_cell=500ではセル数掃引が平坦(32/139/556=5.61/5.32/5.25)。
4. **DP7線形**: o128=6,078 tok/s・47.48呼/s(単GPU×7の99.6-103.5%)/o64=3,952 tok/s・61.74呼/s(97.9%)。
5. **W1判定**: B_cell=200なら400万呼=**23.4h(o128)/18.0h(o64)=予算内**。**契約書サイズのB_cell=500では29.8h=W1を24%超過**。回復レバー実測: 個体末尾500→300で+27.4%・o128→o64で+37.6%(B_cell=200でのみ測定)・Zipf1.5で+5.6%。
6. 未測定(正直): B_cell=500でのo64/c128/Zipf1.5・B_cell=800のセル掃引・契約サイズでのDP7・**種別に依存しないセル節**(機構が示す最強の緩和策)・セル単位の時間バッチ・fp8 KV・14B/32B・品質。

## 第5段の結論(2026-09-04・BN-4/BN-5)

1. **BN-4 セルアフィニティ=不採用**: 機構は実在(GPUあたりセル数100→20・ヒット率+4-9pt)だが上限が小さく(完全均衡でB_cell=200: +5.4%/500: +10.0%)、**Zipf不均衡(群重み最大/平均1.875)のコストが常に上回る**(実負荷: −44%/−32%・上位3複製: −17%/−2%・上位20複製@500: +4%)。損益分岐は負荷係数1.054/1.10未満=実装可能な割当では届かない。**方法論の収穫: 不均衡な艦隊では「クライアント合算スループット」は罠**(合算6,091 vs 壁時計3,225)→matrix5.csvに壁時計列を追加・以後の不均衡比較はwall列を使う。
2. **BN-5 ブロック順序**: 「全体→セル→種別」(種別非依存セル節)はセル節500では+4-5%(o128: 35.5→37.0呼/s・o64: 45.1→47.3)だが、**B_cell=200では−7%・契約書v1サイズでも−4%**(o128: 54.4→52.4)=素朴な木サイズ則は誤り。**ブロック順序は従来の[全体→種別→セル→個体]のまま**。
3. **BN-5 契約書サイズ(最大の効き目)**: v1(静的750+セル250+個体300=1,300tok)はv0(800+500+500=1,800)比で **o128: 36.1→54.4呼/s(+51%)・o64: 45.1→75.3呼/s(+67%)**・ヒット率64.6%・KV busy 0.40。
4. **W1判定(DP7実測・400万呼/シミュ日)**: **v1サイズ=o128で20.4h・o64で14.8h=予算内**。v0サイズ=o128で30.8h・o64で24.6h=超過。第4段の未測定点(セル500・o64)も埋まった(45.1呼/s)。
5. 未測定: 内容ハッシュによる群割当(rank mod 7は有利側)・B_cell 250-500の中間・556セル・上位20複製@200・定常負荷での不均衡ペナルティ(早く捌けたGPUが機械を独占できる分だけ過小)。
