## §2 3-2-5(語彙 v3 の「ひと言」欄)

### 2-1 事実

- 語彙 v3 の厳密形 `TWO_LINE_RE_V3`(`llm/contract.py:879-883`)は「理由/行動/対象/活動/まで」の 5 ラベルで、「ひと言」が無い。v1/v2 の `TWO_LINE_RE`(`:865-868`)には「ひと言: <20 字>」がある。B0 の出力規約(描画、§3)にも無い。mock v3 は「ひと言」を出さない(二層の実装アジェンダ §8 の表)。
- パーサは v3 でも「ひと言」を受け取る。`parse_two_line(..., "v3")` に「ひと言: …」付きの応答を入れると `comment` に入り、`format_ok`・`strict_format_ok` とも True になった(手元で確認)。D-116 の実装アジェンダ §1-2 に「受理はする=別名表に残す・会話プロトコル側で使う」とある。
- 受け手側の配管は一部ある。`engine/systems/llm_io.py:28-55` の `utter` は `comment` を ① `conv.utterance`(受け取って使わない)② 記憶の要旨(空なら理由欄の先頭 40 字=第294 のつなぎ)③ 口コミの抽出(`wom_source=utterance` は v3 でも `comment` を読む=`engine/wom.py:77-82`)に渡す。無いのは、プロンプトで書かせる欄と、相手の次の入力に載せる描画(`renderer.py` に受け渡しが無く、相手に渡るのは定型文 `templates.py:722`)と、発話の届け先の行(10-03 §10-2-1)。

### 2-2 いつ、なぜ消えたか

- **決定**: D-116 B(出力形 v3)。[二層の草案](../../design/v2-action-activity-two-layer-draft.md) §4-2・§5 を、ユーザーが 09-27 に「A〜I 推奨どおり」で決めた。
- **実装**: #46(第275・09-27)で契約表・パーサ・B0 文面が v3 になり、ライブラリの既定は v1 のまま。#48(第277・09-27)で CLI の既定が v3 になった(`cli.py:102`)。
- **根拠**(草案 §4-2 の原文): 「**『ひと言』は会話プロトコルの側へ**(会話中だけ出す=第262 ④『ひと言は届かない』の整理。B0 の tok は ±0 の見込み・要計測)」。第262([llm-calls](../../bench/analysis/llm-calls-2026-09-24/README.md) §0 の 3・4)は、ひと言が `conv.utterance` に渡るのに関数の中で使われず、相手の観測にも載らないと報告していた。毎回書かせても届かない欄を外し、空いた分で「活動・まで」を足し、会話の側で出し直すつもりだった。ところが会話の側は作られなかった。
- その後: 第294(記憶 第 1 段)で会話の要旨が空になることが分かり、Q57 が立った。09-30 に **Q57 = (d)「会話の番のときだけ 40 字程度の『ひと言』を出させる・会話以外の書式は v3 のまま・中身を誘導しない・書式の順守率は実 LLM で(GPU 後)」** と決まった。10-03 §6 ⑤ が「会話が起きていないことを最優先で直す」を要件の改訂にし、関わる作業に Q57 (d) を挙げた。§10-2-1 は「発話の届け先の行を Q57 (d) のアジェンダの必須項目にする」と決めた。
- **10-12 の計画での位置**: Q57 (d) を名指しした段は無い(計画・指示書 10-12・PENDING を grep して 0 件)。一方で、これに依存する段は多い。道具の草案の C0 は「前提: Q57 (d) のひと言と届け先の行」と書いているが、計画の 1-7(C0)は前提に挙げていない。カレンダーの草案の段 2、TM3(発言の長さ=モーラ数×話す速さ)、MR2 の問い 4(会話中は相手の直前の発言を手がかりに)、MR の M5(発話の見えない ID)、口コミの抽出も、本文があることを前提にしている。

### 2-3 必ず戻すための案(10 行・親の判断用・未リサーチ(expedient)の部分あり)

1. **段を名指しで置く**: 「1-8b 発話の口(Q57 (d))」を第 1 期に足す。◎(腕 `--utterance on`・既定 off)、乗るのは 1-3(出来事の記録)と 1-8(J0)。1-7(C0)の前提にも書き足す。
