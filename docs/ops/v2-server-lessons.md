## 2. 計器の穴 — 回す前に決めきる

実機のランは**やり直しが高い**(5,000 体 1 腕 30〜37 分・39 万体 1 日 9 時間)。だから「測り忘れ」の代償が大きい。実際に起きた 4 件。

| 穴 | 何が起きたか | 実装時の規則 |
|---|---|---|
| **実現量が無かった** | 腕の比較が「購入を**選んだ**呼 ÷ 応答した呼」しかなく、世界で実際に何が起きたかが出せなかった。食事は選択の 43% しか成立していない(AB7c)。実現欄は第245 で追加 | 腕の設計に **①実現量/体/日 ②実現/呼 ③実現/選択(成立率) ④費用** の 4 段を必ず置く。分子は**エンジンの計数**から取る |
| **テープに個体ブロックが無い** | `SHARED_BLOCK_IDS` は B0〜B4b だけ。B5(個体)B6(直前の結果)が intern されないので、**テープから場面を再現して問い直せない**(D-32)。D-91 の診断で「食事の失敗理由別の次手」が出せなかった | 記録の設計時に「**この記録だけで後から何を問えるか**」を書く。再問い(オフライン評価)を将来やるなら、個体ブロックか本文 SHA を最初から列に入れる |
| **抑止の内訳が無い** | 診断は deferred/promoted/degraded/suppressed の 4 本の合計だけ。無制限腕で「抑止 20.9 万」が出たが、就寝・域外・不応期の**どれが効いたか分けられない**(第246) | カウンタは**理由ごとに分ける**。合計は後から足せるが、分解は後からできない |
| **runner が n_boarded を持っていなかった** | `RunResult` には在ったが runner の出力欄に無く、第235 の D-91 診断で「実現乗車は未測」と書く羽目になった | 新しい欄を `RunResult` に足したら、**同じコミットで runner の出力にも通す**(欄の追加は列追加のみ=過去の JSON は不変) |

**実装時の 1 行ルール**: 腕・機能を作るときは「この腕の結論は**どの JSON のどの欄**を見て書くか」を先に書く。書けないなら計器が足りない。

## 3. 律速は規模で入れ替わる

| 規模 | 1 tick の壁時計 | 内訳 | 律速 |
|---|---|---|---|
| 5,000 体(C8 の腕) | **1.23 s**(1,440 tick=29.5 分) | — | **エンジン**。呼数を 2.09 倍(36,906→77,303)にしても壁時計は **1.24 倍**(29.5→37 分)にしかならない(第246) |
| 390,067 体(C7 本番) | **22.9 s**(9 時間台) | `fleet_wait` 19.37 s(**84%**)・llm 2.22 s・arbiter 0.50 s・phase_c 0.22 s | **艦隊**。実処理量 78 応答/s(11.2/s/GPU) |

**実装時に効くこと**
- 小規模で測った「1 tick あたり◯ ms」は**大規模の予算に外挿できない**。P2(エンジン)の最適化は 5,000 体では効くが 39 万体では 16% の部分を削るだけ。
- 逆に、5,000 体の腕では**呼数を増やしても時間はほとんど増えない**。無制限の腕を「高くつく」と見積もって避けたのは誤りだった(表の見積りは 1 ラン=呼 50,000 の規約のままで、実費と合っていない)。
- `fleet_wait_s` を 0 にすると応答が全部ラン終端に集まる(エンジンが LLM より桁違いに速いため)。本番は 120。**この値は「tick の歩調を艦隊に合わせる」もので、性能パラメータではない**。

### 繰り延べの真因(2 回間違えた)
- C7 本番で呼の **33.8%(132 万)**が繰り延べ。毎時 107,520=**1,792/tick で 24 時間平坦**(深夜も同数)。
- 1,792 = 艦隊の `queue_capacity` = `max_in_flight`(64/GPU×7=448)× 4。**GPU の容量不足ではなく受理待ち枠の不足**だった(D-55)。
- 枠を上げた c7-day-3 では繰り延べ **0.5%**(14,423)に落ちた。
- **実装時の規則**: 「詰まった」と見たら、まず**どの待ち行列で詰まったか**を数える欄があるか確かめる。無ければ足す。GPU 使用率だけ見ても分からない。

## 4. 予算・上限が結果を作る(最大の発見)

同構成で L4 の呼数上限だけを振った AB8(第247・[親報告](../bench/c8/ablation/ab8_s1_parent_report.md)):

| L4 | 呼/体/日 | 実現購入/体/日 | 売上 円/体 | 実現乗車 | 購入シェア(選択) | 会話 |
|---|---|---|---|---|---|---|
| ×0.5 | 3.97 | 0.78 | 630 | 465 | 50.3% | 0 |
| ×1(現行) | 7.38 | 1.32 | 1,098 | 648 | 43.8% | 3 |
| ×2 | 12.24 | 1.84 | 1,554 | 530 | 37.9% | 18 |
| 無制限 | 15.46 | 1.92 | 1,632 | 407 | 36.4% | 31 |

- 実現購入は**予算にほぼ比例**して増え、×2 で飽和。現行は飽和点の 69%。
- **乗車は逆に減る**(648→407)。呼が増えるほど「乗る」以外の選択が予定を上書きする。
- 購入シェア(選択の %)が 50→36% と動くのは**分母の変化**。増えた呼はセル起床・個体起床で、そこでは購入が 33〜38%(計画境界は 41〜49%)。
- 上限を外しても **15.5 呼/体/日で止まる**。抑止の大半は予算ではなく就寝・域外・不応期。

**実装時に効くこと**
1. **上限・予算は「安全弁」ではなく実験条件**。宣言した上限には、expedient と同じ「結果を駆動していない」検査を課す。
2. **選択の % を腕間で比べない**。起床の構成が変われば分母が変わる。比べるなら実現量/体/日。
3. 上限を変える切替口は**最初から作っておく**(`--l4-scale` は第245 まで存在せず、そのせいで感度試験が 1 度も回せなかった)。決定論を壊さないため `inf` は入れず有限値(体数)を置く。
4. 上限ありで測った過去の効果量には**「予算の影 ±0.5 pp」**が乗っている(AB6b の看板効果 +0.3〜0.6 pp は無制限ではゼロになった・第246)。

## 5. mock と実 LLM で違うもの

### 実 LLM でしか出ないもの
| 現象 | 実測 | 実装時にどうするか |
|---|---|---|
| **書式エラー** | 初回応答の失敗 **18.4%**(153/833・温度 0.7)→ 再生成で実効 0.040。別の回は初回失敗 30%・内訳は `missing_label:対象` 226 件=**モデルがラベルを省いて値だけ並べる** | パーサは「別名・位置読み・段0 辞書」の 3 段を持つ。**実効と厳密の 2 つの率**を必ず両方出す(実効だけ見るとモデルの順守率を見失う) |
| **会話がほぼ出ない** | mock 1 日 401 セッション vs 実 LLM **0〜8 呼**(50,000 呼中)。5,000 体で会話 0.02% | 会話のような「相互作用の成立」は mock の数字を信じない。実 LLM で 0 になる前提で設計する |
| **行動の偏り** | 実 LLM 1 日: 購入 49%・移動 39%。モデル側の選好 | 分布の期待値を mock で作らない |
| **役割語が出ない** | 補充・開閉店の役割行動がほぼ 0(D-38)。一方で**通報が 6,426 回**(顕著行為 228 の 28 倍) | 語彙に入れた語が使われるかは実機まで分からない。**使用率を計器に入れる**(`action_usage`) |
| **テンプレの説明語が写る** | 対象欄に「物のカテゴリ」9,055 呼・「セルID」398 呼(C9b スモーク) | 欄の説明を**例示の形で書かない**。書くなら実機で写りを測る |
| **few-shot の具体値が写る** | W17 v2 で例示の時刻を **47% の体がそのまま写した** | 例示は**その体の事実から生成**する。分布を見るとき最頻値=例示値を最初に疑う |

### mock でしか守れないもの
- **既定バイト不変**(checkpoint `ba01bd0b`)。切替口を足したら mock で必ず確認する。実 LLM では確認できない。
- **腕の分類**: プロンプト本文しか変えない腕(①⑥⑥b⑥c⑦⑦b⑦d①b)は **mock では差が出ない**(`mock_effective: false`)。この腕のテストは「切替口が値を運ぶか」までしか守れない。予算を振る腕(⑧)は mock でも動く。

### 決定論(2 回結論が変わった)
- C7 本番(39 万体)では繰り延べが**時刻依存**なので同 seed の再ランは一致しない(D-54)。
- しかし **5,000 体・`fleet_wait_s 120`・繰り延べ 0 なら bit 一致する**。AB8 の `l4_x1` は、別のコード版で 2 日前に回した AB6b seed 1 の基準腕と **final_hash まで一致**した(第247)。
- **実装時の規則**: 決定論の主張は**「どの規模・どの設定で」**を必ず添える。テープ再生(`--replay`)は繰り延べ行を含めて設計する(テープ版 2)。

## 6. LLM が書いた資産・LLM が読む文面

- **取り込みゲートは資産単体の形しか見ない**。W17 v2 は parse・被覆・深夜違反・就寝行のゲートを全部通ったのに、エンジンの読み口が域外居住者の自宅側の行を舞台の中と読み、出入りが **2.01 本/日**になった。露呈したのは**モック 5,000 体で 1 日回して物差しを見たとき**。
- **語彙の曖昧さが効く**。W17 の場所語 12 語に域内/域外が無いので、域外居住者が自宅側の駅を「駅」と書く(D-69)。語を 1 つ足すだけで行動分布が動く(語彙 v2 で「食事」を足したら乗車が 48% 減った=同じ呼の中の選択率の変化)。
- **静的文の 1 語が腕の差になる**。AB7c の 2 腕の差は静的ブロックの「/ 食事」1 語(603→606 tok)だけだった。
- **実装時の規則**: (1) 新資産・再生成資産は**仮の世界ディレクトリに差し替えてモック 5,000×1,440 tick**を回し、前の資産と同じ物差しで比べる。(2) 文面を変えたら版を上げ、凍結 SHA を更新し、旧版を切替口で残す。(3) 「語を足すだけ」は**分布を動かす変更**として扱う。

## 7. 配備 — 「コードを置けば動く」ではない

09-22 に実際に踏んだ順で書く。

1. **`src/` は `docs/` を実行時に読む**。`core/budget.py` が `docs/design/v2-budget-declaration.md` を探して落ちる。実行に要る docs は少なくとも `docs/design/`・`docs/bench/anchors/`・`docs/bench/pt_shibuya/`・`docs/ops/build-report-C3.md`。
   → **実装時**: 設計書を実行時に読む口を作るときは、その依存を**配備物の定義に書く**(環境変数 `SHIBUYA_BUDGET_MD` のような逃げ道も用意されている)。
2. **世界データは共有する**(9.3 GB)。コード版を増やすたびに複製しない。`ln -s ~/v2/data ~/v2_XXX/data`。
3. **Python は 3.10 しか無かった**(`pyproject` は >=3.12)。3.10 の venv+3.10 対応依存で動かした(U-8・expedient)。
   → **実装時**: 新しい構文・新しい標準ライブラリ機能を使うときは、**実行環境の版**を確かめる。
4. **tmux の環境変数は `export` が伝わらない**(tmux サーバーが先に起動しているため)。コマンド文字列にインラインで渡す。vLLM は `CUDA_HOME=<venv>/…/nvidia/cu13`・`PATH`・`VLLM_BATCH_INVARIANT=1`・`VLLM_USE_FLASHINFER_SAMPLER=0` が要る。
5. **`nohup … &` は ssh セッションが戻らない**。常駐ジョブは `tmux new-window -d -t c5 -n <名前> "bash script.sh"`。
6. **同期と起動は別コマンドにする**(1 本にまとめると分類器に拒否される・09-16 の実測)。
7. **`pkill -f <pattern>` を ssh 越しに撃つと自分を殺す**(コマンド文字列自身がパターンに一致する)。止めるのは `tmux kill-window`。
8. **Git Bash の `/usr/bin/ssh` は Host エイリアスを解決できないことがある** → Windows OpenSSH(`/c/Windows/System32/OpenSSH/ssh.exe`)を直接呼ぶ。
9. **サーバー上の古いスクリプトを使わない**。`~/c5/fleet_gen.py` の古い版が構造化出力(regex)を送らず、3 腕ぶんの生成が **75〜81% length 切断**で無効になった(第156)。必ず配備したコード側(`~/v2/tools/gen/fleet_gen.py`)を使い、md5 で一致を確かめる。
10. **出力に絶対パスが入る**。回収したら `sed -E 's#/home/[a-z0-9_]+/#~/#g'` でマスクし、**grep のヒットでコミットを止める**(`|| true` で流して 4 ファイルを生のまま push した事故がある)。

## 8. 事故の型(3 回以上繰り返したもの)

| 型 | 実例 | 予防 |
|---|---|---|
| **scratch スクリプトの流用** | 入力パス固定・`argv[1]` が出力の集計器を流用し、**9.5 時間分の本番テープを上書きしかけた** | 流用前に `grep -n "argv\|open(.*\"w\"" script.py`。既存成果物のパスを引数に渡さない。出力先は必ず新規名 |
| **出力ディレクトリの取り違え** | 同じ腕を 2 回回して上書き | 起動スクリプトは**出力先が在れば拒否**する(`if [ -e "$OUT" ]; then exit 1; fi`)。全部の起動スクリプトに入れてある |
| **サブの完了報告を信じる** | 「無い」と報告されたものが別の場所に在った(生 GML・第219) | ディスク実在+親自身の pytest で検収。「無い」は親が別の場所を探す |
| **マスク確認を流す** | `|| true` で grep を流して生パスを push | ヒットで `exit 1` |
| **CRLF** | 作業木 CRLF・index LF で patch が当たらない | 台帳スクリプトは読み込み時に `\r\n`→`\n` 正規化してから編集 |
