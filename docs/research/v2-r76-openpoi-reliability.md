## 結論(5 行)

1. **運営者の名前は公開されていない(空欄)**。利用規約は「本サービスの運営者」とだけ書く。ドメインは **2026-09-21 に登録**され、登録者は代理公開サービスの名前で隠れている。公開は Qiita の記事によれば **2026-10-01** である。ドキュメントは GitHub の `naogify/geosearch-poi` の issue を引いており、このアカウントは Geolonia に所属する個人のものである。ただしリポジトリは現在 404 で、運営者と同じ人かどうかは**推測にとどまる**。規約には「予告なく一時停止・終了することがあります」とあり、料金と準拠法の記載はない。
2. **出どころは 2 つあり、どちらにも癖がある**。OpenPOI は Overture Places を版 **2026-08-19.0 に固定**し、その座標をそのまま使っている。この版には、無関係な POI が同じ座標に積み重なる不具合が報告されている(Overture issue #563。日本で 10 件以上が重なる座標が 756 か所、21,355 件 = 0.74%)。Overture 自身も、重複とゴミが多く属性が欠けていると認めている。食品の営業許可(JFF)のほうは廃業した施設も残し、1 件が 1 つの許可を表すので施設の数とは一致しない。OpenPOI のカテゴリは **54.6% が unknown** である(OpenPOI 自身の実測)。
3. **渋谷区の食品の部分の元データは、渋谷区自身のオープンデータである**。CC BY 4.0 で 39,304 件あり、`営業ステータス`・`廃業日`・`施設所在地_方書` の列を持つが、OpenPOI を通すとこれらの列は返らない。**席数の列は、渋谷区のデータにも OpenPOI にも無い**。
4. **席数(D-94)**: ホットペッパーの API は店ごとに `capacity`(総席数)を返す。しかしリクルートの規約は、キャッシュを 24 時間以内に更新する義務(第 5)、取得した情報を第三者のデータベースへ複製保存することの禁止(第 8)、加工・変更の禁止(第 2)を定めている。そのため、**席数を固定した台帳を作ると規約と衝突するおそれが大きい**(親の判断待ち。法的助言ではない)。ぐるなびの無料 API は 2021 年に終わった(二次情報)。指示書 §8 3-6 の「面積×業態ごとの席の密度で生成し、宣言と感度試験をする」を既定のまま残すことを勧める。
5. **置き場所(親の案・未リサーチ)**: OpenPOI は**照合の側の候補**に置き、入力には使わない。ただし二次加工の資料なので、照合の根拠としては弱い。理由は 3 つある。(i) 出どころが二次加工で、版と結合の規則が公開されていない。(ii) 中に渋谷区の営業許可が入っているので、OpenPOI を入力に使うと渋谷区の営業許可を照合に使えなくなる。(iii) 経済センサスはすでに組織の生成の較正に使っている。照合の主役は、ユーザーが歩いて確かめる店にする。OpenPOI・OSM・センサスは、その標本を引く枠と、件数の桁の確認に使う。

## §2 出どころと鮮度(調べること 2)

### 2-1 OpenPOI が書いていること

- 件数: **3,372,487**(Overture 約 249 万+JFF 約 88 万)(#4)。
- Overture は「リリース単位で、現在は 2026-08-19.0 に固定」。JFF は「毎週(月曜 4:00 JST)に再構築」(#1・#4)。
- 結合: 「名寄せ(正規化・重複排除)」と「緯度経度の統合」をする。統合した施設の `licenses`・`attributions` は和集合で、`source` は代表レコードの 1 つだけ(#1・#3)。検索結果の抜粋では、名寄せの点数は「bigram Dice(名称・住所)+Haversine 距離+電話番号一致の重み付け」(#9・△)。**重みと閾値は空欄**。
- **Overture の取り込み条件(confidence の閾値・operating_status の扱い・カテゴリの絞り込み)は書かれていない(空欄)**(#1)。
- 返す欄: `name`・`name_kana`・`prefecture`・`city`・`address`・`category`・`business_type`(category と同じ値)・`lat`・`lng`・`level`(1/2/3/8 = 都道府県/市区町村/町丁目/街区)・`source`・`licenses`・`attributions`。**席数・営業時間・階・建物・鮮度・閉業の欄は無い**(階は住所の文字列に「1F」などで入ることがあるだけ)(#1)。
- 既知の制約(#1 の要約): category/business_type の多くが unknown(「1,840,570件 / 全3,372,487件 ≈ 54.6%」)。Overture の座標をそのまま使うので、観光地・駅・公園の名のレコードで「数 km から数百 km ずれる例」(issue #236)。JFF は住所から位置を付けるので、同じ建物の店は同じ座標。閉業した施設が残ることがある(issue #237)。ランドマーク自体は入っていない。網羅性は元データ次第。

### 2-2 Overture Maps Places(元データ)

- 件数と出どころ(2026 年 9 月時点・全世界): 約 8,100 万件のうち Meta が約 5,900 万。meta 58,783,121 / BrightQuery 10,255,071 / Microsoft 6,135,466 / Foursquare 4,138,835 / AllThePlaces 1,809,219 ほか。「It contains no OpenStreetMap data」(#11)。
- `confidence`: 「a value between 0 and 1 representing the likelihood that the place exists」。存在だけを表し、`operating_status` とは独立。固定の推奨閾値は無く、「relative filtering tool」として使う。提供元どうしで較正されていない(#11)。使われている閾値の例は `0.9`(書店の地図・#21)や `> .95`(Overture の例のクエリ・#11)。
- 結合(conflation): 機械学習の照合とクラスタリング。「a single source is promoted rather than combining attributes」で、属性は混ぜない。2026 年 7 月のリリースでパイプラインを大きく更新した(#11)。
- リリース: 「monthly」。分類表は四半期ごと(#11)。日本の分の最新は少なくとも **2026-09-23.1** まで出ている(queria の行数の注記・#20)。**OpenPOI は 2 版前の 2026-08-19.0 に固定している**。
- 既知の品質課題(Overture 自身): 「Places is known to contain duplicates, a high junk rate, and low property completeness.」confidence は「does not address duplicates or property completeness」(#11)。
- **2026-08-19.0 の座標の不具合**(#12・Open・2026-09-06): 無関係な POI がビット単位で同じ座標に積み重なる。皇居の中の 1 点(35.6833, 139.75)に 71 件(61 の異なる住所・9 区)。日本の範囲では、10 件以上が重なる座標が **756**、該当する POI が **21,355 件(全 2,866,662 件の 0.74%)**。50 件以上の座標 107 のうち 91 は小数 4 桁以下の「丸めた座標」。提供元別では meta が 20,856。前の版 2026-07-22.0 にも同じ 2 座標に 80 件・20 件ある。報告者は「The addresses are largely correct. Only the geometry is gone.」と書いている。**OpenPOI は Overture の座標を「そのまま」使うので、この不具合を受け継ぐ見込みが高い**(推測)。
- operating_status: 「ほとんどのレコードで空です。閉店した施設を除く用途には使えません」(#20)。
- ライセンス: Meta・Microsoft ほかは CDLA-Permissive-2.0、Foursquare は Apache-2.0(NOTICE を開発者向け文書に掲げる)、AllThePlaces は CC0-1.0(#3・#11)。

### 2-3 Japan Food Facilities(JFF)と渋谷区の元データ

- JFF の README(2026-09-28): 施設レコード **1,359,867 件**・座標つき 1,201,498 件・1,731/1,741 市区町村(同じ README の別の欄は 1,727 で数が合わない)。毎週月曜 18:00 UTC に自動更新。コードは MIT、データは各元データのライセンスに従う。「廃業済みや許可期限切れの施設が含まれる場合がある」。提供条件は「予告なく変更または終了する場合があります」(#14)。
- DATA.md: 「1レコードは、原則として1件の営業許可または届出を表します」=**レコード数は施設数ではない**(1 つの施設が業種ごとに複数行)。レコードの重複除去はしない。名前が一致し 50 m 以内の座標を 1 点にそろえる。`geocoding_level` 1・2 の座標は除く。空欄は元データの座標をそのまま使ったことを表す(#15)。

### 4-2 件数の突き合わせの手順(案)

1. **空間の単位をそろえる**: OSM の bbox と町丁目は形が違う。比べる単位は **13 町丁目の面**にする。OSM・OpenPOI の点を町丁目の境界に落として数える。bbox の外の町丁目、町丁目の外の bbox の部分は比べない。
2. **業種の対応表**を先に固定する(推測を含むので台帳に 1 行ずつ):
   - 飲食: センサス中分類 76(+77)↔ OSM `food`(+`nightlife` の飲食の部分)↔ OpenPOI `category = restaurant` ほか飲食系 ↔ 渋谷区の許可の `業態`(飲食店営業)。
   - 小売: 56〜60 ↔ OSM `shop` ↔ OpenPOI `retail_*`。
   - OpenPOI の `unknown`(全国 54.6%)は**別の列で数え、どちらにも入れない**。
3. **単位の違いを先に書いておく**: センサスは「事業所」(1 棟に数十。店を持たない事務所も入る)。JFF は「許可 1 件」(1 施設に複数)。Overture は「場所」(重複がある)。OSM は「書いた人がいる場所」。比が 1 に近いことを合格とはしない。**比べるのは町丁目ごとの順位の相関と、比の町丁目ごとのばらつき**(フロア併記の規律。実データ同士のばらつきを並べる)。
4. **重なりの除去**: OpenPOI の結果から、(i) 同じ座標に 10 件以上が乗る点(issue #563 の基準)、(ii) `level` が 1・2・3(都道府県・市区町村・町丁目の代表点)の点を、別の列として除く。同じ建物で同じ座標の JFF 由来の点は、建物ごとに 1 つに数える列も作る。
5. **時点**: センサス 2021-06・OSM 2025-04・Overture 2026-08・JFF 毎週、と時点が違う。差には閉店と開店が混じる。時点の差を説明できる量(閉店率)は外から得られていない(空欄)ので、件数の差を「誤り」とは呼ばない。

### 4-3 現地で確かめる店の抽出(案)

- **標本の枠**: 小さな区域(例: 宇田川町と神南一丁目の 2 町丁目・推測)で、OSM・OpenPOI・渋谷区の許可(営業中)の 3 つを名前と距離(例: 50 m・JFF の座標をそろえる距離 #15 に合わせる)で突き合わせる。その結果を「3 つすべてにある/2 つにある/1 つだけにある」の層に分ける。
- **層ごとに無作為抽出**: 割合 p を ±10 ポイント(95%)で推定するのに要る数は n = 1.96² × 0.5 × 0.5 / 0.1² ≈ **96**(標準の式の計算・p = 0.5 の最悪の場合)。層ごとに 96 は多いので、まずは「1 つだけにある」層を厚く(各 30〜50・推測)取る。
- **ユーザーが記録する欄**(歩いて分かるものだけ): 店はあるか(ある/閉店/別の店)・入口のある建物(地図上で指す)・階(看板で分かれば)・業種(見た目)・日付。写真は撮らない(人物が写るため。親の案)。
- **結果の使い道**: 出典ごとに「実在率」「閉店の残存率」「位置が建物 1 つ以上ずれる率」を出す。どれを入力に使うかの判断に使う。

### 4-4 「照合に使うデータ」と「入力に使うデータ」の分け方(案)

- 置き場所: 既存の `data/ground_truth/registry.yaml` の `split`(`calibration` / `holdout` / `diagnostic`)の考え方を、POI の出典にも当てはめる。出典ごとに `role: input | verify | diagnostic` を 1 つだけ持たせ、同じ出典を両方に置かない。
- **漏れの経路**(先に全部挙げる):
  1. OpenPOI の中の JFF は渋谷区の許可そのもの → OpenPOI を入力にすると、渋谷区の許可は照合に使えない。
  2. OpenPOI と OSM はどちらにも Overture 以前の同じ元(店の Web・利用者の登録)が入りうる(推測)→ 独立の照合とは言い切れない。
  3. 経済センサスは組織の生成の較正に使用中 → 事業所の数の照合には使えない(`calibration`)。店の層の件数を見るのは `diagnostic`(合否にしない)に置く。
  4. ユーザーの現地確認だけが、どの入力からも独立した `holdout` になる。
- holdout の扱い: 現地確認の標本は、最初に無作為に 2 つに分ける(較正に使う半分・触らない半分)。触らない半分の結果は、入力の作り方を決め終えるまで開かない。

|---|---|---|---|---|
| **A 入力** | OSM W6 の店の層に、OpenPOI の店を足す(または置き換える) | 現地確認(§4-3)で、OpenPOI の実在率が OSM 以上と出ること。D-W7(店名は架空)と R-60 の名前の層の決定 | 個人の店が増える(OSM に無い店・#31 の動機と同じ) | 渋谷区の許可を照合に使えなくなる(§4-4 ①)。版固定の座標の不具合(#12)・unknown 54.6%・階なし。OSM と混ぜると ODbL がかかるおそれ |
| **B 照合(診断)** | 入力は OSM のまま。OpenPOI は「OSM に無い店の候補の一覧」と件数の桁の確認に使い、`diagnostic` に置く | 合否には使わない(独立性が弱いため・§4-4 ②) | 入力を変えずに、OSM の取りこぼしの大きさが分かる | 二次加工物なので、照合の物差しとしては弱い |
| **C 使わない** | 一次の出どころを直接取る(Overture の版を選んで confidence で絞る・渋谷区の許可の CSV) | 取得先のドメインの許可(下)。Overture の取り込みは DuckDB などの道具が要る | 版・閾値・列(廃業日・方書・許可条件)を自分で選べる。結合の規則がブラックボックスでない | 手間が増える。OpenPOI の名寄せの成果は使えない |

**親の案**: **B を既定にし、C の「渋谷区の許可を直接取る」を足す**。理由は §0 の結論 5 のとおり。A は現地確認の結果を見てから決める。なお、渋谷区の許可の取得先(`city-shibuya-data.opendata.arcgis.com`)も Overture の配布元も、CLAUDE.md §7 の許可の一覧に入っていない。取るならユーザーの承認が要る(先に聞く)。

### 7-2 空間の段 0 で OpenPOI を取るときの記録の形(案)

- **取り方**: `bbox` で取る。1 回 200 件が上限でページ送りが無いので、**返った件数が 200 なら bbox を 4 つに割って取り直す**(四分木)。全部の箱が 200 未満になったら終わる。間隔は 1 秒に 1 回(全体の上限 200 req/s を他の利用者と分け合うため・親の案)。応答は UTF-8 で読む。
- **保存**: 応答をそのまま JSONL で保存する(`licenses`・`attributions` を配列のまま。#1 の求め)。`data/realworld/openpoi/`(gitignore 下)に置く。
- **取得の記録(1 回ごとに 1 行)**: 取得日時(UTC)・API の URL と問い合わせ(bbox・q・limit)・応答の件数・ファイルの md5・ドキュメントの生成日時(#1 の版の代わり)・OpenPOI の Overture の版(`2026-08-19.0`)・規約の最終更新日(`2026-09-26`)・`role`(input/verify/diagnostic)。
- **ライセンス台帳の行**: 出典の列を「OpenPOI API(Overture Maps Foundation: CDLA-Permissive-2.0 / Foursquare: Apache-2.0+NOTICE / AllThePlaces: CC0-1.0 / JFF: CC BY 2.0〜4.0・PDL1.0・CC0)」とし、**件数を `source`・`licenses` の組ごとに数えて書く**。出典表示は「出典: OpenPOI API(https://openpoiapi.com/attribution.html)」。
- **取得の直後の検査**(取り込みの門・親の案): ① 同じ座標に 10 件以上が乗る点の数(#12)② `level` の分布 ③ `category = unknown` の率 ④ `source` の内訳 ⑤ bbox の外に落ちた点の数。
- **記録の検査**: 出力のファイルに絶対パスが入っていないことを grep で確かめ、ヒットしたら止める(メモリの規律)。

## §9 親への確認事項

1. Ballantyne & Berragan 2023 の表 1 の見出しは「Average distance」で、本文は「median distance」と書いている(原典の中の揺れ)。引くときはどちらかに決めず、両方を書く。
2. 渋谷区の許可の CSV と Overture の配布元(S3)は、許可の一覧(CLAUDE.md §7)の外にある。取る案(§7-1)は、ユーザーに先に聞く項目である。
3. ホットペッパーの規約の読み(§6-3)は親の読みで、法的助言ではない。D-94 を閉じるか、書面での問い合わせに進むかは、ユーザーの判断である。
