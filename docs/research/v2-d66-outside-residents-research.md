### 5-C 「登録通勤者のうち当日その職場に物理的に来る比率」【推定】

```
在宅率(平均的な平日) = (1)実施率 × (2)実施社員割合 × (平均テレワーク日数 ÷ 5)
  令和7年12月: 0.400 × 0.356 × (0.311×1 + 0.220×2 + 0.163×3 + 0.123×4 + 0.184×5)/5
             = 0.400 × 0.356 × (2.652/5) = 0.400 × 0.356 × 0.5304 = 0.0755
年休欠勤率  = 年間取得日数 12.1 日 ÷ 年間出勤可能日数 245 日 = 0.0494
  (245 = 365 − 土日 104 − 祝日 16。年間休日総数 112.4 日を使うなら 252.6 日 → 0.0479)
出勤率 = (1 − 0.0494) × (1 − 0.0755) = 0.9506 × 0.9245 ≈ 0.879
```

→ **推奨既定値 0.88(= 登録通勤者の 88% が当日、渋谷の勤務先セルに現れる)**。**タグ: expedient**。

**この推定の弱点(全部書く)**
1. **(1)(2) と (3) は母集団が違う**(企業への電話調査 vs 従業員へのインターネット調査)。掛け算は正当化されていない。
2. (1) は**企業数ベース**であって従業者数ベースではない。規模別に見ると 300 人以上の実施率は月により 29.8%〜71.4% と振れが大きく、従業者数で重み付けすると値が変わる。
3. **業種構成が渋谷と違う**。渋谷区の従業者 516,541 人のうち情報通信 94,485 人(18.3%)・サービス業(他に分類されない) 81,863 人(15.8%)(既存答申 `v2-population-synthesis-research.md` §2.5)。令和7年度の**業種別導入率は「学術研究,専門・技術サービス業」95.4% /「情報通信業」94.5%** と平均(64.0%)を大きく上回る → **渋谷は在宅率が都平均より高い方に振れる**。
4. 年休と在宅は独立でない(在宅日は出勤可能日に含まれる)。上式は独立と仮定している。
5. 病欠・出張・直行直帰を含んでいない → **0.88 は上界寄り**。
6. 通学者の出席率は**未確認**(§8-5)。

## §7 実装への含意(D-66 の到着・退出規則への写像)

### 7-A 到着(域外→域内)
- **入力にすべき形**: 週次表(W17)の**その日の最初の域内活動の開始時刻**から逆算して「間に合う便」を選ぶ、という D-66 の骨格は**そのままでよい**。時刻分布を**注入する必要はない**。理由: 現実側の到着分布(通勤降車 8 時台 48.4%・9 時台 17.2%)は、W17 の勤務開始時刻分布と所要時間から**結果として出る**べき量だから(方法論の「時間帯活動確率・OD 較正は借りない」)。
- **照合(検証)に使う**: §1-A の「通勤 降車」列(～6時台 2.60 / 7時台 24.97 / **8時台 48.37** / 9時台 17.22 / 10時台 2.63)と、§1-B の「通勤・通学」行動者率(7時 10.76 / **8時 13.21** / 9時 5.13)。**JSD で測る**。
- **現行の W17 較正カーブとの関係**: `v2-world-data-build-spec.md` §D-W14 は「PT 時間帯別表は未取得 → W12 の hour 重み(=`time_dist_12`)を較正カーブに使う= expedient・昇格条件= PT 時間帯別表の取得」と書いている。**§1-C の c-2 を取れば、この昇格条件がそのまま満たされる**。

### 7-B 退出(域内→域外)
- **退出時刻の形**: 「最後の域内活動の終了で世界が乗車を実行」= §1-C(a) の終業分布がそのまま出てくるはず。**照合先は 2 つ**: センサス「帰宅 乗車」(17時台 17.74 / **18時台 20.65** / 19時台 12.67)と、社会生活基本調査「通勤・通学」夕方正規化(17時 16.8 / **18時 19.8** / 19時 15.9)。**両者が一致しているので、どちらを holdout にしてもよい**(片方を較正・片方を検証に回せる = `v2-boundary-deep-research.md` 面1 の「片方は必ず残す」を満たせる)。
- **「帰宅」総量には使わない**: §1-A 注意 1(原表の脚注)により帰宅トリップは補完されていない=**帰宅の絶対量は過小**。**形だけ使う**こと。**これは新しい caveat なので `time_dist_12.json` の `_meta.caveats` へ追加すべき**(現行 6 項目に無いことを確認済み)。
- **終電の扱い**: 既存の実ダイヤ(`v2-c7-fix-research.md` #7: メトロ3線とも 1〜4 時台は 0 本・初発 5:01・終発 23:56 前後)と、帰宅乗車の 23時台 1.53% / 0時台～ 0.46% は整合。**0 時以降に「最後の活動」が終わる体は、退出できずに滞留する**——これは現実にも起きている現象なので、バグではなく**穴台帳(D-50)の一級の入力**にできる。
