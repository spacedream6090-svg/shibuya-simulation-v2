## 主張(claim)

X・Reddit 型の SNS を **最大 100 万体**の LLM エージェントで模擬する汎用基盤。情報伝播・群分極・herd 効果・誤情報拡散を再現し、**体数が増えるほど群動態が強まり意見が多様になる**。

**Table 2(§4.1「Analysis of Efficiency for One Million Users」・群分極の設定)**

| 規模 | 1M | 100K | 10K |
|---|---|---|---|
| **1 time step あたり時間(h)** | **18.0** | **3.0** | 0.2 |
| **GPU 数(A100)** | **27.0** | **5.0** | 2.0 |
| 新規 tweet / step(K) | 48.5 | 5.2 | 0.6 |

- **1M の数値は散文に無く、Table 2 だけに載っている。**§4.1 の散文でハードウェアに触れるのは 1 文のみ(逐語 ≤125 字): 「**For all scenarios, we use one A100 for RecSys and use multiple GPUs for LLM inference.**」→ **27 GPU のうち 1 枚は推薦系で、LLM 推論は 26 枚**という読みになる(著者は明示していない)。
- **100K は散文にある**(逐語 ≤125 字・§4.1): 「**For instance, using five A100 GPUs, we can simulate the interactions of 100,000 users over 10 time steps within two days.**」→ 10 step ÷ 2 日 = **1 step あたり 4.8 h** で、Table 2 の **3.0 h** と一致しない(「within two days」は上限表現なので矛盾ではないが、**散文と表で値が違う**)。**親の一次確認ではここを見ること。**
- **Table 3(付録 C.1・Reddit の herd 効果の反実仮想)**: 10k = 15 分/step・A100 4 枚 / 1k = 0.83 分/step・4 枚 / 100 = 0.33 分/step・4 枚(新規コメント 1393 / 129 / 14)。**Table 2 の 10K(0.2 h = 12 分・2 枚)と設定が違う**(場面もプラットフォームも別)。
- **モデル**(§3.2・逐語 ≤125 字): 「**Llama3-8b-instruct is used as the base LLM.**」推論は vLLM。付録 C.4 で Qwen1.5-7B-Chat・Internlm2-chat-20b も試行。GPT-4o-mini は**評価者としてのみ**。

## 効く箇所(seam)

- **D-70(計算費の比較表)の 3 例目**。**体あたり GPU 秒**に正規化する(サブ計算・Table 2 から):

| 規模 | 総 GPU·h | **体あたり GPU·s / step** | 体あたり投稿+コメント / step |
|---|---|---|---|
| 1M | 18.0 × 27 = **486** | **1.750** | 0.146 |
| 100K | 3.0 × 5 = **15** | **0.540** | 0.142 |
| 10K | 0.2 × 2 = **0.4** | **0.144** | 0.150 |
| **本 repo**(390,067 体 × 1 シミュ日) | 9.167 × 7 = **64.2** | **0.592 / シミュ日** | 6.94 呼/体/日 |

- **★ この表の最大の所見: OASIS は線形にスケールしていない。** 総費用は 10K→100K で **37.5 倍**、100K→1M で **32.4 倍** = **N^1.51〜1.57**。体あたり費用は 0.144 → 0.540 → 1.750 と **10 倍ごとに約 3.5 倍**に増える。
- **原因は体の活動量ではない**: 体あたりの投稿+コメント数は 0.142〜0.150 で**規模によらず一定**(Table 2 から計算)。増えているのは 1 呼あたりの値段=**環境 DB と推薦系(全投稿を順位づける)の側**。
- **本 repo の 0.592 GPU·s/体/シミュ日 は OASIS の 100K(0.540 GPU·s/体/step)とほぼ同額**。つまり **本 repo の「1 シミュ日」は OASIS の「1 step」と同じ値段で、体数は 3.9 倍**。
- ただし **step の定義が違う**(OASIS の 1 step ≠ 1 シミュ日)ので、厳密な比較には**呼あたりの正規化**が要る。OASIS の 1 step あたり呼数は本文から取れない(活性化確率 0.1/0.01 と行動数が要る)= **空欄**。
- **この repo にとっての含意**: 「100 万体は 27 GPU で届く」と読むのは誤り。**N^1.55 なら 40 万体 → 100 万体で総費用は 4.2 倍**(2.5^1.55)。ただし本 repo には推薦系が無く、知覚は**セル共有 prefix**で O(セル) に閉じているので、**同じ指数にはならない**はず——これが本 repo の設計上の賭け。**未検証**(本 repo は 5,000 / 390,067 の 2 点しか測っていない)。

- **時間エンジンの確率的活性化** = この repo の「起床条件」と同型(ただしこの repo は計画境界 + イベントで、確率ではない)。

## 「結論でなく機構として」の入れ方

- **借りない**: SNS のドメイン(RecSys・21 行動・フィード)。この repo は空間と経済の都市。
- **借りる**: (1) **推薦系に GPU を 1 枚割く**という配分(この repo の艦隊は全部 LLM)。(2) **体数 × 1 step の表を必ず出す**という報告様式 = 受入表 L4 と同じ形。(3) **体あたり GPU 時間で正規化して初めて比較になる**という読み方。

## コスト/スケール含意

- **100 万体は「小さいモデル 1 呼/step + 巨大 GPU + 確率活性化」の産物**。この repo は体あたり 6.94 呼・観測 1,050〜1,300 tok なので、**同じ体あたり費用にはならない**。
- 逆に言えば、**この repo の 0.592 GPU·s/体/シミュ日 は OASIS 100K の 0.540 GPU·s/体/step とほぼ同額**。つまり **この repo の 1 シミュ日 ≈ OASIS の 1 step(100K 規模での)**。「40 万体・1 日」を「1M 体・1 step」と並べるときの換算率はここ。なお **1M 規模の OASIS は 1.750 GPU·s/体/step = 3 倍高い**ので、「1M を 27 GPU で」を体あたりの効率の話と読んではいけない。
