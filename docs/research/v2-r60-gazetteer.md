## 結論 5 行

1. **(e) を覆す根拠は見つからなかった**。先行は階層の地名(GA の場所の木・AgentMove の district/block/street/POI・Nominatim の住所階級)で、LLM に名前で答えさせてエンジン/地名帳が解決する形は主流。ただし **(e) の前提を 3 つ先に決める必要がある**: ① 店の層の名前は実名か(D-W7 名称規則「店舗 POI の名称は架空」・D-19 と正面衝突)② 舞台の 8.7% のセル(45/520)は渋谷区の外=町丁目の層に隣の区(目黒・港と推測)の境界が要る ③ 店名の 31%(728/2,337)はラテン文字だけ=カナの別名は手で(か LLM で)足す=設計者の指紋。
2. **実 LLM(8B・C8 テープ 21 本・93 万呼)は「見えている名前」しか言わない**: 名前として解決できた対象の **99.8%** はその呼のプロンプトに出ていた。道路名・町丁目名はプロンプトに無かったので対象に**ほぼ出ない**(町丁目 0 件/移動)。**地名帳の層は知覚に載せたものだけが使われる**=「いまいる場所」の行と B2 の可視行が地名帳の語彙の入口になる。
3. 移動の対象(357,449 呼)の内訳: テンプレの写し(「物のカテゴリ」等)**47.9%**・自由記述 33.2%・なし 7.5%・セル 5.3%・人 5.0%。自由記述のうち機械的な地名帳の試作 v0(3,289 名)で**解決 42.9%**(完全一致 74%・含む 26%)・残りは**店の種類の語 45,344(38%)**が最大=エンジンの選び手へ回す語。**名指しらしいもの**に限ると解決 **80.3%**(下限)。店名に解決したうち **46.0% はチェーン等で同名が複数**=「見えているもの/近いもの」で絞る規則が必須。※当時の B0 は「対象にはセルID・物のカテゴリ・人ID」と指示していた(v3 は「名前かID」)=**名指しは過小**。
4. ひと言(発話)に地名帳の名(3 字以上)が出る率は **1.39%**(10,281/738,323)=ユーザーの「1% 前後」と一致。うち店 89%・通り等 11%・町丁目 0.2%。
5. 草案: **3 層+索引**(L1 町丁目=e-Stat 小地域・L2 通り/広場/ランドマーク/駅口/交差点・L3 建物と店・街区 1,227 は名前なしの索引として残す)。「いまいる場所」の行は r=30 m で平均 34 字(≒17 tok 推定・現行セル行 30 字)で、L2 が埋まるのは 52%・L2 も L3 も無いのは 32%=**名前の無い場所は町丁目だけで言う**のが実態。解決は「知覚にある名 → 地名帳の完全一致 → 正規化 → 含む → 店の種類はエンジンへ → 失敗は理由つきで返す(黙って動かさない)」。

## 3. 草案(**全体が案・未リサーチ=expedient**。錨のある箇所だけ出典を付けた)

### 3-0 (e) を覆すべき根拠の検討(先に書く・ユーザー指示)

- **覆す根拠は無い**。先行(GA・AgentMove・Nominatim の住所階級)も人の言い方の研究(ランドマーク中心・名前でない言及が半分)も、階層の地名帳+「どの層でもよい」+「種類の語はエンジンへ」を支持する方向。
- ただし実装の**前に**決める必要がある 3 点(どれも (e) の中身を変える):
  1. **店の層の名前 = 実名か架空か**(D-W7 名称規則③「店舗 POI の名称は架空(チェーン名も使わない)」・D-19 は繰り延べ・W14 のゲートとの衝突は既知)。L3 を実名にすると D-W7 を覆す。架空名にすると、実 LLM が口にする名(スターバックス・ローソン=事前知識)が地名帳に無くなる=解決は「種類の語」扱いに落ちる。**(a) L3 は業種+位置の言い方**(衝突記録 #22 の案)**(b) D-19 を先に決める**、のどちらか。
  2. **区外 8.7%**: 町丁目の層に目黒区・港区(推測)の小地域境界が要る=ユーザーの手(e-Stat の zip)。
  3. **ラテン文字だけの店名 728**: カナの別名を LLM で生成するか手で足すか=設計者の指紋。やらないと「カフェミヤマ」型の取りこぼしが残る。

### 3-3 範囲が重なるときの規則と「いまいる場所」の文の型

- 包含の鎖: 店 → 建物 → (入口が面する)L2 → L1。L2 は重なってよい(通りと広場と交差点)。「いまいる場所」に出す L2 は **1 つ**(Nominatim の「Only one object from these ranks shows up in an address」と同じ考え)= 点(ランドマーク・駅口・交差点)が r_pt 内にあればそれ、無ければ最寄りの通り(r_road 内)(案)。
- 文の型(案): `[B2 場所] いまいる場所: 宇田川町 / 渋谷センター街 / スターバックス前(地上)。`。区切りは「 / 」(店名に「・」が出るため)。L2・L3 が無ければ「宇田川町(名前のない路地)」。**階の表記**(地上・デッキ・地下街・○階)は語で。見積り: 平均 34〜37 字 ≒ 17〜19 tok(r=30〜50)=現行 30 字から **+2〜4 tok**。
- 知覚の個人化(指示書 §1-6)で B2 は本人ごとになる=この行は個体部。共有の崩れの費用はセル依存リスト §4 の実測項目に含める。

### 3-4 LLM の答えの解決の手順(案)

1. **前処理**: `normalize_v0`。テンプレの写し(物のカテゴリ・目的地 …)は「対象なし」扱いにして**計器で数える**(v1/v2 で移動の 47.9%)。「種類(名)」は括弧の中を名、外を種類として両方持つ。
2. **本人の知覚と記憶にある名で完全一致**(候補集合=今回の B2 に出た名+記憶の場所)。99.8% はここに入るはず(§2-4)。同名が複数(チェーン)なら**知覚にあるもの→経路の近いもの**。
3. **地名帳全体で完全一致**(知覚外の名。記憶・口コミ・事前知識)。同名は近いもの。**知覚外の名に行けるか**は設計の分岐(憲法「観測に書かれていないことをあなたは知りません」との関係)=ユーザー判断。
4. **正規化の別名**(ケ/ヶ・濤/涛・支店接尾辞・カナ↔ラテン別名・短い別名)。
5. **含む**(3 字以上の最長一致)。
6. **種類の語**(飲食店・コンビニ …)→ 既存の選び手(`engine/poi_target.py`・経路コストへ置き換え予定)。**層の語**(デッキ・地下)→ その層の最寄りの L2。「あたり」→ 近傍歩行(v3 の既存)。
7. **失敗**: 行為を実行せず理由コード(`TARGET_UNRESOLVED`)を返し、逐語を台帳へ(語彙成長 D-71 と同じ扱い)。**黙って最寄りに動かさない**。
- 範囲の地名(L1・L2 の線/面)は**その中の一点**: 歩ける面の点のうち本人から経路の近い点(案)か、街区の重心の中から無作為(乱数は D-102 の鍵で)。施設は入口(W5)。

### 3-5 記憶の「どこで」とテープへの書き方(案)

- 記憶: `place_l1`・`place_l2`・`place_l3`(地名帳の整数 ID・無ければ −1)+`x`・`y`・`level`。文に戻すときは想起の時点の地名帳で「宇田川町 / センター街」と描く。地名帳の版(ハッシュ)を run manifest に。
- テープ: 呼ごとに `target_raw`(逐語・既存)+`target_resolved_id`・`target_layer`・`resolve_stage`(1〜7)・`n_candidates`(同名の数)を足す。**1 呼 +約 10 B**(int32+int8×3)。位置の列(本人 xy と地名帳 ID)はセル依存リスト §5 段 1 と同じ列にする。
- 照合の区域(指示書 §1-3 ④)は地名帳と分ける(L1 の町丁目は統計の小地域と一致するので照合に使えるが、区外は無い)。
