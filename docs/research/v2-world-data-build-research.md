既存答申 docs/research/v2-cell-granularity-research.md が「100m格子で凍結・place_id 抽象で退路」まで決めている。本レーンはそこに**渋谷実測**を足す。

|---|---|---|
| 地上層グラフ(layer=0/未タグ) | V=3,188 / E=4,403 / 連結成分27 | shibuya_osm_wide_v8.json の edges を layer で絞り込み |
| 行き止まり除去後 | V=2,379 / E=3,620 / 連結成分1 | 次数1ノードを不動点まで反復除去 |

| 対象面積 | 6.93 km²(2,523×2,748m) | ノードbboxの外接矩形 |

### 1.2 層(地上/地下街・駅地下/デッキ)の付与法 — 実データ被覆

**実測(shibuya_osm_wide_v8.json)**:

| 層 | エッジ本数 | 総延長 | ノード数 | klass内訳 |
|---|---|---|---|---|
| layer = −2 | 88 | 1,914 m | 75 | footway 68 / steps 19 / pedestrian 1 |
| layer = −1 | 102 | 3,117 m | 41 | footway 56 / steps 14 / service 10 / pedestrian 6 / tertiary 6 / unclassified 6 / path 2 / secondary 2 |
| **地下 計** | **190** | **5,030 m** | **116** | 歩行系(footway/pedestrian/path/steps/corridor)166本 |
| layer = 0/未タグ | 4,448 | 172,971 m | 3,233 | — |
| layer = +1 | 246 | 7,559 m | 118 | footway 126 / steps 55 / pedestrian 43 / service 8 / residential 4 / tertiary 4 / unclassified 3 / primary 2 / path 1 |
| layer = +2 | 60 | 1,181 m | 32 | footway 44 / steps 12 / service 3 / corridor 1 |
| **デッキ 計** | **306** | **8,740 m** | **150** | 歩行系282本 |

**依頼文の「地下歩道141・デッキ148」は再現できなかった**。試した定義と結果:

| 定義 | 地下 | デッキ |
|---|---|---|
| layer≠0 のエッジ | 190 | 306 |
| うち歩行系klass | 166 | 282 |
| footway+pedestrian のみ | 131 | 213 |
| steps を除く | 157 | 239 |
| **端点に層タグ付きノードを持つエッジ** | **148** | 227 |

→ **148 は「地下ノードに接するエッジ数」に一致**。141はどの定義でも出ず**空欄(未確認)**。**親は「141/148がどのファイル・どの定義で得られた数か」を確認すること**(v7以前の抽出か、別スクリプトの可能性)。

**付与法(推奨・決定論)**:
1. **エッジ層 = OSM layer の素値**(欠損=0)。これは既にファイルに入っている。
2. **ノード層 = 接続エッジの層の多数決 → 同数なら「0を含むなら0、含まなければ絶対値最小」**。ノード側のlayerタグ(266件)は**検証にのみ使う**(生成には使わない=決定論の入力を1本に絞る)。
3. **層バンドへの写像**: {−2,−1} → UG(地下街・駅地下)、{0} → GL、{+1,+2} → DECK。3層に潰す(設計書の指定どおり)。**+1と+2を分けない**理由: +2は60本しかなく、デッキ間の移動は階段/エレベータ(steps 12・elevator 2)で表現できる。
4. **層間接続 = klass ∈ {steps, elevator, corridor} かつ両端ノードの層バンドが異なるエッジ**。これが昇降リンク。実測: steps 193本のうち層跨ぎ本数は**本レーンでは未算出=空欄(未確認)**。
5. **セルID = (格子XY, 層バンド)**。層は面的に薄いので、**セル増は453→【推測】550〜600程度**。設計書の「層数は少なくセル増は軽微」は実測と整合。
6. **floorguide の connections(22本)を層間リンクの正典**として上乗せ(駅⇄ビル・ビル⇄ビルの直結を via と level つきで持っている)。これはOSMグラフに存在しない実在接続なので、mechanism タグで別レイヤに置く。

**expedient宣言**: OSM layer は「描画順序」タグであって「物理的な階層」ではない(交差の上下関係を表すためだけに付くことがある)。→ **layer→層バンドの写像は expedient**。感度試験=層を全部GLに潰した対照ラン。

### 1.3 セル間隣接と経路探索の計算量(実測)

| 量 | 実測値 |
|---|---|
| 100m格子・道路ノードを含むセル(広域) | 453 |
| 4近傍隣接ペア | 785(平均次数 3.47) |
| セルあたり道路ノード数 | 平均 7.7 / 最大 68 |
| 歩行グラフ(全層) | ノード3,499 / エッジ4,944 / 総延長186.7 km |
| 次数≥3(交差点) | 2,525ノード / 次数2は397ノード |
| 平均エッジ長 | 37.8 m |

- **セルグラフでの経路探索**: 453ノード・785エッジ。全点対最短経路(Floyd-Warshall)は 453³ = 9.3×10⁷ ops = **1秒未満**、テーブルは 453×453×2byte = **410 KB**。→ **全点対を前計算してメモリ常駐**が最適(ダイクストラを毎回回す理由がない)。
- **道路グラフでの経路探索**: 3,499ノード。全点対 next-hop 表は 3,499²×4byte = **49 MB**、Floyd-Warshall は 4.3×10¹⁰ ops で数十秒〜数分(1回のみ)。→ こちらも**全点対前計算が現実的**。40万体×1日ぶんの経路要求を毎回ダイクストラで解くより桁で安い。M8(世界側静的)に49MBを宣言。
- **MATSim系の先行**: MATSimは**リンク集約(交差点間を1リンクに)**を推奨し、SupersonicOsmNetworkReader → NetworkSimplifier → NetworkCleaner の順で**次数2ノードを削除して交差点間を単一リンクに縮約**する([matsim-libs OsmNetworkReader](https://github.com/matsim-org/matsim-libs/blob/master/matsim/src/main/java/org/matsim/core/utils/io/OsmNetworkReader.java) / [pt2matsim](https://github.com/matsim-org/pt2matsim))。v2に当てると **3,499ノード → 次数≠2の3,102ノード=11%減にとどまる**。→ **OSMの渋谷抽出は既にほぼ縮約済み。MATSim流の簡約を新規に入れる利得は小さい**(実測)。実務での「500m超リンクの分割・20m未満の統合」(AToM)は逆方向の操作で、v2の平均エッジ長37.8mはその帯の内側。

**推奨**: 歩行グラフはそのまま使い、**縮約はしない**。セル層は prefix共有単位としてだけ使い、経路探索は道路ノード上で行う(セル→セルの粗経路をセル全点対表で先に決め、セル内は道路グラフ)。

**先行例(実読)**: [City-Scale Visibility Graph Analysis via GPU-Accelerated HyperBall, arXiv:2604.08374](https://arxiv.org/html/2604.08374) — Valdivia(49.45 km²)を **5m格子・2,706,968ノード・可視半径400m** で構築し、**RTX 3080 Ti Laptop(16GB)で333秒(約5.5分)**。ベンチ最大42,705セルで "completes in **7.25 s** versus depthmapX's **1732 s**"。厳密計算は "O(N·|E|) for the main connected component"、HyperBallで "O(D·|E|·2^p) where D is the graph diameter"。メモリは delta圧縮で "約4x compression"、290万ノードで可視性構築のピークが約35MB。
→ **v2の23.9万点は Valdivia の約1/11。M10≤512MB・前計算≤5分は成立する**(既存の GPU-VGA実測 236kセル/137秒とも整合)。

**手順(決定論)**:
1. 遮蔽物 = PLATEAU LOD2/LOD1 の footprint + 高さ(3,531棟)+ 高さ欠損棟は OSM footprint × 推定高さ。**terrain.npz(2m格子・1088×921・ground0 15.18・z −8.49〜24.335)で地形標高を足す**(2.5D=眼高1.5m+地形)。
2. グリッド点 = 道路エッジの geometry を8mバッファ→2.5m格子でラスタ化→建物footprint内を除去。**層ごとに別グリッド**(UG/GL/DECK)。UGは ubld_lod4(地下街 約332×410m のみ)に限定=**シム全域の屋内は存在しない**(extras/ubld_lod4.json の scope 欄逐語:「渋谷駅周辺地下街のみ(約 332m×410m)。シム bbox 全域の屋内は存在しない」)。
3. 可視物 = 「店頭=入口点」。**OSM実入口は16棟分しかない**(meta buildings_with_entrances: 16、entrances 配列を持つのは16棟)。残り7,194棟の entrance は**最寄り道路ノードへの決定論射影**(distinct 1,756ノード・全て道路ノード集合内)。→ **「店頭=入口点」は 16棟がmechanism、7,194棟がexpedient**。感度試験=入口を建物重心に置いた対照。
4. ハッシュ: (ジオメトリ版, グリッド定義, 遮蔽物集合) の SHA256 をテーブルヘッダに書く。同じ入力→同じ出力。

**屋内を作らない前提での「店頭」の扱い(推奨)**: 建物は不透明ボリューム、POIは**入口点に投影された看板(a)**として街路グリッドから見える。floorguide の10棟(99フロア行)だけは**階の用途**を持つので、「入口に立つと B2 に『地下2階に食物販』が1行載る」という**入口=階への窓口**表現にする。屋内を作らずに垂直方向の情報が届く。

> 「bosai の point JSON は公式 API として仕様公開されたものではない…**保持期間は約10日。過ぎた日の 10 分値は後追い取得できない**。」

→ **依頼文の「930日」は手元データと一致しない=親が出所を確認すべき**。data/realworld/wbgt/2026・jma_xml/2026 は本レーンでは中身未確認=**空欄**。

### 6.2 「特定日を再生」する手順(推奨)

1. **再生対象日を1日選ぶ**(決定論: 日付をシード)。現状は35日の中からしか選べない。
2. **B3(共有静的・時間帯ブロック)への射影**:
   - 気温 → 段階語彙(暑い/やや暑い/快適/涼しい/寒い)。境界は**WBGT指針値に釘付け**(正規化規約⑤「段階語彙は法定/LOS境界に釘付け」)。
   - precipitation1h → 段階(なし/小雨/雨/強い雨)。
   - sun10m / sun1h → 「日射あり/なし」の二値。これが**影グリッドの有効/無効スイッチ**。
   - 時刻は正規化規約⑨により**5分丸め**。
3. **都市バイアス補正(expedient・宣言必須)**: 北の丸公園→渋谷スクランブルの系統差。**補正係数の出典は本レーンでは見つからず=空欄(未確認)**。当面は**補正なし**で出荷し、「渋谷の実効気温は系統的に高い(方向は既知・大きさ不明)」を台帳に書く。
4. **体感温度(B5内受容)への接続**:
   - 影グリッド(2.5m格子・§3.2の姉妹テーブル・1byte/点=239KB)を日照ありのときだけ有効化。
   - 経路コスト: **日陰を歩いた距離は日向に対し係数 0.86 で割り引かれる**(Scientific Reports 12, 2022。R3-2 で正典化済み — docs/research/v2-perception-u17-research.md §5.3「日陰を歩いた距離は日向を歩いた距離に対して係数 0.86 で割り引かれる」)。
   - **WBGTとの接続式は本レーンでは確認できず=空欄(未確認)**。data/realworld/wbgt/ に環境省WBGT実測がある可能性が高く、**「アメダス気温+湿度→WBGT推定式」ではなく実測WBGTを直接使う**のが筋(推定式は expedient になる)。
5. **決定論**: (日付, 観測点ID, 段階境界表版) のハッシュで再現。**シミュ実行中の API 呼び出しは禁止**(ODPT _index.json の usage_note「決定論保護のため、シミュ実行中はこの静的キャッシュのみ読む」を気象にも適用)。
