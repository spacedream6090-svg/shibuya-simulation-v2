## §0 要旨

1. 長く動くエージェントの一貫性は、主にモデルの外のファイルで作られている。Anthropic のハーネスは、進み具合のファイル・型の決まった機能の一覧・git の履歴を毎回読み直し、1 回に 1 機能だけ進める [S1]。同じ会社の後の記事は、ハーネスの部品はどれも「モデルにできないことへの仮定」だから、モデルが替わるたびに 1 つずつ外して確かめると書く [S2]。
2. 文脈の作り方は 2 型ある。追記を続けて上限の近くで圧縮する型(Claude Agent SDK・OpenHands)と、保存した状態から毎回組み立てる型(Letta の記憶の塊)である [S5][S18][S16]。住民を追記型のまま 1 日回すと、14 呼で 52,220 トークンになり、予算の 3 万を超える(§5-4・置き方は【推測】)。
3. 途中の入力の実務は、溜める・拒む・止めて足す・戻してやり直すの 4 通りに分かれる [S13]。Claude Code と OpenAI の steering は、走っている道具や出力の区切りまで待って足す形で、生成中の文には入れない [S7][S10]。11-05 の「途中の文を世界の時刻で切って足す」に近い先例は、実務より研究の側にある [S42][S44]。
4. 途中の文に足す形は Qwen3-8B でも測られている [S42]。更新が遅く届くほど成績が落ち(最大 60%・モデルごとの内訳は読めていない)、更新による誤りの約 8 割は更新を疑って前の筋を続けるものだった。本人の声で受け止める短い文を足すと、GSM8K と MATH-500 ではこの問題が解消した。どれも算数とプログラミングの課題の値で、日常の判断の値ではない。
5. 逆の向きの先例もある。無関係な短文で誤答が増え [S45][S46]、隠した指示を混ぜると Qwen3-8B の MMLU-Redux は 84.0% から 1% 未満まで落ちた [S43]。「本当に?」と問うだけで答えを変える率は平均 46% だった [S47]。だから「流される」と「無視する」の両方を測ることになる【見立て】。同じ考えの途中から刺激の有無で続きを複数回標本し、刺激なしの標本どうしのばらつき(フロア)と比べる形で測れる【見立て】(§6-2)。
6. 道具の見せ方で結果は変わる。SWE-agent は同じモデルで、見せ方だけを替えると SWE-bench Lite の解決率が 18.0% から 10.3〜16.3% に下がった [S19]。同じ働きの道具を並べると前に置いた道具が選ばれやすく、説明の小さな差でも選択が動く [S20]。一覧を見せる形と自由文の形を直接比べた対照実験は見つからなかった(§10 の U4)。
7. 行為を道具の呼び出しで出させる形の利点は、穴が型で埋まることである。vLLM の named と required は構文の正しさを保証する [S35]。危うさは 3 つある。一覧がそのままメニューになる(D2)、JSON の強制で推論の質が落ちる [S21]、本人の言葉に無い値を型が埋めさせる(A2-1 と擦れる)【見立て】。自由文で答えてから形に直すと質の差はほぼ消える [S21]。vLLM は考えの部分に文法をかけないので、この順は Qwen3 でも作れる [S36]。
8. 多数を回す先例は、自由文を GM が裁く Concordia、共有の状態を読み書きする並行のモジュールと 1 か所の決定を持つ PIANO、順序を持たない非同期の AgentSociety に分かれる(§4)。費用を下げた値としては、AGA が方策の再利用と要約で Generative Agents の 31.1〜42.7% にした例がある [S30]。
9. 安く回す鍵は接頭辞のキャッシュだが、当たる範囲は狭い。vLLM は満ちたブロックの完全一致だけを使う [S33]。今の予算の割りでは、全員で共有する 750 トークンが入力の 57.7% にあたる。人ごとの 300 トークンを全員ぶん KV に置くと 15.5 TB になるので、人ごとの接頭辞が当たるのは 1 つの熟考の中の短い間だけと見込む【見立て】(§5)。
10. ReAct 型は 3 歩で触るトークンが 1 呼の 3.3 倍(4,464)、キャッシュが当たっても新しく計算する分は 1,612 になる。14 呼のうち 25% を 3 歩にすると 1 日 29,946 で予算の上端に届く(§7・置き方は【推測】)。Qwen3 のチャットの型は本物の user の発話より前の考えを捨てるので、知覚を入れる役の選び方が 9-3c に直接かかる [S39]。§8 に部品ごとの選択肢と全体の案 M0〜M6 の比較、§9 に決めるべき題 16 を置いた。推薦は書かない。

### 2-2 共通して読み取れること【見立て】

- 一貫性の主な作り手は、白紙に近い文脈へ読み直させる手順と、書き換えの範囲を縛った外の記録である(S1 の `passes` だけ・S17 の不変の事象)。
- 「思い出すもの」を増やすより、「文脈に出さないもの」を決める工夫が多い(S19 の直前 5 件・S31 の復元できる圧縮・S40 の観察を隠す形)。
- 確かめ方は、本人の自己評価を信じない方向に揃っている(S1・S2)。世界の結果を外から見て返す形が多い。
- 部品の価値は外して測る(S2 は 1 つずつ外し、S19 は表で出す)。

### 2-3 コーディングのハーネスと住民の違い【見立て】

### 3-2 一覧の偏り [S20] ◎

BiasBusters: 同じ働きの道具 5 つ × 10 群 × 100 問を、並びを 5 通りに回して測った。値は一様からの全変動距離(0 なら偏りなし)。

| モデル | 道具の銘柄の偏り δ_API | 位置の偏り δ_pos | 合わせて δ_model |
|---|---|---|---|
| Qwen3 235B | 0.330 | 0.168 | 0.249 |
| GPT-3.5-turbo | 0.320 | 0.336 | 0.328 |
| ToolLLaMA | 0.277 | 0.391 | 0.334 |
| Gemini 2.5 Flash | 0.365 | 0.306 | 0.335 |
| Claude 3.5 Sonnet | 0.370 | 0.325 | 0.347 |
| DeepSeek-V3.2-Exp | 0.249 | 0.504 | 0.377 |
| GPT-4.1 mini | 0.331 | 0.423 | 0.377 |

- 前に置いた道具が選ばれやすい。銘柄の好みが弱いモデルほど位置に頼る。並びを揺らせば位置の偏りは消せるが、銘柄の偏りは残る。
- Qwen3 は 1.7B〜235B を試したが、この表にあるのは 235B だけ。小さいモデルほど偏りが大きく、32B で目立って下がると書く(数値は図だけ)。**8B の値は読めていない**(§10 の U5)。
- 追加学習の作用: 偏った追加学習で Qwen3-8B の 1 つの道具の取り分が 0.006 → 0.128 に動いた。

- 【見立て】これは「同じ働きの道具」の間の偏りで、「違う行為の間」(歩く・買う・話す)の促しを測ったものではない。D2 への写しは間接である。

閉じた行動空間の社会シミュの例として、1,000 体の投稿サイトの模擬で「LLM に 1 つ選ばせる形」はマルコフ型の基準から分布がずれ、モデルとプロンプトでずれ方が変わると報告がある [S22] △。社会シミュの総説は、閉じた領域と開いた領域を分ける [S23] △。別の批判の論文は、文だけの形では行為の可否を LLM が暗黙に決めてしまうので、外の機構が前提を確かめる混成の形を挙げる [S24] △。文字のゲームでは、正解の行為の一覧を与えない言語モデルが、半分のゲームで一覧ありのモデルに並ぶか上回った CALM(2020)がある [S25] △。

### 3-3 形式の制約と推論の質 [S21] ◎

Let Me Speak Freely(GSM8K の正解率 %・本文の表)。

| モデル | 自由文 | JSON の指示 | JSON-mode(文法で強制) |
|---|---|---|---|
| Gemini-1.5-Flash | 89.3 | 89.2 | 47.78 |
| GPT-3.5-Turbo | 76.6 | 49.3 | 29.87 |
| LLaMA-3-8B | 74.7 | 48.9 | 65.38 |

- 推論の課題では形式が厳しいほど落ちる。自由文で答えてから形に直す形(NL-to-Format)は自由文とほぼ同じ。
- Last Letter で JSON-mode が 0.67〜7.56% に落ちた原因として、答えの鍵が理由の鍵より前に置かれ、考える前に答えていたことを挙げる(GPT-3.5 の JSON-mode で 100%)。**鍵の順は推論の順になる**。
- 分類の課題では逆に上がることがある(Gemini の DDXPlus は 41.6 → 84.92)。候補が絞られて選択の誤りが減る、という仮説。
- 文法そのものより、スキーマを見せたことで落ちる場合がある(Claude の JSON 指示は 23.44 → スキーマを外すと 86.99)。
- 新しいモデルと JSON スキーマでは差が小さい(gpt-4o-mini の GSM8K は自由文 94.57・スキーマ 91.71)。Qwen3-8B の値は無い。

- 【見立て】PIANO の「モジュールは状態なしの関数で、共有の状態を読み書きする」は、11-03 の「全員の状態の配列にかける関数」に近い。ただし PIANO の Agent State は可変の文で、配列に乗るのは数値の欄だけ(R-135 §7)。

## §5 安く回す工夫

### 5-1 vLLM の接頭辞のキャッシュの規則 [S33] ◎

- 鍵は親の鍵+そのブロックの token+追加の値(LoRA・画像・`cache_salt`)の連鎖。**1 字でも違えばそこから後ろは全部外れる**。
- 満ちたブロックだけが入る(文書の例は 16 と 4 で、既定の値の記載はこの頁に無い。既存の注は 16 トークン単位=[LLM 配信の答申](v2-llm-serving-deep-research.md))。
- 生成した token も、ブロックが満ちれば入る。
- 追い出しは LRU。要求が終わると後ろのブロックから先に追い出されやすい順で空きの列に入る(「最後のブロックは多くの token を含むので再利用されにくい」)。
- `sha256` の既定は版をまたいで同じとは限らない。

### 5-6 毎回入れるもの、必要なときに取り出すもの

- Anthropic の文脈の指針は「高い信号の最小の集合」「軽い識別子を持って実行時に取り出す」「圧縮は再現率から始める」「最も安全な圧縮は道具の結果を消すこと」と書く [S3] ◎。
- Claude Code は CLAUDE.md を毎回入れ、MEMORY.md は頭の 200 行か 25 KB までを起動時に入れる [S5][S7] ◎。
- 人物の逸れの先行研究は、3 つの一貫性(プロンプトとの一致・行と行の一致・問いへの答えの一致)を計器にし、行と行の一致は高いままで、最初のプロンプトからの逸れが問題だと報告している [S55] ○(行と行の所見は検索の抜粋 △)。強化学習の微調整で不一致を 55% 超減らした。人物を何回おきに入れ直すと効くかの対照の値は見つからなかった(§10 の U6)。
- 【見立て】今の白紙の呼びは人物を毎回入れているので「最初のプロンプトから遠ざかる」型の逸れは起きない。起きているのは逆で、前の呼びの考えとのつながりが無い(U8「脳が思考ごとに入れ替わる」)。先例の逸れの計器は向きが違うので、行と行の一致に当たる「前の熟考との一致」を別に定義することになる。

- 位置は token で決まる。`return_token_ids` と token の口なら正確に切れる [S34][S37]。文に戻して入れ直すと token が変わることがある【見立て】。
- 考えの途中の文で切ると文の途中で止まる。研究は位置の割合で切っている [S42]。文の切れ目に寄せるかは題(§9 の H7)。
- **切った後ろの部分の扱い**: 9-3c は「返事は最後まで生成し、後からその位置で切る」、9-5 は「使わなかった返事は『考えかけたこと』として記憶とテープに残す」と書く。切った後ろの文は世界の時刻では本人がまだ考えていない文なので、本人の記憶に入れると、考えていないことを覚える形になる【見立て】。両決定の関係は原文から読み取れない(§9 の H7。食い違いの候補として報告)。
- 差し込みが 2 回続く場合、テープの鎖は親子の連鎖になる(§8-5)。
