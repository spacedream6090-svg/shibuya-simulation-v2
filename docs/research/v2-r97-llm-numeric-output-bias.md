## 結論(5 行)

1. **LLM は「好きな数」に強く寄り、温度を上げてもほとんど崩れない。** 6 モデル × 7 言語(日本語を含む)× 3 の数の範囲 × 6 温度 × 100 回 = 75,600 回の実験〔親の訂正: 原典は「6 models × 7 languages × 3 ranges × 6 temperatures × 100 numbers = 75600 calls」で、初版は範囲の 3 が抜けていた〕では、1〜10 で「7」が全モデルの最頻値で、GPT-4o-mini・Phi-4・Gemini 2.0 は約 80% が 7 でした。1〜100 では 37・47・73 などに集中し、両端を避けます。χ² 検定で一様と言えた設定は 1 つもありません(最良でも p = 2.19 × 10⁻¹⁵)。8B の Llama 3.1 と 7B の Mistral は温度を変えても分布がほとんど変わりません(Coronado-Blázquez 2025・原典)。採点の場面では 5 と 10 の倍数への寄り(round number bias)が報告されています(△)。
2. **人も丸い値に強く寄る。ただし、比べる相手で「正しい割合」が変わる。** 旅行調査の自己申告の時刻は、5 分の倍数以外が 5% しかなく、ちょうど何時 0 分が 22% です(Rietveld 2002・原典)。日本(熊本 2012)では 10 分単位への丸めが多い(Sato & Maruyama 2020・抄録)。一方、第三者が分単位で記録した首相の動静では、移動の出発と到着の時刻は 0〜59 分に一様でした。会議の開始時刻だけが丸い分に集まります(Sanko & Iriguchi 2022・原典)。数を直接書かせると、日本の成人の約 6 割の答えが丸い値になり、目盛りで答えさせると丸い値はほぼ消えます(Honda ほか 2022・○)。
3. **出させ方で分布が変わる。** 1 回 1 個を独立に引く方法は、多くのモデルで分布を再現できません(11 モデル中 10 が 15 分布のどれにも合格しない)。1 回の応答に 1,000 個まとめて書かせる方法は中央値 7% の合格率です(Zhao ほか 2026・原典)。古い基盤モデルでは逆に独立に引く方が良かった(Hopkins ほか 2023・原典)。指示調整したモデルは、分布を言葉で正しく説明できるのに、その分布から引けません(Xiao ほか 2025・Jang ほか 2026・○)。分布を 1 回で書かせると、人の調査との誤差が半分以下になったという報告があります(Jang ほか 2026・○)。
4. **大きいモデルほど偏りが小さい、とは言えない。** API の大きなモデル(GPT-4o-mini・Gemini 2.0)は 8B 級と同じかそれ以上に決定的でした(Coronado-Blázquez 2025)。古い LLaMA では大きいほど誤差が小さく、指示調整で誤差が増えました(Hopkins ほか 2023)。指示調整したモデルは、比べられたどの系統でも元の基盤モデルより悪い(Jang ほか 2026・抄録)。R-88 の「8B 級で弱点が特に強いと示した原典は無い」と合わせると、偏りの大きさを決めるのは大きさより指示調整と出させ方です。
5. **日本語に特有の報告は少ない。** 上の 75,600 回の実験では、日本語は偏りの指数が最も小さい言語でした。ただし Gemini 2.0 の 1〜5 は日本語だけ最頻値が「1」にずれ、Phi-4 は日本語では数を返せませんでした。全角数字・「約」・時刻の書き方(「7時半」「19:30」)の偏りを測った研究は見つかりませんでした(空欄)。

## 1. LLM が数値を生成するときの丸い値・好きな数への偏り(調べること (1))

### 1-1 乱数を頼んだときの「好きな数」(#1・◎・時点 2025-02)

- 設定: DeepSeek-R1(14B・蒸留)・Gemini 2.0・GPT-4o-mini・Llama 3.1(8B)・Mistral(7B)・Phi-4(14B)。言語は中・英・仏・ヒンディー・日・露・西。温度 0.1・0.3・0.5・0.8・1.0・2.0。範囲 1〜5・1〜10・1〜100。各 100 回で計 75,600 回。プロンプトは「1 から X の乱数を 1 つ。数だけを返して」。
- 1〜5: どのモデルも「3」が最多で、両端(1 と 5)をほぼ選ばない。Phi-4 は温度に関わらず 3 と 4 しか出さない。
- 1〜10: 「7」がすべてのモデルで最多。GPT-4o-mini・Phi-4・Gemini 2.0 は全体の約 80% が 7。Gemini 2.0 の T = 2.0 では、7 の割合が露 80%・ヒンディー 92%・英 100%、日 34%・西 54%・仏 57%。
- 1〜100: モデルごとに決まった値に集まる(「バーコード」状)。Gemini 2.0 と GPT-4o-mini は最低温度で 1 種類の値しか出さない。20 未満か 90 超を出したのは DeepSeek-R1 と Llama 3.1-8B だけ。大きい方へ偏る。最頻の数は 37・47・73 など(素数)。
- 検定: どの設定でも一様と言えず、最も一様に近い設定(Llama 3.1-8B・T = 0.1・西語・1〜5)でも p = 2.19 × 10⁻¹⁵。Cramér の V は最良で約 0.45、多くは 1 近く(Python の randint で 100 個を作ると V = 0.09 ± 0.03)。
- 著者は、人の「中央を選ぶ偏り」「素数をランダムらしく感じる」と同じだと解釈している(Towse ほか 2014 を引用)。

### 1-2 桁の偏り(#4・◎)

- 正解の桁を一様にした問題でも、オープンなモデル(LLaMA・Qwen・Gemma・OLMo・Mistral の各系統)は小さい数字(1 など)を出しすぎ、8・9 を出さなさすぎる。事前学習の文書(OLMo-mix-1124)の数字の分布がベンフォードの法則に近いことが原因と論じている。

### 1-3 採点・評価の場面での 5 と 10 の倍数(#20・#21・△)

- LLM に 1〜100 で点を付けさせると、60・70・80・90 や 75・85・95 に山ができる、という報告がある(Stureborg ほか 2024)。別の報告では 1〜100 の成績付けで 5 の倍数に寄り、65 を最も好む(CBEval)。どちらも検索結果の要約で、本文の数値は確認していない。

### 1-4 支払意思額では人と同じ丸め方を再現する(#7・◎)

- 商品の説明から支払意思額の分布を LLM(GPT-4o)に作らせると、実データの生存関数の段差(0 と 5 で終わる値)と同じ位置に段差が出た。著者は「人が支払意思額で 0 や 5 で終わる丸い値を答える現象を LLM も示す」と書き、これが価格の最適化を助ける理由の 1 つだとしている。割合の数値は無い(図だけ)。

## 2. 一貫性: 同じ問いで数値がどれだけばらつくか(調べること (2))

- 温度の効き方はモデルで違う(#1): 西語の 1〜5 では温度が効くのは Gemini 2.0 だけで、ほかのモデルにはほぼ効かない。1〜100 では Gemini 2.0 と GPT-4o-mini は温度を上げると広がるが、Mistral-7B と Llama 3.1-8B はほとんど変わらない。著者は API のモデルに追加の指示がある可能性を挙げている。
- 同じモデルの中では答えがすぐ安定し、モデルの間では一致しない(#19・○): オープンな 9 モデル・3 領域(空の旅・飲食店・消費財)で、最頻の答えは繰り返しの中ですぐ定まるが、系統と大きさが違うとほぼ合わない。結果を決めるのはプロンプトの言い回しよりモデルの選択だった。温度・貪欲な復号・言い回しと選択肢の順の摂動でも確かめている。
- 摂動による答えの変わり方の床(再実行 2.5〜23.7%・言い換え 14.1%)は R-88 §3 にある(再掲しない)。
- 予測の場面の値(検索結果の要約・△・本書では採らない): 同じ入力を 3 回で分散の 96% が観測間の違い、など。原典未読なので数値は使わない。
- 時点: 2025〜2026 の報告。モデルが替わると傾向が変わる(#1 の Gemini の API とアプリの食い違いの例)。

## 4. 分布を出させる方法の比較(調べること (4))

| 方法 | 報告 | 等級 |
|---|---|---|
| 数を 1 個ずつ独立に引く(温度で散らす) | 11 モデル中 10 が 15 分布のどれにも合格しない。一様分布でも Wasserstein 距離はまとめて書かせる方法の約 0.01 から約 0.15 に広がる(#2)。指示調整したモデルは同じ人物像の同じ問いに半分以上の項目で同じ答えを返す(#12) | ◎ / ○ |
| 1 回の応答に多数をまとめて書かせる | 合格率の中央値 7%・最良のモデルで 40%。N を増やすほど悪くなる(#2)。古い基盤モデル(LLaMA)では逆に、まとめて書かせると型が崩れ、独立に引く方が誤差が小さかった(#3) | ◎ |
| 分布(確率)を言葉で書かせる | 指示調整したモデルは分布を正しく説明できるのに引けない(#11・#12・#15)。分布を 1 回で書かせると人の調査との誤差が半分以下(#12)。確率つきで候補を複数書かせると多様性が 1.6〜2.1 倍(#13) | ○ |
| 選択肢(段階)の番号で返させる | 判断モデルの段階の出力には第 1 水準を避ける位置の偏りがある(R-94 結論 5)。数を直接書かせるより目盛りで答えさせる方が人では丸めが消える(#9)。LLM で「目盛り型」が丸めを消すかを測った研究は見つからなかった(空欄) | (R-94)/ ○ |
| 数のトークンの確率(logprob)を読む | 数のトークンの偏りを乱数の生成で測り、採点の確率を補正すると基準の方法より良い(#18)。数値の予測分布を引き出す LLM Processes(#16)・内部状態から平均や分位点を読むプローブ(#17)がある | ○ |
| 外の乱数(コード・エンジン)で引き、LLM には分布か段階だけを出させる | 行動シミュレーションの文脈で、コードの道具を使うと引く精度が一部改善する(#15)。著者らは統計的な保証が要るなら外の道具が必要と結論(#2) | ○ / ◎ |

## 5. 日本語での数値の出し方(調べること (5))

- #1 の日本語の結果: 1〜5 と 1〜10 の偏りの指数の平均で、日本語は 7 言語の中で最も偏りが小さかった(DeepSeek-R1 の日本語の成績に助けられた面がある)。Gemini 2.0 の 1〜5 では日本語だけ最頻が「1」になり、2 番目が「3」だった。Phi-4 は日本語では全範囲で数を返せなかった(数の列や文を返した)。DeepSeek-R1 の日本語・T = 0.8 で範囲外の「9」が 1 回。
- 数字の書き方(漢数字・全角数字・万/億の区切り)の影響: 数字の書き方による計算の精度の低下を調べた ACL 2026 の論文(#8)は、対象の書き方に中国の数字は含むが日本語の書き方を含まない。日本語の書き方で調べた研究は見つからなかった(空欄)。
- 「約」「くらい」「7時半」「19:30」「午後 7 時」の使い分けで出る値の偏りを測った研究は見つからなかった(空欄)。
- 手元の記録: W17 v2 の生成では、8B が例示の「07:23」を 47% 写し、体の事実の時刻は 25% だった。例示を体ごとの事実から組んで解消した(注目事象 E-12・D-68)。これは「丸い値」ではなく「例示の値」への偏り(アンカー)で、§6 の当てはめで同じ物差しに入れる。

### 案 2: 偏りを避ける出し方の候補

- (i) 数を直接書かせる(現状の方針どおり)。照合の項で丸めの割合とばらつきを監視する。
- (ii) 段階や幅で書かせ、エンジンが人ごとの性質から値に直す(DM13 (a) の「数字で考えない量」と同じ形)。人の研究では目盛りで丸めが消える(#9)。ただし「人が数字で考える量」で丸めが消えるのは現実と合わない可能性がある(推測)。
- (iii) 分布(候補と確率)を書かせ、エンジンの乱数で引く(#12・#13 の向き)。1 体ずつの予定に使うと呼び出しの長さが増える(費用は未計測)。
- (iv) 判断モデルの確率(logprob)を読む(#18 の補正を含む)。段階の出力の位置の偏り(R-94)の対照試験が先に要る。
- (v) 例示の具体値を体の事実から組む(E-12 で済んだ対策)。例示の値の写りを照合の項に入れる。
- どの案も、実 LLM での測定は GPU の後(§4 の (c) の範囲では、案を決めて照合の項の判定関数を先に作れる)。

### 案 3: 判定関数の形(作れるものから)

- 分の値の 60 区分のヒストグラムと、Rietveld の丸めの模型による期待値との χ²。同じ問いを 1 体あたり k 回聞いたときの値の散らばり(最頻値の割合)。モデルの間の違いを見るための、同じ問い・同じ人物像での最頻値の一致率(#19)。
- 物差しのフロア: 人の自己申告(5 分の倍数以外 5%=#5)と、実際の動き(一様=#6)の両端を併記する(CLAUDE.md §5 のフロア併記)。
