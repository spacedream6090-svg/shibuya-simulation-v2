## §0 要旨

1. LLM エージェントの間の広がりを人数の割合で測った先例は 3 本あった(Agent Smith・Flooding・NetSafe)。どれも植えない条件(0.00)か 1 巡目と比べ、巡ごとの割合を追う。8B 級の公開モデルで測ったのは Flooding(Vicuna 7B・LLaMA 3 8B・Gemma 7B で、3 巡の後に良い体の 22〜51% が誤った事実で答えた)と Agent Smith(LLaVA-1.5 7B)。Qwen3-8B の値は無い。
2. 広がるかどうかの境目は Agent Smith が式で示した。1 回の出会いでうつる確率 β と記憶から落ちる確率 γ について、β≤2γ なら感染は 0 に向かう。記憶の棚を小さくすると広がりが抑えられた。
3. 「0 に近い」の言い方は 2 通りある。読んだ人 n 人で写した人が 0 なら、写す確率の 95% の上限は約 3/n(1% 未満と言うには 300 人超【算術】)。もう 1 つは、途中で消える鎖の大きさから R を出す方法(Blumberg & Lloyd-Smith 2013。R の最尤の値は、全件のうち 2 次の伝わりで起きた件の割合)。
4. 囲い・印・記憶の出どころの印の有り無しで「何人にうつったか」を比べた表は、読めた範囲に無かった(空欄)。公開のセット(AgentDojo・InjecAgent=どちらも MIT・BIPIA)は 1 体の乗っ取りを測るもので、広がりは測らない。日本語のセットも無い。
5. 人のデータでは、日本の 2020 年の調査で誤った情報を共有した方法が「会話・電話・メール」29.2%・メッセージアプリ 11.8%・SNS 2.0〜2.6% だった(◎)。関東大震災の流言は約 1 日で 28 の警察署の管内に広がった(◎)。3.11 の SNS の噂は訂正まで約 21 時間かかり、噂を書いた人の 15.7% が後で訂正を書いた(◎)。
6. 対面の口コミで 1 人が何人に伝えるか、対面の噂の R の実測は見つからなかった(R-49 と同じ空欄)。インドの村の知らせでは、参加者は参加しない人の 7 倍伝えやすかった(○)。伝言の実験では 5〜6 回で細部の約 70% が失われる(△)が、実地の噂では中身はほとんど変わらなかった(△)。
7. 一次確認: Spotlighting は記録の数値と合う。ただし「2% 未満」は最良の組の値で、印を散らす形の Q&A では GPT-3.5-Turbo が 8.0% だった。区切りだけの形は著者自身が「勧めない」と書く。Prompt Infection は要旨までしか読めず(本文は取得の道具の安全検査が止めた)、記録の「記憶を引き出す仕組み」と「単独では防ぎきれず」は確かめられない。Johnson ら 1993 は出どころを推し量る誤りやすい過程として書いており、記録の「印を残す」はその誤りへの機械の側の手当てとして読むのが原典に近い。
8. Langer ら 1978 の表 1 は、著者の原稿にも公的な保管庫にも見つからず、読めなかった。
9. 人と LLM の広がりを並べる形の表を §3-4 に置いた。推薦は書かない。親に確かめてほしい数値は §7 の末尾。

## §1 問いと前提

### 1-1 問い(発注文)

1. 問い 1: 複数の LLM エージェントの間で、植えた文(自己複製する注入・決まりを書き換える文・誤情報)がどれだけ広がるかを測った研究の比較の表。あわせて、「広がらなかった」ことを確かめる試験の設計(何人・何歩・何回)、植える文の公開のセット(名前・大きさ・型・ライセンスだけ)、記憶を通じた広がりを扱った研究。§2。
2. 問い 2: 人の噂・説得の広がりのデータ(比べる相手)。対面の場面に近いものを優先。噂・口コミが何人に伝わるか・何世代伝わるか・中身がどう変わるか/頼みや呼びかけに応じる割合(追補 1 と重ねない)/誤った情報の広がる速さと範囲(対面と SNS を分ける)/日本の調査。§3。
3. 問い 3: 記録 2-72 が引く Prompt Infection(Lee & Tiwari 2024)と Spotlighting(Hines ら 2024)、出どころの監視(Johnson ら 1993)の一次確認。§4。
4. 範囲の外: 守りの実装の設計。どの守りを採るかの推薦。

### 1-2 前提(記録の決定)

- 2-72 ④ 広がりの試験: 読んだ人の決まりを書き換えて写させる文を植え、何人に広がるかを数える(0 に近いことを確かめる)。噂と説得の広がりは別に人のデータと比べる。
- 2-72 ③ 区切りの守り: 囲い・住民が書いた文に書いた人・時・場所の印・記憶にも出どころの印(Johnson ら 1993)・上下を守れるモデル。
- 2-86 その 3: 区切りの記号は見えない字を挟んで崩す/`〔出どころ〕「本文」` で包む/本文の中の書式に似た記号だけ形を替える(言葉は変えない)/印の付かない外の文字列にも同じ置き換え。
- 2-62: 起きやすさの順は「呼びかけへの反応のずれ」≫ 住民どうしの出力の形のにじみ ≫ 区切り記号の混入。住民から住民へ広がる攻撃は最初の種が要る(攻撃者の住民を作らない限りシミュレーションの中にいない)。

- 「何人にうつったか」を数で出している先例は、Agent Smith(感染の割合の時系列)・Flooding(良い体のうち誤った事実で答えた割合)・NetSafe(巡ごとの正答の割合)の 3 本だった。どれも「植えた後に、植えた側が何もしなくても広がるか」を、植えない条件(0.00)や 1 巡目と比べて測っている。
- 広がるかどうかを分ける量として、Agent Smith は β(1 回の出会いでうつる確率)と γ(1 回あたり記憶から落ちる=回復する確率)の比を挙げ、「β≤2γ なら感染の割合は 0 に向かう」と式で示した(2 人 1 組で問う側からだけうつる作りなので、係数 2 はこの作りに固有)。記憶の棚を小さくすると γ が上がり広がりが抑えられた。これは記録 2-72 の「記憶を引き出す仕組みが守られていないと弱い」と同じ向きの、数で測った結果である。
- 8B 級の公開モデルで測ったのは Flooding(Vicuna 7B・LLaMA 3 8B・Gemma 7B)と Agent Smith(LLaVA-1.5 7B・13B)。NetSafe と Prompt Infection は GPT 系だけ。Qwen3-8B で測った研究はこの回に見つけていない。
- 守りの効き目を広がりの数で測った先例は、Prompt Infection(LLM Tagging と既存の守りの組み合わせ・数値は読めていない)と Morris II(見張りの検出の率)だけだった。囲い・印・記憶の出どころの印の有り無しで「何人にうつったか」を比べた表は、読めた範囲には無い(空欄)。

### 6-2 取り方で迷った所(親に判断してほしい)

1. **Prompt Infection の検索の抜粋**: HTML は安全検査が止めたので読み直していない。別の調べもの(多エージェントの注入の広がりの一般の検索)の結果に、この論文の本文の中身の要約が出た。これを △ として使っていた。**親の裁定(第348)**: 自動の安全検査が止めた頁の中身を、別の道で埋めない(R-149 の追補 1 の U1 では、止まった頁の中身を本文に入れていない)。検索の抜粋で出た本文の中身は、§2-1 の 1 行目・§2-3 の表・§4-1 から外した。この論文について本書が言えるのは、要旨の範囲だけである。
2. **holdout の行に当たる値**: 前書きの「封の注」のとおり。
3. **PDF 2 本の読み方**: 総務省の報告書([S24])と内閣府の報告書([S23])は、WebFetch がリポの外の道具の結果の置き場に自動で残した写しを、システムの Python の pymupdf(`-I` で起動・読み取りのスクリプトはリポの外の作業用の場所)で文字にし、語で該当の頁を探して読んだ(R-136・R-155 と同じ形)。リポにも data/ にも保存していない。どちらも公的機関の頁で、断りの表示は無かった(内閣府は robots.txt が 404)。
4. **Langer ら 1978 を探したときの検索の要約**: 検索の道具の要約が、第三者のサイトの PDF の中身(人数・頼みの文の言い回し)を返した。開いても使ってもいないが、要約として目には入った。本書の §3-3 には何も入れていない。
