## Q1. 母集団合成の標準手法と、LLMペルソナ「後付け」の先行例

### 1-1. 手法系統と精度指標

**標準指標は SRMSE(Standardized Root Mean Square Error)。** 定義と代表値を一次で確認できたのは PLoS One 2026 の sample-free 合成論文。

> "SRMSE ranging from 0.001 for gender to 0.158 for household composition."
> — Jones, Dawson & Mills, "A large language model framework for sample-free population synthesis," *PLoS One* (2026), DOI 10.1371/journal.pone.0341704 【✔実読】

同論文の**代表値(109か国の中央値)**:

| 属性 | SRMSE(中央値) |
|---|---|
| 性別 | 0.003 |
| 世帯規模 | 0.026 |
| 世帯構成 | 0.062 |
| 年齢 | 0.128 |

**IPUとの比較(Newcastleの1地区)**: LLM法は年齢で優る(**0.013 vs 0.058**)が、世帯構成ではIPUが優る(**0.081 vs 0.206**)。
→ **含意**: 「LLMは周辺分布のフィットは得意・世帯という構造の再現は苦手」。v2の40万体は世帯構造を主語にしない(既決の種別=住民/通勤/来街/従業/乗務/指令)ので、**この弱点は当たらない**。逆に**世帯を後で導入するなら合成器を分けるべき**(前回答申U-G ④と一致)。

**深層生成(VAE)の代表値**: SVAE-Pop2 で SRMSE 0.49、MVAE-Pop2 で 0.36 が報告されている(Computational Urban Science, Springer, 2025)。ただし当該ページは Springer の認証リダイレクト(303)で**本文を実読できず**、値は検索結果の要約経由。**【空欄(未確認)= 親の一次確認対象】**
- DOI: 10.1007/s43762-025-00195-9

**評価指標の使い分け(実読ソースの記述に基づく整理)**:
- SRMSE = **周辺分布**の一致(カテゴリ別頻度の比較)
- JSD = **結合分布**の一致(分割表全体の比較)
→ v2では**両方を台帳に載せる**(前回答申U-Gの「zeros率・2標本AUC・Cramér's V差」と合わせて6指標)。

### 1-2. 都市ABMの標準ワークフロー(ActivitySim)

ActivitySim v1.3 の実行順序を公式ドキュメントで確認【✔実読: activitysim.github.io/activitysim/v1.3.1/users-guide/example_models.html】。**母集団合成(PopulationSim)は前段で、活動生成はこの23ステップ**:

1. School Location → 2. Workplace Location → 3. Auto Ownership → 4. Free Parking → **5. CDAP (Coordinated Daily Activity Pattern)** → 6. Mandatory Tour Frequency → 7. Mandatory Tour Scheduling → 8-12. Joint Tour (Frequency/Composition/Participation/Destination/Scheduling) → 13-15. Non-Mandatory Tour (Frequency/Destination/Scheduling) → 16. Tour Mode Choice → 17. At-Work Subtour → 18. Intermediate Stop Frequency → 19-22. Trip (Purpose/Destination/Scheduling/Mode) → 23. Parking Location Choice

**v2への含意(重要)**:
- **順序が「場所 → 日パターン → ツアー → トリップ」**であり、**場所割当が先**。v2の「セル割当 → 週次スケジュール生成」の順序はこの標準と一致する。
- **CDAPが分岐点**: 「必須(mandatory)/非必須/在宅」の3値を先に決めてから頻度・時刻を決める。**LLMに丸投げせず、この3値だけエンジンで先に決める**のが最も安い一貫性担保。

### 1-3. LLMペルソナの「後付け」— 先行例と検証

**(a) LLM都市シミュの移動は空間制約を再現できない(最重要の反証)**

> "although the simulators capture some high-level semantic activity distributions, they struggle to reproduce core spatial and temporal constraints."
> — Santos, Viana & Silva, "When Plausible Is Not Realistic: Evaluating Human Mobility in LLM-Based Urban Simulation," arXiv:2606.13835 (2026) 【✔実読】

評価対象: **AgentSociety** と **CitySim**。実データ: Greater Paris(GNSS・3,337人・7日)/ Shanghai(CDR・58,502人・10日)。

| 指標 | AgentSociety の誤差 |
|---|---|
| 移動距離(Wasserstein) | 14.83 ± 0.35 km |
| 回転半径(radius of gyration) | 7.29 ± 0.28 km |
| OD一致(Common Part of Commuters) | **0.088 ± 0.002** |
| 滞在時間の不一致 | 3.96 ± 0.12 時間 |

> "realistic mobility diversity is unstable across default prompting configurations and may require explicit profile-aware initialization."

→ **v2への含意**: 「状態と集約はエンジン、意思決定と発話だけLLM」という v2 の背骨は、**この実測で外部から支持されている**。移動先・滞在時間をLLMに決めさせると CPC 0.09 まで壊れる。**週次スケジュール表もLLM生成 → エンジンで到達可能性・時間収支を強制修正、という二段構えが必須**(Q4参照)。

**(b) LLM合成人口の「制御可能性」は使用前に測るもの**

> "does it respond to stimuli of known valence in an ordered, replicable, group-structured way? We call this controllability."
> — Degli Esposti, "Calibrating the Instrument: Controllability of an LLM-Driven Synthetic Population," arXiv:2607.00910 (2026-07-01) 【✔abstract実読・本文は未読】

SIVE実験: 架空自治体Montelago・**120体**の合成ペルソナ・7条件(強正〜強負)・7つの事前登録基準(fidelity / stability / noise floor / specificity / sensitivity / ordering)を温度スイープで評価 → **全温度で7基準すべて合格**。副産物として「弱正」と設計したメッセージを instrument が機能的に負と識別(較正失敗が診断成功に転化)。

→ **v2への含意**: 「外的妥当性(現実と合うか)より先に内的妥当性(自分の課した潜在構造を自分で回収できるか)を測れ」。**Phase 2初回5,000体の前に、120体規模の controllability テストを1本挟むのは安い保険**【推奨】。

**(c) 統合的な立場**: 前回答申 U-G が既に確認済みの Murata+ (IEEE TCSS 2022) 「日本の合成人口への従業地割当・市の割当精度88.2%」が、**「居住地固定の合成人口に職場を後付けできる」= 手元プール再利用の直接根拠**。本レーンはこれを否定する材料を見つけていない。

## Q5. 個体差パラメータの導出

### 5-1. 手元の材料は Big Five ではない

プールの `traits` は **`internal_locus` / `nfc`(need for cognition) / `risk_tolerance` の3次元**、いずれも一様乱数由来とみられる連続値(0-1)。加えて `drive_threshold` / `fire_weight` / `bedtime_min` / `sleep_steps` が個体ごとに存在。
→ **Big Five の実証(下記)を直接は使えない。3次元 → 行動パラメータの写像を新規に定義する必要がある。**

### 5-2. 性格 → 行動の実証(効果量は小さい)

**社交量**: 外向性・協調性は社会ネットワークのサイズと正の関連(高齢者コホート)。ただし**14年間の変化は予測しない**。
- 出典: "Personality Traits Predict Social Network Size in Older Adults" (PMC10226003) 【△検索要約のみ・本文未読 = 親の確認対象】
- SNS利用との相関は**小さい**: 神経症傾向 r̄ = 0.08、外向性 r̄ = 0.09(メタ分析・Computers in Human Behavior 97, 2019, doi:10.1016/j.chb.2019.03.009)【△検索要約のみ・本文未読】

→ **含意(重要)**: **r ≈ 0.1 は「性格から行動量を決める」根拠にならない。** 前回答申U-Gの結論(「分散は構造=名簿・伝記・活動性で作り、生成に頼らない」「活動性 a_i をエンジン側の外生パラメータとしてべき分布で配る」)と完全に整合する。
→ **推奨: 記憶転写率・関係辺の生成率は traits から連続写像するのではなく、`a_i`(外生べき分布)を主軸にし、traits は ±10-15% の弱い変調に留める。** これを超える写像はexpedient(強)として感度試験対象。

### 5-3. 決定論的導出(ハッシュ)の先行例

**確認できた設計パターン**:
- **SHA-256(global_seed, query_id, agent/tool名)のタプルをハッシュしてシードを導出**する完全決定論的環境生成(arXiv:2601.15322 系の記述)【△検索要約のみ・本文未読】
- 並列ABMでは「各ワーカが global_seed + worker_id から固有のサブ系列を得る」が標準。ただし「並列PRNGは隠れ相関やサブストリーム重複という実務上の問題を持つ」との警告も。(arXiv:1507.04047 "Parallelization Strategies for Spatial Agent-Based Models")【△検索要約のみ】

**v2への推奨(具体形)**:
```
param(agent_id, param_name) = f( int.from_bytes(sha256(f"{GLOBAL_SEED}|{agent_id}|{param_name}").digest()[:8]) )
```
- **利点**: (i) 40万体分のパラメータ表を保存しなくてよい(バイト予算に効く) (ii) 並列順序に依存しない=DP7でも再現 (iii) パラメータを1本追加してもそれ以前の値が動かない(`param_name` で名前空間分離)
- **注意**: **PRNGサブストリーム重複の警告**があるので、SHA-256の出力を**直接**値に写像し、PRNGのシードとして「使い回さない」こと。1パラメータ1ハッシュ。

| **5. 方面OD差し替え** | `residence_line` の一様を **第13回大都市交通センサスOD** の重みへ置換 | 方面別構成比 vs OD表の JSD | JSD < 0.01【推測ライン】 |
| **6. セル割当** | 自宅=町丁目別人口 / 勤務=経済センサス町丁目×産業 / 学校=学校台帳 | セル別体数 vs 現実側の相関、**空セル率** | 空セル率 0%・相関 r>0.9【推測ライン】 |
| **7. スケジュール生成** | Q4の3段(段0エンジン→段1 LLM→段2強制修正) | 時間収支残差・段2修正率・目的別JSD | 残差0分・修正率<20% |
| **(後) 診断のみ** | **D1′(KDDI)との比較を報告**。合わせに行かない | 年代TVD・性別差・在圏構成差 | **合否なし・台帳に「歪む場所」として記録** |

### 6-b. 5,000体(Phase 2初回)の抽出法

**★「同じ構成比の縮尺コピー」は不可。** 40万→5,000(1/80)にすると:
- 乗務員 1,299 → **16体**(駅員4・運転士1・車掌0)= **運行が成立しない**
- 指令 → **0体**
- 議員34 → **0体**

**推奨: 二層抽出**
1. **定員先取り層(縮尺しない)**: 乗務員・指令・議員・警察/消防など**機能に必要な最小定員をそのまま入れる**(概算300-400体)。この層は「街が動くのに必要」であって統計的代表性の対象ではない。**expedient宣言**。
2. **統計層(縮尺する)**: 残り約4,600体を 住民/通勤/来街 の**40万体版と同じ構成比**で層化抽出。各層内は**年齢×性別セルで比例配分**(単純無作為でなく層化=希少セルの消失を防ぐ)。

**holdoutを汚さない担保(3点)**
1. 抽出の重みに **D1′(KDDI)由来の値を一切使わない**。使うのは国勢調査・経済センサス・交通センサス・D10のみ。
2. 5,000体版の**年代/性別/在圏構成をD1′と比較する処理は、抽出パイプラインの外**(検証スクリプト側)に置く。コードレベルで分離する。
3. 比較結果を見て**抽出パラメータを触ったら、その時点でD1′はcalibrationへ降格**と台帳に書く(registry.yaml の `split` を書き換える)。これを**明文の掟**にする。
