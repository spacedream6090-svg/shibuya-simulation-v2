## ① 結論(推奨=知覚更新の規則・冒頭10行)

1. **「毎ステップ知覚」は物理的に不可能**。Generative Agentsの実装は10秒/ステップ=**8,640ステップ/シミュ日**[実読]、実測トークンは**約508,200 tok/体/シミュ日**[実読・算出]。v2の中央需要(400万呼/40万体=**10呼/体/日**・約16,280 tok/体/日。W1=24hで到達可能な帯はo128で約360-400万呼・o32で約600万呼=ベンチ第3段)は**呼び出し数で864分の1・トークンで31分の1**。規則を変えるしかない。
2. **知覚更新(エンジン)と認知起床(LLM)を別物として契約する**。前者はO(セル+移動体)の算術で毎tick回してよい。後者は**起床イベント**であり、これだけが予算対象。
3. **配送はpushでなくpull-on-wake**。「配送は全員」(人物観測M5)は*セル共有ブロックへの参照権*として実装し、個体へのコピーはしない。個体は起床時に自分の`last_seen_version`とセルの現バージョンを比較して差分を読む(Dirty Flag/UE Dormancy/Unity ECS change-versionの3系統が同一形に収束[実読])。
4. **変化の定義=「共有ブロックのバイト列のハッシュが変わったこと」**。このハッシュは①prefixキャッシュキー②変化検出器③dormant再送抑止の判定 の**三役を1つの成果物で果たす**(prefix経済とバイト一致の既決定を再利用=追加コストほぼゼロ)。
5. **量子化(Fruin LOS段・騒音4段)そのものを変化検出器に使い、必ずヒステリシスを付ける**(境界チャタリングは無限イベント源)。先例=UE AI Perceptionの Sight Radius / Lose Sight Radius の非対称[実読]。
6. **起床トリガは6類のみ**: (a)個体宛イベント(会話・接触・被害) (b)近接他者集合の差分(知人∩セル・上位k) (c)内受容の閾値割れ (d)計画境界(活動終了・日の開始) (e)**顕著性アキュムレータの閾値超え** (f)ハートビート(最大無起床間隔)。(e)以外はすべて先例あり。
7. **顕著性アキュムレータの先例は実在する**: Generative Agentsは「直近イベントの重要度スコアの総和が閾値(実装値**150**)を超えたら」内省を起こし、実測**1日2〜3回**[実読]。v2のT2目安0.5-2回/人/日と同じ桁。CrytekのADSRエンベロープ(attack/decay/sustain/release・ソース×イベント型ごとに1本・トラック値=最大値)[実読]が減衰つき蓄積の実装形。
8. **T0→T1昇格の判定は「習慣の前提条件の破れ=予測誤差」を第一とする**(既決定と一致)。理論的裏付けはEvent Segmentation Theory(予測誤差スパイク=イベント境界)[実読]、定量形はBayesian surprise(KL(prior‖posterior)がsurprisalより有意に人の分節を予測: r=0.10・97.7パーセンタイル)[実読]。
9. **需要が予算を超えたときは先着でなく価値順に配る**。先例=LOD Trader(criticality×audacity÷costで貪欲交換・オーバーヘッド**57µs/frame=フレーム時間の0.17%**)[実読]。ベンチの「必要19.8呼/s/GPUに対し実測9.94=ちょうど2倍不足」を、破綻でなく宣言つき劣化に変える唯一の装置。
10. **知覚潜時δ_percを思考時間δ_thinkから分離せよ**。現行はT1=δ_min=0.2秒固定だが、これは*予期せぬ事象への反応も0.2秒*を意味し非現実。単純反応時間213-231ms[実読]は予期ありの下限として整合するが、予期なし1.25秒・驚愕1.5秒[二次]とは合わない。δ_total = δ_perc(トリガ類別) + δ_think(既存α表)を提案。

## ② ユーザーがまず読む大枠

**問題の形**。「いつ知覚するか」は感覚の設計ではなく**予算の設計**である。R3-1〜7で「何を知覚するか」は決まった(構造化観測・可視性事前計算・5段人物観測・騒音2段半径・内受容3変数)。残った問いは「その観測をいつ個体の頭の中に入れるか」で、ここだけが**LLM呼び出し回数を直接決める**。

**先行の3つの流儀と、それぞれの死に方**。

| 流儀 | 代表 | 実測コスト | v2に効くか |
|---|---|---|---|
| **毎ステップ知覚+毎回「反応すべきか」をLLMに聞く** | Generative Agents | 10秒/ステップ=8,640ステップ/日・25体2日で25.41M tok[実読] | ✗ 40万体で2.0×10¹¹ tok/シミュ日 |
| **時間帯ごとの活動確率で抽選起床** | OASIS(100万体) | 1ステップ=3シミュ分に**18.0時間**・A100×27枚[実読]。1シミュ日=480ステップ=8,640時間 | ✗ しかもスケールが**約N^1.54**(超線形)=v1 runBの二乗爆発と同じ病 |
| **計画境界+固定間隔で再計画** | GATSim(都市交通) | 再計画は「日の開始・待ち時間・活動中の周期(一般30分床/就業150分床)・活動終了」[実読] | △ 骨格として採用可。ただし**顕著事象での割り込みが弱い** |

**v2が採るべき第4の形**。上の3つはいずれも「**エンジンが何を知ったか**」を起床判定に使っていない。v2は可視性を事前計算し、密度も騒音も内受容もエンジン側の数値として持っている——つまり**LLMを呼ばずに「今この個体にとって何が変わったか」をスカラーで測れる**。これはGenerative Agentsのimportance(LLMに毎回1-10で採点させる)を、**エンジン算術で置き換える**ということであり、コストが2桁変わる。この形の先例は見つからなかった(→⑤未発見)。

**人間側の根拠が「有界化」を支持する**。人は変化に驚くほど鈍い。周辺的な変化の検出には平均17.1回の交替(10.9秒)を要し、注目対象の変化でも7.3回(4.7秒)[実読]。課題に従事していると、目の前を横切るゴリラを**46%が見落とす**(192名)[実読]。同時に注意を向けられるのは4-5項目[実読]。したがって**「配送されたものが全部届く」実装はむしろ非現実**であり、有界化は性能上の妥協ではなく忠実度の要求である——ここは「歪む場所の宣言」ではなく**歪みを直す**方向に働く珍しい論点。

**最重要の設計判断は1行**: 変化検出のハッシュを、prefixキャッシュのキーと同一物にする。これで「変化検出のコスト」がほぼゼロになり、R3-8の未決論点(ブロック順序・isovist×セル共有の衝突)も同時に閉じる。

## ③ 問い1-6の証拠

### 問1. ゲームAIの刺激モデル(刺激→awareness蓄積→状態遷移)

#### 1-1. Unreal Engine AI Perception [実読: 公式ドキュメント]

出典: https://dev.epicgames.com/documentation/en-us/unreal-engine/ai-perception-in-unreal-engine

- 感覚は6種: AI Damage / AI Hearing / AI Prediction / AI Sight / AI Team / AI Touch。
- Sightのパラメータ(逐語):
  - Sight Radius: 「The max distance over which this sense can start perceiving.」
  - **Lose Sight Radius**: 「The max distance in which a seen target is no longer perceived by the sight sense.」
  - Peripheral Vision Half Angle Degrees / Auto Success Range from Last Seen Location / Point of View Backward Offset / Near Clipping Radius / Detection by Affiliation
  - **Max Age**: 「Determines the duration in which the stimuli generated by this sense becomes forgotten (0 means never forgotten).」
- **忘却は既定で無効**: Project Settings > Engine > AI System > **Forget Stale Actors** を true にして初めて Max Age が効く。
- 更新は**イベント通知**: `On Perception Updated`(更新されたアクタ配列)/ `On Target Perception Updated`(当該アクタ+AIStimulus構造体)。
- **更新頻度・性能コストの記述はドキュメントに無い**[実読で確認した不在]。

**v2への含意**: ①**Sight Radius ≠ Lose Sight Radius という非対称は、そのままヒステリシスの正典形**。v2の順序尺度(Fruin LOS段・騒音4段)にも「上がる閾値」と「下がる閾値」を別に持たせるべき。②Max Age=「刺激の賞味期限」は、v2のdormant配送に対する対概念(いつ忘れるか)。**R3-3のdormant配送は「変化まで再送しない」だけを決めており、「いつ古くなるか」を決めていない**——ここはR3-8で埋めるべき穴。

#### 1-2. Crytek Target Tracks Perception System (Game AI Pro 1, Ch.31, Rich Welsh) [実読: PDF全文抽出]

出典: http://www.gameaipro.com/GameAIPro/GameAIPro_Chapter31_Crytek's_Target_Tracks_Perception_System.pdf

- **Stim(刺激)の構造**(逐語): 「The type of stimulus being generated…, the entity ID of the source, the position or direction from which the stimulus originated, and a radius within which that stimulus can be perceived.」
- **3段の事前フィルタ**(コスト削減の本体):
  1. **購読**: 「Having agents subscribe to event types that they are interested in and comparing that to the event type of a stim makes this a very cheap test.」
  2. **半径**: 「by looking at both the perception range of each agent and the perceivable radius that is part of the stim data. If the agent is too far away to perceive this stim, then it can be discarded.」
  3. **所属フラグ**: 「event types can be registered with flags such as "hostile only"」
- **視覚だけはpull型で内製**: perception managerが全AIを走査し、視距離とFOV内なら**非同期レイキャスト**を発行。逐語:「As raycasts are expensive to perform and the visibility tests aren't urgent enough to require the results within the same frame, requesting deferred raycasts is perfectly acceptable.」
- **Target Track**: ターゲット1体につき1本のコンテナ。**「Each Target Track will only remember a maximum of one envelope per event type.」**(同型の新刺激は既存を更新するだけ=イベント数が飽和する)。トラックの値=**内包エンベロープの最大値**。
- **ADSRエンベロープ**(音楽のADSRから命名)の4相:
  - Attack: ignore time(知覚遅延・「faking speed of sound delays」用)、peak value、time。0→peakへ上昇。
  - Decay: peakから sustain 値へ微減。理由の逐語:「so that new stims have a chance of being recognized as a higher priority over stims that have been sustained for a while」
  - Sustain: peakの指定分数で維持。刺激が有効な限り継続。
  - Release: 刺激が無効化(音が止む/LOSが切れる)した時点から緩やかに0へ。途中で有効化されれば戻る。

**v2への含意**: **これがv2の顕著性アキュムレータの実装形の第一候補**。特に「(ソース×イベント型)ごとに1本・トラック値=最大値」は**イベント数を体数×型数で上に抑える**構造で、40万体で必須。Releaseフェーズ=忘却曲線=UEのMax Ageの連続版。ignore time は R3-7 の音速遅延・R3-8のδ_percにそのまま使える枠。

#### 1-3. Splinter Cell Blacklist (Game AI Pro 2, Ch.28, Martin Walsh) [実読: PDF全文抽出]

出典: http://www.gameaipro.com/GameAIPro2/GameAIPro2_Chapter28_Modeling_Perception_and_Awareness_in_Tom_Clancy's_Splinter_Cell_Blacklist.pdf

- **知覚と気づきの定義**(逐語): 「awareness is a set of discreet mental states (levels of awareness) that represent an increasingly more detailed understanding of the thing being perceived and that can be reached progressively over time through sensory perception.」
- 実装は「進捗バー」だが、NPC側の状態は実質2値(「I don't see anything suspicious」/「that's enemy #1 over there!」)+中間の1状態(調査に行く)。
- 視覚: プレイヤーの**8本のボーン**にレイキャスト。姿勢に応じた本数が見えたら**検出タイマー**が起動。タイマーの全長は「プレイヤーがいる検出形状」で決まり、距離で線形スケール。
- 形状はcone→box→**coffin(棺)型**へ進化(遠距離で横に広がるconeの不自然さの解消)。
- **閾値の残酷さ**(逐語): 「If the player is 1 cm outside of that threshold, then the NPC will stand there forever without seeing the player. One centimeter inside and the player will be detected within a couple of seconds at most.」
- 聴覚: 「every audio event has a radius and priority; if an NPC is in range of the event, he will hear it and react differently based on the event, who else is in range, and his current state.」
- **音の距離はユークリッドでなく「エリアパス」**(部屋の連結グラフ上の choke point 経由の折れ線距離)。「Although this is clearly a rough approximation, in practice, the results were accurate enough that we made the switch and never looked back.」
- 公平性のための調整: 画面外かつ十分遠いNPCは**特定イベントの聴覚を1/2に**。原則の逐語:「in the case of player perception versus simulation accuracy, player perception should win.」
- **性能・更新頻度の数値は本章に無い**[実読で確認した不在]。

**v2への含意**: ①「気づき=離散的心的状態を漸進的に登る」はv2の認知LOD(T0/T1/T2)と同型。②**閾値の残酷さは v2 の量子化観測にそのまま伝染する**(密度bandの境界で行動が不連続に飛ぶ)→ヒステリシス+最小滞留時間が必須。③「エリアパスで音距離」はR3-7の街渓谷補正と同じ発想の粗い版で、v2の方が精密(ASJ RTN+密度項)。④**「プレイヤーの知覚が勝つ」原則はv2では逆**(観測者がいない=世界そのものがプロダクト)。ここはゲーム知見の**輸入禁止項**として明記すべき。

#### 1-4. UE Actor Network Dormancy [実読: 公式ドキュメント]

出典: https://dev.epicgames.com/documentation/unreal-engine/actor-network-dormancy-in-unreal-engine

- 逐語: 「Actor Network Dormancy (`AActor::NetDormancy`) is one of the most impactful server optimizations a multiplayer project can make, potentially saving multiple milliseconds of server CPU time per frame.」
- 状態5値: DORM_Never / DORM_Awake / DORM_DormantAll / DORM_DormantPartial / DORM_Initial。
- `FlushNetDormancy`: 「forces the actor to replicate at least one update to all connections on which it is relevant without actually changing its dormancy state.」
- **重要な逆警告**(逐語): 「Actors that require frequent updates, such as pawns, are not likely to benefit, and, due to the additional overhead of changing or flushing an actor's dormancy state, doing this too frequently might be even less performant than just keeping the actor awake.」

**v2への含意**: R3-3の「dormant配送(変化まで再送しない)」は正しいが、**高頻度で変わるブロックにdormantを付けると逆効果**。→ ブロックを変化率で階層化する必要がある(→④のブロック順序提案)。

### 問2. LLMエージェントの再知覚トリガ(いつLLMを呼ぶか)

#### 2-1. Generative Agents (Park et al. 2023) [実読: ar5iv HTML + 公開リポジトリの設定ファイル]

出典: arXiv:2304.03442 / https://ar5iv.labs.arxiv.org/html/2304.03442 / GitHub joonspk-research/generative_agents

- **毎ステップ知覚**: 「The sandbox server is also responsible for sending all agents and objects that are within a preset visual range for each agent to that agent's memory.」/「At each time step of the sandbox engine, the agents output a natural language statement describing their current action.」
- **反応判定プロンプト**(逐語): 「[Agent's Summary Description] It is [date/time]. [Agent name]'s status: [status]. Observation: [observation]. Summary of relevant context from [Agent]'s memory: [context]. **Should [Agent] react to the observation, and if so, what would be an appropriate reaction?**」
- **割り込み=計画の再生成**: 反応が起きた時点から既存計画を作り直す。
- 計画の粒度: 日→時間→**「We then recursively decompose this again into 5–15 minute chunks」**
- 想起スコア: 「score = α_recency·recency + α_importance·importance + α_relevance·relevance」・**減衰係数0.995**・「all α's are set to 1」
- 重要度プロンプト: 「On the scale of 1 to 10, where 1 is purely mundane … and 10 is extremely poignant …」
- **内省トリガ**(逐語): 「we generate reflections when the sum of the importance scores for the latest events perceived by the agents exceeds a threshold (**150** in our implementation).」/「In practice, our agents reflected roughly **two or three times a day**.」
- **コスト**(逐語): 「The present study required substantial time and resources to simulate 25 agents for two days, costing thousands of dollars in token credits and taking multiple days to complete.」
- **リポジトリ実測値**[実読: raw.githubusercontent.com]:
  - `meta.json`: **`"sec_per_step": 10`**(1ステップ=10シミュ秒 → **8,640ステップ/シミュ日**)
  - persona `scratch.json`: **`vision_r: 8`, `att_bandwidth: 8`, `retention: 8`**(視界半径8タイル・1ステップで拾う観測の上限8件・保持8)、`recency_decay: 0.995`、`importance_trigger_max: 150` / `importance_trigger_curr: 150`、`daily_reflection_time: 180`, `daily_reflection_size: 5`

**v2への含意(最重要)**:
- **`att_bandwidth: 8` は「1ステップの観測を上位8件で切る」という有界化の既成事実**。v2のM2「近接他者上位k=3-4」はこれより厳しいが同型。
- **`importance_trigger_max: 150` は顕著性アキュムレータの実在する先例**。v2との違いは、GAは重要度をLLMに毎回採点させる(高い)のに対し、v2はエンジン算術で出せる(ほぼ無料)。**この置換がv2の独自性の中核**。
- 減衰0.995/ステップ=10秒 → 半減期は log0.5/log0.995 ≈ 138.3ステップ ≈ **23.1分**[算出]。v2の顕著性アキュムレータの減衰時定数の初期値の目安になる。

#### 2-2. OASIS(100万体・ソーシャルメディア) [実読: arXiv HTML v4]

出典: arXiv:2411.11581 / https://arxiv.org/html/2411.11581v4

- **Time Engine**: 「each agent is initialized with a 24-dimensional vector representing the probability of activity in each hour」=**時間帯別の活動確率での抽選起床**。全員同時起床はしない。
- **1ステップ=3シミュ分**(逐語: 「one time step is equal to 3 minutes in OASIS.」)
- **効率表(Table 2)**[実読・HTML抽出]:

| 規模 | 1M | 100K | 10K |
|---|---|---|---|
| 1ステップあたり時間(h) | **18.0** | 3.0 | 0.2 |
| GPU(A100) | 27 | 5 | 2 |
| 新規ツイート/ステップ(K) | 48.5 | 5.2 | 0.6 |
| 新規コメント/ステップ(K) | 97.1 | 9.0 | 0.9 |

- 別記述: 「using five A100 GPUs, we can simulate the interactions of 100,000 users over 10 time steps within two days.」(=4.8h/ステップ。表の3.0hと同オーダーだが不一致。**どちらかが別条件**[実読・矛盾を確認])

**v2への含意**:
- GPU時間で規格化すると 10K:0.4 / 100K:15 / 1M:486 GPU·h/ステップ → **スケール指数 ≈ N^1.51〜N^1.57**[算出]=**超線形**。原因は推薦システム(全ユーザー×全投稿)と推定[推測]。
- **これはv1 runBのSNS推薦 ranked_timeline_for の二乗爆発と同じ病**(既知の教訓)。v2の知覚契約は**「イベント数がO(体数×可視物数)にならないこと」を契約テストにすべき**。
- 1シミュ日=480ステップ → 100万体で 8,640時間 = **360日/シミュ日**。「体数を増やす」ではなく「1体あたりの起床を減らす」以外に道がない、の実測証拠。

#### 2-3. GATSim(都市交通・生成エージェント) [実読: arXiv HTML v2]

出典: arXiv:2506.23306(Qi Liu, Can Li, Wanjing Ma)/ https://arxiv.org/html/2506.23306v2

- **再計画トリガの列挙**(逐語):
  1. 「simulation day initiation」
  2. 「waiting periods at network nodes such as traffic intersections or transit stops」
  3. 「periodic intervals during ongoing activities based on reflection frequencies」
  4. 「natural transition points when activities conclude」
- **反省頻度の床**(逐語): 「global minimum intervals of **30 minutes** for general activities and extended intervals of **150 minutes** for work activities.」
- **知覚の3チャネル**(逐語):
  - 「Spatial perception monitors nearby network events and conditions within the agent's immediate vicinity」
  - 「Social perception maintains awareness of family member states, friend activities, and coworker conditions」
  - 「Broadcast perception receives system-wide announcements including weather alerts, major events, infrastructure disruptions」
- 規模: 「a synthetic population of 70 individuals」/「13-node network」。**LLM呼び出し数・トークン・実時間の開示なし**[実読で確認した不在]。ステップ幅の明示もなし(「discrete-time orchestration」のみ)。

### 問3. 顕著性・変化検出(何を「変化」と呼ぶか・人間の有界性)

#### 3-1. Change blindness: Rensink, O'Regan & Clark 1997 [実読: 原典PDF全文抽出]

出典: Rensink, R.A., O'Regan, J.K., Clark, J.J. (1997) "To See or not to See: The Need for Attention to Perceive Changes in Scenes", *Psychological Science*, 8(5), 368-373. PDF: https://www2.psych.ubc.ca/~rensink/publications/download/PsychSci97-RR.pdf

- 手続き: 画像**240 ms**表示・空白**80 ms**の交替(1周期640 ms)。画像27°×18°。各実験10名。同定エラー率は全実験平均**1.2%**。
- 関心度の定義: 5名の naive observer が場面を口頭記述し、**3名以上が言及した対象=Central Interest (CI)**、それ以外=**Marginal Interest (MI)**。
- **実験1の結果**(逐語):
  - MI: 「requiring an average of **17.1 alternations (10.9 s)** before being identified; indeed, for some images observers required over **80 alternations (50 s)**」
  - CI: 「with an average of **7.3 alternations [4.7 seconds]**」
  - **空白を除いた対照**: 「identification required only **1.4 alternations (0.9 s)**」・CI/MI差も型間差も有意でない(p>0.3)
- 図2の個別例: MI 16.2交替(10.4s)/ CI 4.0交替(2.6s)
- 注意容量: 短時間呈示実験の検出成績は「corresponded to a monitoring of **4-5 randomly-selected items**, a value similar to the number of items that can be simultaneously attended (Pashler, 1987; Pylyshyn & Storm, 1988; Wolfe, Cave & Franzel, 1989)」

#### 3-2. Inattentional blindness: Simons & Chabris 1999 [実読: 原典PDF全文抽出]

出典: Simons, D.J. & Chabris, C.F. (1999) "Gorillas in our midst: sustained inattentional blindness for dynamic events", *Perception*, 28, 1059-1074. PDF: http://www.chabris.com/Simons1999.pdf

- **全体**: 「Out of all 192 observers across all conditions, **54% noticed** the unexpected event and **46% failed to notice**」
- 課題難度: 「More observers noticed the unexpected event in the **Easy (64%)** than in the **Hard (45%)**」
- 事象種別: 「Umbrella Woman was noticed more often than the Gorilla overall (**65% versus 44%**)」

#### 3-3. 変化検出の理論: Event Segmentation Theory と Bayesian surprise [実読: 二次レビュー+原著論文]

- **EST(Zacks, Speer, Swallow, Braver, Reynolds 2007)**の中核[実読: レビュー記述]: 人は「working event model」を保持して次を予測し、**予測誤差が急上昇したときにイベントモデルを更新する。その更新体験がイベント境界である。** 感覚入力からイベントモデルへの経路は**誤差検出でゲートされている**(予測が当たっている間、感覚入力はモデルに到達しない)。
- **定量形**: Kumar, M., Goldstein, A., Michelmann, S., Zacks, J.M., Hasson, U., Norman, K.A. (2023) "Bayesian Surprise Predicts Human Event Segmentation in Story Listening", *Cognitive Science*, 47(10), e13343. https://doi.org/10.1111/cogs.13343 [実読: PMC11654724]
  - Bayesian surprise = 事前分布と事後分布の**KLダイバージェンス**。実装式(逐語): 「Bayesian surprise(Pt,Pt−1)=−∑ pv·log(qv/pv)」
  - 結果: **transient Bayesian surprise**(drift=0.10・20語窓)が **r=0.10(97.7パーセンタイル)**、AIC比較でも最良。対照の **surprisal(次単語の確率だけ)は窓幅を通じてほぼゼロ〜負相関**。
  - 逐語の要点: 「Bayesian surprise factors in the shape of the entire probability distribution, whereas surprisal only factors in the probability of the next word.」
  - 素材: 「Monkey in the Middle」(30分)、「Pieman」(7.5分)、「Tunnel Under the World」(25分)、区間あたり30-42名。**境界の毎分頻度の集計値は本文に無し**[実読で確認した不在]。
- **予測誤差を行動トリガに使う工学先例**: Pathak, Agrawal, Efros, Darrell (2017) "Curiosity-driven Exploration by Self-supervised Prediction", arXiv:1705.05363 [実読: abstract]。逐語:「the error in an agent's ability to predict the consequence of its own actions in a visual feature space learned by a self-supervised inverse dynamics model」を内発報酬に。

**v2への含意**:
- **「予測誤差でゲートする」はESTの本体であり、v2の既決定「T1は習慣の前提条件が破れた時に発火」と完全一致**。理論名を答申に載せておく価値がある(方法論の正当化に効く)。
- **surprisalでなくBayesian surpriseが効く、という結果はv2に直接効く**: 「観測値が意外だった」ではなく「**観測後に信念分布の形が変わった**」を測れ、ということ。v2でこれを安価に近似するなら「**量子化された観測ベクトルのbandが変わったか**」が事実上のKL近似になる(bandが変われば分布の形が変わる)。→ **量子化=変化検出=surprise近似の三位一体**。
- 人の有界性の数値(46%見落とし・MI変化に10.9秒・注意4-5項目)は、**v2の有界化が「性能のための妥協」でなく「忠実度の要求」であること**の根拠。特に **Rensink の「4-5項目」は既決定の M2「近接他者上位k=3-4」を独立に支持する**。

### 問4. 認知LODとの接続(T0→T1昇格の条件設計)

#### 4-1. 予算制約下のLOD配分: LOD Trader (Game AI Pro 1, Ch.14, Ben Sunshine-Hill) [実読: PDF全文抽出]

出典: http://www.gameaipro.com/GameAIPro/GameAIPro_Chapter14_Phenomenal_AI_Level-of-Detail_Control_with_the_LOD_Trader.pdf

- 距離ベースLODの否定(逐語): 「There's no "LOD threshold distance" we could pick which would respect our budget and give most visible characters the detail we want.」
- 目的(逐語): 「It attempts to maximize the realism of the game simulation without going over the computation budget, and does it in a remarkably short period of time (tens of microseconds).」
- **BIR(Break in Realism)の3分類**——LOD低下が壊すものの型:
  - **US(Unrealistic State)**: 今この瞬間の状態が変(空の皿から食べる等)。「US's don't require any long period of observation, only momentary attention」
  - **FD(Fundamental Discontinuity)**: 「a character's current state is incompatible with the player's memory of his past state」——角を曲がった隙に消える、留守中ずっと固まっていた等。**観測されていない間に起きても、記憶と戻ってきた時の齟齬として顕在化する。**
  - **ULTB(Unrealistic Long-Term Behavior)**: 長時間観察して初めて分かる(目的なくうろつく・ガス欠しない車)。
- criticality の因子: US = observability × attention / FD = memory × return time / ULTB = duration
  - observability: 「proportional to the amount of screen space (or number of pixels) p_i … divided by some "saturation size" p_sat」、p_sat は「a fully visible character 4 meters away」
  - attention: observability の EMA(**k=2 → 1.5秒で95%減衰**)+ focusing項(カメラ前方ベクトルとの内積のEMA)を重み **0.7 / 0.3** で合成。さらに全キャラの合計 attentional load L(+定数の ambient load)で割って**注意の有限性**を表現。
  - return time: Weibull分布のフィットで **k ≈ 0.8**
- **配分アルゴリズム**: 上げ(upgrade)/下げ(downgrade)の各遷移について value = realism改善 ÷ 相対コスト増 を計算し、優先度キューで貪欲に交換。予算超過するまで上げ、超えたら最も価値の低い下げを繰り返す。
- **実測**(逐語): 「its average execution time was **57 microseconds per frame, or 0.17% of the target frame time**. Its memory usage was **500 kB** for the transition data and **48 bytes per entity**」/ 対象は「hundreds of characters」「eight separate features」「hundreds of potential feature solutions」
- 検証: 盲検実験で距離ベースLODよりBIRの経験頻度が有意に少ない [Sunshine-Hill 11]。

**v2への含意(設計の核)**:
- **v2は同じ問題に既に直面している**: ベンチ結論「中央400万呼=16h・高端800万=32h・必要19.8呼/s/GPUに対し実測9.94=ちょうど2倍不足」。**LOD Traderは「予算を超えたときに何を諦めるか」を宣言的に決める装置**であり、v2に欠けている唯一の部品。
- **BIRの3分類はそのままv2の「知覚を遅らせると何が壊れるか」の分類になる**:
  - US → 状態の不整合(店員がいないのに商品が減る)
  - **FD → dormant配送の固有リスク**。「変化まで再送しない」と、久しぶりに起床した個体の記憶と世界が不連続に飛ぶ。**FDは観測されていない間に起きても顕在化する**という指摘は、dormant設計への直接の警告。→ 起床時に「前回からの差分要約」を必ず渡す規則が要る。
  - ULTB → 長期の行動が不自然(T0習慣だけで1日回した個体が同じ行動を反復)。→ ハートビートの存在理由。
- **48 bytes/entity** は v2 の個体予算(≤30KB/体)に対して無視できる。40万体で19.2MB。
- ただし v2 は 400,000 体で「hundreds」ではない → 全体ソートは不可。**バケット化優先度(顕著性を16段に量子化してバケットから取る)でO(N)化**を提案[推測: 私の設計案]。

#### 5-2. v2でのイベント数の試算 [算出・前提は明示]

前提: bbox 1.39 km²、場所セル(prefix共有単位)100m級 ≈ **139セル**、可視性格子2.5m = 222,400セル(**静的**=変化検出不要)、40万体。

### 問6. 時間の整合(知覚→判断→行動の遅延と現実の反応時間)

#### 6-1. 単純反応時間 [実読]

Woods, D.L., Wyma, J.M., Yund, E.W., Herron, T.J., & Reed, B. (2015) "Factors influencing the latency of simple reaction time", *Frontiers in Human Neuroscience*, 9, 131. https://doi.org/10.3389/fnhum.2015.00131

- 実験1(**1,469名**・18-65歳): 生値 **231 ms** / ハードウェア補正 **213 ms**
- 実験2(**189名**・18-82歳): 生値 **238 ms** / 補正 **220 ms**
- 歴史的基準: Galton(1884-1893)の視覚SRT **181-189 ms**

**v2への含意**: **既決定の δ_min = 0.2秒(Stivers 2009のターン間隙)は、視覚単純反応時間(213-231ms)とも独立に一致する**。2経路の収束=δ_minは頑健。ただしこれは**「予期している刺激」への下限**である。

#### 6-2. 予期の効果 [二次: 原典未読]

Green, M. (2000) "'How Long Does It Take to Stop?' Methodological Analysis of Driver Perception-Brake Times", *Transportation Human Factors*, 2(3), 195-216. https://doi.org/10.1207/STHF0203_1

複数の二次情報が一致して伝える数値[二次・**原典未読**]:
- 予期あり(タイミングも場所も既知): **0.70-0.75 秒**
- 予期なしだがよくある信号(先行車のブレーキランプ): **約1.25 秒**
- 驚愕事象(物体が突然進路に入る): **約1.5 秒**
- 「最も重要な変数はドライバの予期であり、RTを2倍変える」

同様に[二次・原典未読]、歩行者のモーションキャプチャ研究で「平均 perception-reaction time **0.48秒**・平均 start-up time delay **0.39秒**」との報告(Transportation Research Interdisciplinary Perspectives系・ScienceDirect S2214367X23001102。403で本文取得できず)。

#### 6-3. 三時計との整合 [設計上の指摘]

現行の決定は δ = max(δ_min, α×出力token) で、**T1は「δ_min固定(比例なし)」**。これは思考時間としては正しいが、**知覚から反応開始までの潜時をゼロと置いている**。結果:
- 突発事象(叫び声・接触・車の急接近)に対して、40万体全員が **0.2秒**で反応を開始する。
- 現実の予期なし反応は 1.25-1.5秒[二次]。**約6-7倍速い集団**になる。
- 影響が出る場所: 群衆の衝撃波伝播速度、避難・回避挙動、会話の割り込み、広告の注意ゲート(注視0.9-3.3秒の枠と整合しない)。

→ **δ_perc の導入を提案**(→④)。

### 4-1. 知覚更新の規則(契約の本体・6条)

**第1条(二層分離)**: 「知覚更新」と「認知起床」を別の契約とする。
- **知覚更新**=エンジン側のSoA算術。毎物理tick回してよい。LLMを呼ばない。予算は物理側。
- **認知起床**=LLM呼び出しの発生。予算はW1/L2。**契約テスト: 知覚更新の回数は起床回数の上限にならない**(独立であることを型で示す)。

**第2条(pull-on-wake)**: セル共有ブロックはpushしない。各セルは `version` と `hash` を持ち、個体は起床時に自分の `last_seen_hash` と比較して差分だけを読む。
- 「配送は全員」(人物観測M5決定)は**参照権の意味に読み替える**——同一バイト列を全員が読む権利があり、実体コピーは発生しない。**決定文の意味論は保存される**。
- [先例] Dirty Flag(「defer until the result is needed」)/ UE Dormancy / Unity ECS `DidChange`。

**第3条(変化=共有ブロックのハッシュ変化)**: 変化検出器はセル共有ブロックの**シリアライズ済みバイト列のハッシュ**とする。
- このハッシュは **①prefixキャッシュキー ②変化検出器 ③dormant再送抑止の判定** の三役。
- prefix経済(バイト一致・実測1.6-2.0x)のために**どのみちバイト列を作る**ので、追加コストはハッシュ計算のみ(139セル×数KB×毎tick)。
- Unity ECS 方式(バージョン番号)の偽陽性問題を**構造的に回避**できる[実読: 偽陽性の存在を公式ドキュメントで確認]。

**第4条(量子化=検出器・ヒステリシス必須)**: 密度(Fruin LOS段)・騒音(4段)・混雑・明るさ等の順序尺度は、**量子化そのものが変化検出器**である。ただし境界チャタリングを禁じる:
- 上昇閾値 ≠ 下降閾値(ヒステリシス幅 h)。[先例] UE `Sight Radius` vs `Lose Sight Radius`。
- 新bandの**最小滞留時間 T_hold**(提案初期値 60秒)を満たして初めて変化とする。
- 初期値提案: h = band幅の10%、T_hold = 60秒。**両方 expedient タグ+±50%感度試験**(騒音 hear_radius と同じ扱い)。

**第5条(FD対策=起床時の差分要約)**: 起床した個体には必ず「前回起床からの差分要約」を渡す。
- [先例] LOD Trader の **FD(Fundamental Discontinuity)BIR**: 「観測されていない間の変化でも、記憶と再訪時の齟齬として顕在化する」。dormant配送の固有リスクはこれ。
- 差分要約は**構造化スロットの差分**(band変化・可視物の出入り・知人の出入り)であり、LLM生成でない(=無料)。

**第6条(知覚潜時の分離)**: δ_total = **δ_perc(トリガ類)** + δ_think(既存α表)。

| トリガ類 | δ_perc 提案値 | 根拠 |
|---|---|---|
| 計画境界・自発(予定済み) | 0 | 起床が既に予定されている |
| 予期ありの刺激(信号・呼びかけ待ち) | 0.2 秒 | Woods 2015 SRT 213-231ms[実読]・Stivers δ_min[既決] |
| 予期なしのよくある事象 | 1.25 秒 | Green 2000[二次] |
| 驚愕(突発・接触・叫び) | 1.5 秒 | Green 2000[二次] |

- **[二次]の2値は expedient タグ+±50%感度試験を義務**とする(騒音と同じ規律)。
- 「予期あり/なし」の判定は**T0習慣の前提条件で決まる**(習慣が予期していたか)=EST の予測誤差ゲートと同型[実読]。追加のLLM呼び出しは不要。

### 5-4. R3-8起草時に私が判断できなかった論点(ユーザー判断が要る)

1. **δ_perc の導入は「現実整合の改善」か「複雑さの追加」か**。導入すると突発反応が現実的になるが、パラメータが4つ増え、うち2つは[二次]の値。**入れない選択も合理的**(その場合「v2のエージェントは驚愕反応が6倍速い」を**歪む場所として宣言**する)。
2. **p_notice(注意到達確率)の初期値**。Simons & Chabris から 0.5(課題従事下)/ 1.0(手空き)/ 0.45-0.64(負荷勾配)が引けるが、これは**実験室の値で渋谷の値ではない**。expedient+感度試験で入れるか、そもそも数値を置かず「較正データが現れるまで保留」(R3-4嗅覚と同じ扱い)にするか。
3. **ハートビートの有無**。入れると居住者の起床が1日2-3回増えて予算を圧迫する。入れないと ULTB BIR(T0だけで1日回った個体の長期挙動が不自然)が出る。**「夜間T2内省が1日1回ある」ことでULTBは既に部分的に救われている**ので、ハートビートを落とす選択が予算上は有利[推測]。
4. **試算(D)の696万呼をどう400万呼に落とすか**。私の推奨は ①ハートビート廃止(-2〜3) ②計画境界の床をGATSimより緩く(一般30分→60分)(-3〜5) ③出力長T1=32tok上限(U19)。この3手で平均12前後まで落ちるが、**なお10には届かない**。**残りはアービタによる繰り延べで吸収する=「予算内に収める」でなく「予算内に収まるまで遅らせる」**という設計思想の転換が要る。ここはユーザー決定事項。
