## 0. 宣言 — **これは選定器ではない**

**本プローブは「足切り器 + 観測削減の安全確認器」である。モデル選定(U14)の最終根拠にはならない。**

理由は統計である。81項目・3モデル・n<100 の規模では、**検出可能な最小差は12〜25ポイント**(不一致率依存・検出力80%)であり、10ポイント差の判定はできない。分野の推奨規模は新規evalで1,000問である。

したがって本プローブが出せる結論は、次の3つに限られる。

- **(a) 足切り**: 明白な破綻(制約違反率・書式エラー率・日本語文字比率)の検出。破綻頻度30%対5%のような大きな差なら見える。
- **(b) 観測削減の安全確認**: 契約書v1(1,300tok)がv0(1,800tok)と同じ判断をするか。**これがv0で最も価値の高い測定**であり、W1予算(o64で14.8h対24.6h)という不可逆の決定の、唯一の品質側の裏付けになる。
- **(c) 32B級の存在判定**: 「32Bでないと解けない項目が実在するか」。存在の有無の問いなので少数例でも意味がある。

**本選定は Phase 2-3 の eval 基盤で n≥300 の拡張版を用いて行う。v0が作る資産は「固定評価セットの初版」である。**

## 2. 問題セットの構成(81問・171呼/モデル)

| 系統 | 問数 | 判定 | max_tokens | 主な指標 |
|---|---|---|---|---|
| ① T1行動判断+ひと言 | 8 | 機械(制約充足・gold) | 64 | `violation_rate`(所持金/営業時間/物理/条例/所持スロット)。1問は過剰拒否の対照、1問は突発反応のgold |
| ② 会話の切り上げ | 6 | 機械(主)+LLMペア(従) | 64 | 終了合図の検出・断るべき誘いの拒否・過剰拒否の対照1問 |
| ③ 役割知識QA | 10 | 機械(正規表現・完全一致) | 32 | `qa_accuracy`。正答が法令・条例・公式手引きで一意のものだけ |
| ④ T2内省 | 6 | 機械(ログ照合)+目視 | 256 | `hallucination_rate`(ログにない事実主張)・`recall_rate`(顕著イベントの再現) |
| ⑤ 裁定の一貫性 | 6(同型ペア3組) | 機械(裁定+差分スキーマ) | 128 | 裁定のgold一致・差分スキーマ検証・**同型ペアで同じ裁定を出すか** |
| ⑥ 観測削減の判断一致率 | **45場面 × 3水準 = 135呼** | 機械(一致率) | 64 | `agree_v0_v1` / `agree_full_v1` / `agree_full_v0`(行動・行き先[完全/隣接許容])+ Wilson LB95 |

**③だけは system ブロックに役割知識を載せていない。** ①②④⑤⑥のsystemには条例・営業時間・所持の規則が書いてあり(=「知っているか」ではなく「適用できるか」を測る設計)、同じsystemを③に使うと**答えがsystemに書いてあることになる**。③は知識の想起そのものを測るので、憲法・出力規約だけの短いsystem(約255tok)を使う。

**合計 81項目 / 1モデルあたり 171呼**(36 + 135)。3モデルで513呼。
参考: ベンチ第5段のDP7実測は v1サイズ・o64 で 75.3呼/s。**GPU時間は分オーダー**である。

⑥の層構成(**顕著性の尾を意図的に厚くしてある**):

| 層 | 場面数 | 内容 | v1で落ちる駆動情報 |
|---|---|---|---|
| plain(平凡) | 15 | 平常密度・顕著行為なし・内受容も閾値内 | なし(対照群。ここで不一致なら測定系が壊れている) |
| mid(境界) | 15 | 閉店5分前5・密度/騒音段階の跨ぎ5・条例の境界時刻5 | 閉店5場面のみ(B2看板の3番目以降) |
| tail(顕著性の尾) | 15 | 傍受5・広告4・顕著行為の競合3・知人が近接4位3 | **15場面すべて** |

事前登録: **45場面のうち20場面を「v1で駆動情報が落ちる=不一致のリスクあり」と測定前に宣言してある**(`expected.predicted_disagreement`)。事後に不一致を説明するのではなく、**予測が当たったかを見る**。

**注意**: この層構成(15/15/15)は運用時の場面分布よりはるかに敵対的である。運用では平凡な場面が大半を占める。したがって集計では、混合セット全体の一致率に加えて**層別の一致率**と、宣言つきの運用分布(`scorer.TIER_PRIOR` = plain 0.80 / mid 0.15 / tail 0.05)で再重み付けした値を併記する。**この重みは仮定であって実測ではない。**

## 3. 観測3水準の切り詰め規則(=試験対象そのもの)

契約書§2.2の予算に合わせて、同じ場面を3通りに描画する。

| 要素 | full(参照上界) | v0(1,800tok) | v1(1,300tok・決定候補) |
|---|---|---|---|
| B0 共通静的(役割知識) | 長(上位集合) | 中 | **中(v0と同一)** |
| B2 可視物 | 12件 | 8件 | 3件 |
| B2 看板(店頭表示) | 7件 | 4件 | 1件 |
| B2 構成・印象 | 6+4行 | 1+1行 | 0 |
| B4b 近景(25m級) | 3件 | 2件 | 1件 |
| B4 顕著行為 | 3件 | 2件 | 1件 |
| B5 近接人物 | 上位4 | 上位4 | 上位3 |
| B5 傍受 | 2件 | 1件 | **なし** |
| B5 広告 | あり | あり | **なし** |
| B5 被注視 | 常に(空でも固定文言) | 常に | 閾値超のみ |
| B5 固定文言(関係・可視差分・所持2行目) | あり | あり | **なし** |
| B5 直近・記憶 | 3+3行 | 2+1行 | 0 |
| **概算トークン(平均)** | **3,108** | **1,875** | **1,327** |

**v0とv1のB0(共通静的)は同一にしてある。** 契約書の静的予算差は800対750=50tokしかなく、ここで役割知識の量まで変えると「観測の削減」と「役割知識の削減」が交絡するため。
→ **主ゲートは `agree_v0_v1`**(静的が同一・セル依存部と個体部だけを削った清浄な対比=これがまさにv0→v1の予算決定)。
→ `agree_full_*` は full の静的が上位集合であるぶん**交絡を含む**。副次指標として報告する。

概算トークンは「1.30文字/トークン」という粗い係数による**推定**である。真値は測定時にAPIの `usage.prompt_tokens` として `quality_ledger.csv` の `prompt_tokens` 列に記録される。**Qwen3系トークナイザの日本語効率の実測値は未入手**なので、この係数は当てにしないこと。

## 4. 実行手順

### 4-0. 前提(サーバー側)

- 各vLLMサーバーを **`VLLM_BATCH_INVARIANT=1`** 付きで起動する(温度0でもバッチ非不変性で出力が揺れる。ベンチ台帳の実測でコストは−2%以下=常用可)。
- 並行度は結果に効く。**比較するモデルは同じ並行度で回す**(既定 8/エンドポイント)。ベンチ実測の膝は c=64/GPU なので、8は十分安全側。
- 1エンドポイント=1モデル。3モデルなら3ポート。

### 4-1. 測定前チェック(必ず)

```bash
python selftest.py            # 42件 ALL PASS を確認する
python run_probe.py --dry-run # 171タスク・各系統の概算トークンとmax_tokensを確認する
cat item_set_hash.txt         # 問題セットの版を記録する
```

### 4-2. 試走(1モデル・3問)

```bash
python run_probe.py --endpoints http://127.0.0.1:8000 --limit 3
head -3 quality_ledger.csv
cat raw/*/F1-01__main.txt     # 生出力が日本語で、指定の行形式になっているかを目で見る
```

### 4-3. 本測定

```bash
python run_probe.py \
  --endpoints http://127.0.0.1:8000,http://127.0.0.1:8001,http://127.0.0.1:8002 \
  --quants int8,int8,awq \
  --engine-ver 0.28.0 \
  --conc 8 \
  --out quality_ledger.csv
```

途中で止まっても `--out` を同じにすれば **(model, probe_id, variant) 単位で再開**する。

### 4-4. 集計と目視

```bash
python scorer.py --ledger quality_ledger.csv --probes probes.jsonl --report report.md
python make_visual_review.py --ledger quality_ledger.csv   # 目視用紙に出力を流し込む
```

### 4-5. 任意: 安定性サブセット(②④・temp0.7×R=5)

```bash
python run_probe.py --endpoints http://127.0.0.1:8000 --stability --repeats 5
```

反復は**モデル間比較をほとんど強くしない**(級内相関0.8・R=5でも実効nは45→65程度)。反復は**安定性そのものの測定**(pass^k / self_agreement)としてのみ使う。本測定(温度0)では反復しない。**温度0 + batch_invariant で出力が揺れたら、それは品質指標ではなく環境のバグである。**

## 5. ゲート定義

### 5-1. ⑥ 観測削減(**主目的**)

主指標 = `agree_v0_v1_lb95`(行動クラスの一致率のWilson片側95%下限)。

| 判定 | 条件 | 意味と次の手 |
|---|---|---|
| **合格** | LB95 ≥ **0.80** | v1予算(セル依存≤250・個体≤300・o64)は**安全**。W1=14.8hの決定を品質側から支持できる |
| **条件付き合格** | 0.75 ≤ LB95 < 0.80 | 不一致の全件が層tailに集中し、かつ全件が「v1で落ちた情報を要する」と説明できる場合に限り合格扱い。説明できない不一致が1件でもplain層にあれば不合格側へ |
| **不合格** | LB95 < 0.75 | **個体部予算(B5+B6=300tok)を見直す**。回復レバーの候補は、傍受を残す/近接を上位4に戻す/広告のスカラー化。いずれも呼数への効きはベンチ台帳の実測(個体末尾300→800で−40.6%)から見積もる |

**45場面での上限は LB95 = 0.935(45/45一致時)。**「一致率90%を保証する」とは**v0では名乗れない**(n≥200 が必要)。ユーザーへの提示は必ず「LB80%を通った/通らない」という言い方にする。

副次指標(全て報告する): `agree_full_v1` / `agree_full_v0`(交絡あり)・行き先の完全一致と隣接セル許容・層別(plain/mid/tail)・運用分布での再重み付け値。

**不一致の全件レビューが必須**(45場面なら全件可能・これがv0で最も価値の高い成果物になる)。集計レポートは不一致を表で全件並べる。各件を手で3分類すること:

- (i) 削られた情報が判断を駆動した = **真の代償**
- (ii) どちらの判断も妥当(タイ)= 無害
- (iii) 出力の揺れ = 測定ノイズ(batch_invariantで消えるはず。消えないなら環境のバグ)

### 5-2. ①③⑤ 足切り閾値(案・すべて破綻検出用)

| 指標 | 閾値 | 根拠 |
|---|---|---|
| ① `violation_rate` | ≤ **0.25** | n=8では12〜25pt未満の差は見えない。閾値は「4問に1問以上で制約を破る」= 明白な破綻 |
| ③ `qa_accuracy` | ≥ **0.60** | n=10。10問中6問未満なら役割知識の前提能力(層2)が足りない |
| ⑤ `pair_consistency` | **3組中3組一致** | n=3。統計的な意味はなく、同型場面で裁定が割れる破綻の検出のみ |
| `format_error_rate` | ≤ **0.10** | **品質スコアとは別勘定**。パース失敗率と性能は独立という実証がある(パース失敗0.148%でも性能差38.15%) |
| `ja_char_ratio`(平均) | ≥ **0.85**(暫定) | 破綻検出用。**この絶対閾値は転用できるか不明**(Qwen3-8Bの日本語文字比率73.20%という実測は長文自由生成でのもの)。実測後に再設定する |
| `kana_ratio`(平均) | ≥ **0.20** | 中国語混入の検出器。漢字は中国語と共有するため、ja_char_ratioでは中国語混入を捉えられない |

**足切りを通ったモデルの間の順位づけは、このプローブではしない。**

### 5-3. ⑥以外の合否は「弱い証拠」にすぎない

②のLLMペア判定については `judge_protocol.md` §7 の定型文をそのまま報告に載せる。

## 7. 未確認事項・限界(報告前に必ず読む)

1. **概算トークン係数(1.30文字/tok)は推測。** Qwen3系トークナイザの日本語効率の実測値は未入手。真値は `prompt_tokens` 列で確かめること。**v1が本当に1,300tokに収まっているかは、測定の最初の1行で確認する。**
2. **路上飲酒禁止の対象区域の町名・座標は公式ページ本文になく、別PDFの地図のみ。** セル単位の禁止フラグは作れていないので、本プローブでは観測側に「ここは渋谷駅周辺地域に含まれます」と明記して逃げている。Phase 2で地図読み取りが要る。
3. **行き先の「隣接セル許容」の群分け(`scorer.ADJACENCY_GROUPS`)は暫定。** 100mセルで隣に行くのを同判断と見なすかは世界観の問題であり、**ユーザー判断項目**。既定では完全一致と隣接許容の両方を出す。
4. **運用分布の重み(`TIER_PRIOR` = plain .80 / mid .15 / tail .05)は仮定であって実測ではない。** 再重み付け値は参考値として扱う。
5. **`agree_full_*` は交絡を含む**(fullのB0が上位集合)。主ゲートは `agree_v0_v1`。
6. **`ja_char_ratio` の絶対閾値0.85は暫定。** Qwen3-8Bの73.20%という実測は長文自由生成でのものであり、64トークンの定型出力に転用できるかは未確認。
7. **判定者パネルを候補外にできない**(サーバーに候補モデルしかない)。judge_protocol §2の限界を必ず報告に添える。
8. **⑤の同型ペアは3組**。`pair_consistency` に統計的な意味はなく、破綻検出のみ。
9. **④の幻覚検出は `P-\d{3}` / `C-\d{4}` / 金額 のパターンに限られる。** 「存在しない出来事を描写する」型の幻覚は拾えない。だから④は目視6問に全問入れてある。
10. **45場面での LB95 の上限は 0.935。** 90%ゲートを主張するには n≥200 が必要。
11. **32B AWQ TP4 はスループット上は不成立**(4枚で264 tok/s = 14B INT8 1枚以下)。それでも品質プローブには含める——**品質差の存在判定はここでしかできず、コストは数分**だから。
12. **「文脈長 対 判断一致率」を直接測った先行研究は見つからなかった。** ⑥はv2のオリジナルの寄与になりうるが、比較できる相場観がない。近い先例は「インタビュー記録の80%を削除しても正規化精度0.83→0.79」という当人予測タスクの結果であり、行動選択タスクではない。
