# ペア比較判定プロトコル(品質プローブv0・系統②専用)

> 版: jp-v0.1(2026-09-05)/ 対象: 系統② 発話生成・会話の切り上げ 6問のみ
> **LLM判定はここ以外では使わない。**①③⑤⑥は機械判定、④は機械照合+ユーザー目視。

---

## 0. この文書が守る原則(答申§3-5の必須7条)

1. **ペア比較のみ。絶対評価は禁止。**——日本語の5段階絶対評価はモデル間で4点以上に張り付いて差が消える実測がある(全モデル4.13〜5.00、文法の壊れた出力と正常な出力が両方満点になった例あり)。同じ判定者に正解と比較させるペア形式へ変えると2.5〜3.84に広がった。
2. **AB順序を入れ替えて2回判定し、両順で一致した判定だけを採用する。** 不一致は捨てずに `tie(判定不能)` として別勘定にする。——最強クラスの判定者でも順序を入れ替えると3回に1回は判定が変わる(GPT-4の位置一貫性65.0%、Claude-v1は23.8%)。
3. **判定者は候補モデルを含めない別系統の複数体**が理想(パネル判定)。→ **本v0では満たせない。§2の暫定運用と限界を読むこと。**
4. **参照回答つきで判定させる**(reference-guided)。——参照なしで数学・推論を採点させると誤判定70%、参照ありで15%に下がる実測。
5. **長さを揃えるか、長さを共変量として記録する。**——冗長性バイアスの実測がある(繰り返しリスト攻撃の失敗率: Claude-v1 91.3%、GPT-3.5 91.3%、GPT-4 8.7%)。本プロトコルでは出力長を必ず記録し、勝敗と出力長の相関を報告に添える。
6. **判定プロンプトは版管理し、ハッシュを台帳に記録する。**
7. **LLM判定の出力は「順位」だけに使い、絶対値を予算・設計に反映しない。**

---

## 1. 何を判定させるか

系統②の6問(F2-01〜F2-06)について、2モデルの出力を並べて
**「渋谷の街にいる普通の人の発話として、どちらがより自然で、状況に合っているか」**
だけを判定させる。信憑性・社会規範・秘密といった主観次元は、LLM判定と人手の相関が0.22〜0.45まで落ちる実測があるため、**採点項目を1つに絞る**。

判定に使う情報:
- 場面(probes.jsonl の observation)
- 問い
- 参照回答(§4)
- 回答A / 回答B(順序を入れ替えて2回)

---

## 2. 判定者の構成——**本v0の限界を先に書く**

**理想**: 候補モデル(Qwen3-8B INT8 / 14B INT8 / 32B AWQ)を含まない、別系統の小型モデル3体のパネル。

**実際**: borrowed-2026-09 のサーバーに載っているのは候補モデルだけである(ベンチ台帳の候補=Qwen3-8B INT8・14B INT8・32B AWQ TP4)。別系統の判定者は用意できない。

**暫定運用(採用)**: **各ペアを、そのペアに含まれない第3の候補モデルが判定する。**

| 比較するペア | 判定者 |
|---|---|
| 8B 対 14B | 32B AWQ |
| 8B 対 32B | 14B INT8 |
| 14B 対 32B | 8B INT8 |

**この暫定運用の限界(報告に必ず添えること)**:

- **自己選好は避けられているが、系統内選好は避けられていない。** 判定者も候補も全てQwen3系である。同一系統内のバイアスはパネルでも薄まらない。自己増強バイアスは「回答の出所を匿名化しても大半のモデルが自分の出力を高く評価した」と報告されている。
- **パネルではない(1ペアにつき判定者1体)。** 多数決による分散低減が効かない。
- **32B AWQを判定者に使うが、32BはスループットではTP4で264 tok/s=14B 1枚(317)以下**であり、判定に使うのは「品質差の存在判定」の一環である。判定コストは6問×3ペア×2順序=36呼で数分。
- したがって**本判定の結論は「弱い順位の示唆」までであり、モデル選定の根拠にはならない**。§6の集計しきい値を下回るときは「差が言えない」と書く。

**将来(Phase 2-3のeval基盤)**: 候補外の別系統3体を用意してパネル化する。それまでLLM判定の重みを上げない。

## 3. 判定プロンプト(文面凍結・変更したら版を上げる)

```
あなたは日本語の発話を比べる審査員です。次の場面で、二人の登場人物が返した発話を比べてください。

【場面】
{observation}

【問い】
{question}

【参照回答(良い回答の一例。これと同じである必要はありません)】
{reference}

【回答A】
{answer_a}

【回答B】
{answer_b}

判定の基準は一つだけです:「渋谷の街にいる普通の人の発話として、どちらがより自然で、状況に合っているか」。
長さの差は理由にしないでください。丁寧さの多さも理由にしないでください。

次の2行だけを書いてください。
理由: <40字以内・1文>
判定: <A または B または 引き分け>
```

- 判定者への呼び出しは `temperature=0`, `top_p=1.0`, `seed=20260905`, `max_tokens=96`。
- サーバーは `VLLM_BATCH_INVARIANT=1` で起動しておく。
- `prompt_template_hash` = 上のコードブロック本文(波括弧のプレースホルダを含む生テキスト)の sha256 を quality_ledger の同名列に記録する。

---

## 4. 参照回答(系統②6問・手書き)

参照回答は「これが正解」ではなく、**判定者に基準の高さを見せるためのアンカー**である。

| probe | 参照回答 |
|---|---|
| **F2-01**(用件が済んだ立ち話) | 「資料ありがとうございます。すみません、朝礼があるのでそろそろ行きますね。続きはまた今度で」 |
| **F2-02**(所持金1,000円で5,000円の店) | 「ごめん、今日は手持ちが千円しかないから無理。予約してくれたのに悪いけど、また今度にして」 |
| **F2-03**(シフト5分前のもう1杯) | 「すみません、17時からシフトなので今日はここまでで。またご一緒させてください」 |
| **F2-04**(断る理由のない誘い) | 「いいですね、行きましょう。時間もあるので30分くらいなら大丈夫です」 |
| **F2-05**(啓発地区での勧誘) | 「結構です」(そのまま歩き続ける) |
| **F2-06**(終電が迫る立ち話) | 「すみません、終電なので失礼します。続きはまた明日で」 |

**参照回答の性格**: F2-04 は「断らないのが正しい」対照問題である。参照回答が断っていないことに注意(過剰拒否を良しとしないアンカー)。

## 5. 実行手順

```
# 1. ②の本測定(3モデル)を先に済ませ、raw/<model>/F2-0*.txt を作る
python run_probe.py --endpoints <ep1>,<ep2>,<ep3> --families 2

# 2. ペア判定(AB両順)。判定結果は judge_ledger.csv へ
#    列: pair, probe_id, judge_model, order(AB|BA), winner(A|B|tie), reason, out_tokens,
#        len_a, len_b, prompt_template_hash, ts
#    ※ 判定器のスクリプトはv0では手動運用でよい(6問×3ペア×2順序=36呼)。
```

判定結果の記録では、**AとBがどのモデルだったかを判定者に見せない**(モデル名を出力に含めない)。順序AB/BAの割り当ては probe_id とペアから決定論的に決める。

---

## 6. 集計規則

1. **AB両順で一致した判定だけを「決着」とする。** 不一致は `tie(判定不能)` に入れ、決着数から外す。
2. `judge_pair_consistency` = 両順一致の割合。**この値が 0.65 を下回る判定者の結果は採用しない**(MT-BenchのGPT-4の位置一貫性が65.0%であり、それ未満なら判定者として使えない)。
3. 決着したペアだけに符号検定(exact binomial・両側 p<0.05)をかける。有意ライン:

| 決着ペア数 | 勝ちが「差あり」になる数 |
|---|---|
| 10 | 9 (90%) |
| 20 | 15 (75%) |
| 25 | 18 (72%) |
| 30 | 21 (70%) |
| 50 | 33 (66%) |

**本v0は1ペアあたり決着が最大6件しかない。上の表に照らせば、6件では有意にならない。**
→ **結論の書き方は「順位の示唆」までとし、「差がある」とは書かない。**

4. 出力長と勝敗の相関(点双列相関)を必ず併記する。相関が高ければ冗長性バイアスを疑う。

## 7. 報告の定型文(そのまま使う)

```
系統②のLLMペア判定は、候補モデルと同一系統(Qwen3)の第3モデルを判定者に用いた暫定運用である。
別系統パネルではないため、系統内選好バイアスは除去できていない。
決着ペア数は1組あたり最大6件で、符号検定で有意になる規模ではない。
したがって本判定の結論は「順位の示唆」に限られ、モデル選定の根拠にはならない。
主たる判定は機械判定(終了合図の検出・断るべき誘いの拒否率・日本語文字比率・書式エラー率)側にある。
```
